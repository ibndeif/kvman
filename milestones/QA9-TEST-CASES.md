# QA 9 — a long chat in the running app (ADR 0009, 193–200)

Found by building a todo app in Arabic on a fresh home: the first message failed for want of a key with no way to pick another model, the welcome chat kept its title, a connector call's card dumped its 19 KB command and none of its words, an empty output showed a bare light bar, the cost read `$US 0.0070`, a long chat scrolled the whole page and never followed the newest message, and the model ran `true` to keep going. The product owner chose: no welcome by default, the model picker at the top of the Chat page in the chat's own header, a line and a disabled send when the model has no key, the call card always saying what the call is, and "follow the newest unless I scrolled up". Every scenario names its test. Backend tests use the test kernel and the fake model; `test/web/` mounts components in happy-dom against the fake `kvman`; `test/e2e/` drives Chromium against a real kvman.

## Happy path

- **QA9-H1 No welcome by default.** Retired by QA 33 (ADR 0022, 1): QA33-H10 covers it.
- **QA9-H2 The Chat page shows the model a new chat would use.** *Given* `kvai.defaultModel` `fake/m1` and `kvcoder.model` `null`, *then* the picker in the header reads `M1`, and the thinking select shows `kvcoder.thinking` (`medium` by default, `high` when set); *given* `kvcoder.model` `zed/z1`, *then* the picker reads `Z1`. (`extensions/kvcoder/test/web/chat-start.test.ts`)
- **QA9-H3 A picked model and thinking level are set before the first message.** *Given* the person picks `Z1` and the thinking level `low` and sends, *then* the calls run in this order: `kvcoder.session.create`, `kvcoder.session.configure { sessionId, model: 'zed/z1', thinking: 'low' }`, `kvcoder.message.send`, and the page opens the new chat; *given* only the model was picked, `configure` carries only `model`. (`extensions/kvcoder/test/web/chat-start.test.ts`)
- **QA9-H4 No pick, no configure.** *Given* the person sends without picking anything, *then* `kvcoder.session.configure` is not called. (`extensions/kvcoder/test/web/chat-start.test.ts`)
- **QA9-H5 A model with no key is said, linked, and not sendable.** *Given* the model's provider has status `needsKey`, *then* a line under the question says "<provider title> needs an API key" with an "Add a key" link to the page `kvai.provider` with `providerId`, the send button is disabled, and Enter sends nothing; *when* the person picks a model of a ready provider, *then* the line goes and sending works. (`extensions/kvcoder/test/web/chat-start.test.ts`)
- **QA9-H6 No model at all.** *Given* `kvcoder.model` and `kvai.defaultModel` are both `null`, *then* the picker reads "Choose a model", a line says to choose one, and sending is off until one is picked. (`extensions/kvcoder/test/web/chat-start.test.ts`)
- **QA9-H7 A call without a title shows its description as the title.** *Given* a stored `bash` call (a connector call, with no `details` on its result) that has `description` "Create the todo app HTML file" and no `title`, *then* its card's title is that description, and the description line is not repeated. (`extensions/kvcoder/test/web/call-card.test.ts`)
- **QA9-H8 A long description gives a cut title and is shown in full.** *Given* a description of 80 characters and no title, *then* the title is its first 60 characters and `…`, and the description line shows all 80. (`extensions/kvcoder/test/web/call-card.test.ts`)
- **QA9-H9 A card's command is one short line, and opening it shows everything.** *Given* a command of 19 000 characters, *then* the row holds at most 200 characters of it followed by `…`; *when* the card is opened, *then* its command block holds all 19 000 characters, then its output block. (`extensions/kvcoder/test/web/call-card.test.ts`)
- **QA9-H10 An empty output has no block.** *Given* a result with an empty output, *when* the card is opened, *then* it shows the command block and no output block. (`extensions/kvcoder/test/web/call-card.test.ts`)
- **QA9-H11 The activity line uses the description until the title arrives.** *Given* a `toolcall` chunk with a `description` and no `title` yet, *then* the activity line shows the derived title and the description, not "Preparing…". (`extensions/kvcoder/test/web/live-view.test.ts`)
- **QA9-H12 Command and output blocks are dark in both themes.** *Given* the dark theme and the light theme, *then* an opened card's blocks have a background whose luminance is under 0.2 and text over 0.6. (`extensions/kvcoder/test/e2e/chat-scroll.test.ts`)
- **QA9-H13 In Arabic a cost is an isolated left-to-right run.** *Given* the page language `ar` and a cost of `0.007`, *then* `formatCost` returns U+2066, the amount with `0.0070` and `US$`, and U+2069; in `en` it returns `$0.0070` with no isolate; kvwebui's `usd` status format returns the same strings in both languages. (`extensions/kvcoder/test/web/formats.test.ts`, `extensions/kvwebui/test/web/status-params.test.ts`)
- **QA9-H14 A long chat scrolls inside its column.** *Given* a chat whose answer is 80 paragraphs, in a window 1280 by 800, *then* `main` has no scroll (`scrollHeight <= clientHeight`), the message list scrolls, and the header's top and the send box's bottom are both inside the window. (`extensions/kvcoder/test/e2e/chat-scroll.test.ts`)
- **QA9-H15 Opening a chat shows its last message.** *Given* the chat of QA9-H14, *then* once it has loaded, the message list is scrolled to the end (within 2 px). (`extensions/kvcoder/test/e2e/chat-scroll.test.ts`)
- **QA9-H16 While at the end, new content keeps the view at the end.** *Given* the list is at the end and a message, streamed text, or the activity line is added, *then* the list is at the end again after the update. (`extensions/kvcoder/test/web/follow-latest.test.ts`, `extensions/kvcoder/test/e2e/chat-scroll.test.ts`)
- **QA9-H17 Scrolling up stops following; the button and sending resume it.** *Given* the person scrolls up by more than 80 px, *then* new content does not move the view and the "Jump to latest" button shows; *when* the person clicks it, *then* the list is at the end and the button is gone; *when* the person scrolls up again and sends a message, *then* the list returns to the end. (`extensions/kvcoder/test/web/follow-latest.test.ts`, `extensions/kvcoder/test/e2e/chat-scroll.test.ts`)
- **QA9-H18 The prompt says not to make a call that does nothing.** *Then* the base prompt holds the sentence of ADR 0009, 200. (`extensions/kvcoder/test/unit/prompt-build.test.ts`)

## Edge cases

- **QA9-E1 A preset can still turn the welcome on.** Retired by QA 33 (ADR 0022, 1): the welcome is removed.
- **QA9-E2 The header's picker lists ready providers' models and the shown model only.** *Given* providers `zed` (ready), `fake` (`noKey`), and `locked` (`needsKey`) and the default model `locked/l1`, *then* the groups are Fake, Locked (with `L1` only), and Zed AI. (`extensions/kvcoder/test/web/chat-start.test.ts`)
- **QA9-E3 A failed load doesn't lock the page.** *Given* `kvai.provider.list` rejects, *then* an error toast shows and sending is on; while the lists load, sending is off. (`extensions/kvcoder/test/web/chat-start.test.ts`)
- **QA9-E4 A failed `configure` stops the send.** *Given* `kvcoder.session.configure` rejects, *then* a toast shows and `kvcoder.message.send` is not called. (`extensions/kvcoder/test/web/chat-start.test.ts`)
- **QA9-E5 The pick is for one send.** *Given* the person picked `Z1` and the thinking level `low` and sent, *then* a later visit to the Chat page shows the settings' model and thinking level again. (`extensions/kvcoder/test/web/chat-start.test.ts`)
- **QA9-E6 The derived title's edges.** *Given* a description of exactly 60 characters, *then* the title is it as it is; of 61, its first 60 and `…`; a blank `title` is missing; a given title is kept and the description shows when it differs. (`extensions/kvcoder/test/unit/call-title.test.ts`, `extensions/kvcoder/test/web/call-card.test.ts`)
- **QA9-E7 No title and no description.** *Given* a call with neither, *then* the row shows the command, cut to 200 characters, as its only text. (`extensions/kvcoder/test/web/call-card.test.ts`)
- **QA9-E8 A shell call's card is as before.** *Given* a result with `details` (title, description, exit code, time), *then* its card shows them as in QA7. (`extensions/kvcoder/test/web/call-card.test.ts`)
- **QA9-E9 The follow threshold is exact.** *Given* the list is 80 px from the end, *then* new content follows; at 81 px it does not. (`extensions/kvcoder/test/web/follow-latest.test.ts`)
- **QA9-E10 Another chat lands at its end.** *Given* the person scrolled up in chat A and opens chat B, *then* B is shown at its end, following again, with no "Jump to latest". (`extensions/kvcoder/test/web/follow-latest.test.ts`)
- **QA9-E11 A short chat has no button.** *Given* all messages fit, *then* "Jump to latest" is not shown. (`extensions/kvcoder/test/web/follow-latest.test.ts`)
- **QA9-E12 The session list scrolls on its own.** *Given* 60 sessions, *then* the list is scrollable, `main` has no scroll, and the conversation beside it is unchanged. (`extensions/kvcoder/test/e2e/chat-scroll.test.ts`)
- **QA9-E13 Every new text is in both languages.** *Then* `en` and `ar` have the same keys, including the new ones (the key-needed line, "Add a key", "Choose a model", "Jump to latest", the card's command and output labels). (`extensions/kvcoder/test/locales.test.ts`)
- **QA9-E14 The Chat page in Arabic and a narrow window.** *Given* `ar` and a window 600 wide, *then* the header with its picker, and the send button fit without scrolling sideways.
- **QA9-H19 A new chat looks like a chat.** *Given* the Chat page, *then* it has the chat's header at the top (title "New chat", the model picker, the thinking select, and none of the tabs, menu, Running chip, or totals), the question in the middle, and the send box at the bottom. (`extensions/kvcoder/test/web/chat-start.test.ts`, `extensions/kvcoder/test/e2e/chat-scroll.test.ts`) (`extensions/kvcoder/test/e2e/chat-scroll.test.ts`)
- **QA9-E15 A reply that only calls a tool shows no empty block.** *Given* an assistant message with a tool call and neither text nor thinking, *then* it renders nothing, so cards sit one gap apart; a message with text or thinking renders as before. (`extensions/kvcoder/test/web/call-card.test.ts`)
