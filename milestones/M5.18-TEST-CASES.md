# M5.18 — OpenUI in the conversation and in artifacts: test cases

Read: `06` §6.1, §6.4, §6.8, and §6.9; `08` §8.5 (openui, artifact, delegate) and §8.7; ADR 0124.

The layers: kvwebui's app mounted in happy-dom against the fake API (`test/web/`); kvwebui's built app in Chromium
(`test/e2e/`); the generated reference pages as files and through `kvwebui.docs.get` (`test/`); kvcoder's connector,
grants, and artifacts through the test kernel (`test/`); kvcoder's conversation mounted in happy-dom (`test/web/`); a
real chat, by hand.

The 43 components of this milestone are: `Stack`, `Tabs`, `TabItem`, `Accordion`, `AccordionItem`, `Steps`,
`StepsItem`, `Separator`, `SectionBlock`, `SectionItem`, `Card`, `CardHeader`, `TextContent`, `MarkDownRenderer`,
`Callout`, `TextCallout`, `CodeBlock`, `InlineHeader`, `Form`, `FormControl`, `Label`, `Input`, `TextArea`, `Select`,
`SelectItem`, `DatePicker`, `Slider`, `CheckBoxGroup`, `CheckBoxItem`, `RadioGroup`, `RadioItem`, `SwitchGroup`,
`SwitchItem`, `Chips`, `ChipItem`, `Button`, `Buttons`, `IconButton`, `Icon`, `Tag`, `TagBlock`, `FollowUpBlock`, and
`FollowUpItem`.

## Happy path

### M5.18-H1 — a fenced `openui` block in Markdown draws its components
- **Given** a Markdown view whose text is a paragraph, a fenced `openui` block (`root = Card([header, body])` with a `CardHeader` and a `TextContent`), and another paragraph
- **When** it is shown
- **Then** both paragraphs are Markdown in their places, and between them the card is drawn with its header's title and its text; no `<pre>` holds the block's source
- Test: `extensions/kvwebui/test/web/openui-blocks.test.ts`

### M5.18-H2 — a block streamed line by line draws as it arrives
- **Given** a Markdown view showing a block whose text grows one line at a time, with `root` first and its children defined after it
- **When** each line arrives
- **Then** each child appears once its line has arrived, and the last state is the same DOM as the whole block shown at once
- Test: `extensions/kvwebui/test/web/openui-blocks.test.ts`

### M5.18-H3 — the `openui` view draws with `openuiLibrary`
- **Given** `kvman.View` with `{ type: 'openui', source }`, where `source` is `root = Stack([title, tags])` with a `TextContent` and a `TagBlock`
- **When** it is shown
- **Then** the stack, the text, and each tag are drawn; the same source in a fenced block is drawn with the chat library, whose root is `Card`
- Test: `extensions/kvwebui/test/web/openui-view.test.ts`

### M5.18-H4 — each layout and content component draws from its signature
- **Given** one example per component of `Stack`, `Tabs`/`TabItem`, `Accordion`/`AccordionItem`, `Steps`/`StepsItem`, `Separator`, `SectionBlock`/`SectionItem`, `Card`, `CardHeader`, `TextContent`, `MarkDownRenderer`, `Callout`, `TextCallout`, `CodeBlock`, `InlineHeader`, `Tag`, `TagBlock`, written by OpenUI's signature
- **When** each is drawn
- **Then** each shows its texts; a `TabItem`'s content shows when its tab is pressed and the first is shown at first; an `AccordionItem` opens and closes; `CodeBlock` shows its code in a monospace block with Copy, which copies it; `TextContent` and `MarkDownRenderer` draw Markdown through the sanitized renderer (a `<script>` in it is not in the DOM); every text the model wrote has `dir="auto"`
- Test: `extensions/kvwebui/test/web/openui-layout.test.ts`

### M5.18-H5 — each form component draws, and a bound control updates what depends on it
- **Given** a `Form` with one `FormControl` per control: `Input`, `TextArea`, `Select` with `SelectItem`s, `DatePicker`, `Slider`, `CheckBoxGroup`, `RadioGroup`, and `Chips`; a `SwitchGroup` and a `Label` beside the form; and an `Input` bound to `$name` with a `TextContent("Hello " + $name)`
- **When** the person types, picks, checks, slides, and presses chips
- **Then** each control shows its value; `DatePicker` is the browser's date input; typing in the bound `Input` changes the text to `Hello <typed>`
- Test: `extensions/kvwebui/test/web/openui-forms.test.ts`

### M5.18-H6 — a button sends its text through `onMessage`
- **Given** `kvman.View` with an `openui` view and `onMessage`, holding `Button("Yes", Action([@ToAssistant("Use the first plan")]))`, `Button("Maybe")`, a `FollowUpBlock` with `FollowUpItem("Tell me more")`, and an `IconButton` with an action
- **When** the person presses each
- **Then** `onMessage` is called with `Use the first plan`, `Maybe` (a button with no action sends its label), `Tell me more`, and the icon button's message, once each, in order
- Test: `extensions/kvwebui/test/web/openui-presses.test.ts`

### M5.18-H7 — a form's button sends the form's values
- **Given** a `Form` whose `FormControl`s are an `Input` labelled "Name", a `Select` labelled "Room" whose items have values `a` and `b` and labels "Garden" and "Sea", a `CheckBoxGroup` labelled "Extras" with the items "Breakfast" and "Parking", a range `Slider` labelled "Budget", and an empty `TextArea` labelled "Notes", with `Buttons([Button("Send", Action([@ToAssistant("Book it")]))])`
- **When** the person types `Ada`, picks Sea, checks both extras, sets the budget to 100 and 300, and presses Send
- **Then** `onMessage` gets `Book it`, a blank line, then `Name: Ada`, `Room: Sea`, `Extras: Breakfast, Parking`, `Budget: 100 – 300`, and `Notes: (empty)`, one per line in the controls' order (ADR 0124, 14)
- Test: `extensions/kvwebui/test/web/openui-presses.test.ts`

### M5.18-H8 — `@OpenUrl` opens a web address through `kvman.open`
- **Given** a view with `onMessage` and `Button("Docs", Action([@OpenUrl("https://example.com/docs")]))`
- **When** the person presses it
- **Then** the address opens in a new tab through `kvman.open` and `onMessage` isn't called
- Test: `extensions/kvwebui/test/web/openui-presses.test.ts`

### M5.18-H9 — `$variables` with `@Set` and `@Reset` change only the page
- **Given** a view with `$count = 0`, `TextContent("Count " + $count)`, `Button("Add", Action([@Set($count, $count + 1)]))`, and `Button("Clear", Action([@Reset($count)]))`
- **When** the person presses Add twice, then Clear
- **Then** the text reads `Count 1`, `Count 2`, then `Count 0`; `onMessage` is never called and no request is made
- Test: `extensions/kvwebui/test/web/openui-presses.test.ts`

### M5.18-H10 — `Icon` draws a Lucide icon by name, from a chunk loaded on first use
- **Given** kvwebui's built app in Chromium
- **When** a page with no icon block is opened, then a block with `Icon("rocket")` and `IconButton("Launch", Icon("rocket"), …)` is shown
- **Then** the rocket's module was not requested before the block; then it is requested once and both draw the rocket's SVG
- Test: `extensions/kvwebui/test/e2e/openui.test.ts`

### M5.18-H11 — the components follow the theme and right to left
- **Given** kvwebui's built app in Chromium with a block of every component of this milestone
- **When** it is shown in the light theme, the dark theme, and in Arabic
- **Then** every component's colors come from the `--kv-*` variables (none is pure white or black), and in Arabic the stack, the tabs, the steps, the accordion's chevrons, and the form's labels mirror (each component's start is on the right)
- Test: `extensions/kvwebui/test/e2e/openui.test.ts`

### M5.18-H12 — the reference pages are what the script writes
- **Given** the repository
- **When** `openui:reference` writes its pages to a temporary folder
- **Then** each file equals the one in kvwebui's `docs/`: `openui-chat.md` and `openui.md` (the indexes), and one page per group with a built component, `openui-chat-<group>` and `openui-<group>`, whose first line is `# <group>`
- Test: `extensions/kvwebui/test/openui-reference.test.ts`

### M5.18-H13 — an index names the rules, the syntax, and each group's components
- **Given** the pages `openui-chat` and `openui`
- **When** they are read through `kvwebui.docs.get`
- **Then** each has kvman's rules (a fenced `openui` block in a reply, `format: 'openui'` for an artifact, no `Query`, `Mutation`, or `@Run`, images only from the workspace or `data:`, what a press sends), OpenUI Lang's syntax, actions, streaming, and rules, one line per group with exactly its built components, and an example for its place; `kvwebui.docs.list` lists every page
- Test: `extensions/kvwebui/test/openui-reference.test.ts`

### M5.18-H14 — `openui guide` gives the index for the place
- **Given** a lead chat with kvwebui and kvcoder loaded
- **When** the agent calls `openui guide { place: 'reply' }`, then `{ place: 'artifact' }`
- **Then** they answer `{ guide }` with the text of `openui-chat` and of `openui`
- Test: `extensions/kvcoder/test/openui-connector.test.ts`

### M5.18-H15 — `openui guide` with groups gives those groups
- **Given** a lead chat
- **When** the agent calls `openui guide { place: 'artifact', groups: ['Forms', 'Buttons'] }`
- **Then** `guide` is the page `openui-forms`, a blank line, then `openui-buttons`, in that order
- Test: `extensions/kvcoder/test/openui-connector.test.ts`

### M5.18-H16 — the lead's index lists `openui` with its one command line
- **Given** a lead chat
- **When** its prompt is built
- **Then** the connector index has `openui` with its description and the line for `guide` with its signature, and none of the guide's text
- Test: `extensions/kvcoder/test/openui-connector.test.ts`

### M5.18-H17 — an `openui` artifact is stored and shown through the `openui` view
- **Given** a lead chat
- **When** the agent calls `artifact write { id: 'dash', title: 'Dashboard', format: 'openui', content }`
- **Then** it is stored with `format: 'openui'` and version 1; `artifact get` and `kvcoder.artifact.get` return it; the panel shows it through `{ type: 'openui', source: content }` with `onMessage`, its kind reads "OpenUI", and Source shows its text
- Test: `extensions/kvcoder/test/artifact-openui.test.ts`, `extensions/kvcoder/test/web/openui-conversation.test.ts`

### M5.18-H18 — a press in the newest reply sends the person's message
- **Given** an idle lead chat whose newest reply has a fenced `openui` block with `Button("Go", Action([@ToAssistant("Start the build")]))`
- **When** the person presses Go
- **Then** `kvcoder.message.send` runs with `text: 'Start the build'` and a `sendId`, as a typed message does, and the message shows in the chat
- Test: `extensions/kvcoder/test/web/openui-conversation.test.ts`

### M5.18-H19 — a press while the agent works steers the turn
- **Given** a running lead turn whose newest stored reply has a block with a button
- **When** the person presses it
- **Then** `kvcoder.message.send` runs with its text, as a typed message sent while the agent works does
- Test: `extensions/kvcoder/test/web/openui-conversation.test.ts`

### M5.18-H20 — a press in an `openui` artifact sends the person's message
- **Given** a lead chat with an `openui` artifact holding a button, shown in the panel
- **When** the person presses it
- **Then** `kvcoder.message.send` runs with its text
- Test: `extensions/kvcoder/test/web/openui-conversation.test.ts`

### M5.18-H21 — by hand: choices, follow-ups, and a short form in a real chat
- **Given** a real chat with a model
- **When** the person asks for something with a choice to make, in English and then in Arabic
- **Then** the lead reads `openui guide` and the groups it needs, answers with buttons and follow-ups, and with a short form whose answer it reads and acts on
- Test: by hand (README)

## Edge cases

### M5.18-E1 — a block that draws nothing shows its source
- **Given** a Markdown view with a finished fenced `openui` block that is plain text (`hello world`), and another whose `root` is an unknown component
- **When** it is shown
- **Then** each block is a code block holding its source, and the text "Couldn't draw this UI" is above it, in the page's language
- Test: `extensions/kvwebui/test/web/openui-blocks.test.ts`

### M5.18-E2 — an unknown component or a missing required field leaves out that part
- **Given** a block whose `Stack` holds a `TextContent`, an unknown `Chart3D(…)`, and a `Callout` with no `title`
- **When** it is shown
- **Then** the text is drawn, and neither the unknown component nor the callout is; no error card replaces the block
- Test: `extensions/kvwebui/test/web/openui-blocks.test.ts`

### M5.18-E3 — a block still streaming never shows its source
- **Given** a Markdown view whose text ends in an open fence `openui` with `root = Card([later])` and `later` not yet arrived
- **When** it is shown while streaming
- **Then** what has parsed is drawn and no source code block nor the failure text is shown
- Test: `extensions/kvwebui/test/web/openui-blocks.test.ts`

### M5.18-E4 — `Query`, `Mutation`, and `@Run` do nothing
- **Given** a block with `data = Query("tickets", {})`, `TextContent("Rows " + @Count(data.rows))`, and `Button("Run", Action([@Run(data)]))`, shown with `onMessage`
- **When** it is drawn and the button pressed
- **Then** no request is made, the text draws with what `null` gives, `onMessage` isn't called, and nothing throws
- Test: `extensions/kvwebui/test/web/openui-presses.test.ts`

### M5.18-E5 — without `onMessage`, presses do nothing and controls are disabled
- **Given** the same block as M5.18-H6 and a form, in a Markdown view with no `onMessage`
- **When** the person presses each button and follow-up
- **Then** every button, follow-up, and form control is disabled, and nothing is sent or opened
- Test: `extensions/kvwebui/test/web/openui-presses.test.ts`

### M5.18-E6 — controls are disabled while the block streams
- **Given** a view with `onMessage` whose block is still streaming
- **When** the person presses its button
- **Then** it is disabled and `onMessage` isn't called; once the stream ends it works
- Test: `extensions/kvwebui/test/web/openui-presses.test.ts`

### M5.18-E7 — a form whose rules fail sends nothing
- **Given** a `Form` with an `Input` with `{required: true, email: true}` and a primary button with `@ToAssistant`
- **When** the person presses it with the field empty, then with `not-an-email`
- **Then** `onMessage` isn't called and the field shows its rule's error in the page's language each time; with a valid email it sends
- Test: `extensions/kvwebui/test/web/openui-presses.test.ts`

### M5.18-E8 — `@OpenUrl` opens only http and https
- **Given** buttons with `@OpenUrl` of `javascript:alert(1)`, `data:text/html,x`, `file:///etc/passwd`, and `/relative`
- **When** the person presses each
- **Then** nothing opens and `onMessage` isn't called
- Test: `extensions/kvwebui/test/web/openui-presses.test.ts`

### M5.18-E9 — an unknown icon falls back as OpenUI's does
- **Given** `Icon("no-such-icon", "finance")`, `Icon("no-such-icon")`, and an `IconButton` with the second
- **When** they are drawn
- **Then** the first draws `dollar-sign`, the second `circle-dot`, and the icon button shows its accessible name and works
- Test: `extensions/kvwebui/test/web/openui-layout.test.ts`

### M5.18-E10 — drawing makes no network request
- **Given** kvwebui's built app in Chromium
- **When** a block of every component of this milestone, with a `MarkDownRenderer` holding a Markdown image of `https://example.com/x.png` and a link, is drawn and its buttons pressed
- **Then** no request leaves for any address other than kvman's own
- Test: `extensions/kvwebui/test/e2e/openui.test.ts`

### M5.18-E11 — the `openui` view is checked like any view
- **Given** `kvman.View` with `{ type: 'openui' }` with no `source`, and with `source: 5`
- **When** it is shown
- **Then** an error card with `VALIDATION_FAILED` and its issues is shown
- Test: `extensions/kvwebui/test/web/openui-view.test.ts`

### M5.18-E12 — the components use logical styles only
- **Given** the source of every OpenUI component of kvwebui
- **When** it is read
- **Then** no class or style uses a physical left or right (`ml-`, `mr-`, `pl-`, `pr-`, `left`, `right`, `border-l`, `border-r`, `rounded-l`, `rounded-r`, `text-left`, `text-right`, `margin-left`, `padding-right`, …)
- Test: `extensions/kvwebui/test/sources.test.ts`

### M5.18-E13 — kvwebui's own texts are translated
- **Given** the locale catalogs
- **When** the keys of the OpenUI texts are read ("Couldn't draw this UI", Copy and Copied, the form rules' errors, the accordion's and tabs' labels)
- **Then** each has an `en` and an `ar` text
- Test: `extensions/kvwebui/test/locales.test.ts` (M2.2-E17 checks every text the app names, `en` and `ar` with the same keys and placeholders)

### M5.18-E14 — the pages never use `Query`, `Mutation`, or `@Run`, and use Lang 0.5's actions
- **Given** every generated page
- **When** it is read
- **Then** none has `Query(`, `Mutation(`, or `@Run(` (the index says there are none); no note passes a bare `@ToAssistant`, `@OpenUrl`, `@Set`, or `@Reset` where an action goes, each is inside `Action([…])`
- Test: `extensions/kvwebui/test/openui-reference.test.ts`

### M5.18-E15 — the pages hold only built components, and no empty group
- **Given** the generated pages
- **When** they are read
- **Then** no signature, note, or union names a component of M5.19 or M5.20 (`Table`, `Image`, `Modal`, `BarChart`, …); a group with no built component (`Tables`, `Charts (2D)`, `Cards`, …) has no page and no line in its index
- Test: `extensions/kvwebui/test/openui-reference.test.ts`

### M5.18-E16 — the sizes
- **Given** the generated pages
- **When** their sizes are measured
- **Then** each index is at most 8 KB, and each library's group pages joined (the answer of `openui guide` for every group) are at most 30 KB
- Test: `extensions/kvwebui/test/openui-reference.test.ts`

### M5.18-E17 — an unknown group fails and names the groups
- **Given** a lead chat
- **When** the agent calls `openui guide { place: 'reply', groups: ['Charts (2D)'] }`, and `{ place: 'artifact', groups: ['Forms', 'Nope'] }`
- **Then** each fails `VALIDATION_FAILED` with a message that names the unknown group and lists the place's groups
- Test: `extensions/kvcoder/test/openui-connector.test.ts`

### M5.18-E18 — bad payloads fail
- **Given** a lead chat
- **When** the agent calls `openui guide {}`, `{ place: 'page' }`, `{ place: 'reply', groups: [] }`, 14 groups, or an unknown key
- **Then** each fails `VALIDATION_FAILED`
- Test: `extensions/kvcoder/test/openui-connector.test.ts`

### M5.18-E19 — a helper never has `openui`
- **Given** a helper session of a lead chat, with `connectors: null`, and one whose worker lists `openui`
- **When** its prompt is built and it calls `openui guide { place: 'reply' }`
- **Then** its index has no `openui`, and the call fails `VALIDATION_FAILED` with "openui isn't available in this subagent.", as a call to `ask` does
- Test: `extensions/kvcoder/test/openui-connector.test.ts`

### M5.18-E20 — turned off, the connector is gone and `openui` artifacts are refused
- **Given** `kvcoder.connectors.disabled` holding `openui`
- **When** the lead's prompt is built, the agent calls `openui guide { place: 'reply' }`, and `artifact write { format: 'openui', … }`
- **Then** the index has no `openui`; the call gets the answer for a connector that doesn't exist; the write fails `VALIDATION_FAILED` with "The openui connector is turned off." and stores nothing; an `openui` artifact written before is still listed and shown
- Test: `extensions/kvcoder/test/artifact-openui.test.ts`, `extensions/kvcoder/test/openui-connector.test.ts`

### M5.18-E21 — an `openui` artifact is never inferred
- **Given** a lead chat
- **When** the agent writes, with no `format`, content that starts with `root = Card(`
- **Then** it is stored as `markdown`
- Test: `extensions/kvcoder/test/artifact-openui.test.ts`

### M5.18-E22 — `artifact edit` keeps an `openui` artifact's format
- **Given** an `openui` artifact
- **When** the agent edits one line of it
- **Then** it stays `openui`, at version 2, with the edit applied
- Test: `extensions/kvcoder/test/artifact-openui.test.ts`

### M5.18-E23 — older replies are drawn disabled

### M5.18-E24 — a helper's chat and the streaming answer are drawn disabled

- **Then** each is disabled and nothing is sent

### M5.18-E25 — a press leaves the send box alone, and a failed one says so

### M5.18-E26 — the new texts are translated
