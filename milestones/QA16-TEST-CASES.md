# QA 16 — the providers UI, made usable and prettier (ADR 0009, 238–249)

Asked to "optimize and enhance the providers UI user experience and make it usable and prettier". The product owner chose, from mockups: connected first, then connect, then all providers; a short fixed list of quick-connect tiles; coloured letter avatars; and a searchable model picker. Tests mount the components in happy-dom with a fake injected `kvman` (`extensions/kvai/test/web/support/fake-kvman.ts`) and kvai's real catalogs. Behaviours of the connection section that QA 15 already covers (sign-in chunks, Disconnect, Remove, failures) keep their QA15 ids and move to the new component's tests.

## Happy path

- **QA16-H1 The default-model card.** *Given* a default model `openai/gpt-6-luna` named "GPT-6 Luna" whose provider is connected with a plan, *then* the card shows the avatar "O", the label, "GPT-6 Luna", the id, "Connected with your ChatGPT plan"-style line from the provider's connection, a "Ready" chip, and a "Change model" button; *given* `ready: false`, the chip reads "Not ready". (`extensions/kvai/test/web/providers-default.test.ts`)
- **QA16-H2 "Connected" lists what is usable.** *Given* rows for OpenAI (plan), OpenRouter (key), a custom `relay`, and unconnected Anthropic, *then* "Connected" has a card each for the first three, with the right line ("Connected with your plan", "Connected with an API key", "Your own server"), its model count, a "Default" chip only on the default model's provider, and a count of 3 in the heading; "Manage" calls `kvman.navigate('kvai.provider', { providerId })`. (`extensions/kvai/test/web/providers-connected.test.ts`)
- **QA16-H3 The quick-connect tiles.** *Given* nothing connected and every featured provider present, *then* "With your plan" shows Claude, ChatGPT, and GitHub Copilot ("Sign in with your plan"), "With an API key, or your own server" shows Anthropic, Google, xAI, and "Your own server"; a tile opens its provider's page (`kvai.provider` with `providerId` `anthropic`, `openai`, `github-copilot`, `anthropic`, `google`, `xai`), and "Your own server" opens `kvai.provider-add`. (`extensions/kvai/test/web/providers-connect.test.ts`)
- **QA16-H4 "All providers".** *Given* 60 unconnected built-in providers, *then* 25 are shown A–Z by title, each with the avatar, the title, "N models", and a "Connect" link to its page; "Show 25 more" shows 50, then 60 and no button. Connected and custom providers are not in this list. (`extensions/kvai/test/web/providers-all.test.ts`)
- **QA16-H5 Search narrows "All providers".** *Given* titles "Amazon Bedrock", "Azure OpenAI", "Baseten" with ids `amazon-bedrock`, `azure-openai-responses`, `baseten`, *then* typing `  OPENAI ` shows only Azure OpenAI, and `zzz` shows "No provider matches." (`extensions/kvai/test/web/providers-all.test.ts`)
- **QA16-H6 The avatar.** *Then* the letter is the title's first letter in upper case, the colour is the palette entry at (sum of the id's character codes) mod 8, the same id always gives the same colour, the palette is exactly the eight colours of ADR 243, and the avatar is `aria-hidden`. (`extensions/kvai/test/web/provider-avatar.test.ts`)
- **QA16-H7 The model picker picks.** *Given* callable providers OpenAI (2 models) and a custom `relay` (1 model) and an unconnected Anthropic, *when* "Change model" is pressed, *then* the popover lists the three models under "OpenAI" and "relay" titles and none of Anthropic's, `kvai.model.list` was called for the two callable providers only, typing narrows by name or id ignoring case, and picking one calls `kernel.settings.set { key: 'kvai.defaultModel', value: '<provider>/<model>', scope: 'global' }`, toasts "The default model is set." (`kvman.toast('kvai.ui.models.defaultSet', {}, 'success')`), closes, and refreshes. (`extensions/kvai/test/web/model-picker.test.ts`)
- **QA16-H8 The picker works from the keyboard and closes.** *Then* the search box has focus when it opens; ArrowDown highlights the first model, again the second; ArrowUp goes back; Enter picks the highlighted one; Escape closes without calling anything; a click outside closes. (`extensions/kvai/test/web/model-picker.test.ts`)
- **QA16-H9 The Provider page's header and a connected provider.** *Given* OpenAI connected with a plan, *then* the header shows the avatar, the title, `openai · 44 models`, and a "Connected" chip; the section shows "Connected with your plan", Disconnect, and "Prefer an API key instead?" with a button that opens the key choice; saving a key there calls `kvai.provider.key.set`. A provider connected by a key shows the plan version. The back link is `kvman.navigate('kvai.models')`. (`extensions/kvai/test/web/provider-page.test.ts`)
- **QA16-H10 A provider that isn't connected.** *Given* Anthropic offering both, *then* two choices show, "Your plan" first and highlighted (`data-highlight="true"`) with "Sign in with your plan" and the terms note, and "An API key" with the password field; `openai-codex` (`apiKey: false`) shows only the plan choice; a custom provider (`signIn: false`) shows only the key choice and "Your own server". (`extensions/kvai/test/web/provider-page.test.ts`)
- **QA16-H11 A sign-in in the new layout.** *Then* every QA15-H11 behaviour holds in the new section: the link (`rel="noopener noreferrer"`, `http(s)` only), the device code, the prompt field or choice sending `kvai.provider.signin.answer`, "Working…", the spinner row, "Open the sign-in page again", Cancel calling `kvai.provider.signin.cancel`, and the refresh and toast when it ends. The ids QA15-H11 and QA15-E18 name these tests. (`extensions/kvai/test/web/provider-signin.test.ts`)
- **QA16-H12 The provider's models.** *Given* 60 models, *then* "Models 60" shows 25 rows A–Z, each with the name, the id, "Thinking" with a check for a reasoning model, the context window, and "Make default" (the default model's row has a "Default" chip, `data-default="true"`, and no button); "Show 25 more" adds 25; "Make default" calls `kernel.settings.set` as in H7 and toasts; the search matches name or id ignoring case, and `zzz` shows "No model matches." (`extensions/kvai/test/web/provider-models.test.ts`)
- **QA16-H13 The pages are wired and built.** *Then* the `models` page's view tree is a heading, a text, and `{ type: 'custom', component: 'kvai.providers', props: {} }`; the `provider` page's is `{ type: 'custom', component: 'kvai.provider', props: { providerId: { $param: 'providerId' } } }` only; `web-build.config.ts` lists `providers` and `provider` and no `connection`; `web/components/providers.vue` and `provider.vue` exist and `connection.vue` does not; every text key kvai's view trees name exists in both catalogs. (`extensions/kvai/test/ui.test.ts`)

## Edge cases

- **QA16-E1 Empty states.** *Then* with nothing connected "Connected" says "Nothing is connected yet. Pick a provider below."; with no default model the card says "No default model yet…" with "Choose a model"; a picker with no callable provider says "Connect a provider first."; a model search with no match says "No model matches." (`extensions/kvai/test/web/providers-default.test.ts`, `providers-connected.test.ts`, `model-picker.test.ts`)
- **QA16-E2 Tiles drop out.** *Given* Anthropic connected and `google` missing from the list, *then* the Claude and Anthropic tiles and the Google tile are not shown, the other tiles are, "Your own server" always is, and a group with no tile left is hidden. (`extensions/kvai/test/web/providers-connect.test.ts`)
- **QA16-E3 Failures show a translated reason.** *Given* `kvai.provider.list` fails with a Problem, *then* the page shows its text and no sections; *given* `kernel.settings.set` fails, the picker stays open and shows the text and nothing is toasted; *given* `kvai.model.list` fails for one provider, the picker shows the error and still lists the others; an unknown provider on the Provider page shows `kvai/PROVIDER_UNKNOWN`'s text. (`extensions/kvai/test/web/providers-default.test.ts`, `model-picker.test.ts`, `provider-page.test.ts`)
- **QA16-E4 The picker's cap.** *Given* 150 callable models, *then* 100 show with "Keep typing to narrow the list.", and a search that leaves 3 shows 3 and no hint. (`extensions/kvai/test/web/model-picker.test.ts`)
- **QA16-E5 Search is forgiving.** *Then* surrounding spaces and upper case don't matter in the three searches (providers, picker, provider's models). (`extensions/kvai/test/web/providers-all.test.ts`, `model-picker.test.ts`, `provider-models.test.ts`)
- **QA16-E6 Right to left.** *Then* `web/styles/kvai.css` uses none of `margin-left`, `margin-right`, `padding-left`, `padding-right`, `left:`, `right:`, `border-left`, `border-right`, `text-align: left`, `text-align: right`, and has a `:dir(rtl)` rule that mirrors the arrow and chevron icons. (`extensions/kvai/test/web/provider-page.test.ts`)
- **QA16-E7 No raw keys.** *Then* every state of both components (each of H1–H12 and the empty and failed ones), rendered with the `en` and the `ar` catalog, shows no text that is a `kvai.` key. (`extensions/kvai/test/web/providers-default.test.ts`, `provider-page.test.ts`)
- **QA16-E8 Disconnect, Remove, and failures keep working.** *Then* the QA15 scenarios H10 (as H9/H10 here), H12, E18, E19, and E21 pass against `kvai.provider`: Disconnect and Remove provider ask first and call their commands; a failed one shows its text and changes nothing; a built-in provider has no Remove provider. (`extensions/kvai/test/web/provider-actions.test.ts`)
- **QA16-E9 Switching the provider.** *Given* the Provider page's `providerId` changes while a sign-in runs, *then* the running sign-in is cancelled (`kvai.provider.signin.cancel`) and the new provider is read. (`extensions/kvai/test/web/provider-signin.test.ts`)
