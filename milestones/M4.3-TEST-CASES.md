# M4.3 — Publishing the extension: test cases

Read: `15` §15.7; ADR 0026, 8 to 10; ADR 0038, 52; ADR 0099, 36, 37, and 49.

The workflow is read as a file; it runs only on a version tag, and publishing needs the product owner's publisher and tokens. The `.vsix` is built and listed by a test, and installed by hand with `code --install-extension`.

## Happy path

### M4.3-H1 — `pnpm vscode:package` writes the `.vsix` with one bundled file and no `node_modules`
- **Given** the repository after `pnpm install`
- **When** `pnpm vscode:package` runs, and `vsce ls` lists what it packed
- **Then** `packages/vscode/dist/kvman.vsix` exists; the packed files are the bundle `extension.js`, `page/relay.js`, `page.css`, the manifest `package.json` at the root version with the name `kvman` and the publisher `ibndeif`, its two `package.nls` files, the two icons, the README, and the license, and no `node_modules`
- Test: `packages/vscode/test/package.test.ts`

### M4.3-H2 — the release's `vscode` job builds, attaches to the tag's draft release, and publishes
- **Given** `.github/workflows/release.yml`
- **When** its `vscode` job is read
- **Then** it runs on the version tag, checks the tag against the root version first, installs, runs `pnpm vscode:package`, creates the tag's draft release when none exists, uploads the `.vsix` to it, then runs `vsce publish` with `VSCE_PAT` and `ovsx publish` with `OVSX_PAT`, each from its repository secret; only this job has `contents: write`
- Test: `packages/cli/test/release-workflow.test.ts`

### M4.3-H3 — the user guide has a page for the extension
- **Given** the user guide
- **When** its pages are read
- **Then** `vscode-extension.md` covers installing the extension, the install offer, where the view is, local folders only, and the shared home, with a Next list, and the index links it
- Test: `packages/cli/test/docs.test.ts`

## Edge cases

### M4.3-E1 — a failed packaging publishes nothing
- **Given** the `vscode` job
- **When** its steps are read in order
- **Then** packaging comes before the release upload and both publishes, each a step of its own, so a failed step stops the job before anything is attached or published
- Test: `packages/cli/test/release-workflow.test.ts`

### M4.3-E2 — the tokens come from repository secrets only
- **Given** the workflow and every tracked file
- **When** they are read
- **Then** `VSCE_PAT` and `OVSX_PAT` appear only as `${{ secrets.VSCE_PAT }}` and `${{ secrets.OVSX_PAT }}`
- Test: `packages/cli/test/release-workflow.test.ts`
