# QA 21 — each extension's configuration (ADR 0014)

Asked: the Settings page shows only the general settings; each extension is configured from the Extensions page, by a configuration UI the extension manages (kvcoder: the connectors, with on and off), not by a list of its API. Decided in ADR 0014; plan 06 §6.3, §6.4, and §6.6, plan 08 §8.2 to §8.7. This file is the contract; every scenario's test name starts with its id.

*Changed by QA 22 (ADR 0015): kvwebui's page shows only its theme (H7 is now QA22-H1), the connectors list no longer says where a connector comes from (H11), and the model settings are rows the extensions draw (H10).*

## Happy path

- **QA21-H1 The Settings page holds kvman's own settings.** *Given* settings of `kernel`, `kvwebui`, and `notes`, *then* the page shows the `kernel.*` rows only, with no scope switch, no Secrets section, and its search box; changing one sends `scope: 'global'`. `extensions/kvwebui/test/web/settings-page.test.ts`
- **QA21-H2 The Extensions page is a list of links.** *Then* each extension shows its title, package name, version, and source, as a link to `/kvwebui/extension/<namespace>`, and nothing of its commands, queries, or handlers; the search box filters by title or package name. `extensions/kvwebui/test/web/extensions-page.test.ts`
- **QA21-H3 An extension's page shows its configuration.** *Given* `notes.ui.get` with `configuration` holding a heading and `setting { key: 'notes.pageSize' }`, *when* the person opens `/kvwebui/extension/notes`, *then* the page shows the link back, the title, name, version, and source, "Remove", the scope switch, the heading, and the row `setting-notes.pageSize`. `extensions/kvwebui/test/web/extension-page.test.ts`
- **QA21-H4 A setting row saves into the page's scope.** *When* the person changes `notes.pageSize` on "All workspaces", then on "Only ahmed", *then* the calls are `kernel.settings.set` with `scope: 'global'`, then `scope: 'workspace'`. `extensions/kvwebui/test/web/extension-page.test.ts`
- **QA21-H5 Secrets are on the extension's page.** *Given* secrets of two extensions, *then* `/kvwebui/extension/notes` lists only `@acme/notes`'s, masked; "Add a secret" sends `kernel.secrets.set { extension: '@acme/notes', name, value }` and shows no value; Delete asks, then sends `kernel.secrets.delete`. `extensions/kvwebui/test/web/extension-page.test.ts`
- **QA21-H6 A custom component reads the page's scope.** *Given* a `custom` view in a configuration, *then* its `kvman.scope.value` is `global`, and `workspace` after the person picks "Only ahmed"; on a normal page it is `global`. `extensions/kvwebui/test/web/extension-page.test.ts`
- **QA21-H7 kvwebui's own page.** *Then* `/kvwebui/extension/kvwebui` shows `kvwebui.theme`, `kvwebui.nav.order`, and `kvwebui.nav.hidden` as rows, and `kvwebui.title` and `kvwebui.home` locked. `extensions/kvwebui/test/web/extension-page.test.ts`
- **QA21-H8 A connector that is off is gone for the agent.** *Given* `kvcoder.connectors.disabled` `['fs', 'todo']` and a registered connector `todo`, *then* the prompt's connector index has neither, and a call `run { connector: 'fs', … }` returns `error VALIDATION_FAILED: There is no connector fs. The connectors are: …` without `fs` or `todo`. `extensions/kvcoder/test/connectors-disabled.test.ts`
- **QA21-H9 `kvcoder.connector.list` says what is on.** *Given* connectors `todo` and `gh` with `gh` disabled, *then* the rows have `enabled: true` and `enabled: false`. `extensions/kvcoder/test/connectors-disabled.test.ts`
- **QA21-H10 kvcoder and kvai give a configuration.** *Then* `kvcoder.ui.get` has a `configuration` whose `setting` keys are kvcoder's own registered keys, with the component `kvcoder.connectors`, and `kvai.ui.get` has one with `kvai.defaultModel`; kvwebui's checks accept both. `extensions/kvcoder/test/ui.test.ts`, `extensions/kvwebui/test/kvai-ui.test.ts`
- **QA21-H11 The connectors list turns one off.** *Given* the list on "All workspaces" with nothing off, *then* it shows kvcoder's six and the registered `todo`, each with a pressed switch; *when* the person turns `shell` off, *then* `kernel.settings.set { key: 'kvcoder.connectors.disabled', value: ['shell'], scope: 'global' }` runs and the switch shows off. `extensions/kvcoder/test/web/connectors-list.test.ts`
- **QA21-H12 The connectors list follows the scope.** *Given* `kvman.scope` `workspace`, *when* the person turns `todo` off, *then* the call has `scope: 'workspace'`; once the value comes from the workspace, the list shows "Changed" and a reset that runs `kernel.settings.reset { key, scope: 'workspace' }`. `extensions/kvcoder/test/web/connectors-list.test.ts`
- **QA21-H13 In the real app.** *Given* kvman in Chromium with the `coder` preset, *when* the person opens Extensions, then Coder, and turns `fs` off, *then* the switch shows off, and after a reload it is still off; the Settings page shows only kvman's own rows. `extensions/kvcoder/test/e2e/configuration.test.ts`

## Edge cases

- **QA21-E1 A `setting` outside `configuration` is invalid.** *Given* a page whose view has `setting { key: 'notes.pageSize' }`, *then* the extension contributes nothing and its failure names `pages.0.view` and "belongs in configuration". `extensions/kvwebui/test/web/contributions.test.ts`
- **QA21-E2 A `setting` of another extension is invalid.** *Given* a `configuration` with `setting { key: 'kvwebui.theme' }` from `notes`, *then* the extension contributes nothing and its failure says the key isn't one of its settings. `extensions/kvwebui/test/web/contributions.test.ts`
- **QA21-E3 A configuration is checked like a view.** *Given* a `configuration` that names a query that isn't public, or a `$param`, *then* the answer is invalid. `extensions/kvwebui/test/web/contributions.test.ts`
- **QA21-E4 An extension with nothing to configure.** *Given* an extension without `configuration`, *then* its page shows `extension-nothing`, no scope switch, and its Secrets section. `extensions/kvwebui/test/web/extension-page.test.ts`
- **QA21-E5 An unknown namespace.** *Then* `/kvwebui/extension/nope` shows "page not found". `extensions/kvwebui/test/web/extension-page.test.ts`
- **QA21-E6 A removed extension.** *Given* a loaded extension the stored preset no longer has, *then* its row and its page show "Removed after restart", and the page has no "Remove". `extensions/kvwebui/test/web/extension-page.test.ts`
- **QA21-E7 A subagent doesn't get a connector that is off.** *Given* `ask` in `kvcoder.connectors.disabled`, *then* a subagent session's prompt has no `ask`; and `subagent run` naming a disabled connector fails `A subagent can't have the connector <name>.` `extensions/kvcoder/test/connectors-disabled.test.ts`
- **QA21-E8 A name nothing has is ignored, and the workspace's list wins.** *Given* the global list `['nope']` and the workspace's `['shell']`, *then* in that workspace only `shell` is off, and in Home every connector is on. `extensions/kvcoder/test/connectors-disabled.test.ts`
- **QA21-E9 The list applies from the next step.** *Given* a chat whose first step ran with `fs` on, *when* `fs` is turned off, *then* the next step's prompt has no `fs`. `extensions/kvcoder/test/connectors-disabled.test.ts`
- **QA21-E10 A workspace's own list can't be edited from "All workspaces".** *Given* the value from the workspace and `kvman.scope` `global`, *then* every switch is disabled and `connectors-own-value` names the workspace. `extensions/kvcoder/test/web/connectors-list.test.ts`
- **QA21-E11 Turning one on keeps the names the list doesn't show.** *Given* the list `['gone', 'fs']`, *when* the person turns `fs` on, *then* the value sent is `['gone']`. `extensions/kvcoder/test/web/connectors-list.test.ts`
- **QA21-E12 A rejected change says so.** *Given* `kernel.settings.set` fails, *then* the switch keeps its state and a toast shows the Problem. `extensions/kvcoder/test/web/connectors-list.test.ts`
- **QA21-E14 `kvman-check` reads the configuration's keys.** *Given* a `configuration` whose card title has no catalog entry, *then* the check reports it in every catalog as used by `<namespace>.ui.get`. `packages/testkit/test/check/locale-keys.test.ts`
- **QA21-E13 The web list names kvcoder's own connectors.** *Then* the names the component lists first equal `builtinConnectors`, and each has `kvcoder.config.connector.<name>` in `en` and `ar`. `extensions/kvcoder/test/web/connectors-list.test.ts`
