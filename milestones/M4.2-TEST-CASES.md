# M4.2 — The VS Code extension: test cases

Read: `15` §15.1 to §15.6, §15.8; `14` §14.2, §14.4 (the hints); `01` §1.2 (the start folder, installing); `04` §4.2; `12` §12.1; ADR 0099.

No test drives a real VS Code (ADR 0099, 35). The extension is built so that what it decides is apart from VS Code:

- **The session** (`packages/vscode/src/session.ts`) takes what happens (the view shown, a command, kvman's version, a line, the trust answer, kvman ending, a health answer, a button) and answers with the next view and the effects to carry out (check the version, install, start kvman, ask the trust question, write a line, close the input, check health, open an address, open the log). Its tests give it happenings and compare the answers.
- **The kvman process** (`kvman-process.ts`) is tested against `test/fixtures/fake-kvman.mjs`, a Node program that speaks the lines a test asks for and records its arguments, folder, and input.
- **The controller and the VS Code adapter** (`controller.ts`, `extension.ts`) are tested with a fake of the `vscode` module, aliased in the package's vitest project.
- **The view's page** (`page/relay.ts`) and its HTML (`view-html.ts`) are tested with `happy-dom`.

Each vitest test's name starts with its id. Tests use temporary folders and never the real `~/.kvman`.

The by-hand check (ADR 0099, 35) is the first step of the milestone and is recorded at the end of this file.

## Happy path

### M4.2-H1 — showing the view starts kvman in the local folder and frames its URL
- **Given** a window whose first folder is a local `file:` folder, and a kvman at least as new as the minimum
- **When** the view is shown, `--version` answers, and kvman writes `running` with `http://127.0.0.1:3737/?workspace=w1`
- **Then** `<kvman.path> --pipe --no-open` is started in that folder, and the view's frame is `http://127.0.0.1:3737/?workspace=w1&open=parent`; this window owns kvman
- Test: `packages/vscode/test/session.test.ts`, `packages/vscode/test/controller.test.ts`

### M4.2-H2 — a window with no folder starts kvman in the user's home folder
- **Given** a window with no folder
- **When** the start folder is chosen
- **Then** it is the user's home folder
- Test: `packages/vscode/test/start-folder.test.ts`

### M4.2-H3 — a remote or virtual first folder shows the local-only message and runs nothing
- **Given** a window whose first folder is `vscode-remote://ssh-remote+box/home/a`, and one with `vscode-vfs://github/a/b`
- **When** the view is shown
- **Then** it says "kvman works on local folders only for now." and nothing is run
- Test: `packages/vscode/test/start-folder.test.ts`, `packages/vscode/test/session.test.ts`

### M4.2-H4 — no kvman: "Install kvman" runs the npm task, and code 0 starts kvman
- **Given** `--version` can't start the program
- **When** the view is shown, then "Install kvman" is pressed and the task ends with code 0
- **Then** the view says "kvman isn't installed." with "Install kvman"; the task named "Install kvman" runs `npm i -g kvman --no-fund --loglevel=error`; the view says it is installing; code 0 starts kvman
- Test: `packages/vscode/test/session.test.ts`, `packages/vscode/test/install-task.test.ts`

### M4.2-H5 — the install task fails: npm missing, or another code
- **Given** the install task
- **When** it ends with 127 on Linux, 9009 on Windows, and 1
- **Then** 127 and 9009 show "npm wasn't found. Install Node.js 24, then try again." with a link to `https://nodejs.org`; 1 shows "kvman couldn't be installed. The terminal shows why." with "Try again"
- Test: `packages/vscode/test/session.test.ts`, `packages/vscode/test/install-task.test.ts`

### M4.2-H6 — a kvman older than the minimum isn't started
- **Given** `--version` answers `0.3.9` and the minimum is `0.4.7`
- **When** the view is shown
- **Then** the view says "kvman 0.3.9 is older than this extension needs (0.4.7)." with "Update kvman", nothing is started, and "Update kvman" runs the task with `kvman@latest`
- Test: `packages/vscode/test/version.test.ts`, `packages/vscode/test/session.test.ts`

### M4.2-H7 — kvman is started directly on Linux and macOS, and through cmd.exe on Windows
- **Given** `kvman.path` `C:\Program Files\nodejs\kvman.cmd` on Windows, and `kvman` on Linux and macOS
- **When** the start command is built
- **Then** on Windows it is `cmd.exe /d /s /c ""C:\Program Files\nodejs\kvman.cmd" --pipe --no-open"` with verbatim arguments; on Linux and macOS it is `kvman --pipe --no-open`
- Test: `packages/vscode/test/kvman-process.test.ts`

### M4.2-H8 — a `trust` line asks with each version; "Run them" and closing answer it
- **Given** kvman started
- **When** a `trust` line with two versions comes; once "Run them" is chosen, once the message is closed
- **Then** the modal message lists `name@version (source)` for each; the answers written are `{"trust":true}` and `{"trust":false}`
- Test: `packages/vscode/test/session.test.ts`, `packages/vscode/test/controller.test.ts`

### M4.2-H9 — a `failed` line shows the Problem and its hint; the buttons act
- **Given** kvman started
- **When** `failed` comes with `PORT_IN_USE`, and with `INTERNAL`; then "Show the log" and "Try again" are pressed
- **Then** the view shows "kvman could not start", the code, the message, and the `PORT_IN_USE` hint, or `<home>/logs/kvman.log` for `INTERNAL`; "Show the log" opens that file; "Try again" starts kvman again
- Test: `packages/vscode/test/session.test.ts`, `packages/vscode/test/web/view-html.test.ts`

### M4.2-H10 — a `joined` line frames kvman, and this window doesn't own it
- **Given** kvman started
- **When** `joined` comes and the program then exits 0
- **Then** the view's frame is the line's URL with `&open=parent`, the exit changes nothing, and closing the window closes no input
- Test: `packages/vscode/test/session.test.ts`

### M4.2-H11 — closing the window that owns kvman closes its input, and kvman exits 0
- **Given** the fake kvman in `exits-on-close` mode, started by the process module
- **When** the input is closed
- **Then** the program exits 0, and no signal was sent
- Test: `packages/vscode/test/kvman-process.test.ts`

### M4.2-H12 — after the owner closes, another window starts kvman again and owns it
- **Given** a window that joined kvman on port 3737
- **When** the view is shown again and the health check finds no kvman, then `running` comes
- **Then** the session checks `kernel.health.get` on 3737, starts kvman, and the window then owns it; a check that finds kvman starts nothing
- Test: `packages/vscode/test/session.test.ts`, `packages/vscode/test/health.test.ts`

### M4.2-H13 — a restart's `running` line with another port moves the frame
- **Given** the frame at port 3737
- **When** `restarting`, then `running` with port 3800 come
- **Then** `restarting` changes nothing, and the frame moves to the new URL with `&open=parent`
- Test: `packages/vscode/test/session.test.ts`

### M4.2-H14 — a kvman that ends by itself, or an unreadable line, shows "stopped"
- **Given** a window that owns kvman
- **When** the program exits, and, in another session, a line `hello` comes
- **Then** the view says "kvman stopped unexpectedly." with "Start again" and "Show the log"; the unreadable line first closes kvman's input; "Start again" starts kvman
- Test: `packages/vscode/test/session.test.ts`, `packages/vscode/test/lines.test.ts`

### M4.2-H15 — a new window from the frame opens in the system's browser
- **Given** the view framing `http://127.0.0.1:3737`
- **When** the page receives `{ kind: 'kvman.open', url: 'https://auth.example/x' }` from the frame's window at that origin, and the extension gets it
- **Then** the page passes it on, and the extension opens it with `vscode.env.openExternal`
- Test: `packages/vscode/test/web/relay.test.ts`, `packages/vscode/test/controller.test.ts`

### M4.2-H16 — the page's policy allows only kvman's frame
- **Given** the frame view for port 3737 and a nonce
- **When** its HTML is made
- **Then** its policy is `default-src 'none'; frame-src http://127.0.0.1:3737; script-src 'nonce-<nonce>'; style-src <webview source>`, the frame has `allow="clipboard-read; clipboard-write"` and no `sandbox`
- Test: `packages/vscode/test/web/view-html.test.ts`

### M4.2-H17 — the text follows VS Code's language
- **Given** `vscode.env.language` `ar`, `ar-EG`, `en`, and `de`
- **When** the view's text is made
- **Then** `ar` and `ar-EG` give Arabic with `dir="rtl"`; `en` and `de` give English with `dir="ltr"`; the catalogs have the same keys and placeholders, and the manifest's `package.nls` files the same keys
- Test: `packages/vscode/test/catalog.test.ts`, `packages/vscode/test/web/view-html.test.ts`

### M4.2-H18 — the extension's calls carry no Origin, and it never reads secrets.json
- **Given** a fake kvman API on 127.0.0.1 that records headers
- **When** the health check calls it
- **Then** the request has the Host `127.0.0.1:<port>` and no `Origin`; no source file names `secrets.json`
- Test: `packages/vscode/test/health.test.ts`

### M4.2-H19 — "Open in browser" opens the start workspace, starting kvman first
- **Given** no kvman running, then kvman framed
- **When** `kvman.openInBrowser` runs
- **Then** kvman starts, and once `running` comes `http://127.0.0.1:3737/?workspace=w1` is opened; a second run opens it at once
- Test: `packages/vscode/test/session.test.ts`

## Edge cases

### M4.2-E1 — the version is checked before the first start in a window only
- **Given** a session that has started kvman once
- **When** "Start again" is pressed after it stopped
- **Then** kvman is started without a second `--version`
- Test: `packages/vscode/test/session.test.ts`

### M4.2-E2 — a kvman as new as the extension passes, below the minimum too
- **Given** an extension at `0.4.6` with the minimum `0.4.7`
- **When** `--version` answers `0.4.6`
- **Then** it is new enough; with the extension at `0.4.7`, `0.4.6` is too old; an answer with no version (`hello`) counts as no kvman
- Test: `packages/vscode/test/version.test.ts`

### M4.2-E3 — every line shape is read; anything else is unreadable
- **Given** the five line shapes of §14.2, and `hello`, `{}`, `{"kind":"running","url":5}`, and `{"kind":"other"}`
- **When** each is read
- **Then** the five give typed lines and the rest give nothing
- Test: `packages/vscode/test/lines.test.ts`

### M4.2-E4 — the page drops messages of another source, origin, or shape
- **Given** the relay page for port 3737
- **When** messages come from another window, from the origin `http://127.0.0.1:9999`, and of another shape from the frame
- **Then** only well-formed messages from the frame's window at kvman's origin are passed on; the extension drops a `file:` or `javascript:` address and a message of another shape
- Test: `packages/vscode/test/web/relay.test.ts`, `packages/vscode/test/page-messages.test.ts`

### M4.2-E5 — lines of an old run are ignored
- **Given** a kvman that was replaced by a new start
- **When** the old program writes a line or exits
- **Then** nothing changes
- Test: `packages/vscode/test/controller.test.ts`

### M4.2-E6 — lines that arrive in pieces are read whole
- **Given** the fake kvman writing a `running` line in two chunks
- **When** the process module reads it
- **Then** one `running` line is given
- Test: `packages/vscode/test/kvman-process.test.ts`

### M4.2-E7 — the view's text is escaped
- **Given** a Problem message `<img src=x onerror=alert(1)>`
- **When** the failed view's HTML is made
- **Then** it holds `&lt;img` and no `<img`
- Test: `packages/vscode/test/web/view-html.test.ts`

### M4.2-E8 — the import wall
- **Given** files of `packages/vscode`
- **When** they import `vscode`, `zod`, `node:child_process`, `@kvman/sdk`, `kvman`, and `marked`
- **Then** the first three pass and the rest fail lint
- Test: `test/tooling/import-walls-packages.test.ts`

### M4.2-E9 — the manifest contributes what plan 15 lists
- **Given** the built manifest
- **When** it is read
- **Then** it has the view container `kvman` in `secondarySidebar`, the webview view `kvman.view`, the commands `kvman.open`, `kvman.openInBrowser`, and `kvman.install`, the setting `kvman.path` defaulting to `kvman`, the kind `ui`, `engines.vscode` `^1.106.0`, the publisher `ibndeif`, the name `kvman`, and the root version
- Test: `packages/vscode/test/manifest.test.ts`

## The by-hand check (ADR 0099, 35)

Done on 2026-10-22, on Linux, with the VS Code installed here (1.141.2, the snap; 1.106 itself wasn't at hand). VS Code ran with a profile, extensions folder, and kvman home of their own, `kvman.path` named a script that runs the repository's CLI on port 3911, and Playwright watched the window through VS Code's debugging port.

- **The view frames kvman.** "kvman: Open" showed the view in the secondary side bar, beside VS Code's own Chat, and the frame `http://127.0.0.1:3911/` inside the view's `vscode-webview://` frames showed kvwebui's nav (page title "Chat · folder · kvman Coder"). So the listener's policy lets VS Code's `vscode-webview:` and `vscode-file:` ancestors through, and VS Code's Electron let the view reach `127.0.0.1`.
- **A website can't frame kvman**: covered in Chromium by M4.1-H2.
- **Closing VS Code stops kvman**: after the window's VS Code quit, kvman left port 3911 within 2 seconds, and no kvman process was left.
- **Seen**: at the side bar's starting width kvwebui shows its narrow layout (the icon rail and the chat list), as ADR 0099, 34 says; the person widens the side bar for more room.
