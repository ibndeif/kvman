# QA 29 — the `mcp` connector and its servers (ADR 0020, 3 to 7, 9, 10, 12, 14, 15, and 17)

Asked: "add an mcp connector, and it should add configs in the UI to let the user add their MCPs". Decided in ADR 0020; plan 08 §8.2 to §8.7. Sign-in is QA 30. This file is the contract; every scenario's test name starts with its id. The tests use a fixture MCP server (`test/support/mcp-fixture.ts`), run as a command and served on `127.0.0.1`.

## Happy path

- **QA29-H1 A command server's tools are listed.** *Given* the fixture as a command server `demo`, *when* the model runs `mcp tools { server: 'demo' }`, *then* the result is `{ server, tools: [{ name, description }] }` with the fixture's tools. `extensions/kvcoder/test/mcp-connector.test.ts`
- **QA29-H2 One tool's arguments.** *When* the model runs `mcp tools { server: 'demo', tool: 'echo' }`, *then* the result has the tool's `name`, `description`, and `arguments`, its input JSON Schema. `extensions/kvcoder/test/mcp-connector.test.ts`
- **QA29-H3 A tool is called.** *When* the model runs `mcp call { server: 'demo', tool: 'echo', arguments: { text: 'hi' }, risky: false }`, *then* the result is the tool's text, `hi`, and the call's card details name `mcp` and `call`. `extensions/kvcoder/test/mcp-connector.test.ts`
- **QA29-H4 A server over HTTP works the same.** *Given* the fixture served on `127.0.0.1` as `remote`, *then* `tools` lists its tools and `call` returns the tool's text. `extensions/kvcoder/test/mcp-http.test.ts`
- **QA29-H5 Secrets reach the server and nowhere else.** *Given* `env: ['TOKEN']` with the secret `mcp.demo.env.TOKEN`, and `headers: ['Authorization']` with `mcp.remote.header.Authorization`, *then* the command's tool `env` reads the value, the HTTP server receives the header, and the value is in no setting, no job row's input, and not in `logs/kvman.log`. `extensions/kvcoder/test/mcp-secrets.test.ts`
- **QA29-H6 The prompt names the servers.** *Given* two servers, *then* the connector index has `- mcp: … Servers: demo (A demo server), remote (Over HTTP).` with the lines `tools { server, tool? }`, `call  { server, tool, arguments?, timeoutMs?, risky }`, and `help  { command? }`, and the `run` tool's `connector` enum has `mcp`. `extensions/kvcoder/test/mcp-prompt.test.ts`
- **QA29-H7 A call asks as a shell call does.** *Given* `kvcoder.shell.approval` `auto`, *then* `call` with `risky: true` waits for an approval and runs once allowed, and with `risky: false` runs at once; *given* `ask`, every `call` asks; `tools` never asks. `extensions/kvcoder/test/mcp-approval.test.ts`
- **QA29-H8 `kvcoder.mcp.server.check` says a server is ready.** *Then* it answers `{ status: 'ready', tools: 8 }` for the fixture, which has eight tools. `extensions/kvcoder/test/mcp-servers.test.ts`
- **QA29-H9 A workspace's own servers replace the global ones.** *Given* `demo` globally and `other` in the workspace, *then* the workspace's prompt names only `other`. `extensions/kvcoder/test/mcp-prompt.test.ts`
- **QA29-H10 `mcp` has a row and a cog.** *Then* the connectors list shows seven own connectors, `mcp` last with its catalog description and a cog. `extensions/kvcoder/test/web/connectors-list.test.ts`
- **QA29-H11 The dialog lists the servers and checks each.** *Given* two servers, *when* the dialog opens, *then* each row shows its name and description, "Checking…", then "Ready · 8 tools" for one and "Could not connect" with the Problem's sentence for the other. `extensions/kvcoder/test/web/mcp-servers.test.ts`
- **QA29-H12 Adding a command server.** *When* the person fills Name, Description, Command, Arguments (one per line), and one variable with a value, and presses Save, *then* `kernel.settings.set` runs with the list and the page's scope, then `kernel.secrets.set { extension: '@kvman/kvcoder', name: 'mcp.github.env.TOKEN', value }`, then the check; the row appears. `extensions/kvcoder/test/web/mcp-server-form.test.ts`
- **QA29-H13 Adding a URL server.** *When* "Runs as" is "A URL", *then* the form asks for the URL and headers, and Save stores `{ name, description, url, headers }` with each header's value as `mcp.<name>.header.<Header>`. `extensions/kvcoder/test/web/mcp-server-form.test.ts`
- **QA29-H14 Editing keeps what isn't changed.** *Given* a server with a set variable, *when* Edit opens, *then* Name is fixed, the variable shows "Set" and "Replace" with no value, and Save with only a new description writes no secret. Replacing writes the new value; removing a variable deletes its secret. `extensions/kvcoder/test/web/mcp-server-form.test.ts`
- **QA29-H15 Removing a server.** *When* the person presses Remove and confirms, *then* the list is written without it and every secret named `mcp.<name>.…` is deleted; Cancel changes nothing. `extensions/kvcoder/test/web/mcp-servers.test.ts`
- **QA29-H16 In the real app.** *Given* kvman in Chromium, *when* the person opens `mcp`'s cog, adds the fixture as a command server with a variable, and saves, *then* the row shows "Ready · 8 tools", the setting holds the entry without the value, and `secrets.json` holds the value; after a reload the row is there and Edit shows the variable as "Set". `extensions/kvcoder/test/e2e/mcp-servers.test.ts`

## Edge cases

- **QA29-E1 No server, no connector.** *Given* `kvcoder.mcp.servers` `[]`, *then* the prompt and the `run` tool have no `mcp`, the prompt equals the one before this milestone, and a call to `mcp` gets `There is no connector mcp. The connectors are: …`. `extensions/kvcoder/test/mcp-prompt.test.ts`
- **QA29-E2 Turned off.** *Given* servers and `mcp` in `kvcoder.connectors.disabled`, *then* it is left out and a call gets the answer for a connector that doesn't exist. `extensions/kvcoder/test/mcp-prompt.test.ts`
- **QA29-E3 A subagent.** *Then* a subagent given `connectors: ['mcp']` can call it, and one given `['fs']` gets `mcp isn't available in this subagent.` `extensions/kvcoder/test/mcp-prompt.test.ts`
- **QA29-E4 An unknown server.** *Then* `tools` and `call` fail `kvcoder/MCP_SERVER_NOT_FOUND`, naming the servers; `kvcoder.mcp.server.check` fails with the same code. `extensions/kvcoder/test/mcp-connector.test.ts`
- **QA29-E5 An unknown tool.** *Then* `tools { tool }` and `call` fail `NOT_FOUND` with `demo has no tool nope. Its tools are: …`. `extensions/kvcoder/test/mcp-connector.test.ts`
- **QA29-E6 A tool that reports an error.** *When* the fixture's `fail` is called, *then* the result is its text as an error result. `extensions/kvcoder/test/mcp-connector.test.ts`
- **QA29-E7 A result that isn't text.** *When* `picture` is called, *then* the result is its text and `[image omitted]`, joined by a blank line. `extensions/kvcoder/test/mcp-connector.test.ts`
- **QA29-E8 A long result is cut.** *When* `big` returns 40 KB, *then* the result keeps its first and last 15 KB around `[… N bytes omitted …]`. `extensions/kvcoder/test/mcp-connector.test.ts`
- **QA29-E9 Invalid payloads.** *Then* `call` without `risky`, with an unknown key, or with `arguments` that isn't an object fails `VALIDATION_FAILED` with the command's signature, and nobody is asked. `extensions/kvcoder/test/mcp-approval.test.ts`
- **QA29-E10 A command that can't start.** *Given* `command: 'no-such-program-kvman'`, *then* `call` fails `kvcoder/MCP_CONNECT_FAILED` with the reason, and the check answers `{ status: 'failed', problem }`. `extensions/kvcoder/test/mcp-stdio.test.ts`
- **QA29-E11 A command that isn't an MCP server.** *Given* a program that prints to its error output and exits, *then* the call fails `kvcoder/MCP_CONNECT_FAILED` and the reason ends with what it printed. `extensions/kvcoder/test/mcp-stdio.test.ts`
- **QA29-E12 The process tree is killed when the call ends.** *Given* the fixture's `spawn` tool, which starts a child and returns both pids, *when* the call returns, *then* neither process is alive. `extensions/kvcoder/test/mcp-stdio.test.ts`
- **QA29-E13 A timeout.** *Given* `timeoutMs: 300` and the fixture's `sleep`, *then* the call fails `kvcoder/MCP_CONNECT_FAILED` saying it didn't answer in time, and the server's process is gone. A `timeoutMs` over 600 000 is cut to 600 000 (`extensions/kvcoder/test/unit/mcp-command-spawn.test.ts`). `extensions/kvcoder/test/mcp-stdio.test.ts`
- **QA29-E14 Cancel.** *Given* a `sleep` call running, *when* the turn is cancelled, *then* the server's process is gone and the turn ends cancelled. `extensions/kvcoder/test/mcp-stdio.test.ts`
- **QA29-E15 The start and the kill per OS.** *Then* `commandSpawn('linux' | 'darwin', …)` starts detached and `'win32'` doesn't, both hide the window, and the tree kill is the group or `taskkill /PID <pid> /T /F`. `extensions/kvcoder/test/unit/mcp-command-spawn.test.ts`
- **QA29-E16 A server that can't be reached.** *Given* a URL nothing listens on, *then* the call fails `kvcoder/MCP_CONNECT_FAILED`; *given* a server answering 401, *then* it fails `kvcoder/MCP_SIGN_IN_NEEDED` and the check answers `{ status: 'signInNeeded' }`. `extensions/kvcoder/test/mcp-http.test.ts`
- **QA29-E17 A secret never leaves in a reason.** *Given* a command that prints its `TOKEN` to its error output and exits, *then* the Problem's reason has `***` in its place. `extensions/kvcoder/test/mcp-secrets.test.ts`
- **QA29-E18 A missing secret.** *Given* `env: ['TOKEN']` with no secret, *then* the server starts without the variable. `extensions/kvcoder/test/mcp-secrets.test.ts`
- **QA29-E19 An invalid list.** *Then* `kernel.settings.set` of `kvcoder.mcp.servers` fails `VALIDATION_FAILED` for: a name that isn't kebab case, two servers with one name, an entry with both `command` and `url`, an unknown key, a URL that isn't http or https, a variable name with a space, and a header name with a colon. `extensions/kvcoder/test/mcp-servers.test.ts`
- **QA29-E20 `mcp` can't be registered.** *Then* `kvcoder.connector.register { name: 'mcp', … }` fails `kvcoder/NAME_TAKEN`. `extensions/kvcoder/test/mcp-servers.test.ts`
- **QA29-E21 Help.** *Then* `mcp help` lists `tools` and `call`, and `mcp help { command: 'call' }` gives its payload with a description for every field. `extensions/kvcoder/test/mcp-connector.test.ts`
- **QA29-E22 The form refuses what the list would.** *Then* an empty name, a name already in the list, a name that isn't kebab case, an empty description, an empty command, a URL that isn't http or https, a variable without a name or a value, and a name given twice each show under their field, and nothing is written. `extensions/kvcoder/test/web/mcp-server-form.test.ts`
- **QA29-E23 A workspace's own list from All workspaces.** *Then* the dialog says the workspace has its own list, and Add, Edit, and Remove are disabled. `extensions/kvcoder/test/web/mcp-servers.test.ts`
- **QA29-E24 No servers.** *Then* the dialog says "No servers yet. Add one and the agent can use its tools." `extensions/kvcoder/test/web/mcp-servers.test.ts`
- **QA29-E25 A save that fails.** *Given* `kernel.settings.set` fails, *then* the Problem is toasted and the form stays open with what was typed. `extensions/kvcoder/test/web/mcp-server-form.test.ts`
- **QA29-E26 A value is never shown.** *Then* a value field is `type="password"` with `autocomplete="off"`, and the dialog reads no secret value: it only lists names (`kernel.secrets.list`). `extensions/kvcoder/test/web/mcp-server-form.test.ts`
