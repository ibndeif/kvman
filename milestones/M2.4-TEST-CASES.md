# M2.4 — Capabilities and isolation: test cases

Read: `05` §5.7, `03` §3.5, §3.8 ("Who" column), `13` §13.6, and the parts they cite: `03` §3.6 (host crash, stuck host), `04` §4.1 (the read pool), `06` §6.2 (native addons), §6.4 (global types), §6.5 (isolation), `09` §9.5 (the tool set), `08` §8.13 (grant commands). ADRs 0002, 0052, 0067, 0071, 0079, 0082, 0118, 0123, and 0128–0133.

Where the tests live:

- **Pure pieces**, in `packages/kernel/test/`: the isolation order in a grant, the sandboxed host's flags and environment, idle unload in a pool, and the read pool.
- **Hosts through a runtime**, in `packages/testkit/test/isolation/`. The runtime has a home folder, installed fixture snapshots (ADR 0114), and applied presets written by the test helper (ADR 0124). Sandboxed hosts are real child processes.
- **Capability checks through a runtime**, in `packages/testkit/test/capabilities/`.
- **Crash points**, in `packages/testkit/test/faults/hosts.test.ts`, on child kernels.
- **Protocol shapes**, in `packages/protocol/test/capability-queries.test.ts`.

Scope: M2.4 enforces the capabilities of the `ctx` surfaces that exist: `command`, `send`, `query`, `publish`, `live`, `reply`, the store, config and secrets, and kernel commands and queries. `ctx.files`, `ctx.process`, `ctx.llm`, and `ui.*` enforce theirs in M2.5, M2.6, M2.9, and M2.12 (`15` M2.4 Split).

Terms used in the scenarios:

- "**Person**" is `user:local`. A "**process**" sender is `proc:<id>` acting for its extension.
- "**Probe**" is the fixture `@acme/probe` (namespace `probe`):
  - it requests `shared` isolation and the capabilities `files.read`, `process`, and `network`;
  - `probe.work {text}` writes and reads its kv, its `items` collection, and its `trail` log, calls its own internal `probe.inner` with `ctx.command`, publishes `probe.worked`, and returns what it read;
  - it subscribes to its own `probe.worked` and counts the deliveries in its kv;
  - `probe.whoami` returns its host's `pid` and `threadId`; `probe.global.ping` (scope `global`) does the same without a workspace;
  - `probe.read {path, caught}`, `probe.sqlite`, `probe.spawn`, `probe.addon`, `probe.env`, `probe.noise`, `probe.exit`, and `probe.forge` try what their names say (`caught: true` returns the error code instead of throwing);
  - `probe.hang` (`timeoutMs` 1 s, one attempt) never returns and ignores its signal; `probe.hold` waits a minute on its first attempt and returns on the next; `probe.exit` and `probe.forge` misbehave only on their first attempt;
  - `probe.seed {count, size}` writes documents, and the query `probe.scan {limit?}` finds them;
  - `probe.tool` (a command), `probe.lookup` (a query), and `probe.global.tool` (a command with scope `global`) are flagged `agentTool`; `probe.approve` has `access: 'user'`; `probe.progress` is a live event.
- "**Intruder**" is `@acme/intruder` (namespace `intruder`), with no capabilities; each of its commands tries one `ctx` surface on Probe or the kernel and returns the code it got.
- "**Caller**" is `@acme/caller`, which requests `calls ['probe.*']`; `caller.ping` (in a workspace) and `caller.global` (scope `global`) call `probe.global.ping`.
- "**Assistant**" is `@acme/assistant`, which requests `tools` only; `assistant.use {type}` and `assistant.global.use {type}` (scope `global`) call a type and return the code.
- "**Listener**" is `@acme/listener`, which subscribes to `probe.worked` and `kernel.extension.enabled`. "**Bystander**" is `@acme/bystander`, which subscribes only to its own `bystander.noted`.
- "**Warden**" is `@acme/warden`, which requests `kernel.admin`; `warden.call` and `warden.ask` send a kernel command or query and return its value or code.
- "**Grants of X at L**" are exactly X's requested and derived capabilities with isolation L. "**Helper grant**" is a preset entry written by the test helper that bypasses the validity check, used only to prove the kernel's own enforcement.
- "**Enabled in A at L**" means a preset row for workspace A that enables the fixture with its grants at L.

## Happy path

### M2.4-H1 — the same sample extension runs in all three isolation modes
- **Test**: `packages/testkit/test/isolation/modes.test.ts`
- **Given** Probe enabled in A at `shared`, in B at `dedicated`, and in C at `sandboxed`.
- **When** the person sends `probe.work {text: 'x'}` in each workspace, then `probe.whoami`.
- **Then**:
  - each `probe.work` replies with the same value: the kv value, the document, the log entry, and `probe.inner`'s reply it read back;
  - each workspace's own subscription counted one `probe.worked` delivery;
  - A's `whoami` runs on a shared pool thread, B's on a dedicated thread that is not in the shared pool, both in the kernel's process;
  - C's runs in a child process whose `pid` is not the kernel's;
  - the host listing shows the keys `(@acme/probe, shared)`, `(@acme/probe, dedicated)`, and `(@acme/probe, sandboxed)`.

### M2.4-H2 — every `ctx` surface denies without its capability
- **Test**: `packages/testkit/test/capabilities/surfaces.test.ts`
- **Given** Probe enabled in A at `shared`, and Intruder enabled in A at `sandboxed`.
- **When** Intruder tries, one command each:
  - `ctx.command('probe.work')` and `ctx.query('probe.scan')`;
  - `ctx.send('probe.work')` and `ctx.publish('probe.worked')`;
  - `ctx.live('probe.progress', …)`;
  - `ctx.command('probe.tool')` (an agent tool) and `ctx.query('probe.lookup')`;
  - the admin command `kernel.workspace.rename` and the admin query `kernel.messages.list`.
- **Then**:
  - each call fails `CAPABILITY_DENIED`, and each unit with a send or publish fails `CAPABILITY_DENIED` at commit and stores nothing;
  - Probe has no message from Intruder, and workspace A keeps its name.

### M2.4-H3 — a sandboxed extension cannot read a file outside its access or load `node:sqlite`
- **Test**: `packages/testkit/test/isolation/sandbox.test.ts`
- **Given** Probe enabled in A at `sandboxed` (with `files.read` granted) and in B at `shared`.
- **When** the person sends `probe.read {path: <home>/kvman.db, caught: true}` and `probe.sqlite` in A, and the same read in B.
- **Then**:
  - in A the read returns `ERR_ACCESS_DENIED`;
  - `import`, `require`, and `process.getBuiltinModule` of `node:sqlite` fail with `ERR_UNKNOWN_BUILTIN_MODULE` twice, and `undefined`;
  - in B the read returns the file's first bytes (the control: `shared` is trusted code).

### M2.4-H4 — a foreign event reaches only granted subscribers
- **Test**: `packages/testkit/test/capabilities/events.test.ts`
- **Given**:
  - in A, Probe, Bystander, and Listener with a helper grant that lacks `subscribes probe.worked`;
  - in B, Probe and Listener with its full grants.
- **When** the person sends `probe.work` in A and in B.
- **Then**:
  - no `messages` row delivers `probe.worked` to Bystander or to A's Listener;
  - B's Listener gets exactly one delivery and handles it.

### M2.4-H5 — a large `find` from a sandboxed extension does not delay `/health`
- **Test**: `packages/testkit/test/isolation/health-latency.timing.test.ts` (run after every other test, one file at a time)
- **Given**:
  - a runtime with its HTTP adapter;
  - Probe enabled in A at `sandboxed`;
  - 5,000 `items` documents of about 3 KB each (`probe.seed`).
- **When** after one warm-up request, the person sends `probe.scan` in A, and `GET /api/v1/health` is requested every 10 ms until the scan answers.
- **Then**:
  - every health request answers `200` within 25 ms, and at least one was made while the scan ran;
  - the scan returns 5,000 documents.

## Edge cases

### Isolation and hosts

### M2.4-E1 — a grant's isolation is the requested level or higher
- **Test**: `packages/kernel/test/registry/grant-validity.test.ts`
- **Given** manifests that request `shared`, `dedicated`, and no isolation, and a `builtin:` manifest.
- **When** each is checked against grants at every level.
- **Then**:
  - a `shared` request accepts all three levels, and a `dedicated` request accepts `dedicated` and `sandboxed`;
  - no request accepts only `sandboxed`, and the builtin accepts only `shared`;
  - a refused level is reported in `isolation` with an otherwise empty difference.

### M2.4-E2 — enabling with a raised isolation succeeds
- **Test**: `packages/testkit/test/isolation/modes.test.ts`
- **Given** Probe installed, workspace A with an empty preset row.
- **When** the person enables Probe in A with its grants at `dedicated`.
- **Then** the reply is the new revision, and `kernel.extensions.list` shows `isolation: { A: 'dedicated' }`.

### M2.4-E3 — one extension at two levels runs in two hosts
- **Test**: `packages/testkit/test/isolation/modes.test.ts`
- **Given** Probe enabled in A at `sandboxed` and in B at `shared`.
- **When** the person sends `probe.whoami` in A and in B.
- **Then** A's answer comes from a child process and B's from the kernel's process.

### M2.4-E4 — a global invocation runs at the most isolated level of its workspaces
- **Test**: `packages/testkit/test/isolation/modes.test.ts`
- **Given** Probe enabled in A at `shared` and in B at `sandboxed`.
- **When** the person sends `probe.global.ping` without a workspace.
- **Then** it runs in the sandboxed child process.

### M2.4-E5 — a new isolation applies to the next message
- **Test**: `packages/testkit/test/isolation/modes.test.ts`
- **Given** Probe enabled in A at `shared`, and one `probe.whoami` answered.
- **When** the person re-enables Probe in A at `sandboxed` and sends `probe.whoami` again.
- **Then** the second answer comes from a child process.

### M2.4-E6 — a sandboxed host starts with exactly the flags of ADR 0129
- **Test**: `packages/kernel/test/hosts/sandbox-flags.test.ts`
- **Given** a snapshot folder and the kernel's read roots.
- **When** the host's start arguments and environment are built.
- **Then**:
  - the flags are `--permission`, one `--allow-fs-read` for the snapshot and for each kernel root, and `--no-experimental-sqlite`, with no other `--allow-*` flag;
  - the environment is empty;
  - stdin, stdout, and stderr are ignored, and the frame pipe is file descriptor 3.

### M2.4-E7 — a granted capability never widens the sandbox
- **Test**: `packages/testkit/test/isolation/sandbox.test.ts`
- **Given** Probe enabled in A at `sandboxed` with `process` and `files.read` granted.
- **When** the person sends `probe.spawn {caught: true}` and `probe.read {path: <a file in the workspace folder>, caught: true}`.
- **Then** both return `ERR_ACCESS_DENIED`.

### M2.4-E8 — a blocked operation that ends a handler fails `CAPABILITY_DENIED`
- **Test**: `packages/testkit/test/isolation/sandbox.test.ts`
- **Given** Probe enabled in A at `sandboxed`.
- **When** the person sends `probe.read {path: <home>/kvman.db, caught: false}` and `probe.spawn {caught: false}`.
- **Then**:
  - each fails `CAPABILITY_DENIED` after one attempt, not retried;
  - the details name "a file read" and "a child process", and neither contains the path.

### M2.4-E9 — a native addon in a sandboxed host fails `CAPABILITY_DENIED`
- **Test**: `packages/testkit/test/isolation/sandbox.test.ts`
- **Given** Probe enabled in A at `sandboxed`.
- **When** the person sends `probe.addon`, which calls `process.dlopen`.
- **Then** it fails `CAPABILITY_DENIED`, and the detail names "a native addon".

### M2.4-E10 — a sandboxed host sees an empty environment
- **Test**: `packages/testkit/test/isolation/sandbox.test.ts`
- **Given** the kernel's process has `KVMAN_TEST_TOKEN` set, and Probe enabled in A at `sandboxed`.
- **When** the person sends `probe.env`.
- **Then** it returns no variable names.

### M2.4-E11 — output written by a sandboxed extension does not reach the frame pipe
- **Test**: `packages/testkit/test/isolation/sandbox.test.ts`
- **Given** Probe enabled in A at `sandboxed`.
- **When** the person sends `probe.noise`, which writes lines of JSON-like text to stdout and stderr, then `probe.whoami`.
- **Then** both succeed, and the host's process is the same for both.

### M2.4-E12 — a sandboxed host that exits is a host crash
- **Test**: `packages/testkit/test/isolation/supervision.test.ts`
- **Given** Probe enabled in A at `sandboxed`.
- **When** the person sends `probe.exit`, whose first attempt calls `process.exit(1)` and whose second returns.
- **Then**:
  - the command succeeds on attempt 2;
  - Probe is charged one host failure;
  - the second attempt runs in a new process.

### M2.4-E13 — a stuck sandboxed handler gets its process killed
- **Test**: `packages/testkit/test/isolation/supervision.test.ts`
- **Given** Probe enabled in A at `sandboxed`, and `probe.hold` running on its host.
- **When** the person sends `probe.hang`, and the kernel's clock passes its 1 s timeout and the 2 s grace.
- **Then**:
  - the process is killed, and Probe is charged one host failure;
  - `probe.hold` is redelivered without an attempt penalty and succeeds in a new process.

### M2.4-E14 — an invalid frame from a sandboxed host ends it
- **Test**: `packages/testkit/test/isolation/supervision.test.ts`
- **Given** Probe enabled in A at `sandboxed`.
- **When** the person sends `probe.forge`, whose first attempt writes a line that is not a frame to file descriptor 3.
- **Then**:
  - the kernel logs the invalid frame, kills the process, and treats it as lost;
  - Probe is charged one host failure;
  - the command succeeds on its second attempt, in a new process.

### M2.4-E15 — an idle host stops after 10 minutes without an invocation
- **Test**: `packages/kernel/test/hosts/idle-unload.test.ts`
- **Given** a pool with fake threads and the kernel's timers faked.
- **When**:
  - a thread finishes its last invocation, and 9 minutes 59 seconds pass;
  - an invocation starts and ends, and 10 minutes pass after it.
- **Then**:
  - the thread is still running after the first wait;
  - it is terminated after the second, without an exit being reported as a crash;
  - the next acquire starts a new thread.

### M2.4-E16 — a thread with an invocation in flight is never stopped as idle
- **Test**: `packages/kernel/test/hosts/idle-unload.test.ts`
- **Given** a pool thread with one long invocation in flight.
- **When** 20 minutes pass on the kernel's clock.
- **Then** the thread is still running; once released, it stops 10 minutes later.

### M2.4-E17 — an idle sandboxed process exits and a later message starts a new one
- **Test**: `packages/testkit/test/isolation/supervision.test.ts`
- **Given** Probe enabled in A at `sandboxed`, and one `probe.whoami` answered.
- **When** the kernel's clock moves 10 minutes, and the person sends `probe.whoami` again.
- **Then**:
  - the first process has exited;
  - the second answer comes from a new `pid`;
  - Probe has no host failure.

### Reads through the read pool

### M2.4-E18 — a sandboxed handler reads its own pending writes
- **Test**: `packages/testkit/test/isolation/reads.test.ts`
- **Given** Probe enabled in A at `sandboxed`, with committed documents.
- **When** a handler puts one document, deletes another, then runs `find`, `count`, `get`, and a kv `list` in the same unit.
- **Then** each read shows the committed rows with its own writes applied.

### M2.4-E19 — a sandboxed read over the cap fails like any other
- **Test**: `packages/testkit/test/isolation/reads.test.ts`
- **Given** Probe enabled in A at `sandboxed` with 5,001 documents.
- **When** the person sends `probe.scan` without a limit, and `probe.scan {where on an unsupported field name}`.
- **Then** the first fails `STORE_RESULT_TOO_LARGE`, and the second fails `VALIDATION_FAILED`.

### M2.4-E20 — the kernel chooses the owner and workspace of every pool read
- **Test**: `packages/kernel/test/hosts/read-pool.test.ts`
- **Given** kv rows of two extensions in two workspaces and globally, and a read pool.
- **When** `store.read` calls are served for an invocation of the first extension in workspace A: a workspace read, a global read, and a workspace read from a global invocation.
- **Then**:
  - the reads see only the first extension's rows, in A and in the global scope;
  - the workspace read without a workspace fails `WORKSPACE_INVALID`.

### M2.4-E21 — shared and dedicated hosts do not read through the pool
- **Test**: `packages/kernel/test/hosts/read-pool.test.ts`
- **Given** an invocation running on a shared worker.
- **When** it sends a `store.read` call.
- **Then** the call fails `CAPABILITY_DENIED`.

### M2.4-E22 — the pool runs `readPoolSize` threads, started when first needed
- **Test**: `packages/kernel/test/hosts/read-pool.test.ts`
- **Given** read pools of size 1 and of the default size.
- **When** no read has run, then two reads run at once.
- **Then**:
  - neither pool has started a thread before the first read;
  - the default pool runs two threads and the other one;
  - both answer both reads.

### Capabilities

### M2.4-E23 — the grant checked is the calling invocation's
- **Test**: `packages/testkit/test/capabilities/surfaces.test.ts`
- **Given**:
  - Probe enabled in A at `shared`;
  - Caller enabled in A with its full grants, and in B with a helper grant without `calls`.
- **When** the person sends `caller.ping` in A and `caller.global` without a workspace.
- **Then**:
  - `caller.ping` reaches `probe.global.ping`, because A's grant covers it;
  - `caller.global` fails `CAPABILITY_DENIED`, because the intersection of A's and B's grants has no `calls`.

### M2.4-E24 — `tools` covers the workspace's enabled, not disabled agent tools
- **Test**: `packages/testkit/test/capabilities/surfaces.test.ts`
- **Given** Probe and Assistant enabled in A.
- **When** Assistant calls `probe.tool`, `probe.lookup`, and `probe.work` (not a tool).
- **Then** the two tools succeed and `probe.work` fails `CAPABILITY_DENIED`.
- **And when** the applied preset lists `probe.tool` in Probe's `disable`, the call to `probe.tool` fails `CAPABILITY_DENIED`, while `probe.lookup` still succeeds.
- **And** the global agent tool `probe.global.tool` succeeds from A, and fails `CAPABILITY_DENIED` when Assistant calls it from `assistant.global.use` without a workspace.

### M2.4-E25 — an admin query answers only administrators
- **Test**: `packages/testkit/test/capabilities/kernel-queries.test.ts`
- **Given** Warden and Intruder enabled in A.
- **When** `kernel.messages.list` is sent by the person, by Warden, by Intruder, and by a process of Warden.
- **Then** the person and Warden get a list, and Intruder and the process get `CAPABILITY_DENIED`.

### M2.4-E26 — `kernel.messages.list` filters, orders, and limits without payloads
- **Test**: `packages/testkit/test/capabilities/kernel-queries.test.ts`
- **Given** 250 finished `probe.whoami` commands in A, one `probe.whoami` in B delayed by a minute (pending), and one `probe.read` in C that failed `CAPABILITY_DENIED` (Probe sandboxed there).
- **When** the person lists with no filter, with each of `state`, `type`, `extension`, `workspaceId`, and `correlationId`, and with `limit: 5`.
- **Then**:
  - the unfiltered list has 200 items, newest first, and `total` counts every stored message;
  - each filter returns only its matches, and `limit: 5` returns the 5 newest;
  - no item has a payload or result.
- **And** `limit: 1001` fails `VALIDATION_FAILED`.

### M2.4-E27 — `kernel.subscribers.list` lists who would receive an event
- **Test**: `packages/testkit/test/capabilities/kernel-queries.test.ts`
- **Given** Probe, Listener, and Bystander enabled in A with their grants.
- **When** the person asks for `probe.worked` and for `kernel.extension.enabled` in A.
- **Then**:
  - `probe.worked` lists Listener (its `calls`) and Probe (its own subscription), sorted by name, both `active`;
  - `kernel.extension.enabled` lists Listener.
- **And**:
  - once Listener is quarantined, it is listed with `status: 'quarantined'`;
  - with a helper grant that lacks `subscribes probe.worked`, Listener is not listed for `probe.worked`.

### M2.4-E28 — `kernel.subscribers.list` refuses bad requests and answers empty for unknown types
- **Test**: `packages/testkit/test/capabilities/kernel-queries.test.ts`
- **Given** workspace A with Probe enabled.
- **When** the person asks with an unknown workspace, with `type: 'probe.*'`, with an unregistered type, and with the live event `probe.progress`.
- **Then**:
  - the unknown workspace fails `WORKSPACE_INVALID`, and the pattern fails `VALIDATION_FAILED`;
  - the unregistered type and the live event return `[]`.

### M2.4-E29 — grant commands accept only a person
- **Test**: `packages/testkit/test/capabilities/surfaces.test.ts`
- **Given** Warden (holding `kernel.admin`) enabled in A.
- **When** Warden sends `kernel.workspace.rename`, then `kernel.extension.enable`, `kernel.workspace.forget`, `kernel.extension.uninstall`, and `kernel.shutdown`, and a process of Warden sends `kernel.extension.enable`.
- **Then**:
  - the rename succeeds (admin);
  - each other command fails `CALLER_NOT_ALLOWED`, and nothing changes;
  - the person's own enable succeeds.

### Crash points and protocol

### M2.4-E30 — a killed kernel leaves no sandboxed host running
- **Test**: `packages/testkit/test/faults/hosts.test.ts`
- **Given** a child kernel with Probe enabled in A at `sandboxed`, and one `probe.whoami` answered (its `pid` recorded).
- **When** the child kernel is killed with `SIGKILL`.
- **Then** the sandboxed host's process exits.

### M2.4-E31 — the new call and query shapes are strict
- **Test**: `packages/protocol/test/capability-queries.test.ts`
- **Given** the `store.read` call, the `kernel.messages.list` request and result, and the `kernel.subscribers.list` request and result.
- **When** each is parsed with valid and invalid values.
- **Then**:
  - a `store.read` with an `owner`, a `ws`, or an unknown `op` is refused;
  - `limit` above 1,000 or below 1 is refused;
  - a subscribers `type` pattern is refused;
  - valid values parse unchanged.
