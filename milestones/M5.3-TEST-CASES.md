# M5.3 — Narration: test cases

Read: `16` §16.2, §16.6; ADR 0107, 4, 5, 7, 21, and 22.

The layers: the captions as unit tests; each service's request through a stand-in `fetch` (`extensions/kvvideo/test/unit/speech-services.test.ts`), so no test reaches the network; `narrate` through the test kernel with stand-in `piper`, `ffmpeg`, and `ffprobe` programs; and the settings and keys through the test kernel.

## Happy path

### M5.3-H1 — ElevenLabs is asked with its request
- **Given** the key `el-key`, no voice, and no model
- **When** the text "Welcome to Notes." is narrated
- **Then** one `POST` goes to `https://api.elevenlabs.io/v1/text-to-speech/JBFqnCBsd6RMkjVDRZzb?output_format=mp3_44100_128` with `xi-api-key: el-key`, `Content-Type: application/json`, and `{ "text": "Welcome to Notes.", "model_id": "eleven_multilingual_v2" }`; its body is the audio; a voice and a model of the settings replace the defaults
- Test: `extensions/kvvideo/test/unit/speech-services.test.ts`

### M5.3-H2 — OpenAI is asked with its request
- **Given** the key `oa-key`, no voice, and no model
- **When** the same text is narrated
- **Then** one `POST` goes to `https://api.openai.com/v1/audio/speech` with `Authorization: Bearer oa-key` and `{ "model": "gpt-4o-mini-tts", "voice": "alloy", "input": "Welcome to Notes.", "response_format": "mp3" }`; a voice and a model of the settings replace the defaults
- Test: `extensions/kvvideo/test/unit/speech-services.test.ts`

### M5.3-H3 — Piper narrates on this computer, and ffmpeg makes the MP3
- **Given** the service `piper` with a voice, a stand-in Piper that writes a WAV at its `-f`, a stand-in ffmpeg that writes the MP3 at its last argument, and a stand-in ffprobe that answers `2.5`
- **When** `narrate { text: "Open the app. Then sign in.", file: "videos/n/01.mp3" }` runs
- **Then** Piper got `-m <voice> -f <wav> -- <text>`, ffmpeg got `-i <wav> -codec:a libmp3lame -b:a 128k`, the file is ffmpeg's MP3, and the answer is `{ file: 'videos/n/01.mp3', durationMs: 2500, captions }`
- Test: `extensions/kvvideo/test/narrate.test.ts`

### M5.3-H4 — captions in proportion
- **Given** "Open the app. Then sign in." and 2600 ms
- **When** the captions are made
- **Then** they are `Open the app.` from 0 to 1300 and `Then sign in.` from 1300 to 2600
- Test: `extensions/kvvideo/test/unit/captions.test.ts`

### M5.3-H5 — long sentences, line breaks, Arabic, and white space
- **Given** a sentence of 60 characters, a line break inside a sentence, an Arabic sentence ending in `؟`, a `…` ending, and runs of spaces and tabs
- **When** the captions are made
- **Then** lines are whole words of at most 42 characters, filled as far as they go; a line break starts a new caption; `؟` and `…` end sentences; white space within a line is one space; a word over 42 characters is a line of its own; times are rounded down with no gap, and the last ends at the length
- Test: `extensions/kvvideo/test/unit/captions.test.ts`

### M5.3-H6 — the connector has narrate
- **Given** kvvideo loaded
- **When** the connector list is read
- **Then** `video` has `narrate` → `kvvideo.narration.make`, a command, with an example
- Test: `extensions/kvvideo/test/narrate.test.ts`

## Edge cases

### M5.3-E1 — no service chosen
- **Given** no `kvvideo.narration.service`
- **When** `narrate` runs
- **Then** it fails `kvvideo/NARRATION_NOT_SET { setting: 'kvvideo.narration.service' }`; Piper without a voice fails it with `kvvideo.narration.voice`; nothing is written
- Test: `extensions/kvvideo/test/narrate.test.ts`

### M5.3-E2 — no key
- **Given** ElevenLabs, then OpenAI, without their secret
- **When** `narrate` runs
- **Then** it fails `kvvideo/NARRATION_KEY_MISSING { service, secret }` with `elevenlabs.apiKey`, then `openai.apiKey`
- Test: `extensions/kvvideo/test/narrate.test.ts`

### M5.3-E3 — the service refuses, or can't be reached
- **Given** a stand-in `fetch` that answers 401 with a body of 400 characters, then one that rejects, then one that never answers
- **When** a service narrates
- **Then** it fails `kvvideo/NARRATION_FAILED` with `{ service, status: 401, reason }` (the first 300 characters), then `{ service, reason }`, then `{ service, reason }` after 60 s, without the key in the Problem
- Test: `extensions/kvvideo/test/unit/speech-services.test.ts`

### M5.3-E4 — Piper or ffmpeg fails
- **Given** a stand-in Piper that exits 1 printing "voice not found", then a Piper that works and an ffmpeg that exits 1
- **When** `narrate` runs
- **Then** each fails `kvvideo/NARRATION_FAILED { service: 'piper', reason }` with the program's last lines; nothing is written
- Test: `extensions/kvvideo/test/narrate.test.ts`

### M5.3-E5 — the input and output rules
- **Given** kvvideo with Piper
- **When** `narrate` gets an empty text, 4001 characters, `clip.wav`, an existing file without `replace`, and a path outside the workspace
- **Then** each fails `VALIDATION_FAILED` before a program runs
- Test: `extensions/kvvideo/test/narrate.test.ts`

### M5.3-E6 — the key is never in an answer or a Problem
- **Given** ElevenLabs and OpenAI with the key `el-secret-123`, narrating through a stand-in `fetch` that answers 401 echoing its headers, then succeeds
- **When** each call ends
- **Then** neither the Problem nor the answer holds `el-secret-123`; kvvideo's code calls `ctx.log` nowhere with a key (it reads a key only to send it)
- Test: `extensions/kvvideo/test/unit/speech-services.test.ts`
