# QA 51 — The builder knows kvman, builds on what exists, and never edits kvman itself (ADR 0080)

Asked: "optimize the prompts and the docs so the agent knows everything needed to build kvman extensions and presets. kvman's source code is never edited under any circumstances, and the extensions must use the available APIs of kvman or of existing extensions. The builder should be able to depend on existing extensions … or build something new." The owner chose strict rules in the prompts, a new `extensions-get` read, dependencies loaded from the project's `node_modules`, bundled dependencies added to the preview, the four guides as the whole reference, and the person's own words.

## Happy path

- **QA51-H1 The guide forbids changing kvman itself.** *Then* the guide of `/build-kvman` has the part "kvman itself is never changed." after the rules for a person and before "This app, or a different app.", naming `@kvman/*` packages installed or as source in the workspace, the home folder `~/.kvman` and `KVMAN_HOME`, and `dist/` and `node_modules/`, for `fs` and the shell alike, and says that an extension uses only `@kvman/sdk` and public names and that what isn't offered is said plainly. `extensions/kvbuilder/test/guide.test.ts`
- **QA51-H2 The guide designs before it builds.** *Then* it has "Design first." after "This app, or a different app." and before "Build an extension, in this order:", with a need-to-extension map that names kvwebui's `views` and `components`, kvai's `models`, and kvcoder's `connectors` and `sections`, `extensions-get`, and the execution map. `extensions/kvbuilder/test/guide.test.ts`
- **QA51-H3 The guide's method declares and installs dependencies.** *Then* the build steps, in order, are `docs get`, `ext new`, the dependency step with `npm install --save-dev --save-exact`, `Write it with \`fs\``, `ext check`, `ext test`, `preview start`, the preview calls, and `extensions-install`. `extensions/kvbuilder/test/guide.test.ts`
- **QA51-H4 The guide matches a developer's words.** *Then* after the sentence that keeps kvman's words from the person, the guide says a person who uses them first is a developer and the agent may use them too. `extensions/kvbuilder/test/guide.test.ts`
- **QA51-H5 `extensions-get` gives one extension's public shapes.** *Given* the bundled extensions, *then* `kvbuilder.app.extensions.get { name: '@kvman/kvcoder' }` answers its name, version, source, and namespace as `kernel.extensions.list` has them, every public command and query of it with the same description and JSON Schemas, none of its private ones, and its settings with the schema `kernel.settings.list` gives; it is a public query and is the `kvman` connector's `extensions-get`, which doesn't ask. `extensions/kvbuilder/test/app-reads.test.ts`
- **QA51-H6 A test kernel loads a project's installed dependencies.** *Given* a project that declares `@test/base` (which declares `@test/root`) in `kvman.dependencies`, with both in its `node_modules` (each with a `main` and no `src/`), *when* `createTestKernel({ extensions: [project] })` starts, *then* exactly the three load, the installed two as `bundled` (by `main`) and the project as `path:`, and the project's query calls `@test/base`'s public query. `packages/testkit/test/loading/installed-dependencies.test.ts`
- **QA51-H7 `kvman-check` passes a project with an installed dependency.** *Given* that project, *then* `kvman-check --json` prints `[]` and exits 0. `packages/testkit/test/check/check-dependencies.test.ts`
- **QA51-H8 The preview adds a bundled dependency.** *Given* a project that declares `@kvman/kvbuilder`, whose installed copy declares `@kvman/kvcoder` and `@kvman/kvai`, *then* the generated preset has the project as `path:`, `@kvman/kvai`, `@kvman/kvwebui`, `@kvman/kvbuilder`, and `@kvman/kvcoder` as `bundled`, and `kvwebui.home` `kvwebui.extensions`. `packages/testkit/test/bin/preview-preset.test.ts`
- **QA51-H9 The docs teach what the guide relies on.** *Then* the `sdk` guide documents `kvman.dependencies` with its exact devDependency, `ctx.files`, `ctx.processes`, `ctx.schedule` with `key` and `cancel`, `ctx.cancel`, `syncOnly`, `maxInputBytes`, `progress`, all eight handler points, and the testkit's `workspaceId`, `execAsync`, `waitForJob`, `clock.advance`, and `restart`; `conventions` has "Never edit kvman" and "Use what exists"; `building` names nine commands that change the app, `rolledBack`, and `extensions-get`; the scaffold's `AGENTS.md` names the dependency line and kvman's packages and home as never edited. `packages/testkit/test/docs/built-in-guides.test.ts`, `extensions/kvbuilder/test/docs-own.test.ts`, `packages/testkit/test/scaffold/harness-files.test.ts`

## Edge cases

- **QA51-E1 The guide still fits a section with the index.** *Then* the guide is at most 16 KB, and the guide plus a full 16 KB index leaves room under the 64 KB that the sections of a prompt may hold. `extensions/kvbuilder/test/guide.test.ts`
- **QA51-E2 The guide keeps its earlier rules.** *Then* every sentence QA35, QA36, and QA42 pinned is still there, in the same order of parts. `extensions/kvbuilder/test/guide.test.ts`
- **QA51-E3 `extensions-get` of an unknown name fails `NOT_FOUND`.** *Then* `{ name: '@acme/none' }` fails `NOT_FOUND`, and a name that isn't a package name fails `VALIDATION_FAILED`. `extensions/kvbuilder/test/app-reads.test.ts`
- **QA51-E4 A dependency that isn't installed is the kernel's failure.** *Given* a project that declares `@test/missing` with nothing installed, *then* `createTestKernel` fails `EXTENSION_INVALID` with "depends on @test/missing, which is not in this run" (M1.4-E1 unchanged). `packages/testkit/test/loading/installed-dependencies.test.ts`
- **QA51-E5 `kvman-check` names the npm line for a dependency that isn't installed.** *Given* a project that declares `@test/missing` and `@test/other` with neither installed, *then* `kvman-check --json` exits 1 with two error findings, each naming the dependency and `npm install --save-dev --save-exact`, and no load finding. `packages/testkit/test/check/check-dependencies.test.ts`
- **QA51-E6 A named folder wins over an installed copy.** *Given* the project and a `path:` folder of `@test/base` both passed in `extensions`, *then* the kernel loads that folder (its `kvman.source`) and not the installed copy. `packages/testkit/test/loading/installed-dependencies.test.ts`
- **QA51-E7 An installed dependency out of range is the kernel's failure.** *Given* an installed `@test/base` at 2.0.0 for a range `^0.1.0`, *then* `createTestKernel` fails `EXTENSION_INVALID` with "needs @test/base ^0.1.0, but the run has 2.0.0". `packages/testkit/test/loading/installed-dependencies.test.ts`
- **QA51-E8 The preview adds no dependency that isn't bundled, and a given preset is kept.** *Given* a project that declares `@acme/other` and `@kvman/kvcoder`, *then* the generated preset has `@kvman/kvcoder` and not `@acme/other`; *and given* a preset file, *then* the preview uses its extensions with the dev ones added and adds no dependency. `packages/testkit/test/bin/preview-preset.test.ts`
- **QA51-E9 The bundled names match the `kvman` package.** *Then* the testkit's bundled names are exactly the dependencies of `packages/cli/package.json` that have a `kvman` field. `packages/testkit/test/bin/preview-preset.test.ts`
