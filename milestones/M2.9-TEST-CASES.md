# M2.9 — LLM service: test cases

Read:

- `05` §5.11, `03` §3.12, `04` §4.1 (the `llm_models` and `llm_usage` tables, the `kernel_settings` row `llm.defaults`).
- The parts they cite:
  - `02` §2.3 (live events, runs, resets), §2.9 (deadlines);
  - `03` §3.4 (limits, retries), §3.8 (the `kernel.llm.*` rows);
  - `05` §5.4 (`ctx.llm`), §5.7 (`llm`, `provides-llm`), §5.10 (`fakeProvider`), §5.12 (the manifest's `llm`);
  - `06` §6.3 (`PROVIDER_CONFLICT`);
  - `07` §7.3 (the preset's `llm.defaults`);
  - `13` §13.2 (the `LLM_*` codes).
- ADRs 0014, 0059, 0072, 0123, 0133, 0148, 0151, and 0152–0154.

Earlier tests that M2.9 changes: M2.2-H5 and M2.2-E41 (`packages/testkit/test/install/uninstall.test.ts`) now expect no `llm_models` rows after an uninstall that keeps data. The product owner settled the disagreement between ADR 0152 and `06` §6.8: model rows go at every uninstall, and `06` §6.8 is corrected.

Earlier kernel defects the M2.9 tests found, fixed at their cause:

- A cancelled message's stored reply did not reach a waiter that registered after the cancel committed: `cancelled` was missing from the reply waiters' final states (E13, E16).
- A kernel command whose retryable failure made it dead stored `MESSAGE_DEAD` but never delivered it to its waiters (`KernelCommits` dropped the scheduler's result) (E12).
- Uninstall left the hosts that loaded the extension running, so a later install of another build under the same name ran the old code; uninstall now retires them as a reload does (H4).

Where the tests live:

- **Pure pieces**, in `packages/kernel/test/llm/`: model resolution, cost, the token estimate, and usage grouping.
- **Protocol shapes**, in `packages/protocol/test/llm-service.test.ts`.
- **The fake provider**, in `packages/testkit/test/llm/fake-provider.test.ts`.
- **Through a runtime**, in `packages/testkit/test/llm/`: workspaces A and B with applied presets, installed fixtures (ADR 0114), and the fake clock.

Terms:

- "**Person**" is `user:local`, an administrator.
- "**Fake**" is the testkit's `fakeProvider(options)` (ADR 0154), installed as a fixture: package `@kvman/fake-provider`, provider `fake`, model `fake-model`.
- "**Asker**" is `@acme/asker` (namespace `asker`), requesting `llm`, with live events `asker.tokens.generated` and `asker.thinking.generated` (chunk `text`) and a live event `asker.progress.updated` whose chunk is not `text`. Its commands:
  - `asker.ask { purpose, model?, thinking?, live?, failOnce? }` calls `ctx.llm.complete` and returns the result; with `failOnce`, its first attempt throws a retryable error *after* the call returns;
  - `asker.ask-global` is a global-scope command doing the same without a workspace;
  - `asker.count` and `asker.models` call `ctx.llm.countTokens` and `ctx.llm.models`.
- "**Mute**" is `@acme/mute`: the same `ask` command, without the `llm` capability.
- "**Lister**" is `@acme/lister-llm`, provider `lister`. Its `listModels` returns the models in its global config `listed`, or throws when `failList` is set. Its `countTokens` returns 42. It registers one static model, `lister-static`.
- "**Slow**" is provider `slow`, whose `complete` waits until its signal aborts.
- "**Broken**" is provider `broken`, whose `complete` behaves by its config `mode`:
  - `plain` sends one delta `partial`, then throws a plain `Error`;
  - `invalid` returns a result that does not match `llmResultSchema`;
  - `overflow` throws `llmProblem('LLM_CONTEXT_OVERFLOW', …)`;
  - `unconfigured` throws `llmProblem('LLM_NOT_CONFIGURED', …)`.

  Its `status` throws.
- "**Twin**" is `@acme/twin`, which also registers provider `fake`.
- **Workspace folders and the home folder** are temporary folders, never the real `~/.kvman` or `~/kvman`.
