# QA 37 — installing an extension by its source alone (ADR 0025)

Asked: the Extensions page's "Add an extension" form has a name field, while an extension's name is read from its package.json. Decided in ADR 0025; plan 02 §2.12, plan 06 §6.6, and plan 09 §9.1. This file is the contract; every scenario's test name starts with its id. Kernel and kvcustomizer tests run a test kernel; the page's tests run the Vue app on the fake API.

`kernel.extensions.install` takes `{ source }`, where `source` is `bundled:<name>`, `npm:<name>@<exact version>`, or `path:<folder>`; the preset file is unchanged (`bundled`, `npm:<exact version>`, `path:<folder>` under the name). The existing tests that install (QA17-H1, QA17-H5, QA17-E2, the preset-edit, restart, and kvcustomizer tests) keep their ids and call the new input; they are not repeated here. QA34-H6, QA34-H7, QA34-E7, and QA34-E9 are now QA37-H8, QA37-H9, QA37-E8, and QA37-E7 below, and QA34-E8 (a `name` that isn't the project's) is retired with the field.

## Happy path

- **QA37-H1 `installSourceSchema` accepts the three forms.** *Then* `bundled:@kvman/kvcoder`, `npm:@acme/notes@1.2.3`, `npm:notes@1.0.0-beta.1`, and `path:../notes` parse, and a `kernel.extensions.install` input is `{ source }` only. `packages/sdk/test/install-source.test.ts`
- **QA37-H2 An npm source names the extension.** *When* `kernel.extensions.install { source: 'npm:@acme/notes@1.2.3' }` runs, *then* the preset file has `"@acme/notes": "npm:1.2.3"`, and the answer is `{ file, restartRequired: true }`. `packages/kernel/test/preset-edit/install-source.test.ts`
- **QA37-H3 A bundled source names the extension.** *Given* a bundled `@kvman/kvcoder` removed from the preset, *when* `source: 'bundled:@kvman/kvcoder'` is installed, *then* the file has `"@kvman/kvcoder": "bundled"`. `packages/kernel/test/preset-edit/install-source.test.ts`
- **QA37-H4 A path source takes the name from package.json.** *Given* a folder whose package.json is named `@test/notes`, *when* `source: 'path:<folder relative to the preset file>'` is installed, *then* the file has `"@test/notes": "path:<that relative folder>"`, as it was given. `packages/kernel/test/preset-edit/install-source.test.ts`
- **QA37-H5 An absolute folder works.** *Then* `path:<absolute folder>` installs under the folder's name and is stored as given. `packages/kernel/test/preset-edit/install-source.test.ts`
- **QA37-H6 The bundled preset's first edit resolves against `<home>/presets`.** *Given* the bundled preset and a folder relative to `<home>/presets`, *when* it is installed, *then* the home copy has the entry under the folder's name. `packages/kernel/test/preset-edit/install-source.test.ts`
- **QA37-H7 The kernel checks the name only.** *Given* a folder whose package.json has a valid `name` and no `kvman` field, *then* the install succeeds (the loader judges the manifest at the next start). `packages/kernel/test/preset-edit/install-source.test.ts`
- **QA37-H8 kvcustomizer installs a workspace project by its folder.** *Given* a project `notes` in the workspace folder, *when* `kvcustomizer.app.extensions.install { source: 'path:notes' }` runs, *then* the preset has the project's package name with `path:<absolute folder>`. `extensions/kvcustomizer/test/app-install.test.ts`
- **QA37-H9 kvcustomizer passes `npm:` and `bundled:` on.** *Then* `{ source: 'npm:@acme/notes@1.2.3' }` is stored as `npm:1.2.3` under its name, and a `bundled:` source reaches the kernel, which judges it (`VALIDATION_FAILED` for a name that isn't bundled). `extensions/kvcustomizer/test/app-install.test.ts`
- **QA37-H10 The connector's help shows the new payloads.** *Then* `kvman help { command: 'extensions-install' }` shows examples `{"source":"npm:@acme/notes@1.2.3"}` and `{"source":"path:notes"}`, with no `name`; the guides `init` and `customizing` and the developer docs show `{ source }`. `extensions/kvcustomizer/test/run-form.test.ts`, `extensions/kvcustomizer/test/init.test.ts`
- **QA37-H11 The form has one field.** *Then* the "Add an extension" form has a Source field and no Name field; "Install" is enabled when the source is filled, and calls `kernel.extensions.install` with `{ source }`, then reloads the preset, shows the toast, and clears the field, in English and in Arabic. `extensions/kvwebui/test/web/extensions-manage.test.ts`
- **QA37-H12 A real kvman installs a project by its folder.** *Given* a running kvman child, *when* `kernel.extensions.install { source: 'path:<project>' }` runs and kvman restarts, *then* `kernel.extensions.list` has the project under its package name. `packages/cli/test/restart/restart.test.ts`

## Edge cases

- **QA37-E1 The old input fails.** *Then* `{ name: '@acme/notes', source: 'npm:@acme/notes@1.2.3' }` (a `name`), `{ source: 'npm:1.2.3' }`, and `{ source: 'bundled' }` fail `VALIDATION_FAILED`, and the file is untouched. `packages/kernel/test/preset-edit/install-source.test.ts`
- **QA37-E2 A bad source fails.** *Then* `npm:@acme/notes` (no version), `npm:@acme/notes@^1.2.3`, `npm:not a name!@1.0.0`, `npm:@1.0.0`, `bundled:`, `path:`, `git:x`, and `''` fail `VALIDATION_FAILED`. `packages/sdk/test/install-source.test.ts`, `packages/kernel/test/preset-edit/install-source.test.ts`
- **QA37-E3 A name that isn't bundled fails.** *Then* `bundled:@acme/a` fails `VALIDATION_FAILED` naming `bundled`. `packages/kernel/test/preset-edit/install-source.test.ts`
- **QA37-E4 A folder with no package.json fails.** *Given* a missing folder, and a folder without package.json, *then* each fails `VALIDATION_FAILED` with the folder in `params`, and the file is untouched. `packages/kernel/test/preset-edit/install-source.test.ts`
- **QA37-E5 A package.json with no usable name fails.** *Given* package.json that isn't JSON, one with no `name`, and one named `not a name!`, *then* each fails `VALIDATION_FAILED`. `packages/kernel/test/preset-edit/install-source.test.ts`
- **QA37-E6 A name already in the preset fails.** *Given* a `path:` folder whose package name is in the preset, and an `npm:` source of one that is, *then* each fails `VALIDATION_FAILED` ("already in the preset"). `packages/kernel/test/preset-edit/install-source.test.ts`
- **QA37-E7 kvcustomizer refuses a folder outside the workspace.** *Then* `path:../elsewhere` and `path:<filesystem root>` fail `VALIDATION_FAILED`. `extensions/kvcustomizer/test/app-install.test.ts`
- **QA37-E8 kvcustomizer refuses a folder that isn't a project.** *Given* a folder with no package.json, one with no `kvman` field, and a missing one, *then* each fails `kvcustomizer/NOT_A_PROJECT`. `extensions/kvcustomizer/test/app-install.test.ts`
- **QA37-E9 kvcustomizer takes no name.** *Then* `{ name: 'notes', source: 'path:notes' }` fails `VALIDATION_FAILED` at the command's input. `extensions/kvcustomizer/test/app-install.test.ts`
- **QA37-E10 The form's Install waits for a source.** *Given* an empty or blank source, *then* "Install" is disabled and calls nothing. `extensions/kvwebui/test/web/extensions-manage.test.ts`
- **QA37-E11 A failed install shows its Problem.** *Given* the kernel answers `VALIDATION_FAILED`, *then* the form shows the Problem, keeps the source, and the preset is not reloaded. `extensions/kvwebui/test/web/extensions-manage.test.ts`
