# QA 32 — the `opencode`, `pi`, and `claude` kinds of worker (ADR 0021, 3, 10 to 17, and 31 to 38)

Asked: the agent delegates work to "subagent, opencode, pi, claude code", and "each of them must have their own configs". Decided in ADR 0021; plan 08 §8.1, §8.5, §8.6, and §8.7. This file is the contract; every scenario's test name starts with its id. The tests never run the real programs: `test/support/worker-programs.ts` puts fixture programs named `opencode`, `pi`, and `claude` on the test kernel's `PATH`, which record their arguments and print, wait, or fail as the task says. The fixtures are scripts, so the tests that start one run on Linux and macOS; the per-OS choices (the process group, the tree kill) are tested as pure functions on every OS.

## Happy path

- **QA32-H1 The three kinds are entries of the setting.** *Then* `kvcoder.delegate.workers` takes an `opencode`, a `pi`, and a `claude` entry with their fields, each `null` where allowed, and the shipped five are unchanged. `extensions/kvcoder/test/unit/worker-programs.test.ts`
- **QA32-H2 Each kind's command line.** *Then* the arguments are, with every field set and with every field `null`: `opencode run --format json [--model m] [--agent a] [--auto] -- <instructions, blank line, task>`; `pi -p [--model m] [--thinking t] [--tools a,b] [--append-system-prompt i] -- <task>`; `claude -p --permission-mode p [--model m] [--effort e] [--append-system-prompt i] -- <task>`. `extensions/kvcoder/test/unit/worker-programs.test.ts`
- **QA32-H3 Each kind's answer.** *Then* `pi`'s and `claude`'s answer is the standard output, trimmed; `opencode`'s is the text events after the last `tool_use`, joined by a blank line, with lines that aren't JSON ignored, and its `error` events give the reasons. `extensions/kvcoder/test/unit/worker-programs.test.ts`
- **QA32-H4 A run suspends the turn and its answer is the result.** *Given* a `claude` worker with `approval: 'auto'`, *when* the agent calls `delegate run`, *then* the session is `waiting` with the pending call `{ kind: 'worker', runId }`, the program ran in the workspace folder with the worker's arguments and the task after `--`, and when it exits its standard output is the call's result and the next step runs. `extensions/kvcoder/test/worker-runs.test.ts`
- **QA32-H5 opencode and pi run the same way.** *Then* an `opencode` worker's result is its events' answer, with the instructions before the task, and a `pi` worker's is its output. `extensions/kvcoder/test/worker-runs.test.ts`
- **QA32-H6 Approval.** *Given* a worker with `approval: 'ask'`, *then* the call becomes an approval question holding the call; allowed, the pending call becomes `{ kind: 'worker', runId }` and the program runs; denied, the result is `denied by the user` and nothing runs. `extensions/kvcoder/test/worker-runs.test.ts`
- **QA32-H7 A background run.** *Then* `background: true` returns `started <runId>`, the turn goes on, and when the program exits its answer arrives as a message with `source: { kind: 'job', jobId: <runId> }`, which starts a turn when the chat is idle. `extensions/kvcoder/test/worker-runs.test.ts`
- **QA32-H8 The run is a job row.** *Then* `kvcoder.job.list` and `background list` have the run as `{ id, kind: 'worker', title: <worker>, call: <description>, status }`, `running` and then `succeeded` with `endedAt`, and `kvcoder.job.get` and `background output` give its `output` once it ended. `extensions/kvcoder/test/worker-jobs.test.ts`
- **QA32-H9 Stop.** *When* the person runs `kvcoder.job.cancel` on a run the turn waits on, *then* the program's tree is killed, the call's result is the error `<worker> was stopped`, the next step runs, and the row is `cancelled`. `extensions/kvcoder/test/worker-jobs.test.ts`
- **QA32-H10 The program check.** *Then* at a chat's first step each program worker is checked, the session's checks hold `worker:<name>`, a worker whose program is found is named in the index, and `kvcoder.delegate.worker.check` answers `ready` for it and for a `subagent`. `extensions/kvcoder/test/worker-checks.test.ts`
- **QA32-H11 Nothing is added to the usage.** *Then* after a run the session's and the turn's usage are what its model calls alone gave. `extensions/kvcoder/test/worker-runs.test.ts`
- **QA32-H12 The form has the kinds.** *When* "Add a worker" is saved with the kind opencode, a model, an agent, "Start at once", and 45 minutes, *then* the entry written is `{ name, description, enabled: true, kind: 'opencode', instructions, approval: 'auto', timeoutMs: 2700000, model, agent, autoApprove: false }` (its own approval turned off, ADR 0021, 39); the pi and Claude Code kinds write theirs, with empty fields as `null` and `tools` one per line. `extensions/kvcoder/test/web/worker-kinds.test.ts`
- **QA32-H13 Editing a program worker.** *Then* Edit shows its values with Kind fixed, and no Connectors, Model picker, or Thinking select of a subagent. `extensions/kvcoder/test/web/worker-kinds.test.ts`
- **QA32-H14 A row's state.** *Then* a program worker's row says "Checking…", then nothing more when the check answers `ready`, or "opencode not found" with "Check again", which checks once more; a subagent's row is never checked. `extensions/kvcoder/test/web/worker-kinds.test.ts`
- **QA32-H15 The run's card.** *Given* a turn waiting on `{ kind: 'worker', runId }`, *then* the conversation shows a card with the worker's name, the call's description, "Running" with the time, and Stop, which runs `kvcoder.job.cancel { sessionId, id: runId }`. `extensions/kvcoder/test/web/worker-card.test.ts`
- **QA32-H16 The Running chip.** *Then* a `worker` row shows its title and time, Stop while it runs, and its output under Logs once it ended. `extensions/kvcoder/test/web/jobs-chip.test.ts`
- **QA32-H17 In the real app.** *Given* kvman in Chromium, *when* the person adds a Claude Code worker from `delegate`'s dialog, *then* its row shows the kind "Claude Code" and, after a reload, still does, and the stored entry has `kind: 'claude'` and `permissionMode: 'acceptEdits'`. `extensions/kvcoder/test/e2e/configuration.test.ts`

## Edge cases

- **QA32-E1 The setting is strict for a program kind.** *Then* it fails `VALIDATION_FAILED` for a subagent's field on a program (`connectors`), a `timeoutMs` under 60 000 or over 7 200 000, an `approval` that isn't `ask` or `auto`, a `permissionMode`, `effort`, or `thinking` that isn't one of its values, an empty tool name, and a missing field. `extensions/kvcoder/test/unit/worker-programs.test.ts`
- **QA32-E2 A program that exits with another code.** *Then* the result is the error `<worker> exited with code 3`, then its standard error and its answer so far, and the row is `failed` with `exitCode: 3`. `extensions/kvcoder/test/worker-runs.test.ts`
- **QA32-E3 opencode's error events.** *Then* an `opencode` run that prints an `error` event and exits 1 returns `<worker> exited with code 1` and the event's message. `extensions/kvcoder/test/worker-runs.test.ts`
- **QA32-E4 No answer.** *Then* a program that exits 0 and prints nothing returns the error `<worker> returned no answer`. `extensions/kvcoder/test/worker-runs.test.ts`
- **QA32-E5 The time limit.** *Given* a run that passes its limit, *then* the process tree is killed and the result is the error `<worker> timed out after <N> s`. `extensions/kvcoder/test/unit/worker-programs.test.ts`
- **QA32-E6 A program that can't start.** *Given* a program that was removed after its check passed, *then* the result is the error `<worker> could not start: …`, and the turn goes on. `extensions/kvcoder/test/worker-runs.test.ts`
- **QA32-E7 A missing program hides the worker.** *Given* a `pi` worker and no `pi` on the `PATH`, *then* the check is `worker:<name>` not passed, the index doesn't name it, a run fails `kvcoder/WORKER_NOT_FOUND`, `kvcoder.delegate.worker.check` answers `notFound`, and with no other worker `delegate` isn't a connector of the chat. `extensions/kvcoder/test/worker-checks.test.ts`
- **QA32-E8 `worker.check` of an unknown name.** *Then* it fails `kvcoder/WORKER_NOT_FOUND`; a worker that is turned off is still checked. `extensions/kvcoder/test/worker-checks.test.ts`
- **QA32-E9 Cancel stops the run.** *When* `kvcoder.turn.cancel` runs while the turn waits on a run, *then* the program's tree is killed, the row is `cancelled`, the session is idle with the cancel notice, and no result is appended. `extensions/kvcoder/test/worker-jobs.test.ts`
- **QA32-E10 Delete stops the runs.** *When* the session is deleted while a background run goes on, *then* its program is killed and its run record is gone. `extensions/kvcoder/test/worker-jobs.test.ts`
- **QA32-E11 A message while waiting on a run.** *Then* a message sent while the turn waits only on a run is queued and read after the run's result; one sent while it waits on a run's approval denies it. `extensions/kvcoder/test/worker-runs.test.ts`
- **QA32-E12 Two runs in one reply.** *Then* they run at the same time, and their results are appended in the model's call order. `extensions/kvcoder/test/worker-runs.test.ts`
- **QA32-E13 A run whose job is lost.** *Given* a turn waiting on a run, *when* kvman restarts and the run's job fails `INTERRUPTED`, *then* the program is killed, the run is `interrupted`, and the turn ends `interrupted` with the `INTERRUPTED` notice; a background run adds the background message `<worker> was interrupted because kvman stopped.` and starts no turn. (A job that fails with another problem takes the same path with `failed` and `STEP_FAILED`; no test can make a worker thread crash on demand, so that branch has no scenario.) `extensions/kvcoder/test/worker-jobs.test.ts`
- **QA32-E14 Stopping a background run, and one that ended.** *Then* `background stop` of a running background run answers `{ stopped: true }` and adds the background message `<worker> was stopped` without starting a turn; of an ended one, `{ stopped: false }`. `extensions/kvcoder/test/worker-jobs.test.ts`
- **QA32-E15 A worker changed during a run.** *Then* a run keeps the command line it started with when its worker is edited or removed meanwhile, and a worker removed before its approval is allowed gives the error `kvcoder/WORKER_NOT_FOUND` as the call's result. `extensions/kvcoder/test/worker-runs.test.ts`
- **QA32-E16 A subagent can't run a program worker.** *Then* a child session has no `delegate`, whatever kinds of worker there are. `extensions/kvcoder/test/worker-checks.test.ts`
- **QA32-E17 Each OS.** *Then* the program starts in its own process group on Linux and macOS and not on Windows, and its tree is killed by the group there and by `taskkill /PID <pid> /T /F` on Windows. `extensions/kvcoder/test/unit/worker-programs.test.ts`
- **QA32-E18 The form's limits.** *Then* a time limit under 1 or over 120 minutes, or one that isn't a whole number, shows under its field and nothing is written. `extensions/kvcoder/test/web/worker-kinds.test.ts`
- **QA32-E20 Starting at once and approving itself.** *Then* the setting fails `VALIDATION_FAILED` for `approval: 'auto'` with `opencode`'s `autoApprove: true`, and with `claude`'s `permissionMode` of `bypassPermissions`, `auto`, or `dontAsk`; each is taken with `approval: 'ask'`, and `acceptEdits`, `plan`, an `opencode` with `autoApprove: false`, and a `pi` worker are taken with `auto` (ADR 0021, 39). `extensions/kvcoder/test/unit/worker-programs.test.ts`
- **QA32-E21 The form refuses it too.** *When* a worker is saved with "Start at once" and its own approval on, or a mode that asks nobody, *then* the problem shows under "Before a run" and nothing is written; with "Ask me" it is saved. `extensions/kvcoder/test/web/worker-kinds.test.ts`
- **QA32-E19 Both languages.** *Then* every new catalog key has an `en` and an `ar` entry. `extensions/kvcoder/test/locales.test.ts`
