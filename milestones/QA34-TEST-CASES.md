# QA 34 — the agent controls kvman: changes that ask, installing a project, the app's state, and calls (ADR 0022, 5 to 8 and 10 to 15)

Asked: "check and review the part where the agent can contols everything in kvman including developing extensions and optimize and enhance it properly". The review found four defects (ADR 0022), and the product owner chose to fix all four. Decided in ADR 0022; plan 08 §8.3 and §8.4, plan 09 §9.1, §9.3, and §9.4. This file is the contract; every scenario's test name starts with its id. Backend tests run a test kernel with the fake model; `test/e2e/` starts a real preview kvman.

## Happy path

- **QA34-H1 A command entry takes `asks: true`.** *Given* a connector registered with `{ name: 'add', command: 'todo.add', asks: true }` and `{ name: 'list', command: 'todo.list' }`, *then* `kvcoder.connector.list` answers `asks: true` for `add` and `false` for `list`. `extensions/kvcoder/test/connector-asks.test.ts`
- **QA34-H2 A call of it asks under `auto`.** *Given* `kvcoder.shell.approval: 'auto'`, *when* the agent calls that command, *then* the session is `waiting` on an approval question holding `{ description, connector, command, payload }` and nothing has run; allowed, it runs at the next step and its result reaches the model. `extensions/kvcoder/test/connector-asks.test.ts`
- **QA34-H3 `help` says so.** *Then* `help { command: 'add' }` has the line "The person is asked before this runs.", and `help { command: 'list' }` doesn't. `extensions/kvcoder/test/connector-asks.test.ts`
- **QA34-H4 kvcustomizer marks its five changes.** *Then* of the `kvman` connector's commands exactly `model-set`, `settings-set`, `settings-reset`, `extensions-install`, and `extensions-uninstall` have `asks: true`, and no command of `ext`, `preset`, `preview`, or `docs` has. `extensions/kvcustomizer/test/registration.test.ts`
- **QA34-H5 A setting change waits for the person.** *Given* the `coder` extensions, *when* the agent calls `kvman settings-set { key: 'kvwebui.theme', value: 'dark', scope: 'global' }`, *then* the setting is unchanged while the question is pending, and changes when it is allowed. `extensions/kvcustomizer/test/app-asks.test.ts`
- **QA34-H6 Installing a workspace project.** *Given* a project `notes` in the workspace folder whose package name is `notes`, *when* `kvcustomizer.app.extensions.install { name: 'notes', source: 'path:notes' }` runs, *then* it answers `{ file, restartRequired: true }` and `kvcustomizer.app.preset.get` has `notes` as `path:<the absolute folder>`. `extensions/kvcustomizer/test/app-install.test.ts`
- **QA34-H7 Other sources are untouched.** *Then* `npm:1.2.3` and `bundled` reach the kernel as given. `extensions/kvcustomizer/test/app-install.test.ts`
- **QA34-H8 The five reads.** *Then* `kvcustomizer.app.workspaces.list`, `.app.jobs.list { limit }`, `.app.jobs.get { id }`, `.app.processes.list`, and `.app.health.get` answer what `kernel.workspace.list`, `kernel.jobs.list`, `kernel.jobs.get`, `kernel.processes.list`, and `kernel.health.get` answer, and each is a public query. `extensions/kvcustomizer/test/app-reads.test.ts`
- **QA34-H9 `query-get` runs a public query of the app.** *Then* `kvcustomizer.app.query.get { name: 'kernel.health.get' }` answers the health, and `{ name: 'kvcustomizer.guides.get', input: { topic: 'sdk' } }` the guide. `extensions/kvcustomizer/test/app-reads.test.ts`
- **QA34-H10 The connectors name the new commands.** *Then* `kvman` has `workspaces-list`, `jobs-list`, `jobs-get`, `processes-list`, `health-get`, and `query-get`, and `preview` has `query-get` and `command-run`, each with its kernel command. `extensions/kvcustomizer/test/registration.test.ts`
- **QA34-H11 Calling the preview.** *Given* a running preview of a scaffolded project, *then* `kvcustomizer.preview.query.get { name: '<namespace>.greeting.get' }` answers `{ ok: true, output }` with the greeting, and `kvcustomizer.preview.command.run { name: 'kernel.settings.set', input: { key: 'kvwebui.theme', value: 'dark', scope: 'global' } }` answers `{ ok: true, output: {} }` and changes the preview's setting, not the app's. `extensions/kvcustomizer/test/e2e/preview-call.test.ts`
- **QA34-H12 The guide is a method.** *Then* the section has the parts "Build an extension", "Improve an extension", and "Manage the app"; the build steps in order (`docs get`, `ext new`, `fs`, `ext check`, `ext test`, `preview start`, `preview command-run`, `kvman extensions-install`); that the person is asked before a change; and the four kvcoder settings. `extensions/kvcustomizer/test/section.test.ts` *Changed by QA 35 (ADR 0023): there is no `guide` section; the text is `kvman init`'s result.*
- **QA34-H13 The walkthrough checks its work through the preview.** *Given* the `coder` preset in a real kvman, *when* the agent previews its project and calls `preview query-get`, *then* the call's result holds the project's greeting. `extensions/kvcustomizer/test/e2e/walkthrough.test.ts`

## Edge cases

- **QA34-E1 Denied.** *Then* a denied call of a command that asks returns `denied by the user`, and its command never ran. `extensions/kvcoder/test/connector-asks.test.ts`
- **QA34-E2 `asks` takes only `true`.** *Then* `asks: false`, and `asks` on a binary connector, fail `VALIDATION_FAILED`. `extensions/kvcoder/test/connector-asks.test.ts`
- **QA34-E3 A command without `asks` runs at once**, with `auto` and with `ask`: `kvcoder.shell.approval` covers kvcoder's own calls only. `extensions/kvcoder/test/connector-asks.test.ts`
- **QA34-E4 In a subagent.** *Then* a subagent's call of a command that asks shows its approval in the root chat, and runs when allowed. `extensions/kvcoder/test/connector-asks.test.ts`
- **QA34-E5 `help` of the command never asks.** `extensions/kvcoder/test/connector-asks.test.ts`
- **QA34-E6 The reads never ask.** *Then* `kvman settings-list` and `kvman health-get` return at once. `extensions/kvcustomizer/test/app-asks.test.ts`
- **QA34-E7 A folder that isn't a project.** *Then* `path:` to a folder with no package.json, or one without a `kvman` field, fails `kvcustomizer/NOT_A_PROJECT`, and the preset is unchanged. `extensions/kvcustomizer/test/app-install.test.ts`
- **QA34-E8 A name that isn't the project's.** *Then* `{ name: 'other', source: 'path:notes' }` fails `VALIDATION_FAILED`, naming both. `extensions/kvcustomizer/test/app-install.test.ts`
- **QA34-E9 A folder outside the workspace.** *Then* `path:../elsewhere` fails `VALIDATION_FAILED`. `extensions/kvcustomizer/test/app-install.test.ts`
- **QA34-E10 `query-get` of a command.** *Then* `{ name: 'kernel.settings.set' }` fails `VALIDATION_FAILED` and nothing is set. `extensions/kvcustomizer/test/app-reads.test.ts`
- **QA34-E11 `query-get` of an unknown or private name.** *Then* both fail `NOT_FOUND`. `extensions/kvcustomizer/test/app-reads.test.ts`
- **QA34-E12 `query-get` never lists a secret.** *Then* `{ name: 'kernel.secrets.list' }` fails `VALIDATION_FAILED`, and QA17-E15 still holds for every `kvman` command. `extensions/kvcustomizer/test/app-reads.test.ts`
- **QA34-E13 The query's own Problem passes through.** *Then* `{ name: 'kvcustomizer.guides.get', input: { topic: 'nothing' } }` fails `NOT_FOUND` with the guide's message. `extensions/kvcustomizer/test/app-reads.test.ts`
- **QA34-E14 No preview running.** *Then* `preview query-get` and `preview command-run` fail `NOT_FOUND`. `extensions/kvcustomizer/test/preview-call.test.ts`
- **QA34-E15 A failed call in the preview is data.** *Then* `preview query-get { name: 'nobody.nothing.get' }` answers `{ ok: false, problem: { code: 'NOT_FOUND', … } }`. `extensions/kvcustomizer/test/e2e/preview-call.test.ts`
- **QA34-E16 A preview that answers something else.** *Given* an answer that isn't the envelope, *then* the call fails `kvcustomizer/PREVIEW_FAILED`. `extensions/kvcustomizer/test/unit/preview-call.test.ts`
