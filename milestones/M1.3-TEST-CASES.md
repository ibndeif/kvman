# M1.3 — Storage: test cases

Read: `02` §2.5, §2.7, §2.8, §2.13; `01` §1.3; ADR 0009 (M1.2: collections take a schema; ISO times).

Every test opens a fresh home in a temporary folder, never `~/.kvman`. Ids come from the injected clock and random source. Log lines are captured from the kernel's Pino logger through an in-memory destination.

## Happy path

### M1.3-H1 — writes from two worker threads are both visible
- **Given** a home whose `kvman.db` is open on the main thread
- **When** two worker threads each open their own connection and insert a document into the same collection
- **Then** the main thread's connection reads both documents
- Test: `packages/kernel/test/storage/connections.test.ts`

### M1.3-H2 — an async transaction callback rolls back
- **Given** a store
- **When** `transaction` runs a callback that writes through `tx` and returns a Promise
- **Then** the call fails `VALIDATION_FAILED`, and the write is not stored
- Test: `packages/kernel/test/store/transactions.test.ts`

### M1.3-H3 — `find` needs a limit of at most 1000, orders by id, and `count` matches
- **Given** a collection with three documents inserted in order
- **When** `find` runs without a limit, with a limit of 1001, with `order: 'desc'`, and `count` runs with the same filter
- **Then** the first two fail `VALIDATION_FAILED`; `desc` returns the newest first; `count` equals the number of matches
- Test: `packages/kernel/test/store/collections.test.ts`

### M1.3-H4 — a document over 16 MiB fails
- **Given** a collection
- **When** a document whose JSON is over 16 MiB is inserted
- **Then** it fails `TOO_LARGE` with `params.limit` 16 MiB, and nothing is stored
- Test: `packages/kernel/test/store/limits.test.ts`

### M1.3-H5 — settings resolve in order, respect scopes, and skip stale values
- **Given** a key with a default, a preset value, a global value, and a workspace value
- **When** it is read in that workspace, in another workspace, and again after the workspace and global values are reset
- **Then** the workspace value, the global value, and the preset value win in turn, then the default; a global-only key refuses the workspace scope with `VALIDATION_FAILED`; a stored value that no longer fits the key's schema is skipped with a warning, and the next source is used
- Test: `packages/kernel/test/settings/settings.test.ts`

### M1.3-H6 — a secret never appears in SQLite or in logs
- **Given** a home with the database and the logger in use
- **When** an extension sets a secret, and the store and settings are used around it
- **Then** its value is in `secrets.json`, but not in `kvman.db`, its WAL, or any log line
- Test: `packages/kernel/test/secrets/secrets.test.ts`

### M1.3-H7 — a file over 1 GiB fails
- **Given** the files service
- **When** a file of 1 GiB + 1 byte is written
- **Then** it fails `TOO_LARGE` with `params.limit` 1 GiB, and neither a row nor a file under `files/` is left
- Test: `packages/kernel/test/files/files.test.ts`

### M1.3-H8 — the collection `find` benchmark meets its target
- **Given** a collection of 10 000 documents in a home on disk
- **When** `pnpm bench:check` runs `find` with an equality filter
- **Then** its p99 is at most 20 ms (`12` §12.3)
- Test: `bench/store-find.ts` (run by `pnpm bench:check`)

## Edge cases

### Database — `packages/kernel/test/storage/database.test.ts`

| Id | Given | Then |
|---|---|---|
| M1.3-E1 | a new home | `kvman.db` is in WAL mode with a busy timeout, has the kernel's tables (stores, settings, files, jobs, schedules, workspaces, accepted extensions), and keeps its data when reopened |

### Store — `packages/kernel/test/store/*.test.ts`

| Id | Given | Then |
|---|---|---|
| M1.3-E2 | `kv` | `get` of a missing key is `undefined`; `set`, `get`, and `delete` round-trip JSON; a value over 16 MiB fails `TOO_LARGE` (`limits.test.ts`) |
| M1.3-E3 | `insert` and `get` | `insert` returns the document with a UUIDv7 `id`; `get` of a missing id is `undefined` (`collections.test.ts`) |
| M1.3-E4 | a document that doesn't fit the schema | `insert` fails `VALIDATION_FAILED`; fields the schema doesn't know are dropped (`collections.test.ts`) |
| M1.3-E5 | `update` and `delete` | `update` merges top-level fields and stores `null` as `null`; `update` and `delete` of a missing id fail `NOT_FOUND`; an `update` that breaks the schema fails `VALIDATION_FAILED` and changes nothing (`collections.test.ts`) |
| M1.3-E6 | a stored document read through a schema it no longer fits | `get` and `find` fail `VALIDATION_FAILED` (`collections.test.ts`) |
| M1.3-E7 | `find` filters | equality on strings, numbers, booleans, and `null`, combined with AND; an object value or a non-integer limit fails `VALIDATION_FAILED` (`collections.test.ts`) |
| M1.3-E8 | two workspaces, `global`, and two extensions | each scope sees only its own documents and kv values, and one extension never sees another's (`scopes.test.ts`) |
| M1.3-E9 | a transaction | writes to the workspace and to `tx.global` commit together; a throw inside rolls both back; `tx` calls are synchronous (`transactions.test.ts`) |

### Settings — `packages/kernel/test/settings/settings.test.ts`

| Id | Given | Then |
|---|---|---|
| M1.3-E10 | a value that doesn't fit the key's schema, and an unknown key | `set` fails `VALIDATION_FAILED`; `get` and `set` of the unknown key fail `NOT_FOUND` |
| M1.3-E11 | a preset-only key (`scopes: []`) | `set` fails `VALIDATION_FAILED` in both scopes; its preset value resolves |
| M1.3-E12 | the stale-value warning | names the key and scope, never the value |

### Secrets — `packages/kernel/test/secrets/secrets.test.ts`

| Id | Given | Then |
|---|---|---|
| M1.3-E13 | secrets of two extensions | each sees only its own; `get` of a missing name is `undefined`; `delete` removes one |
| M1.3-E14 | `secrets.json` on this OS | Linux and macOS: mode 0600; Windows: no mode change (the profile folder's access rules protect it) |
| M1.3-E15 | a write that can't complete (the home folder made read-only) | fails, and `secrets.json` is still the old file; no temporary file is left after a successful write |

### Files — `packages/kernel/test/files/files.test.ts`

| Id | Given | Then |
|---|---|---|
| M1.3-E16 | `write` of bytes and of a string | stores `files/<id>` and a row `{ id, name, type, size, owner, workspaceId, createdAt }`; `read` returns the content (a string as UTF-8), and `path` is absolute |
| M1.3-E17 | a missing id | `get`, `read`, `path`, and `unlink` fail `NOT_FOUND`; `unlink` of a file removes its row and content |

### Ids — `packages/kernel/test/ids.test.ts`

| Id | Given | Then |
|---|---|---|
| M1.3-E18 | an injected clock and random source | ids are UUIDv7, the same inputs give the same ids, and ids made in the same millisecond still sort in the order they were made |
