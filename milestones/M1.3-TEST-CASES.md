# M1.3 — SDK core and registry: test cases

Read: `05` §5.1, §5.3 (permission, handler, and data rows), §5.5, §5.12, `03` §3.1 item 6, §3.3 step 3; ADRs 0013 (recording rules), 0016 (private names), 0041 (the kernel implements `ext`), 0042 (collected issues), 0043 (`z`), 0044 (typed references), 0045 (registry), 0046 (migrations), 0047 (JSON Schema conversion), 0048 (no workspace), 0049 (shared fixtures), 0050 (`Ctx` and `MigrationContext`).

The kernel's recorder runs `setup` in-process until M2.2 moves it into the sandboxed loader. Tests that write an extension with `defineExtension` and record it with the kernel live in `packages/testkit/test/recording/` (ADR 0041). "The pdf example's non-UI calls" are the permission, handler, and data calls of `05` §5.2 (everything except `registerTranslations` and the UI calls); its handlers use only the `ctx` built so far (`store`, `step`).

## Happy path

### M1.3-H1 — recording the pdf example produces the M0.3 fixture
- **Given** the pdf example of `05` §5.2 with its non-UI calls, written with `defineExtension` and `z` from `@kvman/sdk`
- **When** the kernel records it with version `1.2.0`
- **Then** the manifest's canonical JSON equals the M0.3 fixture's, with the fixture's `ui` sections empty (`settingsSection` `null`) and `translations` `null`; and the recording returns the handler functions under `command:pdf.import`, `command:pdf.translate`, `command:pdf.files.prune`, `query:pdf.files.list`, `query:pdf.files.count`, and `query:pdf.file.get`
- Test: `packages/testkit/test/recording/pdf-recording.test.ts`

### M1.3-H2 — a second recording is compared for determinism
- **Given** a `setup` that registers a command whose description changes on each run
- **When** it is recorded
- **Then** it fails `EXT_MANIFEST_INVALID` with an issue at `types.0.description` saying `setup` recorded something different on its second run; the pdf example records the same canonical JSON on both runs
- Test: `packages/testkit/test/recording/setup-rules.test.ts`

### M1.3-H3 — calling `ext` after `setup` throws
- **Given** a `setup` that keeps its `ext` in a variable
- **When** `ext.registerCommand` is called after recording finished
- **Then** it throws `EXT_MANIFEST_INVALID` with the detail `ext is closed after setup returns`
- Test: `packages/testkit/test/recording/setup-rules.test.ts`

### M1.3-H4 — a duplicate name in one name set fails
- **Given** a `setup` that registers a command `pdf.imported` and then an event `pdf.imported`
- **When** it is recorded
- **Then** it fails `EXT_MANIFEST_INVALID` with an issue at `types.1.type` saying the name is already registered as a command
- Test: `packages/testkit/test/recording/name-rules.test.ts`

### M1.3-H5 — a short public name fails with the full name as hint
- **Given** the pdf extension calling `registerCommand('translate', …)`
- **When** it is recorded
- **Then** it fails `EXT_MANIFEST_INVALID` with an issue at `types.0.type` whose hint is `did you mean "pdf.translate"?`
- Test: `packages/testkit/test/recording/name-rules.test.ts`

## Edge cases

### Recording rules (`05` §5.1, ADRs 0042) — `packages/testkit/test/recording/setup-rules.test.ts`

| Id | Given | Then |
|---|---|---|
| M1.3-E1 | an `async` `setup`, and a `setup` that throws `new Error('boom')` | `EXT_MANIFEST_INVALID` with the detail `setup is synchronous`; `EXT_MANIFEST_INVALID` with the detail `setup threw: boom` |
| M1.3-E2 | a `setup` with three mistakes (a missing description, a short entity name, a private name `Files`) | one `EXT_MANIFEST_INVALID` whose issues name all three paths |

### Manifest entries (`05` §5.3, §5.5, §5.12, ADRs 0013, 0046, 0047) — `packages/testkit/test/recording/manifest-entries.test.ts`

| Id | Given | Then |
|---|---|---|
| M1.3-E3 | registrations that give no optional fields | defaults written explicitly (`access: "all"`, `delivery: "durable"`, `retryable: false`, `idField: "id"` for a collection and an entity, `data.version: 1`, `compatibleWith: []`, `implements: []`); `config` and `permissions.isolation` `null`; every other optional field absent, never `undefined` |
| M1.3-E4 | every optional field of a command, a query, an event, a subscription (with a wildcard), a schedule, a log family, an error, an entity, `registerConfig`, `requestIsolation`, `requireTypes`, `requireComponents`, and `calls` with `types` | each recorded in its manifest section in call order, and the manifest parses with the protocol schema |
| M1.3-E5 | a subscription and a migration, and a command whose `handle` is not a function | functions returned under `subscription:<event>` and `migration:<to>`; the command fails at `types.0.handler` |
| M1.3-E6 | `registerDataVersion(3)` with migrations to 2 and 3, one without step 2, one with step 2 twice, one with step 4, and `compatibleWith` holding 3, 2, or 4 twice (ADR 0142: it lists higher versions) | the first records `migrations` in order with `migration:2`, `migration:3`; each other one fails `EXT_MANIFEST_INVALID` at its path |
| M1.3-E7 | an input schema with `.transform()` | `EXT_MANIFEST_INVALID` with an issue at `types.0.input` (ADR 0047) |

### Names (`05` §5.3, ADRs 0016, 0042) — `packages/testkit/test/recording/name-rules.test.ts`

| Id | Given | Then |
|---|---|---|
| M1.3-E8 | an entity `file`, an event `other.done`, and an error code `NOT_FOUND` in the extension `pdf` | issues at `entities.0.name`, `types.0.type`, and `errors.0.code`, with the hints `did you mean "pdf.file"?`, `did you mean "pdf.other.done"?`, `did you mean "pdf/NOT_FOUND"?`; a subscription to the foreign event `agent.session.deleted` and `requireTypes(['fs.file.get'])` with `calls` for `fs.file.get` are accepted (ADR 0107) |
| M1.3-E9 | a second entity, collection, log, schedule, error, subscription, or capability with a name already used in its set, and a second `registerConfig`, `registerDataVersion`, or `requestIsolation` | one issue at each later entry's path (or at `config`, `data.version`, `permissions.isolation`) saying it is already registered |
| M1.3-E10 | the private names `Files`, `history:*:x`, and `files`, `history:*`, `childRuns` | the first two fail at their paths; the others are accepted |

| Id | Given | Then |
|---|---|---|
