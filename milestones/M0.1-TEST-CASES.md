# M0.1 — Monorepo scaffold: test cases

Read: `01` (all), `14` §14.1, §14.4, §14.7, `00` D55; ADRs 0005, 0006, 0007.

Fixture files live in `test/fixtures/` and are excluded from the repository's own lint and type-check; the tests lint or compile them explicitly. Lint fixtures are linted as if they were located at a path inside a package (the "virtual path" below), which decides the wall that applies.

## Happy path

### M0.1-H1 — every script passes on the empty packages
- **Given** the eight packages of `01` §1.5 (`protocol`, `sdk`, `kernel`, `testkit`, `shell`, `widget-bridge`, `cli`, `devtools`) with empty entry points
- **When** `pnpm typecheck`, `pnpm lint`, `pnpm build`, and `pnpm bench:check` run (and `pnpm test`, which runs this scenario)
- **Then** each exits 0, `pnpm build` writes `dist/index.js` and `dist/index.d.ts` for every package, and `pnpm bench:check` prints `no baseline yet` (`14` §14.4)
- Test: `test/tooling/gates.test.ts`

### M0.1-H2 — a fixture that imports across a wall fails lint
- **Given** the fixture `test/fixtures/lint/protocol-imports-sdk.ts` (`import { … } from '@kvman/sdk'`)
- **When** it is linted at the virtual path `packages/protocol/src/fixture.ts`
- **Then** lint reports an `kvman/import-walls` error naming the wall (`protocol` may import only `zod`)
- Test: `test/tooling/import-walls.test.ts`

### M0.1-H3 — a 301-line fixture fails lint
- **Given** the fixture `test/fixtures/lint/lines-301.ts` (301 lines)
- **When** it is linted at the virtual path `packages/kernel/src/fixture.ts`
- **Then** lint reports a `max-lines` error (limit 300, `14` §14.1)
- Test: `test/tooling/max-lines.test.ts`

## Edge cases

### Import walls (`01` §1.5) — `test/tooling/import-walls.test.ts`

| Id | Given (fixture → virtual path) | Then |
|---|---|---|
| M0.1-E1 | `protocol` imports a third-party package other than `zod` | error; importing `zod` is clean |
| M0.1-E2 | `protocol` imports a Node built-in (`node:fs`) | error (protocol has no I/O) |
| M0.1-E3 | `sdk` imports `@kvman/kernel` | error; importing `@kvman/protocol` is clean |
| M0.1-E4 | `kernel` imports a value from `@kvman/sdk` | error; `import type` from `@kvman/sdk` is clean |
| M0.1-E5 | `kernel` imports `@kvman/devtools` | error (the kernel starts devtools scripts by path, never imports them) |
| M0.1-E6 | `testkit` imports `@kvman/shell` | error; importing `@kvman/kernel`, `@kvman/sdk`, `@kvman/protocol` is clean |
| M0.1-E7 | `shell`, `widget-bridge`, and `cli` each import `@kvman/sdk` | error for each; importing `@kvman/protocol` is clean |
| M0.1-E8 | `devtools` imports `@kvman/kernel` | error; importing `@kvman/testkit` and `@kvman/protocol` is clean |
| M0.1-E9 | an extension (`extensions/todo/src`) imports `@kvman/kernel`, `@kvman/shell`, or another extension (`@kvman/agent`) | error for each; `@kvman/sdk` and `@kvman/protocol` are clean |
| M0.1-E10 | an extension's source imports `@kvman/testkit` | error; the same import in its test file (`extensions/todo/test/`) is clean |
| M0.1-E11 | an example (`examples/pdf-translator/src`) imports `@kvman/kernel` | error |
| M0.1-E12 | any package imports a subpath of another package (`@kvman/protocol/src/index.ts`) | error: only the public entry point |
| M0.1-E13 | a relative import leaves its package (`../../protocol/src/index.ts` from `packages/sdk/src`) | error; a relative import inside the package is clean |
| M0.1-E14 | a wall is crossed by `export … from` and by a dynamic `import()` | error for each |
