# QA 18 — kvcoder's one `run` tool over connectors (ADR 0011)

Asked: replace the shell tool with a `run` tool that runs connector commands (`description`, `connector`, `command`, `payload`), make the shell a connector, give every connector a help command, run every connector command through `ctx.exec`, keep the agent away from jobs and processes, and show how an extension gives its own agent plain-function tools. Decided in ADR 0011 (1–19); plan 08 §8.2 to §8.7. This file is the contract; every scenario's test name starts with its id. Tests of earlier milestones that made calls as shell lines are rewritten to the `run` form and keep their ids; tests of removed behavior (`--async`, the `jobs` connector, heredoc bodies, the line parser, titles) are deleted.

## Happy path

- **QA18-H1 The one tool is `run`.** *Given* a turn, *then* the model request has exactly one tool, `run`, whose parameters are `description`, `connector`, `command`, and `payload`, with `description`, `connector`, and `command` required, and `connector` an enum of the session's connectors (`shell`, `fs`, `artifact`, `background`, `ask`, `subagent`, and the registered ones). (`extensions/kvcoder/test/run-tool.test.ts`)
- **QA18-H2 A commands connector runs through `run`.** *Given* the todo extension's connector, *when* the model calls `run { connector: 'todo', command: 'add', payload: { text } }`, *then* its command runs with the payload as input and the result is its output as JSON indented by 2 spaces, with no `[exit code` line. (`extensions/kvcoder/test/run-tool.test.ts`)
- **QA18-H3 `shell exec` runs a whole line.** *When* the model calls `shell exec { line: 'printf a; printf b | tr b c', risky: false }` (the PowerShell form on Windows), *then* the result is `ac` and `[exit code 0]`. (`extensions/kvcoder/test/shell-connector.test.ts`)
- **QA18-H4 Connector help.** *Then* `todo help {}` returns the connector's description and each command with its description, and `todo help { command: 'add' }` returns the command's description, its input and output JSON Schemas, and its examples written as `run` arguments. (`extensions/kvcoder/test/connector-help.test.ts`)
- **QA18-H5 Built-in help.** *Then* `help {}` of `shell`, `fs`, `artifact`, `background`, `ask`, and `subagent` each lists its commands, and `fs help { command: 'edit' }` holds the input schema with `path`, `edits`, and `risky`, each with a description. (`extensions/kvcoder/test/connector-help.test.ts`)
- **QA18-H6 A binary connector's `exec`.** *Given* a binary connector `node` whose check passes, *when* the model calls `node exec { args: '-e "console.log(6*7)"', risky: false }`, *then* the result is `42` and `[exit code 0]`. (`extensions/kvcoder/test/binary-connector.test.ts`)
- **QA18-H7 A binary connector's help.** *Then* `node help {}` describes `exec` and `help` and holds the output of `node --help`, `node help { command: 'exec' }` holds `exec`'s payload schema, `node help { command: '-p' }` runs `node -p --help`, and with `binary.help: 'node -e "console.log(\'help {command}\')"'` the program's part is `help` and `help build` for `{}` and `{ command: 'build' }`; none asks for approval even with `kvcoder.shell.approval: ask`. (`extensions/kvcoder/test/binary-connector.test.ts`)
- **QA18-H8 The prompt's connector index.** *Then* the system prompt lists each connector as its name and description followed by `Commands: <names>, help.` (the `todo` fixture: `add, wait, fail, list, help`; a binary connector: `exec, help`), holds no payload shape, and names the `run` tool. (`extensions/kvcoder/test/prompt-index.test.ts`)
- **QA18-H9 Background shell, followed up.** *When* the model calls `shell exec { line, background: true, risky: false }` for a line that prints and stays alive, *then* the result starts `started <id>` with the first output; `background list {}` has a row `{ id, kind: 'process', call: <line>, status: 'running' }`; `background output { id }` has the row and its `output`; `background stop { id }` returns `{ "stopped": true }`, the process is gone, and a second stop returns `{ "stopped": false }`. (`extensions/kvcoder/test/background-connector.test.ts`)
- **QA18-H10 A background subagent.** *When* the model calls `subagent run { task, mode: 'fresh', background: true }`, *then* the result is `started <childSessionId>`, the parent's turn goes on, `background list {}` has a `kind: 'subagent'` row, and the child's answer arrives later as a message. (`extensions/kvcoder/test/background-connector.test.ts`)
- **QA18-H11 `risky` in the payload.** *Given* `kvcoder.shell.approval: auto`, *then* `shell exec`, a binary's `exec`, `fs write`, and `fs edit` each run at once with `risky: false`, and each asks with `risky: true` and with `risky` left out; the pending approval holds `{ description, connector, command, payload }`; approved, the call runs at the next step and its result reaches the model. (`extensions/kvcoder/test/run-approval.test.ts`)
- **QA18-H12 `fs read`.** *Given* a file of 5 lines, *then* `fs read { path }` returns `{ path, fromLine: 1, totalLines: 5, content }` with the whole file, and `{ path, fromLine: 2, lines: 2 }` returns lines 2 and 3; it never asks, even with approval `ask`. (`extensions/kvcoder/test/fs-read.test.ts`)
- **QA18-H13 `fs list`.** *Given* a folder with two files and a sub-folder that holds a file, *then* `fs list { path }` returns the three entries sorted by name with `kind` and `bytes` (0 for the folder), `truncated: false`, and nothing of the sub-folder's content; `fs list {}` lists the workspace folder. (`extensions/kvcoder/test/fs-list.test.ts`)
- **QA18-H14 `fs search`.** *Given* files under `src`, `node_modules`, `.git`, and `.cache`, and one binary file, *then* `fs search { pattern: 'register(Command|Query)' }` returns `{ matches: [{ path, line, text }], truncated: false }` for the `src` files only, in path order, with paths relative to the workspace folder; `{ pattern, path: 'src/a.ts' }` searches that one file. (`extensions/kvcoder/test/fs-search.test.ts`)
- **QA18-H15 `ask` through `run`.** *When* the model calls `ask confirm { prompt }`, *then* the turn waits on a question, and the answer `{ confirmed: true }` becomes the call's result as JSON. (`extensions/kvcoder/test/run-tool.test.ts`)
- **QA18-H16 A subagent's connectors.** *When* the model calls `subagent run { task, mode: 'fresh', connectors: ['fs'] }`, *then* the child's `run` tool has the `connector` enum `fs` and `ask` only, and a child call to `shell exec` returns `error VALIDATION_FAILED: shell isn't available in this subagent.` (`extensions/kvcoder/test/subagent-connectors.test.ts`)
- **QA18-H17 Every connector command is a kernel job.** *Then* `kernel.extensions.list` shows kvcoder's private `kvcoder.shell.run`, `kvcoder.binary.run`, `kvcoder.fs.write`, `kvcoder.fs.edit`, `kvcoder.fs.file.get`, `kvcoder.fs.entry.list`, `kvcoder.fs.text.search`, `kvcoder.artifact.write`, `kvcoder.artifact.edit`, `kvcoder.artifact.content.get`, `kvcoder.background.list`, `kvcoder.background.output.get`, `kvcoder.background.stop`, `kvcoder.ask.text.check`, `kvcoder.ask.choice.check`, `kvcoder.ask.confirm.check`, `kvcoder.subagent.check`, and `kvcoder.connector.help.get`, none public, every top-level input field described, and no `kvcoder.connector.run`; another extension calling one fails `NOT_PUBLIC`. (`extensions/kvcoder/test/connector-commands.test.ts`)
- **QA18-H18 `runConnector`.** *Then* `runConnector(kernel, { connector: 'todo', command: 'add', payload })` returns `{ output, exitCode: 0 }` with the JSON output, `{ connector: 'todo', command: 'help' }` and `{ connector: 'fs', command: 'help' }` return help, and `{ connector: 'fs', command: 'write', payload }` returns exit 1 without writing. (`extensions/kvcoder/test/run-connector.test.ts`)
- **QA18-H19 The call card.** *Given* a `run` call and its result, *then* the closed card shows the description, then `fs · edit` and the time; opened, a `shell exec` call shows its line and the output, and an `fs edit` call shows its payload fields and the output; a failed call has the danger border. (`extensions/kvcoder/test/web/call-card.test.ts`)
- **QA18-H20 The live step shows the description.** *Given* `toolcall` chunks of a `run` call, *then* the pending answer shows the call's description as soon as that argument is complete, and `connector · command` once they are. (`extensions/kvcoder/test/web/live-step.test.ts`)
- **QA18-H21 The approval card.** *Given* a pending approval `{ description, connector: 'shell', command: 'exec', payload: { line } }`, *then* the card shows the description and the line, and one of `fs write` shows the description and the path. (`extensions/kvcoder/test/web/question-card.test.ts`)
- **QA18-H22 kvcustomizer's connectors through `run`.** *Then* `runConnector(kernel, { connector: 'ext', command: 'list' })`, `docs get` with a payload, and `kvman settings-list` answer as before, and kvcustomizer's `guide` section and `customizing` page write calls in the `run` form, with no quoted-JSON shell line. (`extensions/kvcustomizer/test/run-form.test.ts`)
- **QA18-H23 The function-tools guide.** *Then* `docs/developers/agents-and-tools.md` exists, is linked from the developer README and `sdk.md`, and its example extension, loaded in a test kernel with a scripted model, answers `7` to "add 3 and 4" by running its `calculate` function inside its handler, and the extension registers no command or query for the tool (`kernel.extensions.list`). (`extensions/kvai/test/function-tools.test.ts`)
- **QA18-H24 The docs describe `run`.** *Then* `docs/developers/connectors.md`, `docs/user-guide/coding-app.md`, `extensions/kvcoder/docs/connectors.md`, and `extensions/kvcustomizer/docs/customizing.md` name the `run` tool, `help`, and the `background` connector, and none of `docs/**`, the extensions' `docs/`, or the README's QA 18 row holds `--async`, `jobs get`, `jobs cancel`, a heredoc connector call, or `<connector> -h`. (`packages/cli/test/docs-run-tool.test.ts`)
- **QA18-H25 `kernel.registrations.list`.** *Then* it answers one row `{ name, kind, extension, public, description }` per command and query of the run's extensions, private ones included, with no schema, to the person and to an extension alike. (`packages/testkit/test/kernel-api/extensions-health.test.ts`)
- **QA18-H26 Several connectors in one call.** *When* an extension calls `kvcoder.connector.register { connectors: [a commands connector, a binary connector, one it already owns] }`, *then* all three are listed, the one it owned is replaced, and the single-connector form still works. (`extensions/kvcoder/test/connector-register.test.ts`)
- **QA18-H27 Every connector lives in its own file.** *Then* `extensions/kvcoder/src/connectors/` has one file for each of `shell`, `fs`, `artifact`, `background`, `ask`, `subagent`, and `binary`, each naming its own jobs and no other connector's; `extensions/kvcustomizer/src/connectors/` has exactly `kvman.ts`, `ext.ts`, `preset.ts`, `preview.ts`, and `docs.ts`, each exporting one connector; and kvcustomizer registers them in one call. (`extensions/kvcoder/test/unit/connector-files.test.ts`)
- **QA18-H28 The start benchmarks share one preset.** *Then* `start.cold` and `rss.idle` both run the `coder` preset with `kernel.workers: 3` added and nothing else changed. (`test/bench/reference-preset.test.ts`)

## Edge cases

- **QA18-E1 Another tool.** *When* the model calls a tool named `bash`, *then* the result is `error VALIDATION_FAILED: The call's arguments are invalid: the tool is run, not bash.` and the turn goes on. (`extensions/kvcoder/test/run-tool.test.ts`)
- **QA18-E2 A string payload.** *When* `payload` is the string `'{"text":"milk"}'`, *then* it is parsed and the command runs; a string that isn't a JSON object fails `VALIDATION_FAILED` saying the payload must be a JSON object. (`extensions/kvcoder/test/run-tool.test.ts`)
- **QA18-E3 A missing or blank description.** *Then* a call with no `description`, or one of spaces, fails `VALIDATION_FAILED` with `description: … (it must be one sentence saying what this call does, for the person)`, and nothing runs. (`extensions/kvcoder/test/run-tool.test.ts`)
- **QA18-E4 An unknown connector or command.** *Then* `connector: 'nope'` fails `VALIDATION_FAILED` naming the session's connectors, and `todo remove` fails `error NOT_FOUND: todo has no command remove; call its help.` (`extensions/kvcoder/test/run-tool.test.ts`)
- **QA18-E5 An invalid payload shows the schema.** *When* `fs edit { file: 'a' }` is called, *then* the result is `error VALIDATION_FAILED:` with each problem and then the command's input JSON Schema; a registered command's invalid payload returns the kernel's `VALIDATION_FAILED` and the schema the same way. (`extensions/kvcoder/test/run-tool.test.ts`)
- **QA18-E6 No payload.** *Then* `todo list` with no `payload` runs with `{}`. (`extensions/kvcoder/test/run-tool.test.ts`)
- **QA18-E7 `help` is reserved.** *Then* `kvcoder.connector.register` with a command named `help` fails `VALIDATION_FAILED`, and registering `shell`, `fs`, `artifact`, `background`, `ask`, or `subagent` fails `kvcoder/NAME_TAKEN`. (`extensions/kvcoder/test/connector-register.test.ts`)
- **QA18-E8 Help of an unknown command.** *Then* `todo help { command: 'nope' }` fails `error NOT_FOUND: todo has no command nope; call its help.` (`extensions/kvcoder/test/connector-help.test.ts`)
- **QA18-E9 A binary whose check failed.** *Then* it isn't in the prompt or the `connector` enum, and a call to it fails `VALIDATION_FAILED` like an unknown connector. (`extensions/kvcoder/test/binary-connector.test.ts`)
- **QA18-E10 A binary's background `exec`.** *Then* `node exec { args, background: true, risky: false }` returns `started <id>`, and `background list` shows it with `call` as the line `node <args>`. (`extensions/kvcoder/test/binary-connector.test.ts`)
- **QA18-E11 The shell's timeout.** *Then* `shell exec { line, timeoutMs: 200, risky: false }` of a line that sleeps returns `[timed out after 0 s; the process tree was killed]` and `[exit code 124]`, and a `timeoutMs` above 600 000 is cut to 600 000. (`extensions/kvcoder/test/shell-connector.test.ts`, `extensions/kvcoder/test/unit/shell-command.test.ts`)
- **QA18-E12 A shell payload's unknown key.** *Then* `shell exec { command: 'ls' }` fails `VALIDATION_FAILED` and names `line`. (`extensions/kvcoder/test/shell-connector.test.ts`)
- **QA18-E13 A denied call.** *Given* approval `ask`, *when* the person answers `{ confirmed: false }` to a `shell exec`, *then* the result is `denied by the user` and nothing ran. (`extensions/kvcoder/test/run-approval.test.ts`)
- **QA18-E14 `help` never asks.** *Given* approval `ask`, *then* `shell help {}` and `fs help {}` return at once. (`extensions/kvcoder/test/run-approval.test.ts`)
- **QA18-E15 `background` of another chat.** *Then* `background output { id }` and `background stop { id }` with an id this chat didn't start fail `kvcoder/JOB_NOT_FOUND`. (`extensions/kvcoder/test/background-connector.test.ts`)
- **QA18-E16 No `--async`.** *Then* a registered command called with `background: true` in its payload runs to its end like any call (the key is the command's own to accept or refuse) and returns its output, not `started`, and no job row is made for a connector call of a turn. (`extensions/kvcoder/test/run-tool.test.ts`)
- **QA18-E17 `fs read` limits.** *Then* a file of 3000 lines returns 2000 lines and `totalLines: 3000`; `lines: 2001` fails `VALIDATION_FAILED`; a file of long lines returns whole lines up to 30 KB; `fromLine` past the end returns an empty `content`; a missing file fails `NOT_FOUND`; a folder, a file that isn't UTF-8, and a path that leaves the workspace (through `..` and through a symlink) fail `VALIDATION_FAILED`. (`extensions/kvcoder/test/fs-read.test.ts`)
- **QA18-E18 `fs list` limits.** *Then* a folder of 1001 files returns 1000 entries and `truncated: true`; a missing folder fails `NOT_FOUND`; a file's path and a path that leaves the workspace fail `VALIDATION_FAILED`. (`extensions/kvcoder/test/fs-list.test.ts`)
- **QA18-E19 `fs search` limits.** *Then* 201 matching lines return 200 matches and `truncated: true`; a line of 800 characters is cut at 500; an invalid regular expression fails `VALIDATION_FAILED`; a missing `path` fails `NOT_FOUND`; a path that leaves the workspace fails `VALIDATION_FAILED`; no match returns `{ matches: [], truncated: false }`. (`extensions/kvcoder/test/fs-search.test.ts`)
- **QA18-E20 An old chat's approval.** *Given* a held result of a stored turn whose approved call is the old form (`{ command, timeoutMs }`), *then* it parses, and running the approved calls runs nothing for it and gives `denied by the user` and `Make this call again with the run tool.` (`extensions/kvcoder/test/unit/old-records.test.ts`)
- **QA18-E21 An old chat's history.** *Given* a session whose stored messages hold a `bash` call and its result, *when* a message is sent, *then* the request to the model holds that call and result unchanged, and the one tool offered is `run`. (`extensions/kvcoder/test/old-calls.test.ts`)
- **QA18-E22 An old call's card.** *Given* a stored `bash { command: 'ls -a' }` call and its result, *then* the card shows `ls -a` as its line and its output when opened. (`extensions/kvcoder/test/web/call-card.test.ts`)
- **QA18-E23 Stored background rows of removed kinds.** *Given* a stored background row of kind `connector`, *then* it still parses, so reading a chat's rows never fails on it; only `subagent` rows and processes are listed. (`extensions/kvcoder/test/unit/old-records.test.ts`)
- **QA18-E24 A subagent can't be given `subagent` or an unknown connector.** *Then* `subagent run { …, connectors: ['subagent'] }` and `connectors: ['nope']` return `error VALIDATION_FAILED: A subagent can't have the connector …`, and a payload with `shell` fails as an unknown key. (`extensions/kvcoder/test/subagent-connectors.test.ts`)
- **QA18-E25 The Windows branch.** *Then* the shell program and arguments for `shell exec` and a binary's `exec` are `pwsh -NoProfile -Command <line>` on `win32` and `bash -lc <line>` elsewhere, and the tool's name is `run` on both. (`extensions/kvcoder/test/unit/shell-command.test.ts`)
- **QA18-E26 A large payload doesn't break the stream.** *Given* a tool call whose `payload` object is over 16 KiB as JSON, *then* kvai's `toolcall` chunk sends `payload: null` and a small object unchanged, and the returned message keeps the whole payload; a `shell exec` whose line is 70 000 characters runs. (`extensions/kvai/test/toolcall-arguments.test.ts`, `extensions/kvcoder/test/big-call.test.ts`)
- **QA18-E27 All or none.** *Given* a call with a valid connector and a second one that is a name another extension owns, a built-in name, a command that isn't the caller's, or the first one's name again, *then* the call fails (`kvcoder/NAME_TAKEN` for the first two, `VALIDATION_FAILED` for the others) and neither connector is stored; an empty list fails `VALIDATION_FAILED`. (`extensions/kvcoder/test/connector-register.test.ts`)
- **QA18-E28 An owner with no command or query.** *Given* an extension that registers only a `kernel.started` handler, a binary connector, and a global section, *then* it has no row in `kernel.registrations.list`, and its connector is still listed and its section still in the prompt. (`extensions/kvcoder/test/connector-register.test.ts`)
