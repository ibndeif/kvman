# M4.6 — The VS Code extension feels native: test cases

Read: `15`; `06` §6.2 (the host messages); ADR 0100, 20 to 30.

The layers are those of M4.2: the session's decisions (`session.test.ts`), the controller with a fake host, the entry with the fake `vscode` module (now with the editor's parts), and the view's page in `happy-dom`, where the frame's window is the iframe's and the extension's messages come with no source. The by-hand check runs in a real VS Code, as in M4.2, and is recorded at the end.

## Happy path

### M4.6-H1 — the manifest: activity bar, title-bar buttons, context menus, VS Code 1.95
- **Given** the manifest
- **When** it is read
- **Then** the container `kvman` is in `activitybar`; `menus.view/title` has `kvman.showPages`, `kvman.openSettings`, and `kvman.openInBrowser` when `view == kvman.view`, each with its icon; `menus.editor/context` has `kvman.addToChat` when `editorHasSelection`, and `menus.explorer/context` when `!explorerResourceIsFolder`; `engines.vscode` is `^1.95.0`; `@types/vscode` is `1.95.0`
- Test: `packages/vscode/test/manifest.test.ts`

### M4.6-H2 — the frame is the line's URL with `&embed=parent`
- **Given** a `running` line with `http://127.0.0.1:3737/?workspace=w1`
- **When** the session reads it
- **Then** the frame is `http://127.0.0.1:3737/?workspace=w1&embed=parent`
- Test: `packages/vscode/test/session.test.ts`

### M4.6-H3 — the page answers `kvman.state` with VS Code's theme, and sends it again on a theme change
- **Given** the view's page with VS Code's variables on its root and `vscode-dark` on its body
- **When** the frame posts `{ kind: 'kvman.state', workspaceId: 'w1' }`, then the body's class becomes `vscode-light`
- **Then** the page posts to the frame, at kvman's origin, `kvman.theme` with `dark: true`, the side bar's background, the foreground, the button colors, the error, warning, and passed colors, and VS Code's fonts and size; then again with `dark: false`; it passes `kvman.state` on to the extension
- Test: `packages/vscode/test/web/relay.test.ts`

### M4.6-H4 — Pages, Open in browser, and Settings use the frame's workspace
- **Given** a framed kvman on 3737 whose frame said `kvman.state` with `w2`
- **When** Pages, Open in browser, and Settings (twice) run
- **Then** Pages sends `{ kind: 'kvman.pages' }` to the frame; Open in browser opens `http://127.0.0.1:3737/?workspace=w2`; Settings opens one "kvman Settings" tab framing `http://127.0.0.1:3737/kvwebui/settings?workspace=w2&embed=parent`, and the second press shows it
- Test: `packages/vscode/test/frame-requests.test.ts`, `packages/vscode/test/editor.test.ts`

### M4.6-H5 — the frame's opens: a file, a diff, and a Git change
- **Given** the view framing kvman
- **When** the frame asks `kvman.openFile` for `/w/a.ts` at line 12, `kvman.openDiff` for `/w/a.ts` (there) and `/w/new.ts` (missing) with `after`, and `kvman.openChange` for `/w/a.ts`, once with Git answering and once failing
- **Then** `/w/a.ts` shows as a preview with the cursor at line 12; the diffs are VS Code's diff of the file (or an empty document) against a read-only document of `after`, titled with the message's title; the change runs `git.openChange` with the file, and its failure shows "There's no Git change to show for this file."
- Test: `packages/vscode/test/editor.test.ts`

### M4.6-H6 — "Add to kvman chat": a selection, a file, and before the frame is ready
- **Given** an editor on `/w/src/a.ts` (language `typescript`) with lines 3 to 5 selected, and a file `/w/README.md` in the explorer
- **When** "Add to kvman chat" runs for each, first before the frame has said `kvman.state`, then after
- **Then** the view is shown; the first text is held, kvman starts, and once `kvman.state` comes the frame gets `{ kind: 'kvman.insert', text: '`src/a.ts:3-5`\n```typescript\n<lines>\n```' }`; the file gives `` `README.md` ``; a one-line selection gives `` `src/a.ts:4` ``
- Test: `packages/vscode/test/add-to-chat.test.ts`, `packages/vscode/test/frame-requests.test.ts`

### M4.6-H7 — the new texts in Arabic
- **Given** VS Code in Arabic
- **When** the extension's catalog and `package.nls.ar.json` are read
- **Then** the Pages, Settings, Open in browser, and Add to kvman chat titles, "kvman Settings", and "There's no Git change to show for this file." are Arabic
- Test: `packages/vscode/test/catalog.test.ts`

## Edge cases

### M4.6-E1 — a relative path, or another shape, opens nothing
- **Given** the extension
- **When** the frame asks `kvman.openFile` for `src/a.ts`, `kvman.openDiff` without `after`, `kvman.openChange` with a number, and `kvman.state` without a workspace
- **Then** nothing opens and the workspace stays
- Test: `packages/vscode/test/page-messages.test.ts`

### M4.6-E2 — the page passes on only the frame's messages, and gives the frame only the extension's
- **Given** the view's page
- **When** another window posts `kvman.state`, and the extension sends `{ from: 'extension', message: { kind: 'kvman.pages' } }`
- **Then** the first gets no theme and isn't passed on; the second is posted to the frame at kvman's origin
- Test: `packages/vscode/test/web/relay.test.ts`

### M4.6-E3 — a new frame waits for its own `kvman.state`
- **Given** a framed kvman whose frame said `kvman.state`
- **When** a restart's `running` line comes, then "Add to kvman chat" runs, then the new frame says `kvman.state`
- **Then** the text is held until the new `kvman.state`, then sent once
- Test: `packages/vscode/test/frame-requests.test.ts`

### M4.6-E4 — Pages and Settings with no frame yet start kvman first
- **Given** no kvman running
- **When** Settings runs, then kvman's `running` line and the frame's `kvman.state` come
- **Then** kvman starts, and Settings opens at the start workspace once kvman runs; Pages with no frame sends nothing
- Test: `packages/vscode/test/frame-requests.test.ts`

## The by-hand check

Done on 2026-10-22, on Linux, in VS Code 1.141.2 with a profile, extensions folder, and kvman home of its own and the repository's kvman on port 3911, driven through VS Code's debugging port, as in M4.2.

- **The view.** "kvman: Open" showed kvman in the primary side bar under its "KV" activity bar icon, with Pages, Settings, and Open in browser in the view's title bar. The frame was embedded (no top bar, nav, or status bar), `--kvwebui-ground` was VS Code's side bar color (`#191a1b` in the default dark theme), and the root font size was `13px`.
- **Pages** opened kvwebui's pages menu in the frame: Chat, Models, Settings, Extensions.
- **Settings** opened the "kvman Settings" tab with kvwebui's settings page in VS Code's editor colors.
- **Closing VS Code** stopped kvman: port 3911 was free within a second.
- **Seen and fixed**: on a new chat the History button's row had a border under the button only; the narrow row now carries one border across the side bar.
- **Seen**: Escape pressed in VS Code doesn't reach the frame, so the pages menu closes on a pick or a press outside it; Escape works when the frame has the focus.
- **Not driven**: "Add to kvman chat" and "Open diff" in the real window; keyboard focus moved into the Settings tab's frame. Their parts are covered by the tests above.
