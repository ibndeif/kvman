# QA 10 — a chat that stops (ADR 0009, 202–209)

Found by using the QA 9 build: a reply that only said what it would do ended the turn, a 403 for a model that needs an 18+ confirmation ended a turn with no way on, the model popover scrolled the page sideways, every card carried `exit 0` or `exit 1` with its command line on the wrong edge, and the layout's buttons showed the arrow. The product owner chose: a stronger prompt (no check in code) for the stalled turn, more temporary failures retried and one-click recovery for the rest, picking a model sets the default model, and no exit chip. Every scenario names its test. Backend tests use the test kernel and the fake model; `test/web/` mounts components in happy-dom; `test/e2e/` drives Chromium against a real kvman.

## Happy path

- **QA10-H1 The prompt makes a reply a call or the finished answer.** *Then* the base prompt holds, as its last working-method line, the rule of ADR 0009, 202: a reply with no tool call is the final answer and ends the turn, when work remains the reply must contain the call, and a reply that only says what it will do ends the turn with nothing done; the sentence about promising "now the question:" is gone. (`extensions/kvcoder/test/unit/prompt-build.test.ts`, `extensions/kvcoder/test/prompt.test.ts`)
- **QA10-H2 More failures are retried, four tries in all.** *Given* a transient failure twice and then an answer, *then* the turn is done with `retry` chunks `{ attempt: 2, of: 4 }` and `{ attempt: 3, of: 4 }`; *given* four transient failures in a row (the last wait is 15 s), *then* the turn ends `failed` after four requests, with the chunks `attempt` 2, 3, and 4 `of: 4`. (`extensions/kvcoder/test/model-retry.test.ts`)
- **QA10-H3 HTTP 408, 409, and 425 are temporary.** *Given* provider failures with reasons `408: …`, `409: …`, `425: …`, *then* `params.transient` is `true`; `400`, `401`, `403`, `404`, and `422` are not. (`extensions/kvai/test/failures.test.ts`)
- **QA10-H4 A failed turn shows Retry and Choose another model.** *Given* an idle chat whose last message is a `STEP_FAILED` notice (and likewise `REPLY_LOST` and `INTERRUPTED`), *then* the conversation shows the buttons "Retry" and "Choose another model" under it. (`extensions/kvcoder/test/web/recovery.test.ts`)
- **QA10-H5 Retry sends "Continue".** *When* the person presses Retry, *then* `kvcoder.message.send { sessionId, text: 'Continue' }` runs (`تابع` in Arabic) and the conversation reads again. (`extensions/kvcoder/test/web/recovery.test.ts`)
- **QA10-H6 Choose another model sets it, remembers it, and goes on.** *When* the person picks `Z1` from the actions' picker, *then* the calls run in this order: `kvcoder.session.configure { sessionId, model: 'zed/z1' }`, `kernel.settings.set { key: 'kvai.defaultModel', value: 'zed/z1', scope: 'global' }`, `kvcoder.message.send { sessionId, text: 'Continue' }`. (`extensions/kvcoder/test/web/recovery.test.ts`)
- **QA10-H7 Picking a model in a header makes it the default.** *Given* the header of a chat, *when* the person picks `Z1`, *then* `kvcoder.session.configure { model }` and `kernel.settings.set { key: 'kvai.defaultModel', value: 'zed/z1', scope: 'global' }` run; picking a thinking level only configures. *Given* a new chat, *when* the person picks `Z1`, *then* `kernel.settings.set` runs at once (not at send), and a later visit shows `Z1` when the settings read returns it. (`extensions/kvcoder/test/web/default-model.test.ts`, `extensions/kvcoder/test/web/chat-start.test.ts`)
- **QA10-H8 A card has no exit chip.** *Given* results with exit codes 0 and 1, *then* no `[data-test="exit-code"]` exists and the text `exit` isn't in the card; the time still shows. (`extensions/kvcoder/test/web/call-card.test.ts`)
- **QA10-H9 A failed call has a danger border.** *Given* a result with exit code 1 (and one that is an error text), *then* its card has the class `kvc-failed`; with exit code 0 it doesn't. (`extensions/kvcoder/test/web/call-card.test.ts`)
- **QA10-H10 A card's lines share one edge.** *Given* a card with title, description, and command in Arabic and in English, in Chromium, *then* the right edges of the three lines are equal (within 1 px) in Arabic and their left edges are equal in English. (`extensions/kvcoder/test/e2e/chat-scroll.test.ts`)
- **QA10-H11 The model popover never scrolls the page sideways.** *Given* windows 1280, 800, 600, and 400 wide, in English and Arabic, *when* the picker of a chat's header is open, *then* the popover lies inside the conversation (its edges within the conversation's) and the page, `main`, and the conversation have no horizontal scroll. (`extensions/kvcoder/test/e2e/chat-scroll.test.ts`)
- **QA10-H12 The layout's buttons show the hand.** *Then* an enabled button of the frame (the navigation toggle, the language and theme buttons, the workspace switcher), a link, a `summary`, and a `select` have `cursor: pointer` in Chromium; a disabled button doesn't. (`extensions/kvwebui/test/e2e/cursor.test.ts`)

## Edge cases

- **QA10-E1 408/409/425 only count at the start of a reason.** *Given* a reason `The 408 widgets failed`, *then* it is not transient. (`extensions/kvai/test/failures.test.ts`)
- **QA10-E2 The actions show only on the last message of an idle chat.** *Given* a `STEP_FAILED` notice followed by a user message, or a running or waiting chat, or a `CANCELLED` or `MAX_STEPS` or `SUMMARY_FAILED` notice last, *then* no actions show. (`extensions/kvcoder/test/web/recovery.test.ts`)
- **QA10-E3 The actions leave when the turn starts.** *When* Retry is pressed and the chat becomes running, *then* the actions are gone. (`extensions/kvcoder/test/web/recovery.test.ts`)
- **QA10-E4 A failing call in the recovery stops it.** *Given* `kvcoder.session.configure` rejects, *then* a toast shows, nothing else runs, and the actions stay. *Given* `kernel.settings.set` rejects, *then* a toast shows, but the model is still set on the chat and "Continue" is still sent. (`extensions/kvcoder/test/web/recovery.test.ts`, `extensions/kvcoder/test/web/default-model.test.ts`)
- **QA10-E5 A failed default write doesn't undo the pick.** *Given* `kernel.settings.set` rejects in a header, *then* a toast shows and the chat keeps the picked model. (`extensions/kvcoder/test/web/default-model.test.ts`)
- **QA10-E6 Picking the model already in use still works.** *Given* the person picks the current model, *then* the same calls run (configure, set default). (`extensions/kvcoder/test/web/default-model.test.ts`)
- **QA10-E7 A card without an exit code has no failure border.** *Given* a card with no `exitCode` (a result with no `[exit code N]`), *then* it isn't marked failed. (`extensions/kvcoder/test/web/call-card.test.ts`)
- **QA10-E8 The recovery popover opens upward and stays inside the column.** *Given* the actions at the end of a short chat, *when* "Choose another model" is open, *then* the popover's bottom is above the button's top and the conversation has no horizontal scroll. (`extensions/kvcoder/test/e2e/chat-scroll.test.ts`)
- **QA10-E9 Every new text is in both languages.** *Then* `en` and `ar` have the same keys, including "Retry", "Choose another model", and "Continue"; `kvcoder.ui.exitCode` stays, for the job list. (`extensions/kvcoder/test/locales.test.ts`)
- **QA10-H13 A JSON error body shows as its message.** *Given* a `STEP_FAILED` notice whose reason is `403: {"message":"This model requires you to complete the following before use: 18+ age confirmation.","code":403}`, *then* the notice shows `403: This model requires you to complete the following before use: 18+ age confirmation.` and no `{"message"`; a reason that isn't a JSON body, and one with an escaped quote in its message, are shown correctly. (`extensions/kvcoder/test/web/notices.test.ts`)
- **QA10-H14 In Arabic a notice's names and reason are isolated.** *Given* the page language `ar` and the notice of QA10-H13, *then* the model's name and the reason are each wrapped in U+2068 … U+2069; in `en` the text holds neither. (`extensions/kvcoder/test/web/notices.test.ts`)
- **QA10-H15 The model popover opens at its button.** *Given* windows 1280, 800, 600, and 400 wide, in English and Arabic, *when* the picker of a chat's header is open, *then* the button's horizontal extent lies within the popover's (within 1 px). (`extensions/kvcoder/test/e2e/chat-scroll.test.ts`)
- **QA10-E11 The open popover re-fits when the layout changes under it.** *Given* the picker of a chat's header is open in a window 1280 wide, *when* the window becomes 700 wide, then 1280 again, *then* after each change the popover lies inside the conversation and the page has no horizontal scroll. (`extensions/kvcoder/test/e2e/chat-scroll.test.ts`)
