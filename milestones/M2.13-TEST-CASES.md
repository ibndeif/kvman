# M2.13 — Testkit, prompts, developer docs: test cases

Read:

- `05` §5.3 (`registerPrompt`, `registerError`), §5.5 (the prompt pattern), §5.9–§5.10, and `14` §14.5.
- The parts they cite:
  - `02` §2.4 (access), §2.8 (deferred replies, `onAbort`, `REPLY_NOT_AWAITING`);
  - `03` §3.7 (processes);
  - `04` §4.3 (collections and filters);
  - `05` §5.7 (isolation), §5.11 (providers), §5.12 (the manifest);
  - `08` §8.10, §8.13 (prompts), §8.16 (catalogs);
  - `10` §10.5 (interviewer);
  - `13` §13.1 (registered codes).
- ADRs 0007, 0042, 0071, 0074, 0100, 0108, 0114, 0128, 0154, 0160, 0161, and 0165–0169.

Earlier tests that M2.13 changes:

- **M2.9's fake provider tests** (`packages/testkit/test/llm/`) build the fake with `fakeProviderExtension(options)`, the definition the descriptor stands for. `fakeProvider(options)` is now the descriptor (ADR 0165).
- **`M1.6-E5`** reads the kernel's warning record where the kernel receives the outcome, with `code` and `type` fields (ADR 0166). The host no longer logs it from `ctx.problem`.

Not in M2.13:

- Remote mode of `createTestKernel`: M6.1 (`15` §15.4).
- Running the 10-minute walkthrough: M2.14 (the CLI steps) and M3.10 (the shell step) (ADR 0168).
- The interviewer and local-guard extensions: M4.

Where the tests live:

- **The test kernel**: `packages/testkit/test/test-kernel/`, with fixtures under `test-kernel/fixtures/extensions/<name>/`, one folder per extension.
- **Prompts**: `packages/testkit/test/prompts/`, with fixtures under `prompts/fixtures/extensions/<name>/`.
- **Examples**: `examples/hello/test/` and `examples/confirm/test/`.
- **Docs**: `test/docs/` at the repository root, beside `scripts/api-reference.ts`.
- **Kernel records and rules**: `packages/testkit/test/test-kernel/` and `packages/testkit/test/validation/`.

`pnpm test` runs `packages/testkit/test/test-kernel/`, `packages/testkit/test/prompts/`, `examples/*/test/`, and `extensions/*/test/` once in each mode. A scenario marked **(both)** passes in shared and sandboxed mode; one that names a mode pins it with `createTestKernel({ isolation })`.

Terms:

- "**The person**" is `user:local`. "**The driver**" is `ext:@kvman/testkit-driver`.
- "**Probe**" is `@acme/probe` (namespace `probe`). It requests `ui`, `process`, `files.read`, `files.write`, and `calls: ['other.*']`, and registers the error `probe/NOPE`. Its entry is `test-kernel/fixtures/extensions/probe/extension.ts`. It registers:
  - `probe.echo { text }` (access `all`), answering `{ text, locale, greeting }`, where `greeting` is `ctx.i18n.t('greeting', { name: text })`;
  - `probe.admin` (access `user`), `probe.hidden` (access `internal`), and `probe.api` (access `extensions`), each answering `{}`;
  - `probe.fail { code }`, which throws `ctx.problem(code)`;
  - `probe.ping { explode? }`, which publishes `probe.pinged { explode }` (durable) and `probe.noticed` (transient) and answers `{}`;
  - `probe.ping-fail`, which publishes `probe.pinged` and then throws `probe/NOPE`;
  - a subscription to `probe.pinged` that throws `probe/UNLISTED` when the event's payload has `explode: true`;
  - `probe.toast`, which calls `ctx.ui.toast({ title: '$t.toast.done' })` and `ctx.ui.notify({ title: '$t.toast.done', key: 'k1' })`;
  - `probe.chain { depth }`, which `ctx.send`s itself with `depth - 1` until 0 and writes kv `reached` at 0;
  - `probe.steps`:
    - it runs `ctx.step('extract', …)`, which appends the line `extract` to the workspace file `runs.txt` (an effect outside the unit of work) and returns 7;
    - it runs `ctx.step('store', …)`, which appends `store`;
    - it writes kv `result: 7`;
    - it answers `{ value: 7 }`;
  - `probe.spawn { command, args?, detached? }`, which spawns and answers `wait()`'s result, or `{ processId }` when detached (with `onExit: 'probe.exited'`, which appends the exit to kv log `exits`);
  - `probe.blob { blobId: z.blobId() }`, answering the blob's text;
  - `probe.relay { type }`, which `ctx.command`s `type` and lets its problem propagate;
  - `probe.state.get`, answering its kv values and logs and the lines of `runs.txt`;
  - `probe.peek { path }`, which reads an absolute path with `node:fs` (outside every kvman API) and answers its length;
  - `en` and `ar` catalogs with `greeting` ("Hello {name}" / "مرحبا {name}") and `toast.done`.
- "**Other**" is `@acme/other` (namespace `other`), without `process`. It has `other.fail`, which throws its registered `other/BROKEN`, and `other.spawn { command }`, which calls `ctx.process.spawn`.
- Single-purpose fixtures under `test-kernel/fixtures/extensions/`:
  - `no-default` (a module with only a named export);
  - `drift` (its `setup` registers `drift.run-<n>` with a module-level counter);
  - `dedicated` (`@acme/dedicated`, which requests `dedicated` isolation);
  - `half-catalog` and `literal` (E22, E23);
  - `thinker` (E34).
- "**Asker**" is `@acme/asker` (namespace `asker`), with `ui`. Its entry is `prompts/fixtures/extensions/asker/extension.ts`. It has two prompts:
  - `asker.question`, with `data { topic, text }`, `answer { answer: z.string().min(1) }`, and `oneOpenPer: (d) => 'topic:' + d.topic`;
  - `asker.tool-call`, with `data { call }`, `answer { allow: z.boolean() }`, and `oneOpenPer: (d) => d.call`.

  It registers:
  - `asker.ask { topic, text }` and `asker.review { call }` (access `all`), which return `open(...)`;
  - `asker.expire-now { commandId }`, which `ctx.send`s `asker.question.expire { commandId, reason: 'cancelled' }`;
  - `asker.ask-soon { topic, text }`, which `ctx.send`s `asker.ask` with `deadlineAt` 2 s after `ctx.now()`;
  - a subscription to `asker.question.asked` that calls the tool-call prompt's `open` when the question's topic is `late` (to prove `open` needs a command; the question's own prompt would first find its open key busy);
  - a subscription to `asker.question.closed` that appends each payload to kv log `closed`;
  - `asker.state.get`.
- "**A question**" is `asker.ask { topic: 't1', text: 'Ship it?' }`, sent by the driver unless the scenario says otherwise.
- "**Hello**" is `examples/hello` (`@kvman/example-hello`, namespace `hello`), the guide's first extension: `hello.greet { name }` answers `{ greeting }` from its `en` and `ar` catalogs and counts greetings in its kv; `hello.greetings.count` answers the count.
- "**Confirm**" is `examples/confirm` (`@kvman/example-confirm`, namespace `confirm`), the sample prompt extension: `confirm.ask { topic, question }` opens the prompt `confirm.request` (`data { topic, question }`, `answer { approved: z.boolean() }`, `oneOpenPer` topic).
