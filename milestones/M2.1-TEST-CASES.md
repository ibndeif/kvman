# M2.1 — Structural validation and schema endpoint: test cases

Read: `06` §6.3 (structural, non-UI), `02` §2.4, §2.6, `05` §5.1 (setup rules), §5.12, `12` §12.7; ADRs 0010 (naming grammar), 0011 (issue severity), 0013 (recording rules), 0016 (lane templates, naming exceptions), 0017 (preset secret check), 0042 (collected issues), 0047 (JSON Schema conversion), 0068 (live subscriptions), 0077 (input view), 0099 (kernel types without a workspace), 0106 (field descriptions), 0107 (required types), 0108 (grammar severity), 0109 (lane paths), 0110 (`kernel.validate`), 0111 (schema endpoint contents), 0112 (schema search).

Where the tests live:

- **Rules through recording and JSON manifests**: `packages/testkit/test/validation/`. Recording goes through `recordExtension` with SDK fixtures, and JSON manifests through the kernel's `validateManifest`.
- **`kernel.validate` and `kernel.schema.get` as queries, and `GET /schema`**: `packages/testkit/test/schema/`, on a booted daemon.
- **Pure pieces** (schema paths, search ranking, the schema document): `packages/kernel/test/validation/` and `packages/kernel/test/registry/`.
- **Protocol shapes**: `packages/protocol/test/`.

"Fails with its hint" means one issue at the named path with severity `error` (absent) and exactly the named hint.

## Happy path

### M2.1-H1 — every structural rule fails its fixture with a hint
- **Given** one fixture per structural rule of `06` §6.3 that is not about UI (the table below), each otherwise valid
- **When** each is recorded, or validated as a JSON manifest where recording cannot produce it
- **Then** each fails at its path with its hint, and no other error. The rules and hints:

  | Rule | Fixture | Path | Hint |
  |---|---|---|---|
  | protocol schema | JSON: `types.0` has a field `color` | `types.0` | `remove "color"` |
  | `manifestVersion` | JSON: `manifestVersion: 2` | `manifestVersion` | `this kvman reads manifest version 1; upgrade kvman` |
  | `meta.name` = package name | recorded with package name `@acme/other` | `meta.name` | `set meta.name to "@acme/other", the name in package.json` |
  | namespace format | JSON: namespace `P` | `meta.namespace` | `use 2–32 lowercase letters, digits, and "-", e.g. "pdf"` |
  | reserved namespace | namespace `kernel` | `meta.namespace` | `choose another namespace; kernel, ui, frame, sys, and preset are reserved` |
  | setup deterministic | a description that changes per run | `types.0.description` | `register the same things on every run; setup reads no clock, random numbers, or state` |
  | description required | a command with description `' '` | `types.0.description` | `add a description in English, for developers and LLMs` |
  | full public names | `registerCommand('translate', …)` | `types.0.type` | `did you mean "pdf.translate"?` |
  | one name, one kind | command and event `pdf.imported` | `types.1.type` | `one name is never used for two kinds; rename one of them` |
  | unique within a kind | two collections `files` | `data.collections.1.name` | `rename one of them` |
  | error code namespace | `registerError('NOT_FOUND', …)` | `errors.0.code` | `did you mean "pdf/NOT_FOUND"?` |
  | error title | JSON: an error with title `''` | `errors.0.title` | `add an English title` |
  | lossless JSON Schema | an input with `.transform()` | `types.0.input` | `keep schemas to what JSON Schema expresses; convert values in the handler instead` |
  | config field description | a config field without `.describe()` | `config.schema.properties.language` | `add .describe('…') to the field "language"` |
  | lane syntax | lane `file:{{ fileId }}` | `types.0.lane` | `write placeholders as {{ $payload.<field> }}, {{ $context.<key> }}, or {{ $message.id }}` |
  | lane path | lane `file:{{ $payload.fileid }}` on input `{ fileId, lang }` | `types.0.lane` | `fields there: fileId, lang` |
  | 5 MB | JSON: examples making the canonical JSON over 5 MB | `` (the root) | `keep the manifest under 5 MB: shorten examples, views, and catalogs` |
  | required types covered | `requireTypes(['fs.file.get'])` with no `calls` | `permissions.requireTypes.0.types.0` | `add ext.requestCapability('calls', { types: ['fs.file.get'] }), or subscribe to it if it is an event` |
  | slash access | a `slash` command with access `extensions` | `types.0.slash` | `set access to all or user, or remove slash` |
  | agent tool access | an `agentTool` query with access `user` | `types.0.agentTool` | `set access to all or extensions, or remove agentTool` |
  | live event shape | JSON: a live event with `payload` and no `chunk` | `types.0.chunk` | `declare chunk ("text", "value", or "data") and no payload` |
  | no subscription to a live event | subscribing to its own live event | `subscriptions.0.event` | `subscribe to a durable or transient event instead` |
  | once-only calls | `registerConfig` twice | `config` | `call registerConfig once` |
  | contiguous migrations | data version 3 without a migration to 2 | `data.migrations` | `register one migration for each version from 2 to 3` |
  | handlers are functions | a command whose `handle` is a string | `types.0.handler` | `pass an async function as handle` |

- Test: `packages/testkit/test/validation/structural-rules.test.ts`

### M2.1-H2 — `/schema` omits internal types and filters by workspace
- **Given** a daemon with `@acme/files` (with an `internal` command) enabled in workspace A only, `@acme/notes` enabled in B only, and `@acme/idle` enabled nowhere
- **When** `GET /api/v1/schema?workspaceId=<A>` and `?workspaceId=<B>` are sent
- **Then**:
  - A's document lists the kernel's types and `@acme/files`'s types, but not its internal command and nothing of the other two;
  - B's lists the kernel's and `@acme/notes`'s;
  - no `internal` type appears anywhere, and both documents parse with the protocol's schema.
- Test: `packages/testkit/test/schema/schema-endpoint.test.ts`

### M2.1-H3 — a `.refine()` rule rejects a payload in the host after the kernel's JSON Schema check passed
- **Given** `notes.add`, whose `text` field is `z.string().refine(…)` rejecting `'forbidden'`
- **When** `POST /api/v1/commands/notes.add { payload: { text: 'forbidden' } }` is sent
- **Then**:
  - the answer is 400 `VALIDATION_FAILED` with the refinement's message as an issue at `text`;
  - the message was admitted: its row exists and is `failed`, so the kernel's JSON Schema check passed and the host refused it.
- Test: `packages/testkit/test/schema/refinements.test.ts`
