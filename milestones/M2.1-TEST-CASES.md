# M2.1 — kvai: test cases

Read: `07`; `03` §3.2 (typed calls), §3.3 (progress); `10` (testkit); ADR 0003; ADR 0009 (M2.1: pi-ai 0.99.1, built-ins, keys, model ids, custom models and APIs, removing, the message, defaults, usage totals, testkit progress, the fake OpenAI server, Problem params).

kvai's tests run `extensions/kvai` in a test kernel (`@kvman/testkit`), next to small test extensions written to a temporary folder: a harness that calls `kvai.complete` from its own command, and a delegate. LLM calls go to the fake OpenAI-compatible server (`@kvman/testkit/fake-openai`) on 127.0.0.1, added with `kvai.provider.add { api: 'openai-completions', baseUrl }`; no test reaches the network. Deltas are observed with the testkit's `onProgress`.

## Happy path

### M2.1-H1 — `kvai.complete` streams text, thinking, and tool-call deltas to the root job, and returns the message and usage
- **Given** the fake server added as provider `fake` with a reasoning model `fake/m1`, and a harness command that calls `kvai.complete` with a system prompt, a user message, and a `bash` tool
- **When** the harness command runs with `onProgress`, and the fake server streams thinking `hmm`, text `Hel` `lo`, a `bash` tool call, `finish_reason: tool_calls`, and usage (15 input, 7 output, 10 cache reads, 5 cache writes)
- **Then** the harness job's stream gets, from `@kvman/kvai`, `{ type: 'thinking', delta: 'hmm' }`, `{ type: 'text', delta: 'Hel' }`, `{ type: 'text', delta: 'lo' }`, `{ type: 'toolcall', name: 'bash' }` in order; the output is `stopReason: 'toolUse'`, a message with the thinking, text, and toolCall blocks and only the core fields, and `usage { input: 15, output: 7, cacheRead: 10, cacheWrite: 5, cost }` with the model's prices; the fake server got the system prompt, the message, and the tool
- Test: `extensions/kvai/test/complete.test.ts`

### M2.1-H2 — a missing key, a missing model, an unknown model, a 429, and an over-long context fail with their codes
- **Given** kvai with no secrets and `kvai.defaultModel` `null`, and the fake server as provider `fake`
- **When** `kvai.complete` runs for `anthropic/claude-sonnet-5-5`, then with no model, then for `fake/nope`, then for `fake/m1` while the server answers 429, then 400 with a context-length message
- **Then** they fail `kvai/KEY_MISSING { provider: 'anthropic' }`, `kvai/NO_MODEL`, `kvai/MODEL_UNKNOWN { model: 'fake/nope' }`, `kvai/RATE_LIMITED { model: 'fake/m1' }`, and `kvai/CONTEXT_TOO_LONG { model: 'fake/m1' }`
- Test: `extensions/kvai/test/failures.test.ts`

### M2.1-H3 — `anthropic/claude-sonnet-5-5` is in pi-ai's built-in list
- **Given** kvai
- **When** `kvai.model.list { provider: 'anthropic' }` runs
- **Then** it has `{ id: 'anthropic/claude-sonnet-5-5', provider: 'anthropic', reasoning: true, builtIn: true, … }`
- Test: `extensions/kvai/test/providers.test.ts`

### M2.1-H4 — a delegate provider forwards the call
- **Given** a test extension's public command `relay.complete` that streams `{ type: 'text', delta: 'via relay' }` and returns a message and usage, added as `kvai.provider.add { id: 'relay', title, delegate: 'relay.complete' }` with a model `relay/r1`
- **When** a harness command calls `kvai.complete { model: 'relay/r1', messages }` with `onProgress`
- **Then** `relay.complete` got the input with `model: 'relay/r1'`; its delta reaches the harness job's stream; kvai returns its output; and its usage counts in `kvai.usage.get`
- Test: `extensions/kvai/test/delegate.test.ts`

### M2.1-H5 — removing a built-in fails `kvai/BUILT_IN`
- **Given** kvai
- **When** `kvai.provider.remove { id: 'anthropic' }` and `kvai.model.remove { id: 'anthropic/claude-sonnet-5-5' }` run
- **Then** both fail `kvai/BUILT_IN` with the id in `params`, and both are still listed
- Test: `extensions/kvai/test/providers.test.ts`

### M2.1-H6 — usage adds up per workspace
- **Given** the fake server, and a second workspace
- **When** two calls to `fake/m1` and one to `fake/m2` run in Home, and one call to `fake/m1` runs in the other workspace
- **Then** Home's `kvai.usage.get` has `fake/m1` with twice one call's tokens and cost and `fake/m2` with one; the other workspace's has only its one call; `kvai.usage.total.get` gives each workspace's summed tokens (input, output, cache reads, and cache writes) and cost
- Test: `extensions/kvai/test/usage.test.ts`

### M2.1-H7 — `kvai.ui.get` contributes the Models page and the status item
- **Given** kvai
- **When** `kvai.ui.get` runs
- **Then** it has a Models page (providers with key state, models with a "make default" row action on `kernel.settings.set`, and forms on `kvai.provider.add` and `kvai.model.add`), a nav item for it, and a status item on `kvai.usage.total.get`; every query and command it names is public in `kernel.extensions.list`, and every text is a key in kvai's `en` catalog
- Test: `extensions/kvai/test/ui.test.ts`

### M2.1-H8 — kvai's catalogs cover its texts in `en` and `ar`
- **Given** `extensions/kvai/locales/en.json` and `ar.json`
- **When** they're read, and kvai loads in a test kernel
- **Then** both have the same keys and placeholders, all under `kvai.`, including every public name's `<name>.description`, `kvai.defaultModel.description`, `kvai.errors.<CODE>` for each code, and every form field's `<command>.fields.<field>`
- Test: `extensions/kvai/test/locales.test.ts`

### M2.1-H9 — the testkit's `onProgress` and the fake OpenAI server
- **Given** a test extension whose command sends progress from itself and from a nested query; and the fake server with two queued scripts
- **When** the command runs through `exec` and `execAsync` with `onProgress`; and two requests reach the fake server, then a third
- **Then** `onProgress` gets every chunk of that call's root job, in order, with its source; the fake server answers the scripts in order, `requests()` records each body and `Authorization` header, and a request with no script left gets a 500
- Test: `packages/testkit/test/progress.test.ts`; `packages/testkit/test/fake-openai.test.ts`

## Edge cases

### The call (`07` §7.1, ADR 0009, 58–59, 63) — `extensions/kvai/test/complete.test.ts`, `extensions/kvai/test/call-options.test.ts`

| Id | Given | Then |
|---|---|---|
| M2.1-E1 | `thinking` `high`, and none | the request has `reasoning_effort: 'high'`; with none (`off`) it has no `reasoning_effort` (`call-options.test.ts`) |
| M2.1-E2 | `maxTokens: 500`, and none | `max_completion_tokens` 500; with none, the model's `maxTokens` (`call-options.test.ts`) |
| M2.1-E3 | the job cancelled while the fake server holds its stream | the fake server sees the request closed, and the job ends `cancelled` (`complete.test.ts`) |
| M2.1-E4 | a finish of `length` | returns with `stopReason: 'length'` (`complete.test.ts`) |
| M2.1-E5 | the returned message sent back as input, with a toolResult message | accepted; the fake server gets the assistant turn and the tool result (`call-options.test.ts`) |
| M2.1-E6 | a message with an unknown role, a block of an unknown type, and a tool without `parameters` | `VALIDATION_FAILED` each (`call-options.test.ts`) |
| M2.1-E7 | no `model` and `kvai.defaultModel` `fake/m1` | the call uses `fake/m1` (`call-options.test.ts`) |
