# M2.3 — kvwebui custom components and effects: test cases

Read: `06` §6.4 (custom components), §6.5 (effects), §6.8; `03` §3.2 (web types), §3.3 (`rootId`, `progress`); `04` §4.4 (the job stream); `02` §2.4 (keyed schedules); ADR 0002 (11, 16, 22); ADR 0008 (23, 57); ADR 0009 (M2.3: custom props, the injected `kvman`, failing components, theme variables, effects at a failed end, an effect's time).

The same three kinds of tests as M2.2:
- **Components** (`extensions/kvwebui/test/web/`): the whole app against the fake HTTP API, which now also answers `async: true` commands with a fresh job id, serves `GET /api/jobs/:id/stream` from a stream the test drives (progress chunks, then a result or a Problem), and answers `kvwebui.effect.take` from a table of effects per job id. `createKvwebui` takes a component loader (`module(url)`, `stylesheet(url)`), and the tests give one that serves fixture Vue components by URL and records every URL asked for.
- **Kernel** (`extensions/kvwebui/test/`, `packages/sdk/test/`): the testkit with kvwebui and a fixture extension, and the SDK's own tests.
- **End to end** (`extensions/kvwebui/test/e2e/`): a real kvman with kvwebui bundled and a fixture extension `demo` by `path:`, whose `kvman.web` folder holds plain ES-module components that import `vue`, and a CSS file; driven by Chromium.

## Happy path

### M2.3-H1 — a custom component shares kvwebui's Vue, streams a job's progress, renders Markdown through `View`, and its CSS loads
- **Given** a real kvman with `demo`, whose page shows `custom { component: 'demo.progress', props: { title: 'demo.progress.title' } }`; `demo/components/progress.js` imports `vue`, reads `inject('kvman')`, and has a Start button that runs `kvman.execAsync('demo.count', {})` and then reads `kvman.stream(jobId)`; `demo.count` sends progress chunks `{ n }` until `demo.release` is run, then returns `{ total }`; `progress.css` gives the component a border of `var(--kv-color-primary)`
- **When** the page opens, the Start button is clicked, the first chunk shows, and `demo.release` is run
- **Then** the component renders with its translated title (so `inject` found kvwebui's `kvman`, which needs the same Vue instance); each chunk appears as it arrives, then the result; a `View` of `markdown` shows `**done**` as bold text; the component's border has the primary color from its CSS; and the module and CSS were requested with `?revision=0`
- Test: `extensions/kvwebui/test/e2e/custom.test.ts`

### M2.3-H2 — a component's `navigate`, `toast`, and `panel` act at once
- **Given** a fixture component with buttons that call `kvman.navigate('notes.item', { id: '7' })`, `kvman.toast('notes.saved', { name: 'x' }, 'success')`, and `kvman.panel('notes.help', true)`
- **When** each button is clicked
- **Then** without any HTTP call, the route becomes `/notes/item/7`, a success toast shows the translated text with its params, and the `notes.help` panel opens (and is remembered for the tab)
- Test: `extensions/kvwebui/test/web/kvman.test.ts`

### M2.3-H3 — a component styled with the theme variables follows a theme switch
- **Given** the `demo` page, whose component's background is `var(--kv-color-surface)` and text `var(--kv-color-text)`
- **When** the theme menu switches from Light to Dark
- **Then** the component's computed background and text colors change to the dark values, without a reload
- Test: `extensions/kvwebui/test/e2e/custom.test.ts`

### M2.3-H4 — `follow` reruns the page's queries when the job ends
- **Given** a page with a table on `notes.note.list` and a component that calls `kvman.follow(jobId)` for a job it didn't start
- **When** the job's stream sends a chunk, then its result
- **Then** the table's query runs again only after the result, and `follow` resolves after that rerun and after `kvwebui.effect.take { jobId }` was called
- Test: `extensions/kvwebui/test/web/streams.test.ts`

### M2.3-H5 — effects from a nested job are kept under the root job, and taken once
- **Given** the testkit with kvwebui and a fixture extension whose command `fx.run` runs `fx.inner`, which adds a toast and a navigate effect, and then adds a refresh effect itself; `fx.run` returns `ctx.job.rootId`
- **When** `fx.run` runs as the user, then `kvwebui.effect.take { jobId }` runs twice with the returned id
- **Then** the first take returns the three effects in the order they were added; the second returns `[]`
- Test: `extensions/kvwebui/test/effects.test.ts`

### M2.3-H6 — the UI applies a job's effects once, when its job ends
- **Given** a button whose command's job has a toast effect and a `notes.help` panel effect
- **When** the button is clicked
- **Then** `kvwebui.effect.take` is called once with the command's job id (from the envelope), the toast shows once, and the panel opens
- Test: `extensions/kvwebui/test/web/effects.test.ts`

### M2.3-H7 — restarting leaves one cleanup schedule, and effects older than an hour are cleaned
- **Given** the testkit with kvwebui, restarted twice, and an effect added under a root job
- **When** the fake clock moves 2 hours
- **Then** `kvwebui.effect.clean` ran once per hour, not three times (one keyed schedule, `effect-clean`), and a take of the old job returns `[]`
- Test: `extensions/kvwebui/test/effects.test.ts`

## Edge cases

### M2.3-E1 — a `custom` view is checked when the answer loads
- **Given** answers whose custom views name `notes.chart` (fine), `other.card` from another loaded extension (fine), `ghost.card` (no such extension), `Notes.Chart` (not kebab case), `notes` (no name), and one whose `props` hold `{ $param: 'id' }` on a page without that param
- **When** the app loads
- **Then** the fine ones render; each other answer contributes nothing and gets the error card with `VALIDATION_FAILED` and an issue at the view's path
- Test: `extensions/kvwebui/test/web/custom.test.ts`

### M2.3-E2 — props resolve `$param` and `$row` references
- **Given** a page with `params: ['id']` showing `custom { props: { id: { $param: 'id' }, fixed: 3 } }`, and a list whose item is `custom { props: { name: { $row: 'name' } } }`
- **When** `/notes/item/7` opens
- **Then** the page's component gets `{ id: '7', fixed: 3 }`, and each list item's component gets its row's `name`
- Test: `extensions/kvwebui/test/web/custom.test.ts`

### M2.3-E3 — the module and its CSS load once, with the revision in their URLs
- **Given** `notes` at revision 4, whose page shows `notes.chart` twice
- **When** the page opens
- **Then** the loader was asked once for `/web/notes/components/chart.js?revision=4` and once for `/web/notes/components/chart.css?revision=4`, and both components render
- Test: `extensions/kvwebui/test/web/custom.test.ts`

### M2.3-E4 — a component that can't load or throws shows `COMPONENT_FAILED`, and the rest of the page works
- **Given** a page with a heading and components whose module fails to import, has no default export, throws in `setup`, and is still loading
- **When** the page opens
- **Then** the loading one shows placeholder rows; each failing one shows the error card with the translated `kvwebui.errors.COMPONENT_FAILED` naming the component and `kvwebui/COMPONENT_FAILED` under Details, with no "Try again"; the heading renders
- Test: `extensions/kvwebui/test/web/custom.test.ts`

### M2.3-E5 — a component without a CSS file still renders
- **Given** the real kvman's `demo` page with `demo.plain`, which has a `.js` and no `.css`
- **When** the page opens
- **Then** the component renders
- Test: `extensions/kvwebui/test/e2e/custom.test.ts`

### M2.3-E6 — `exec` of a command reruns queries and applies effects; of a query, neither; a failure rejects without a toast
- **Given** a page with a table and a component that calls `kvman.exec`
- **When** it execs the command `notes.note.add`, then the query `notes.count.get`, then the command `notes.bad`, which fails `notes/NOPE` and whose job has a toast effect
- **Then** the command resolves to its output, the table reruns, and its effects are taken; the query resolves to its output with no rerun and no take; the failure rejects with a `ProblemError` whose code is `notes/NOPE`, shows no error toast, and still takes and applies its toast effect
- Test: `extensions/kvwebui/test/web/kvman.test.ts`

### M2.3-E7 — a job started with `execAsync` is followed
- **Given** a page with a table and a status item, and a component that calls `kvman.execAsync('notes.reindex', {})`
- **When** the job's stream ends with a result
- **Then** `execAsync` resolved to the job id before the end; at the end, the table and the status item rerun and the job's effects are applied; an `execAsync` the kernel refuses (`VALIDATION_FAILED` for a sync-only command) rejects with that Problem
- Test: `extensions/kvwebui/test/web/streams.test.ts`

### M2.3-E8 — `stream` gives the job's events, ends after the last one, and closes when it's no longer read
- **Given** a component that reads `kvman.stream(jobId)`
- **When** the stream sends two progress chunks, then a Problem; and, for other jobs, when the id is unknown (the envelope with `NOT_FOUND`), when the component breaks out of its loop, and when the component unmounts while reading
- **Then** it gets `{ type: 'progress', source, data }` twice and `{ type: 'problem', problem }`, and the loop ends; the unknown id gives one `problem` event with `NOT_FOUND`; breaking out and unmounting abort the stream's HTTP request; a job the component started with `execAsync` and also streams uses one HTTP request
- Test: `extensions/kvwebui/test/web/streams.test.ts`

### M2.3-E9 — a followed job that fails still applies its effects, and a job is followed once
- **Given** a component that calls `kvman.follow(jobId)` twice for the same job, whose job has a toast effect
- **When** the stream ends with a Problem
- **Then** both calls resolve; `kvwebui.effect.take` was called once; the toast shows once; no error toast shows
- Test: `extensions/kvwebui/test/web/streams.test.ts`

### M2.3-E10 — `workspace` is a live ref
- **Given** a component that shows `kvman.workspace.value.name`, and a second open workspace
- **When** the workspace picker switches to it
- **Then** the component shows the new workspace's name, without being remounted
- Test: `extensions/kvwebui/test/web/kvman.test.ts`

### M2.3-E11 — `toast` defaults to `info`; an unknown panel does nothing; an unknown page shows "page not found"
- **Given** a component with buttons that call `kvman.toast('notes.hello')`, `kvman.panel('ghost.help', true)`, and `kvman.navigate('ghost.page')`
- **When** each is clicked
- **Then** an info toast shows (and closes after 5 s); the open panel doesn't change; the page shows the "page not found" card
- Test: `extensions/kvwebui/test/web/kvman.test.ts`

### M2.3-E12 — `View` renders a view tree, checked like a `ui.get` view
- **Given** a component on a page with `params: ['id']` that renders `<View>` with a `markdown` text holding `**bold**` and a `<script>`, a `heading` whose params use `{ $param: 'id' }`, and a second `<View>` whose tree has a table on the private query `notes.secret.list`
- **When** the page opens
- **Then** the Markdown shows bold text and no script; the heading shows the route param; the second `View` shows the error card with `VALIDATION_FAILED` and the issue naming the query
- Test: `extensions/kvwebui/test/web/view-component.test.ts`

### M2.3-E13 — a button's or form's effects come after `then` or the error toast, in order
- **Given** a button with `then: { toast: 'notes.done' }` whose job has the effects toast `notes.first`, refresh, and navigate `notes.item { id: '2' }`; and a button whose command fails `notes/NOPE` and whose job has a toast effect `notes.after`
- **When** each is clicked
- **Then** the first shows `notes.done`, then `notes.first`, the page's queries rerun, and the route becomes `/notes/item/2`; the second shows the error toast, then `notes.after`
- Test: `extensions/kvwebui/test/web/effects.test.ts`

### M2.3-E14 — `effect.add` validates, and `effect.take` returns only that job's effects
- **Given** the testkit with kvwebui and the fixture extension
- **When** an effect of an unknown type, a navigate whose page isn't `<namespace>.<page>`, and a toast with an unknown level are added; two root jobs add one effect each; and an unknown job id is taken
- **Then** each invalid effect fails `VALIDATION_FAILED`; taking one job returns only its effect, and the other job's stays; the unknown id returns `[]`
- Test: `extensions/kvwebui/test/effects.test.ts`

### M2.3-E15 — cleaning keeps effects younger than an hour
- **Given** an effect added 2 hours ago (by the fake clock) and one added 30 minutes ago
- **When** `kvwebui.effect.clean` runs on its schedule
- **Then** the old one is gone, and the young one is still taken
- Test: `extensions/kvwebui/test/effects.test.ts`

### M2.3-E16 — the theme variables exist for light and dark
- **Given** the real kvman's app
- **When** it shows in Light, then in Dark
- **Then** each of `--kv-color-{background,surface,text,muted,border,primary,on-primary,danger,warning,success}`, `--kv-space-{sm,md,lg}` (8, 16, 24 px), `--kv-radius` (12 px), and `--kv-font-mono` has a value on the root in both, and the colors differ between them
- Test: `extensions/kvwebui/test/e2e/custom.test.ts`

### M2.3-E17 — `@kvman/sdk/web` is types only
- **Given** the SDK's `web` subpath
- **When** its module is imported
- **Then** it exports no runtime value, and it's listed in the SDK's `exports`; its types type kvwebui's `kvman` (kvwebui's implementation is declared as `Kvman`, so the typecheck gate holds it to the shape)
- Test: `packages/sdk/test/web.test.ts`
