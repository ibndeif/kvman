# M2.3 — Workspaces, enable, config, secrets: test cases

Read: `07` §7.1 (not preview workspaces), §7.5, `06` §6.4, `04` §4.4, §4.7, and the parts they cite: `03` §3.3 step 3, §3.6 (quarantine lifted by disable), §3.8 (workspace, enable, config, and secret types), §3.9 step 3 and first run, `05` §5.7 (the grant shape), §5.8, `04` §4.2 (config and secrets in the unit), `14` §14.3 (invariants 10 and 13). ADRs 0048, 0052, 0075, 0099, 0114, 0120, and 0122–0127.

Where the tests live:

- **Pure pieces**, in `packages/kernel/test/`: config merging, validation, and redaction; the grant validity check; the secrets file.
- **The commands, queries, and handlers through a runtime**, in `packages/testkit/test/workspaces/`. The runtime has a home folder, installed fixture snapshots (ADR 0114), and applied presets written by the test helper (ADR 0124).
- **Boot and first run**, in `packages/testkit/test/first-run/home-workspace.test.ts`, on booted daemons.
- **Crash points**, in `packages/testkit/test/faults/workspaces.test.ts`, on child kernels.
- **Protocol shapes**, in `packages/protocol/test/workspace-config.test.ts`.

Terms used in the scenarios:

- "**Person**" is `user:local`. "**Admin extension**" is a fixture holding `kernel.admin` in the workspace.
- "**Desk**" is the fixture `@acme/desk` (namespace `desk`):
  - it registers config with scope `both`: `model` (default `small`), `limit` (a number, default 10), and a required `apiKey` marked secret;
  - `desk.ask` defers with `onAbort: 'desk.expire'`, and `desk.expire` records the abort in its global store;
  - `desk.hang` runs until it is aborted;
  - `desk.settings` and `desk.remember` read and write `ctx.config` and `ctx.secrets`.
- "**Pdf A**" and "**Pdf B**" are `@acme/pdf-a` and `@acme/pdf-b`, both with namespace `pdf`.
- "**Reader**" is `@acme/reader`, which calls `requireTypes(['pdf.import'])`.
- "**Asker**" is `@acme/asker`, which requests `calls ['pdf.*']` and `llm`, requests `dedicated` isolation, and subscribes to `pdf.imported`.
- "**Grants of X**" are exactly X's requested and derived capabilities, with `sandboxed` isolation unless a scenario says otherwise.
- "**Preset row**" is a `workspace_presets` row written by the helper (ADR 0124).

## Happy path

### M2.3-H1 — enabling two extensions with one namespace fails `NAMESPACE_CONFLICT`
- **Test**: `packages/testkit/test/workspaces/enable.test.ts`
- **Given** workspace A with an empty preset row, and Pdf A enabled in it by the person.
- **When** the person enables Pdf B in A with the grants of Pdf B.
- **Then**:
  - the reply fails `NAMESPACE_CONFLICT`, and its detail names `@acme/pdf-a` and the namespace `pdf`;
  - the preset's revision and entries are unchanged, and no event is published;
  - Pdf B can still be enabled in workspace B.

### M2.3-H2 — disabling a required extension fails `EXT_IN_USE` with the dependents
- **Test**: `packages/testkit/test/workspaces/disable.test.ts`
- **Given** Pdf A and Reader enabled in A.
- **When** the person disables Pdf A.
- **Then**:
  - the reply fails `EXT_IN_USE` with `params.dependents` `['@acme/reader']`;
  - nothing changes.
- **And** after Reader is disabled, disabling Pdf A succeeds.

### M2.3-H3 — a stale config revision fails `CONFIG_STALE`
- **Test**: `packages/testkit/test/workspaces/config.test.ts`
- **Given** Desk's workspace config row in A at revision 1.
- **When** the person sends `kernel.config.set {extension: '@acme/desk', scope: 'workspace', workspaceId: A, value: {limit: 5}, revision: 0}`.
- **Then**:
  - the reply fails `CONFIG_STALE`, and the row keeps its value and revision 1;
  - the same write with `revision: 1` succeeds with `{ revision: 2 }`.

### M2.3-H4 — secrets never appear in `kernel.config.get`
- **Test**: `packages/testkit/test/workspaces/secrets.test.ts`
- **Given** Desk's `apiKey` set to `sk-live-0123456789abcd` with `kernel.secret.set`, and a global config row.
- **When** `kernel.config.get {extension: '@acme/desk', workspaceId: A}` is asked by the person and by another extension.
- **Then**:
  - both answers show `merged.apiKey` as `••••abcd`;
  - neither the rows nor any part of either answer contains the secret;
  - no config row in the database contains it;
  - `secrets.json` holds `"@acme/desk/apiKey"`.

### M2.3-H5 — forgetting a workspace with a running handler and a deferred command cancels both and leaves no rows with its id
- **Test**: `packages/testkit/test/workspaces/forget.test.ts`
- **Given** in workspace A:
  - Desk enabled, `desk.hang` running, and `desk.ask` awaiting;
  - kv, docs, and log rows, a config row, a notification, and events.
- **When** the person sends `kernel.workspace.forget {workspaceId: A}`.
- **Then**:
  - the running handler's signal fires and its waiter gets `CANCELLED`;
  - the deferred command ends `CANCELLED`, and `desk.expire` runs (Desk's global store records `{ commandId, reason: 'cancelled' }`);
  - the reply is `{}` and `kernel.workspace.forgotten {workspaceId: A}` is published without a workspace;
  - afterwards no table has a row whose workspace column is A's id (only the global `kernel.workspace.*` events name it in their payloads), even after the aborted handler returns;
  - the folder is untouched;
  - workspace B's rows and Desk's global rows are kept.

### M2.3-H6 — a failed secrets-file write keeps the old value and logs the failure
- **Test**: `packages/testkit/test/workspaces/secrets.test.ts`
- **Given** Desk's `apiKey` set to value one, and a directory in the way of the secrets file's temporary path.
- **When** the person sets it to value two.
- **Then**:
  - the command succeeds;
  - `secrets.json` and `ctx.secrets.get('apiKey')` still give value one;
  - the kernel logs an error naming `@acme/desk` and `apiKey`, and no log line holds either value.

### M2.3-H7 — a config write leaves the applied preset's revision unchanged
- **Test**: `packages/testkit/test/workspaces/config.test.ts`
- **Given** A's preset row at revision 3.
- **When** a workspace write and a global write are made with `kernel.config.set`, and a workspace write with `ctx.config.set`.
- **Then**:
  - the preset row stays at revision 3, and no `kernel.preset.changed` is published;
  - `kernel.config.changed` is published for each write.

### M2.3-H8 — enabling without granting every requested capability fails and lists what is missing
- **Test**: `packages/testkit/test/workspaces/enable.test.ts`
- **Given** Asker installed and an empty preset row in A.
- **When** the person enables it with the grants of Asker minus `llm` and minus the subscription to `pdf.imported`.
- **Then**:
  - the reply fails `CAPABILITY_DENIED` with `params.missing` naming `llm` and `subscribes pdf.imported`, one issue each;
  - nothing changes.

### M2.3-H9 — enabling in a workspace with no applied preset fails `PRESET_REQUIRED`
- **Test**: `packages/testkit/test/workspaces/enable.test.ts`
- **Given** workspace C, opened with `kernel.workspace.open`, with no preset row.
- **When** the person enables Desk there with its grants.
- **Then** the reply fails `PRESET_REQUIRED`, and no preset row is created.

## Edge cases

### Opening and naming workspaces (ADR 0127) — `packages/testkit/test/workspaces/open.test.ts`

| Id | Given | Then |
|---|---|---|
| M2.3-E1 | the person opens a folder, then opens it again through a symlink | the id is the SHA-256 of `fs.realpath.native`, and the name is the folder's basename; the second open replies with the same id and keeps the name; each open publishes `kernel.workspace.opened` without a workspace |
| M2.3-E2 | opening a relative path; a missing path; a file; the kvman home folder; and a folder inside it | the relative path fails `VALIDATION_FAILED`; each of the others fails `WORKSPACE_INVALID`, and no row is written |

| M2.3-E4 | three workspaces, `beta` and two named `alpha` at different paths, where one alpha folder has been deleted | `kernel.workspaces.list` gives alpha, alpha, beta, ties by path, each with `kind: 'normal'` and `trusted: false`; the deleted one has `exists: false`. `kernel.workspace.get` gives `trust: null`; an unknown id fails `WORKSPACE_INVALID` |
| M2.3-E5 | `open` and `rename` from an extension without `kernel.admin`, from the admin extension, and `forget` from the admin extension | the first fails `CAPABILITY_DENIED`, the second succeeds, and the forget fails `CALLER_NOT_ALLOWED` |
| M2.3-E6 | a command and a query for a workspace id that has no row | each is refused `WORKSPACE_INVALID` at admission, and no message row is stored |
