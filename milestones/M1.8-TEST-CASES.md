# M1.8 — CLI: test cases

Read: `01` §1.2–§1.3; `02` §2.9 (npm, trust), §2.10, §2.14; `12` §12.2; ADR 0009 (M1.8: the lock, hand-over, preset names, `--port 0`, npm installs, trust, the terminal, signals and exit codes).

CLI tests run kvman as a child process (`node --conditions=@kvman/source packages/cli/src/main.ts`) with a temporary `--home`, a temporary start folder, and `HOME` (and `USERPROFILE`) pointing to a temporary user folder, so they never touch the real `~/.kvman`. They pass `--no-open` unless the scenario is about the browser, `--port 0`, and `--yes` for `path:` extensions. The pure parts (arguments, preset lookup, the lock, the terminal lines, the browser command, the trust prompt) are unit-tested.

## Happy path

### M1.8-H1 — `kvman --preset <file>` prints and opens the start folder's URL
- **Given** a preset file with a `path:` web extension, and a fake `xdg-open` first on the `PATH` that records its argument
- **When** kvman starts in a folder with `--preset <file>`, once with `--no-open` and once without
- **Then** it prints `http://127.0.0.1:<port>/?workspace=<id>`, where `<id>` is the workspace whose path is that folder (`kernel.workspace.list`); without `--no-open`, the fake `xdg-open` receives that URL
- Test: `packages/cli/test/start/start.test.ts`

### M1.8-H2 — a second kvman hands over, or fails KVMAN_RUNNING
- **Given** kvman running on a home with preset `one`
- **When** a second kvman starts on the same home in another folder, then a third with a preset named `two`
- **Then** the second prints the URL of its folder's workspace on the running kvman's port and exits 0, and that workspace is open in the running kvman; the third exits 1 with `KVMAN_RUNNING`
- Test: `packages/cli/test/start/hand-over.test.ts`

### M1.8-H3 — a stale lock is replaced
- **Given** a `kvman.lock` naming a pid that isn't alive
- **When** kvman starts on that home
- **Then** it starts, and `kvman.lock` holds its own pid and port
- Test: `packages/cli/test/start/lock.test.ts`

### M1.8-H4 — a preset name found both bundled and in `<home>/presets/` fails VALIDATION_FAILED
- **Given** a bundled presets folder and `<home>/presets/` that both have `same.json`
- **When** the preset `same` is looked up
- **Then** it fails `VALIDATION_FAILED`, naming both files (ADR 0009, 45: no bundled preset exists before M2.5)
- Test: `packages/cli/test/preset-lookup.test.ts`

### M1.8-H5 — an untrusted npm extension asks, and without a terminal kvman refuses
- **Given** the in-test registry serving `@acme/hello@1.0.0`, and a preset naming it `npm:1.0.0`
- **When** kvman starts with no terminal and no `--yes`; and the trust prompt runs on a terminal that answers `y`
- **Then** the first exits 1 with `EXTENSION_INVALID` listing `@acme/hello@1.0.0`; the prompt lists the name, version, and source, and `y` accepts it
- Test: `packages/cli/test/start/trust.test.ts`; `packages/cli/test/trust-prompt.test.ts`

### M1.8-H6 — `--yes` accepts, and a new version asks again
- **Given** the registry serving `@acme/hello` 1.0.0 and 1.1.0
- **When** kvman starts with `--yes` on 1.0.0, stops, starts without `--yes` on 1.0.0, then without `--yes` on 1.1.0
- **Then** the first installs it into `extensions/@acme/hello@1.0.0/` and its public command answers; the second starts without asking; the third exits 1 with `EXTENSION_INVALID` listing 1.1.0
- Test: `packages/cli/test/start/trust.test.ts`

### M1.8-H7 — a taken port fails PORT_IN_USE
- **Given** a server listening on a port of 127.0.0.1
- **When** kvman starts with `--port` set to it
- **Then** it exits 1 with `PORT_IN_USE`, and `kvman.lock` is removed
- Test: `packages/cli/test/start/start.test.ts`

### M1.8-H8 — Ctrl+C fails unfinished attempts with INTERRUPTED, keeping jobs with retries left queued
- **Given** two async jobs running and waiting for their signal, one with retries left and one with `retries: 0`
- **When** kvman gets SIGINT, exits, and starts again
- **Then** it exited 0; the first job's attempt failed `INTERRUPTED` and it runs again and succeeds; the second ended `failed` with `INTERRUPTED`
- Test: `packages/cli/test/stop/stop.test.ts`

### M1.8-H9 — logs contain no payloads, and `--log-level` filters them
- **Given** kvman with `--log-level debug`, then with `--log-level warn`
- **When** a command runs with an input and output holding a marker string, and a job fails
- **Then** neither `logs/kvman.log` nor the terminal holds the marker; with `warn`, no `info` or `debug` record is in the file or the terminal, and the warning is in both
- Test: `packages/cli/test/stop/logs.test.ts`

### M1.8-H10 — crash invariants 1, 2, 4, and 6 hold
- **Given** kvman running a `path:` extension
- **When** it's SIGKILLed after an async job is queued, while one runs, during `kernel.secrets.set` writes, and while it runs a long-lived process; then started again
- **Then** (1) the queued and running jobs run again (the running one's attempt failed `INTERRUPTED`), and one without retries ended `failed`; (2) a job that had ended never runs again; (4) `secrets.json` parses and holds either the old or the new value; (6) the process left by the killed kvman is stopped at the next start
- Test: `packages/cli/test/crash/crash.test.ts`

### M1.8-H11 — every M1.7 route scenario passes against a real kvman child process
- **Given** kvman as a child process
- **When** the M1.7 route scenarios run (M1.7-H1…H6, E1, E4, E5, E8, E9, E11, E16, E18–E21)
- **Then** each passes
- Test: `packages/cli/test/http/{routes,security,stream,static,files}.test.ts`

## Edge cases

### Arguments (`01` §1.2, ADR 0009, 46, 50) — `packages/cli/test/arguments.test.ts`

| Id | Given | Then |
|---|---|---|
| M1.8-E1 | `--help`; `--version` | the usage; kvman's version; both exit 0 (`packages/cli/test/start/start.test.ts`) |
| M1.8-E2 | an unknown flag, `--mode tui`, `--log-level loud`, `--port 70000`, `--port x`, and a positional argument | `VALIDATION_FAILED` each |
| M1.8-E3 | `--home`, `KVMAN_HOME`, and neither | `--home` wins over `KVMAN_HOME`, which wins over `~/.kvman` |
| M1.8-E4 | `--port 0`, and no `--port` | port 0; none given, so `kernel.port` applies |

### The lock and hand-over (`01` §1.2–§1.3, ADR 0009, 43–44)

| Id | Given | Then |
|---|---|---|
| M1.8-E5 | a live pid in `kvman.lock` without a port; a live pid whose port doesn't answer | `KVMAN_RUNNING` with the pid, exit 1, the lock left as it was (`packages/cli/test/start/lock.test.ts`) |
| M1.8-E6 | two takers racing for a missing or stale lock | exactly one takes it (`packages/cli/test/lock-file.test.ts`) |
| M1.8-E7 | a bare second `kvman` against a running kvman with another preset; a second one with the same `--preset` and `--mode web` | both hand over and exit 0 (`packages/cli/test/start/hand-over.test.ts`) |
| M1.8-E8 | a second `kvman --mode web` handing over its user's home folder | the URL of Home, `?workspace=home` (`packages/cli/test/start/hand-over.test.ts`) |
| M1.8-E9 | kvman started in its user's home folder | the URL of Home, `?workspace=home` (`packages/cli/test/start/start.test.ts`) |
| M1.8-E10 | a start that fails after taking the lock (an invalid extension) | exit 1 with `EXTENSION_INVALID` and a hint, and the lock is removed (`packages/cli/test/start/lock.test.ts`) |

### Presets (`01` §1.2, `02` §2.10, ADR 0009, 45) — `packages/cli/test/preset-lookup.test.ts`

| Id | Given | Then |
|---|---|---|
| M1.8-E11 | a name only bundled, and only in `<home>/presets/` | each is found, with its folder as the preset folder |

| M1.8-E13 | `./a/p.json`, `a\p.json`, `p.json`, and `p` | files relative to the start folder, except `p`, a name |

### npm installs (`02` §2.9, ADR 0009, 47) — `packages/cli/test/start/npm.test.ts`

| Id | Given | Then |
|---|---|---|
| M1.8-E14 | an installed version at the next start | npm isn't run again: the registry gets no request |
| M1.8-E15 | a version the registry doesn't have | exit 1 with `EXTENSION_INVALID`, and `extensions/<name>@<version>/` is removed |
| M1.8-E16 | an extension whose `@kvman/sdk` peer the registry doesn't serve | it installs, and loads the kernel's sdk |
| M1.8-E25 | npm on Linux and macOS, and on Windows | `npm install --ignore-scripts --omit=dev --legacy-peer-deps --prefix . <name>@<version>`; the same through `cmd.exe /d /s /c` (`packages/kernel/test/extensions/npm-install.test.ts`) |

|---|---|---|
