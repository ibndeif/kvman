# QA 17 — kvcustomizer, tooling for any harness, and managing kvman (ADR 0010)

Asked: "do we really need a kvdev to allow the user to develop extensions?", then that a person must be able to build extensions with kvman, with any other harness, or by hand, that kvdev becomes `kvcustomizer`, the `dev` preset goes, and the user manages extensions from the UI and the agent. Decided in ADR 0010 (1–14). This file is the contract; every scenario's test name starts with its id.

## Happy path

- **QA17-H1 Install writes the person's preset.** *Given* a running kernel whose preset is the home preset `<home>/presets/mine.json`, *when* `kernel.extensions.install { name: '@acme/notes', source: 'npm:1.2.3' }` runs, *then* it answers `{ file: '<home>/presets/mine.json', restartRequired: true }`, the file's `extensions` gains `"@acme/notes": "npm:1.2.3"` and keeps every other key, nothing is installed or loaded, and `kernel.extensions.list` is unchanged. (`packages/kernel/test/preset-edit/install.test.ts`)
- **QA17-H2 The first edit of the bundled preset copies it.** *Given* the bundled preset `coder` is running and `<home>/presets/coder.json` doesn't exist, *when* an install runs, *then* `<home>/presets/coder.json` is written holding the bundled preset's `name`, `extensions`, and `settings` plus the new entry, the answer's `file` is that path, and the bundled file is untouched. A second edit changes that copy and makes no other file. (`packages/kernel/test/preset-edit/bundled-copy.test.ts`)
- **QA17-H3 Uninstall removes an entry.** *Given* a home preset with `@acme/notes`, *when* `kernel.extensions.uninstall { name: '@acme/notes' }` runs, *then* the answer is `{ file, restartRequired: true }`, the file no longer has the entry, and its other entries and settings are unchanged. (`packages/kernel/test/preset-edit/uninstall.test.ts`)
- **QA17-H4 `kernel.preset.get` shows the stored preset.** *Given* the bundled `coder` is running, *then* it answers `origin: 'bundled'`, no `file`, and the preset's `name`, `extensions`, and `settings`; *after an install* it answers `origin: 'home'`, `file` set, and `extensions` including the new entry while `kernel.extensions.list` still lacks it; for `--preset ./app.json` it answers `origin: 'file'` and that file. (`packages/kernel/test/preset-edit/preset-get.test.ts`)
- **QA17-H5 `bundled` puts a removed bundled extension back.** *Given* a home preset without `@kvman/kvcoder`, *when* `install { name: '@kvman/kvcoder', source: 'bundled' }` runs, *then* the entry `"@kvman/kvcoder": "bundled"` is added. (`packages/kernel/test/preset-edit/install.test.ts`)
- **QA17-H6 An edit applies at the next start.** *Given* an install of a `path:` extension into a home preset, *when* the kernel is stopped and started again with that preset, *then* the extension is loaded and its query answers; *and given* an uninstall, *then* after the restart its names are gone (`NOT_FOUND`). (`packages/kernel/test/preset-edit/restart.test.ts`)
- **QA17-H7 A person's preset replaces a bundled one of the same name.** *Given* `<home>/presets/coder.json` with a different `settings`, *when* `kvman --preset coder` or a bare `kvman` starts, *then* that file is the preset run (`kernel.preset.get` gives `origin: 'home'`), and the bundled `coder.json` is not read. (`packages/cli/test/preset-lookup.test.ts`)
- **QA17-H8 `kvman-new` scaffolds a project.** *When* `kvman-new <folder> --name @me/notes --namespace notes --json` runs against the in-test registry, *then* the folder holds everything of plan 09 §9.2 (package.json, src/index.ts, locales `en` and `ar`, test, tsconfig, README), the dependencies are installed, the passing sample test passes, and stdout is `{ "folder", "name", "namespace", "web": false }` as JSON. (`packages/testkit/test/scaffold/kvman-new.test.ts`)
- **QA17-H9 `kvman-new` writes the harness files and the guides.** *Then* the project has `AGENTS.md` (it names `docs/`, `kvman-docs`, `npm run check`, `npm test`, and `dist/`), a `CLAUDE.md` of one line pointing to `AGENTS.md`, and `docs/` with exactly the three kernel-level guides `sdk.md`, `i18n.md`, `presets.md`, byte for byte the testkit's. (`packages/testkit/test/scaffold/harness-files.test.ts`)
- **QA17-H10 `kvman-new --web` adds the web template.** *Then* the plan 09 §9.2 web files and scripts exist, `npm run web:build` builds `dist/web/components/Hello.js`, and `--json` prints `"web": true`. (`packages/testkit/test/scaffold/kvman-new-web.test.ts`)
- **QA17-H11 `kvman-check` still reports.** *Then* every scenario of the existing `kvman-check` tests passes unchanged against the moved scaffold. (`packages/testkit/test/check/*.test.ts`)
- **QA17-H12 `kvman-preset new` and `check`.** *When* `kvman-preset new <file> --name mine` runs, *then* it writes the plan 09 §9.1 skeleton and `--json` prints `{ "file" }`; *when* `kvman-preset check <file> --json` runs against a running kvman on a preset with a bad setting key, an unknown bundled name, and an unknown home page, *then* it prints one `{ file, message, hint }` for each and exits 1; on a valid preset it prints `[]` and exits 0; with no kvman running it checks the schema only and says so on stderr. (`packages/testkit/test/preset/preset-bins.test.ts`)
- **QA17-H13 `kvman-preview` runs a preview.** *Given* `--kvman <entry>` naming a fake kvman, *when* `kvman-preview <folder> --json` runs, *then* it starts that entry with its own temporary home `<os temp>/kvman-preview-<name>` (`--name`, default `preview`), port 3738 (or the next free one), `--yes --no-open`, and a generated preset with the folder as `path:`; once the preview answers `kernel.health.get` it prints `{ "url": … }` as one JSON line and keeps running; on SIGINT or SIGTERM it stops the preview and its `web:watch` processes, removes the home, and exits 0. With no `--kvman` it runs the `kvman` found on the PATH. (`packages/testkit/test/preview/kvman-preview.test.ts`)
- **QA17-H14 The extension is `kvcustomizer`.** *Then* the extension's package is `@kvman/kvcustomizer`, its namespace `kvcustomizer`, its commands are `kvcustomizer.ext.new` and the rest of plan 09 §9.1, no `kvdev` name remains in any package, preset, catalog, doc, or test (a grep test), and kvdev's existing test scenarios pass under the new names. (`extensions/kvcustomizer/test/registration.test.ts`)
- **QA17-H15 `ext new` runs the bin.** *When* `kvcustomizer.ext.new` runs, *then* it spawns the `kvman-new` bin resolved from kvcustomizer's own `@kvman/testkit` dependency with the running Node, with the fields as flags and `--json`, and answers the bin's JSON; it never imports the testkit. `preset new|check` and `preview start` work the same way (`preview start` also passes `--kvman <process.argv[1]>`). (`extensions/kvcustomizer/test/run-bin.test.ts`)
- **QA17-H16 `docs list` and `docs get` pull.** *Given* a kernel with three loaded extensions, two of which serve `<ns>.docs.list` and `<ns>.docs.get` as public queries, *then* `docs list` answers the three built-in guides (`extension: "kvman"`) and each topic of the two, and `docs get` answers the same Markdown as `packages/testkit/docs/<topic>.md` for a built-in topic with no project open, and each extension's page for `{ extension, topic }`. (`extensions/kvcustomizer/test/docs.test.ts`)
- **QA17-H17 The `kvman` connector manages the app.** *Then* `kvman model list` answers the callable models, `kvman model set '{ "model": "openai/gpt-6-luna" }'` sets `kvai.defaultModel` globally, `kvman settings list|set|reset` call `kernel.settings.*`, `kvman extensions list|install|uninstall` call `kernel.extensions.*`, and `kvman preset get` calls `kernel.preset.get`, each through `kvcustomizer.app.<noun>.<verb>`, public, with their input and output validated. `ext` is unchanged. (`extensions/kvcustomizer/test/app-commands.test.ts`)
- **QA17-H18 `coder` loads kvcustomizer.** *Then* `presets/coder.json` lists `@kvman/kvai`, `@kvman/kvwebui`, `@kvman/kvcoder`, `@kvman/kvcustomizer`; `presets/dev.json` doesn't exist; `kvman` with no flags runs `coder` and the agent sees the `kvman`, `ext`, `preset`, `preview`, and `docs` connectors. (`packages/cli/test/bundled-presets.test.ts`, `extensions/kvcustomizer/test/e2e/walkthrough.test.ts`)
- **QA17-H19 The Extensions page lists and adds.** *Given* the page with a stored preset that has one extension more than is loaded, *then* each card shows its name, version, and source as before, the extra one shows "Starts after restart", and a banner reads "Restart kvman to apply"; *when* the form gets `@acme/notes` and `npm:1.2.3` and "Install" is pressed, *then* `kernel.extensions.install` is called with exactly that input, the form clears, and the page shows the new card marked "Starts after restart". (`extensions/kvwebui/test/web/extensions-manage.test.ts`)
- **QA17-H20 The Extensions page removes.** *When* "Remove" on a card is pressed, *then* it asks "Remove @acme/notes?" inline first; *on confirm* `kernel.extensions.uninstall` is called and the card shows "Removed after restart"; *on cancel* nothing is called. (`extensions/kvwebui/test/web/extensions-manage.test.ts`)
- **QA17-H21 The page sets nothing it shouldn't.** *Then* an extension's settings are still set on the Settings page, and the Extensions page calls no `kernel.settings.*` and no `kernel.secrets.*`. (`extensions/kvwebui/test/web/extensions-manage.test.ts`)
- **QA17-H22 The developer documentation exists.** *Then* `docs/developers/` has a README index and the pages listed in `milestones/QA17-DOCS.md` (a getting-started tutorial, the extension anatomy, the SDK reference, views, custom components, localization, connectors and kvcoder extension points, presets, testing with the testkit, hot reload and the preview, the kernel API reference, the HTTP API, errors, and publishing), each non-empty. (`packages/cli/test/docs.test.ts`)
- **QA17-H23 The user guide exists.** *Then* `docs/user-guide/` has a README index and the pages listed in `milestones/QA17-DOCS.md` (installing and starting, the web app, workspaces, models and providers, the coding app, managing extensions, presets, settings, the customizer, troubleshooting), each non-empty. (`packages/cli/test/docs.test.ts`)
- **QA17-H24 The docs are accurate.** *Then* every relative link and `#anchor` in `docs/**/*.md`, the README, and the scaffold's `AGENTS.md` resolves; every kernel command and query of plan 02 §2.12 appears by name in `docs/developers/kernel-api.md`; every kernel error code of plan 05 appears in `docs/developers/errors.md`; and every `kvman` flag of plan 01 §1.2 appears in `docs/user-guide/installing.md`. (`packages/cli/test/docs.test.ts`)
- **QA17-H25 The core extensions document themselves.** *Then* `kvwebui.docs.list` answers `views` and `components`, `kvcoder.docs.list` `connectors` and `sections`, `kvai.docs.list` `models` and `providers`, and `kvcustomizer.docs.list` `customizing`, each `docs.get` answers a non-empty English Markdown page with its `title` and `topic`, the pages are the files of the extension's `docs/` folder, the queries are public, and every page link resolves. (`extensions/kvwebui/test/docs.test.ts`, `extensions/kvcoder/test/docs.test.ts`, `extensions/kvai/test/docs.test.ts`, `extensions/kvcustomizer/test/docs-own.test.ts`)
- **QA17-H26 `kvman-docs` reads a running kvman.** *Given* a kernel with HTTP and an extension that serves docs, *when* `kvman-docs list --home <home>` runs, *then* it finds the port in `<home>/kvman.lock` and prints the three built-in guides and the extension's topics; `kvman-docs get <extension> <topic>` prints the page's Markdown; `--json` prints `[{ extension, topic, title }]` and `{ extension, topic, title, markdown }`; `--url http://127.0.0.1:<port>` works with no lock file; the built-in `kvman-docs get kvman sdk` prints the testkit's page. (`packages/testkit/test/docs/kvman-docs.test.ts`)

(`packages/testkit/test/scaffold/kvman-new.test.ts`)

(`packages/kernel/test/preset-edit/no-core.test.ts`, `packages/testkit/test/docs/kvman-docs.test.ts`)

## Edge cases

- **QA17-E1 A bad source fails.** *Then* `install` with `npm:^1.2.3`, `npm:`, `path:`, `git:x`, an empty `source`, and `bundled` for a name that isn't a bundled extension each fail `VALIDATION_FAILED` saying why, and the file is unchanged. (`packages/kernel/test/preset-edit/install.test.ts`)
- **QA17-E2 A name already present fails.** *Then* `install` of a name already in the preset fails `VALIDATION_FAILED` and writes nothing; an invalid npm package name fails the same way. (`packages/kernel/test/preset-edit/install.test.ts`)
- **QA17-E3 Uninstalling what isn't there fails.** *Then* `uninstall` of a name not in the preset fails `NOT_FOUND`, and writes nothing, and doesn't copy the bundled preset. (`packages/kernel/test/preset-edit/uninstall.test.ts`)
- **QA17-E4 A dependency can't be removed.** *Given* `@kvman/kvcoder`, which depends on kvai and kvwebui, *then* `uninstall` of `@kvman/kvai` fails `VALIDATION_FAILED` naming `@kvman/kvcoder`, and the file is unchanged; uninstalling `@kvman/kvcoder` first, then `@kvman/kvai`, works. (`packages/kernel/test/preset-edit/uninstall.test.ts`)
- **QA17-E5 The result is always a valid preset.** *Then* every file the commands write passes `presetSchema`, is valid JSON with a trailing newline, and keeps the key order `name`, `extensions`, `settings`; a write that fails (the folder isn't writable) fails `VALIDATION_FAILED` and leaves the previous file whole. (`packages/kernel/test/preset-edit/write.test.ts`)
- **QA17-E6 Edits don't race.** *When* two installs of different names run at once, *then* both are in the file; *when* an install and an uninstall run at once, *then* the file holds both results. (`packages/kernel/test/preset-edit/concurrent.test.ts`)
- **QA17-E7 An edit never loads, installs, or trusts.** *Then* after an `npm:` install no npm process ran, no folder appeared under `<home>/extensions`, and no row was added to the accepted extensions; the trust question is asked at the next start as before. (`packages/kernel/test/preset-edit/no-side-effects.test.ts`)
- **QA17-E8 Only these commands touch the preset.** *Then* a settings change (`kernel.settings.set`) never writes a preset file, and `kernel.preset.get` never writes one; both calls are public and answer through HTTP like every kernel command. (`packages/kernel/test/preset-edit/boundaries.test.ts`)
- **QA17-E9 A stored preset broken by hand.** *Given* the preset file was edited to invalid JSON after start, *then* `install`, `uninstall`, and `preset.get` fail `VALIDATION_FAILED` naming the file, and don't overwrite it. (`packages/kernel/test/preset-edit/write.test.ts`)
- **QA17-E10 A named home preset that doesn't exist.** *Then* `--preset nope` still fails `VALIDATION_FAILED`, now saying "neither a bundled one nor …" as before; the old "both bundled and in" failure is gone. (`packages/cli/test/preset-lookup.test.ts`)
- **QA17-E11 `kvman-new` refuses a used folder.** *Then* a non-empty folder fails with `kvcustomizer/FOLDER_NOT_EMPTY` through the connector and exit code 1 with the message on stderr from the bin; a bad `--name` or `--namespace` fails with the plan's `VALIDATION_FAILED`-style message and exit code 1; nothing is written. (`packages/testkit/test/scaffold/kvman-new-rules.test.ts`, `extensions/kvcustomizer/test/ext-new-rules.test.ts`)
- **QA17-E12 A failed install keeps the files.** *Given* an `npm install` that fails, *then* `kvman-new` exits 1 printing the last lines of npm's output, keeps the written files, and the connector fails `kvcustomizer/NPM_FAILED`; `npm` missing from the PATH fails the same. (`packages/testkit/test/scaffold/kvman-new-npm.test.ts`, `extensions/kvcustomizer/test/npm-missing.test.ts`)
- **QA17-E13 `kvman-preview` failures.** *Then* a missing `kvman` on the PATH exits 1 saying so; all ports 3738–3837 taken exits 1 with the `NO_FREE_PORT` text; a preview that doesn't answer in 30 s, or exits first, is stopped, its home is removed, and the last log lines are printed with exit 1; a second `kvman-preview` for the same name while its preview is alive exits 1 with `PREVIEW_FAILED`. (`packages/testkit/test/preview/kvman-preview.test.ts`)
- **QA17-E14 The connector's bin errors map to Problems.** *Then* a bin that exits 1 with a JSON error on stderr (`{ code, message, params }`) becomes the matching `kvcustomizer/…` Problem (`FOLDER_NOT_EMPTY`, `FILE_EXISTS`, `NPM_FAILED`, `NO_FREE_PORT`, `PREVIEW_FAILED`; `VALIDATION_FAILED` stays) with the same message and params, and `--json` is always passed; a bin killed by a signal, or one that exits with any other code or output, fails `HANDLER_FAILED` (the output is logged, never in the message); a cancelled job kills the bin's process tree. (`extensions/kvcustomizer/test/run-bin.test.ts`)
- **QA17-E15 The `kvman` connector never touches secrets.** *Then* no `kvcustomizer.app.*` command reads, writes, lists, or returns a secret, and `kvman settings set` on a key that isn't a setting fails `NOT_FOUND` as `kernel.settings.set` does. (`extensions/kvcustomizer/test/app-commands.test.ts`)
- **QA17-E16 `kvman model set` checks.** *Then* a model id that isn't in `kvai.model.list` for a callable provider fails `VALIDATION_FAILED` and sets nothing. (`extensions/kvcustomizer/test/app-commands.test.ts`)
- **QA17-E17 The Extensions page fails kindly.** *Then* a failed `install` or `uninstall` shows the Problem's text in the page, keeps the form's values, and shows no banner; an empty name or source disables "Install"; with `npm:` and `path:` hints visible. (`extensions/kvwebui/test/web/extensions-manage.test.ts`)
- **QA17-E18 Nothing pending, nothing shown.** *Given* a stored preset equal to what is loaded, *then* the page shows no banner and no "after restart" mark. (`extensions/kvwebui/test/web/extensions-manage.test.ts`)
- **QA17-E19 No raw keys, right to left.** *Then* every state of the page, in `en` and `ar`, shows no text that is a `kvwebui.` key, and the new styles use logical properties only. (`extensions/kvwebui/test/locales.test.ts`, `extensions/kvwebui/test/web/extensions-manage.test.ts`)
- **QA17-E20 The catalogs are complete.** *Then* kvcustomizer and kvwebui have `en` and `ar` text for every new key, title, error code, and `kvcustomizer.app.title`-style key; `kvdev.app.title` is gone. (`extensions/kvcustomizer/test/catalog.test.ts`, `extensions/kvwebui/test/locales.test.ts`)
- **QA17-E21 The model gets the new prompt.** *Then* the global `guide` section says to use `kvman` for the running app and `ext` for a project, to edit a project's files with `fs`, and that a change to the preset applies at the next start. (`extensions/kvcustomizer/test/section.test.ts`)
- **QA17-E22 The scaffold's pins hold.** *Then* the testkit's scaffold versions equal the monorepo's `@kvman/sdk`, `@kvman/testkit`, `typescript`, `vite`, `@vitejs/plugin-vue`, and `vue`. (`packages/testkit/test/scaffold/scaffold-versions.test.ts`)
- **QA17-E23 Walls hold.** *Then* the lint walls pass: kvcustomizer imports neither `@kvman/kernel` nor `@kvman/testkit`; the testkit may import kernel and sdk; `kvman`'s package includes the testkit and the guides. (`pnpm lint`; `packages/cli/test/bundled-presets.test.ts`)
- **QA17-E24 Docs never promise what isn't built.** *Then* no doc names a command, flag, preset, page, or error code that isn't in the plan or the code (the checks of H24 run both ways for the commands and codes), and no doc mentions `kvdev` or a `dev` preset except in a "migrating from kvdev" note. (`packages/cli/test/docs.test.ts`)
- **QA17-E25 One failing extension hides no other.** *Given* an extension whose `docs.list` throws and another whose `docs.get` answers a wrong shape, *then* `docs list` still lists the healthy ones and adds `{ extension, problem }` for each failing one; the failing text is the Problem's, with no stack and no payload. (`extensions/kvcustomizer/test/docs.test.ts`)
- **QA17-E26 Only a documented extension counts.** *Then* an extension with `docs.list` but no `docs.get`, one with private `docs.*` queries, or none, is not listed and produces no error; two extensions may serve the same topic name. (`extensions/kvcustomizer/test/docs.test.ts`)
- **QA17-E27 `docs get` fails clearly.** *Then* an unknown extension, or a topic the extension doesn't serve, fails `NOT_FOUND` saying which; a built-in topic that isn't `sdk`, `i18n`, or `presets` fails `NOT_FOUND`; an invalid topic name fails `VALIDATION_FAILED`. (`extensions/kvcustomizer/test/docs.test.ts`)
- **QA17-E28 `kvman-docs` with no kvman.** *Then* with no lock file, a lock whose process isn't alive, or a lock with no port, `list` prints only the three built-in guides, says on stderr to start kvman, and exits 0; `get` of an extension's topic exits 1 saying so; `get kvman sdk` still works; a `--url` nobody listens on exits 1 for an extension topic. (`packages/testkit/test/docs/kvman-docs.test.ts`)
- **QA17-E29 `kvman-docs` honors the listener's rules.** *Then* it calls only `127.0.0.1` URLs (a `--url` with another host fails `VALIDATION_FAILED`-style exit 1 before any request), sends the Host the listener expects, and never prints a secret, a setting value, or a request body. (`packages/testkit/test/docs/kvman-docs.test.ts`)
- **QA17-E30 The docs pair is checked.** *Then* `kvman-check` warns when an extension has exactly one of `<namespace>.docs.list` and `<namespace>.docs.get`, or a listed topic that `docs.get` doesn't answer, or a topic that isn't kebab-case. (`packages/testkit/test/check/docs-pair.test.ts`)
