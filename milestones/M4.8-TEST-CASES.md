# M4.8 — The VS Code view, sized to read and kept current: test cases

Read: `15` §15.3, §15.4; `06` §6.2; `08` §8.7; ADR 0106.

The layers are those of M4.7: the session's decisions (`session.test.ts`, `joined-version.test.ts`), the controller with a fake host, the health call against a fake server, the view's page in `happy-dom`, kvwebui's pages mounted with the fake API, kvcoder's components, and kvcoder's pages in Chromium with a real kvman and a scripted model for layout. The by-hand check runs in a real VS Code, as in M4.2, and is recorded at the end.

## Happy path

### M4.8-H1 — kvman must be at least as new as the extension
- **Given** an extension at 0.4.8
- **When** `kvman --version` answers `0.4.7`, then, in another window, `0.4.8`
- **Then** the first shows the Update view with `minimum` `0.4.8`; the second starts kvman
- Test: `packages/vscode/test/version.test.ts`, `packages/vscode/test/session.test.ts`

### M4.8-H2 — a joined kvman that is older shows the older-kvman view
- **Given** a started session of an extension at 0.4.8
- **When** a `joined` line comes for port 3737, and `kernel.health.get` answers version `0.4.6`
- **Then** the line's effect is a check of the joined kvman on 3737; the view is `{ kind: 'oldRunning', version: '0.4.6', minimum: '0.4.8' }`; the window doesn't own kvman
- Test: `packages/vscode/test/joined-version.test.ts`

### M4.8-H3 — Start again and Open anyway
- **Given** the older-kvman view
- **When** the person presses Start again; in another session, Open anyway
- **Then** Start again starts kvman (the view is Starting); Open anyway frames the joined kvman's URL with `embed=parent`, not owned, and flushes the frame's waiting requests
- Test: `packages/vscode/test/joined-version.test.ts`

### M4.8-H4 — a joined kvman as new as the extension is framed
- **Given** a started session of an extension at 0.4.7
- **When** a `joined` line comes and the check answers `0.4.7`
- **Then** the view is the frame at the line's URL, not owned
- Test: `packages/vscode/test/joined-version.test.ts`, `packages/vscode/test/session.test.ts`

### M4.8-H5 — the health call reads the running kvman's version
- **Given** a fake kvman answering `{ ok: true, output: { version: '0.4.6' } }`
- **When** the extension asks for the running kvman's version
- **Then** it gets `0.4.6`; the controller turns the check effect into the answered happening
- Test: `packages/vscode/test/health.test.ts`, `packages/vscode/test/controller.test.ts`

### M4.8-H6 — the older-kvman view's page
- **Given** the older-kvman view in English and in Arabic
- **When** its page is made
- **Then** it says "kvman 0.4.6 is already running, and this extension needs 0.4.8. Quit it, then start again." (and its Arabic text), with the buttons Start again (`start`) and Open anyway (`openAnyway`)
- Test: `packages/vscode/test/web/view-html.test.ts`

### M4.8-H7 — the theme's soft background
- **Given** the view's page with VS Code's side bar color and foreground
- **When** the frame says `kvman.state`
- **Then** the theme's `surface` is the side bar color, and its `background` is `color-mix(in srgb, <foreground> 6%, <side bar color>)`
- Test: `packages/vscode/test/web/relay.test.ts`

### M4.8-H8 — body text is the host's size
- **Given** an embedded page
- **When** the host's theme has `fonts.size` `13px`
- **Then** the root's font size is `calc(13px * 8 / 7)`
- Test: `extensions/kvwebui/test/web/embedded-host.test.ts`

### M4.8-H9 — a status item at 0 isn't shown, and shows again when its count rises
- **Given** a status item with `titleCount: 'count'` whose query answers 0
- **When** the page shows, then the count becomes 2 and the items rerun
- **Then** the status bar holds no text of that item, then holds it
- Test: `extensions/kvwebui/test/web/title-count.test.ts`

### M4.8-H10 — the embedded status line is one line
- **Given** an embedded page with a status item
- **When** it shows
- **Then** the line has the `flex-nowrap`, `overflow-hidden`, and `whitespace-nowrap` classes, and the item's text is its tooltip; the page's ground and the line are on the surface color (`bg-surface`)
- Test: `extensions/kvwebui/test/web/embedded-status.test.ts`

### M4.8-H11 — at side-bar width the chat header is one row, and its menu opens inside the view
- **Given** a chat with a running background job, at 300 px wide in Chromium
- **When** the chat page shows, and the person opens the chat's menu
- **Then** the header's buttons and the title share one row (the header at most 64 px high); the jobs chip shows its dot and count, not its words; the menu lies inside the viewport, and nothing scrolls sideways
- Test: `extensions/kvcoder/test/e2e/side-bar-width.test.ts`

### M4.8-H12 — at side-bar width the artifact head is two rows
- **Given** a chat with an artifact, at 300 px wide in Chromium
- **When** the person opens the artifact
- **Then** the title is at least 200 px wide, and the actions are below it, at the inline end; a 64-letter word in the artifact wraps, so its body doesn't scroll sideways
- Test: `extensions/kvcoder/test/e2e/side-bar-width.test.ts`

### M4.8-H13 — the Background chip has its words as label and its count apart
- **Given** a chat with one ended background job, then one running
- **When** the chip shows
- **Then** its `aria-label` and `title` are "Background (1)", then "1 running"; it has a count of `1` and an icon; its words are in a span of their own
- Test: `extensions/kvcoder/test/web/jobs-chip.test.ts`

### M4.8-H14 — chat titles read in their own direction
- **Given** a chat titled in Arabic
- **When** its header and the chat list show
- **Then** the header's title and the list's title have `dir="auto"`
- Test: `extensions/kvcoder/test/web/compact-header.test.ts`, `extensions/kvcoder/test/web/sessions.test.ts`

## Edge cases

### M4.8-E1 — a joined kvman that doesn't answer, or answers without a version, is framed
- **Given** a started session
- **When** a `joined` line comes and the check finds no answer; in another session, an answer without a version
- **Then** each view is the frame, not owned
- Test: `packages/vscode/test/joined-version.test.ts`, `packages/vscode/test/health.test.ts`

### M4.8-E2 — the joined start's exit during the check doesn't show Stopped
- **Given** a `joined` line whose check hasn't answered
- **When** the started kvman exits 0, as a joined start does
- **Then** nothing changes; the check's answer then frames kvman
- Test: `packages/vscode/test/joined-version.test.ts`

### M4.8-E3 — requests made during the check wait for the frame
- **Given** a `joined` line whose check hasn't answered
- **When** "Open in browser" runs, then the check answers a new enough version
- **Then** nothing is opened before the answer; the answer opens the joined kvman's start workspace in the browser
- Test: `packages/vscode/test/joined-version.test.ts`

### M4.8-E4 — versions compare by number
- **Given** the extension's version
- **When** versions such as `0.4.10` and `0.4.9`, or `1.0.0` and `0.9.9`, are compared
- **Then** `0.4.10` is new enough for `0.4.9`, `0.4.9` isn't for `0.4.10`, and an extension at 0.5.0 needs 0.5.0
- Test: `packages/vscode/test/version.test.ts`

### M4.8-E5 — an item without a count, or a count that isn't 0, keeps showing
- **Given** a status item with no `titleCount`, and one whose count field is missing from the output
- **When** the page shows
- **Then** both items show their text
- Test: `extensions/kvwebui/test/web/title-count.test.ts`

### M4.8-E6 — an embedded status line whose only item is at 0 is hidden
- **Given** an embedded page whose only status item has a count of 0
- **When** it shows
- **Then** the status line isn't visible; when kvman stops answering, it shows the reconnecting text
- Test: `extensions/kvwebui/test/web/embedded-status.test.ts`

### M4.8-E7 — the Settings tab mixes into the editor's color
- **Given** the Settings tab's page
- **When** the frame says `kvman.state`
- **Then** `surface` is the editor's color and `background` is the foreground mixed 6% into it
- Test: `packages/vscode/test/web/relay.test.ts`

### M4.8-E8 — every new text has `en` and `ar`
- **Given** the extension's catalogs
- **When** they are compared
- **Then** `vscode.oldRunning` and `vscode.openAnyway` are in both, with the same placeholders
- Test: `packages/vscode/test/catalog.test.ts`

## By-hand check

Done 2026-10-26 in VS Code 1.143.1 (snap, Linux), driven through its debugging port, with `kvman.path` running the repository's kvman on a copy of the owner's database (no `secrets.json`) and a spare port:

- Dark Modern and Light Modern: chat text 13 px (root 14.86 px), the status line one line without "Waiting for you: 0", the person's messages and the cards on a visible fill, and the page flush with the side bar.
- At 300 px: the chat header is one row (History, the Arabic title cut at its own end, the Background chip as an icon and 50, the artifacts button, and "…"); "…" opens its menu inside the view; the artifact panel's name has its own row over the switch and the buttons; nothing scrolls sideways.
- The new-chat heading is 20 px.
- With kvman 0.4.6 from npm already running on the home, the view showed "kvman 0.4.6 is already running, and this extension needs 0.4.7. Quit it, then start again." with Start again and Open anyway; Open anyway framed the 0.4.6 kvman.
