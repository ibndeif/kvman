# M1.4 — Extensions and workers: test cases

Read: `02` §2.1, §2.2, §2.8 (preset checks), §2.9, §2.13; `03`; `10`; ADR 0009 (M1.4: versions, test workers, test Home, sealed registrations, testkit options).

Kernel integration tests live in `packages/testkit/test/` and run the real kernel through `createTestKernel`. Test extensions are small `path:` extensions in `packages/testkit/test/fixtures/extensions/<name>/`, each with a `package.json` (`kvman.source: "index.ts"`, the `@kvman/sdk` peer `^0.1.0`) and an `index.ts` entry. A test that must prove where `@kvman/sdk` comes from copies its fixtures into a temporary folder, where no `node_modules` can resolve it. Logs are read from the test kernel's `logs/kvman.log`.

In this milestone `ctx` has the registrations, `exec`, `job`, `problem`, `store`, `settings.get`, `secrets`, and `log`; the other calls come with their milestones.

## Happy path

### M1.4-H1 — every loading rule stops the kernel with EXTENSION_INVALID
- **Given** test runs whose extensions each break one rule of `02` §2.9 (see M1.4-E1…E11)
- **When** `createTestKernel` starts
- **Then** it fails `EXTENSION_INVALID`, and the message names the offending extension, or prints the cycle
- Test: `packages/testkit/test/loading/loading-rules.test.ts`

### M1.4-H2 — two extensions share the kernel's `@kvman/sdk`, and a `path:` extension loads from its `.ts` source
- **Given** two extensions copied to a temporary folder with no `node_modules`, each with only an `index.ts` (`kvman.source`), each throwing `ctx.problem(…)`'s `ProblemError` and one throwing `new ProblemError(…)` from its own `@kvman/sdk` import
- **When** both are called
- **Then** both load, and both Problems reach the caller with their own codes (the kernel's `instanceof ProblemError` holds, so it is one SDK instance)
- Test: `packages/testkit/test/loading/sdk-sharing.test.ts`

### M1.4-H3 — the preset's settings are checked after load
- **Given** an extension with a key `notes.home` that has no default, and a key `notes.greeting` with a string schema
- **When** the run's settings name an unknown key, give `notes.greeting` a number, or leave `notes.home` unset
- **Then** each start fails `VALIDATION_FAILED` naming the key; with valid settings, `ctx.settings.get` returns the preset's values
- Test: `packages/testkit/test/loading/preset-settings.test.ts`

### M1.4-H4 — handlers keep their own job while 32 interleave, and nested calls on a full worker complete
- **Given** one worker with `kernel.workerConcurrency` 32, and a query that waits a moment, then returns `ctx.job`'s id, root id, workspace, and caller
- **When** 32 calls run at once as different callers, and then 32 calls that each nest a sync call run at once
- **Then** each answer carries its own job id and caller; the nested calls all complete (they take no slot)
- Test: `packages/testkit/test/jobs/current-job.test.ts`

### M1.4-H5 — each access rule, limit, and depth rule fails with its code
- **Given** an extension with private and public commands and queries, size caps, and a recursive command
- **When** each rule is broken (see M1.4-E13…E20)
- **Then** each fails with its code
- Test: `packages/testkit/test/jobs/access.test.ts`

### M1.4-H6 — a crashed worker's jobs fail WORKER_CRASHED, and a new worker takes over
- **Given** one worker running a slow query and a command that ends the worker thread
- **When** the command runs
- **Then** both jobs fail `WORKER_CRASHED`, and the next call succeeds on the replacement worker
- Test: `packages/testkit/test/jobs/crashes.test.ts`

### M1.4-H7 — `ctx.log` lines carry the extension and the job id
- **Given** an extension that logs from its entry and from a handler
- **When** the handler runs
- **Then** `logs/kvman.log` has the handler's line with `extension` and `jobId`, and the entry's line with `extension` and no `jobId`
- Test: `packages/testkit/test/jobs/logging.test.ts`

### M1.4-H8 — the sync `ctx.exec` benchmark meets its target
- **Given** a test kernel with a no-op query
- **When** `pnpm bench:check` runs it
- **Then** p50 ≤ 1 ms and p99 ≤ 5 ms (`12` §12.3)
- Test: `bench/exec-noop.ts` (run by `pnpm bench:check`)

## Edge cases

### Loading (`02` §2.9) — `packages/testkit/test/loading/loading-rules.test.ts`

| Id | Given | Then |
|---|---|---|
| M1.4-E1 | a dependency that isn't in the run | `EXTENSION_INVALID` naming the extension and the missing dependency |
| M1.4-E2 | a dependency whose version is out of range | `EXTENSION_INVALID` naming both and the range |
| M1.4-E3 | an `@kvman/sdk` peer range the kernel's sdk doesn't satisfy, and a manifest without the peer | `EXTENSION_INVALID` naming the extension |
| M1.4-E4 | `a → b → a` | `EXTENSION_INVALID` printing `@test/a → @test/b → @test/a` |
| M1.4-E5 | two extensions with one namespace | `EXTENSION_INVALID` naming both |
| M1.4-E6 | a name outside the namespace, and a name registered twice | `EXTENSION_INVALID` naming the extension and the name |
| M1.4-E7 | a registration without a description, and one whose `input` isn't a zod schema | `EXTENSION_INVALID` |
| M1.4-E8 | an entry that throws, and an entry that isn't a function | `EXTENSION_INVALID` naming the extension |
| M1.4-E9 | an unknown key in the `kvman` field | `EXTENSION_INVALID` |
| M1.4-E10 | a `maxInputBytes` over 32 MiB | `EXTENSION_INVALID` |
| M1.4-E11 | a handler that registers a command (ADR 0009, 12) | the call fails `EXTENSION_INVALID` |
| M1.4-E12 | `b` depends on `a`, with `kernel.workers` 2 | each worker runs `a`'s entry before `b`'s (log order), so each entry ran twice |

### Jobs (`02` §2.1–§2.3, §2.13) — `packages/testkit/test/jobs/*.test.ts`

| Id | Given | Then |
|---|---|---|
| M1.4-E13 | an unknown name | `NOT_FOUND` (`access.test.ts`) |
| M1.4-E14 | a private command called by the user and by another extension; the owner calling it | `NOT_PUBLIC` twice; the owner's call succeeds (`access.test.ts`) |
| M1.4-E15 | a query that runs a command, and a query that writes the store or a secret | `READ_ONLY` (`access.test.ts`) |
| M1.4-E16 | a command that calls itself 20 levels deep | `TOO_DEEP` with `params.limit` 16 at the 17th level (`access.test.ts`) |
| M1.4-E17 | an input over the registration's `maxInputBytes`, and an output over its `maxOutputBytes` | `TOO_LARGE` with the limit (`limits.test.ts`) |
| M1.4-E18 | an input and an output that don't fit their schemas | `VALIDATION_FAILED` (`limits.test.ts`) |
| M1.4-E19 | a handler that throws a plain `Error`, and one that throws `ctx.problem('notes/EMPTY', { field: 'text' })` | `HANDLER_FAILED` whose message isn't the error's (the error's message is in the log), and `notes/EMPTY` with its params (`errors.test.ts`) |
| M1.4-E20 | a handler that runs past its `timeoutMs` | `TIMEOUT`, and its `ctx.job.signal` is aborted (`errors.test.ts`) |
| M1.4-E21 | `ctx.job` and `ctx.store` used in the entry | fail `NO_JOB` (`current-job.test.ts`) |
| M1.4-E22 | a nested call | has its own job id, the root's `rootId`, the parent's workspace, and the calling extension as its caller (`current-job.test.ts`) |

### Testkit (`10`, ADR 0009, 10, 11, 13) — `packages/testkit/test/testkit.test.ts`

| Id | Given | Then |
|---|---|---|
| M1.4-E23 | `exec` with `as` and with an unknown `workspaceId` | the caller is `{ kind: 'extension', name }`; the unknown workspace fails `NOT_FOUND` |
| M1.4-E24 | a test kernel | Home is a temporary folder, not the user's home; it starts one worker; `close()` removes the temporary folders |
| M1.4-E25 | `secrets` in the options, then a handler that sets and reads a secret | the handler reads the given secret, and a later job reads the one it set |
