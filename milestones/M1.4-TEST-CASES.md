# M1.4 — Router and admission: test cases

Read: `02` §2.2–§2.7, §2.10, `03` §3.3, §3.4 (pending index), `04` §4.1–§4.2; ADRs 0032 (priority codes, unit limits), 0034 (failed sends), 0045 (registry), 0048 (no workspace), 0051 (what admission assigns), 0052 (grants as data), 0053 (event deliveries), 0054 (caller lane, kernel context), 0055 (inline payloads), 0056 (Ajv), 0057 (mismatch with `onReply`), 0058 (admission details).

Tests live in `packages/kernel/test/router/` and use a real database, the M1.3 registry built from test manifests (`@acme/pdf`, `@kvman/agent`, `@acme/audit`, `@acme/ocr`), a grants source given as data, and the M1.1 commit pipeline. Sends from handlers are committed as invocation units; people and processes submit through the router's adapter path (a standalone transaction). `kernel.*` and `ui.*` types are not registered until the milestones that build them, so admission knows only extension types.

## Happy path

Each admission failure code has a test (`packages/kernel/test/router/admission-failures.test.ts`).

### M1.4-H1 — a payload that fails its schema is VALIDATION_FAILED
- **Given** `pdf.translate` with input `{ fileId: string, lang: string }`
- **When** a person sends `{ fileId: 7 }`
- **Then** it fails `VALIDATION_FAILED` with issues at `payload.fileId` and `payload.lang`, and nothing is stored

### M1.4-H2 — an unknown type is TYPE_NOT_FOUND
- **Given** no installed extension registers `pdf.unknown`
- **When** a person sends it
- **Then** it fails `TYPE_NOT_FOUND`

### M1.4-H3 — an owner not enabled in the workspace is HANDLER_UNAVAILABLE
- **Given** `@acme/ocr` installed and enabled only in workspace B
- **When** a person sends `ocr.extract` in workspace A
- **Then** it fails `HANDLER_UNAVAILABLE`

### M1.4-H4 — a foreign command without a grant is CAPABILITY_DENIED
- **Given** `@kvman/agent` with no `calls` grant
- **When** its handler sends `pdf.translate`
- **Then** the unit is rejected with `CAPABILITY_DENIED`; with `calls: ['pdf.*']` granted it commits

### M1.4-H5 — a caller outside the access is CALLER_NOT_ALLOWED
- **Given** `agent.prompt.section.set` with access `extensions`
- **When** a person sends it
- **Then** it fails `CALLER_NOT_ALLOWED`

### M1.4-H6 — a reused key with another payload is IDEMPOTENCY_MISMATCH
- **Given** a person's `pdf.translate` committed with key `click-1`
- **When** the person sends key `click-1` with another `lang`
- **Then** it fails `IDEMPOTENCY_MISMATCH` and nothing new is stored

### M1.4-H7 — the same key and digest return the original message
- **Given** a person's `pdf.translate` committed with key `click-1`, then marked done with a reply
- **When** the person sends the same request with key `click-1` again
- **Then** the router returns the original message id and its reply, and stores no new row

## Edge cases

### Envelope and assignment (`02` §2.2, §2.6, §2.10, ADRs 0051, 0054, 0058) — `packages/kernel/test/router/assignment.test.ts`

| Id | Given | Then |
|---|---|---|
| M1.4-E1 | a type name `Pdf.Translate`, a context over 2 KB, both `delayMs` and `at`, and a person's and a process's command without `idempotencyKey` | `VALIDATION_FAILED` each, at `type`, `context`, `delayMs`, and `idempotencyKey` |
| M1.4-E2 | a person's command, and a send from a handler of it | the first gets a ULID `id`, `correlationId` = its `id`, no `causationId`, source `user:local`, `createdAt` now, and context `{ locale: 'en' }`; the second inherits the correlation, the workspace, and the context (plus its additions), with `causationId` = the invocation's id |
| M1.4-E3 | context additions: a new key, a changed inherited `sessionId`, `locale` equal to the inherited one, `locale` changed | the first three are accepted; the last fails `VALIDATION_FAILED` |
| M1.4-E4 | priorities: a person's command, a process's, a kernel root, a send from a handler of an `interactive` command; a handler requesting `background`; a process and a kernel root requesting `interactive` | `interactive`, `normal`, `normal`, `interactive`; `background`; lowered to `normal` each |
| M1.4-E5 | a send with `delayMs: 5000`, one with `at`, one with `deadlineAt`, and one with none | `notBefore` now + 5000, `notBefore` = `at`, `deadlineAt` stored, and neither set |

| Id | Given | Then |
|---|---|---|
| M1.4-E8 | commands with access `all`, `user`, `extensions`, and `internal`, each sent by a person, by the owner's handler, by a process of the owner, by a granted foreign extension, and by the kernel | `all`: everyone; `user`: the person and the kernel; `extensions`: the owner, the process, the foreign extension, and the kernel; `internal`: the owner's handler and the kernel. Every other pair fails `CALLER_NOT_ALLOWED`, except that a foreign extension's `internal` or `user` target fails `CAPABILITY_DENIED` first |

### Capabilities (`05` §5.7, ADR 0052) — `packages/kernel/test/router/capabilities.test.ts`

| Id | Given | Then |
|---|---|---|
| M1.4-E9 | `calls` with an exact type and with `pdf.*`, `tools` against an `agentTool` command, an extension without grants in the workspace, and a process of `@kvman/agent` | the patterns cover `pdf.translate` and `pdf.files.list`; `tools` covers `pdf.translate` (an agent tool) but not `pdf.files.prune`; no grants fails `CAPABILITY_DENIED`; the process is checked with `@kvman/agent`'s grants |
| M1.4-E10 | a durable event published by its owner, by another extension, by a person, by a process, and a publish of the live event `pdf.progress.updated` | the owner's commits; each other fails `CAPABILITY_DENIED` |

### Payloads (ADRs 0055, 0056) — `packages/kernel/test/router/payloads.test.ts`

| Id | Given | Then |
|---|---|---|
| M1.4-E11 | a schema with a `z.blobId()` field, a `label` annotation, and a `uri` format; payloads with a bad blob id, a good one, and a nested wrong field | the bad blob id and the nested field fail `VALIDATION_FAILED` at their paths; the good payload is accepted; the annotation and the format do not break compiling; each type's validator is compiled once |
| M1.4-E12 | a payload of 1 MB and one over 16 MB | the first is stored, spilled to a blob since M2.5 (ADR 0135); the second fails `PAYLOAD_TOO_LARGE` with `{ limit: 'payload', max: 16777216 }` |

### Lanes (`02` §2.6, ADRs 0054, 0058) — `packages/kernel/test/router/lanes.test.ts`

| Id | Given | Then |
|---|---|---|

| M1.4-E14 | a caller lane for a handler without a template, and for one with a template | the first is used; the second fails `VALIDATION_FAILED` |

### Idempotency (`02` §2.7, ADRs 0034, 0057, 0058) — `packages/kernel/test/router/idempotency.test.ts`

| Id | Given | Then |
|---|---|---|
| M1.4-E15 | a handler's sends without keys, a failed send's continuation, and a request digest | keys `<invocationId>:send:<index>` and `<commandId>:reply`; the stored digest equals the protocol's `requestDigest` of `{ type, workspaceId, lane, payload }` |
| M1.4-E16 | two invocations whose handlers both send `pdf.import` with the explicit key `job-7:result` and the same payload (one job result injected once, `02` §2.7) | the second unit commits without storing a second copy |

| M1.4-E18 | `onReply` to a foreign command, to the sender's own non-internal command, and to an unknown type | the unit is rejected with `VALIDATION_FAILED` at `onReply.type` each |

### Events (`02` §2.5, ADR 0053) — `packages/kernel/test/router/events.test.ts`

| Id | Given | Then |
|---|---|---|
| M1.4-E19 | `pdf.imported` published durably, with subscriptions `pdf.imported` and `pdf.*` of `@acme/audit` (granted), `pdf.imported` of `@kvman/agent` (not granted), and `@acme/pdf`'s own `pdf.imported` | one `events` row; three pending delivery rows (two for `@acme/audit`, one for `@acme/pdf`) with new ids, `causationId` = the event id, `handler` `<extension>\|subscription:<pattern>`, and keys `<eventId>:<handler>`; none for `@kvman/agent` |
| M1.4-E20 | a transient event | admitted and returned in the commit result; no `events` or `messages` row |
| M1.4-E21 | a subscriber whose lane template finds none of its paths in the event | the publisher's unit commits; that delivery is `failed` with `VALIDATION_FAILED`; the other deliveries are pending |
| M1.4-E22 | an event payload that fails its schema, and a unit with 600 sends and 401 publishes | `VALIDATION_FAILED`; `PAYLOAD_TOO_LARGE` with `{ limit: 'messages', max: 1000 }` |
