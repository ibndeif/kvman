# M2.2 — Install pipeline: test cases

Read: `06` §6.1–§6.2, §6.5 (rehash), §6.8–§6.9, `03` §3.5 (loader), §3.8 (extension commands and queries), §3.9 steps 4–5; ADRs 0015 (stage result), 0079 (admin checks), 0081 (drift at load), 0086 (quarantined pending messages), 0089 (boot scope), 0113 (dependencies), 0114 (installed extensions in tests), 0115 (builtins and offline first run), 0116 (git and dev sources), 0117 (import scan), 0118 (stage and install details), 0119 (list queries), 0120 (uninstall).

Where the tests live:

- **Pure pieces**, in `packages/kernel/test/install/`: file lists and digests, package checks, the import scan, native code, the git command, the pnpm executable, and the stage result.
- **The pipeline through the kernel's commands**, in `packages/testkit/test/install/`. It runs on a runtime with a home folder, Verdaccio, a local `git daemon`, and the sandboxed loader.
- **Boot and first run**, in `packages/testkit/test/first-run/`, on booted daemons and child kernels.
- **`scripts/pack-builtins`**, in `packages/testkit/test/install/pack-builtins.test.ts`, which runs the script as a child process with Verdaccio as its registry.
- **Protocol shapes**, in `packages/protocol/test/extension-lifecycle.test.ts`.

Terms used in the scenarios:

- "**Sample**" is the fixture package `@acme/sample`. Its namespace is `sample`, its peer dependency is `@kvman/sdk`, and its command is `sample.echo`.
- "**Stage**" and "**install**" send `kernel.extension.stage` and `kernel.extension.install` as a person.
- "**Enabled**" means the runtime's `enabled` input (ADR 0114).

## Happy path

### M2.2-H1 — a sample extension installs from the local test registry and from a git commit
- **Test**: `packages/testkit/test/install/install.test.ts`
- **Given** Sample `1.0.0`, published to Verdaccio, and the same package committed to a repository served by `git daemon`.
- **When** `npm:@acme/sample@1.0.0`, and then `git:git://127.0.0.1:<port>/sample.git#<commit>` as a second name `@acme/sample-git`, are staged, installed, and enabled, and `sample.echo` and `sample-git.echo` are sent.
- **Then** for each source:
  - the stage reply has the name, version, digest, integrity (`sha512-…` from the registry, and `git:<commit>`), a token, and an `expiresAt` 10 minutes ahead;
  - install replies `{ name, digest }`;
  - `extensions/snapshots/<digest>/` holds `node_modules/<name>/`, `manifest.json`, and `files.json`;
  - an `extension_versions` row records the source and integrity, and `active_digest` is the digest;
  - `kernel.extension.installed` is published;
  - the command runs from the snapshot and replies.

### M2.2-H2 — `scripts/pack-builtins` produces the builtin tarballs and `digests.json`
- **Test**: `packages/testkit/test/install/pack-builtins.test.ts`
- **Given** a fixture extensions folder with two packages; one depends on a package from Verdaccio.
- **When** `scripts/pack-builtins` runs on it with an output folder.
- **Then**
  - each package has `<name without "@", "/" as "-">.tgz`;
  - `digests.json` maps each name to `{ file, digest }`;
  - unpacking a tarball gives `node_modules/<name>/` with its hoisted dependency, and that tree's snapshot digest equals `digest`.
  - Run on a folder with no packages, the script writes `digests.json` as `{}`.

### M2.2-H3 — a tampered snapshot is quarantined
- **Test**: `packages/testkit/test/first-run/boot.test.ts`
- **Given** Sample, installed and enabled, then one byte of its entry file changed.
- **When** the daemon boots on that home.
- **Then**
  - boot step 4 quarantines it with reason `EXT_INTEGRITY` and publishes `kernel.extension.quarantined`;
  - `/health` is `degraded`;
  - `sample.echo` fails `HANDLER_UNAVAILABLE`;
  - no host loads it.

### M2.2-H4 — a `setup` that reads a file, or behaves differently on its second run, fails in the loader
- **Test**: `packages/testkit/test/install/loader.test.ts`
- **Given** two packages: one whose `setup` reads the home folder's `kvman.db`, and one whose `setup` registers a random description.
- **When** each is staged.
- **Then**
  - the first fails `EXT_MANIFEST_INVALID` with "setup threw: …" and the sandbox's access error;
  - the second fails `EXT_MANIFEST_INVALID` with the determinism issue and its hint;
  - neither leaves a staging tree.

### M2.2-H5 — uninstall keeps or deletes data as chosen
- **Test**: `packages/testkit/test/install/uninstall.test.ts`
- **Given** two installed, not enabled extensions, `@acme/keep` and `@acme/drop`. Each has:
  - kv, docs, and log rows in two workspaces and global, and a blob ref;
  - a `global_config` row, a `workspace_config` row, and a `schema_versions` row;
  - notifications, and an `llm_models` row;
  - an entry in the applied preset of workspace A.
- **When** `keep` is uninstalled without options and `drop` with `deleteData: true`.
- **Then** both lose their `extensions` and `extension_versions` rows and their snapshots, and each publishes `kernel.extension.uninstalled {name}`.
  - Every row of `keep` stays.
  - Every listed row of `drop` is gone; its entry in A's applied preset is removed, the revision goes up by one, and `kernel.preset.changed {workspaceId: A, revision, cause: 'disable'}` is published.

### M2.2-H6 — an undeclared import, a missing built `main`, or a top-level native import fails with `EXT_SOURCE_INVALID` naming the cause
- **Test**: `packages/testkit/test/install/package-failures.test.ts`
- **Given** three packages:
  - one whose `dist/extension.js` imports `lodash`, which it does not declare;
  - one whose `main` names a file that is not in the package;
  - one whose entry imports, at its top level, a dependency that loads a `.node` addon.
- **When** each is staged.
- **Then** each fails `EXT_SOURCE_INVALID`:
  - "dist/extension.js imports lodash, which package.json does not declare", with `params` `{ file, specifier }`;
  - "main dist/extension.js does not exist; publish or commit the built files";
  - "import native dependency fake-native inside a handler".

### M2.2-H7 — first run succeeds with the network disabled
- **Test**: `packages/testkit/test/first-run/first-run.test.ts`
- **Given** a fresh home, a builtin folder holding two packed fixtures, and `KVMAN_NPM_REGISTRY`, `HTTP_PROXY`, and `HTTPS_PROXY` pointing at a closed local port.
- **When** a child kernel starts.
- **Then**
  - `/health` answers;
  - both builtins are installed with source `builtin:<name>` and integrity `builtin:<kvman version>`, verified, and not enabled;
  - their commands run once they are enabled;
  - pnpm never started;
  - no staging tree is left.
