# M2.2 — kvwebui frame: test cases

Read: `06` §6.1–§6.4, §6.6–§6.8; `02` §2.8 (settings), §2.11 (localization), §2.12 (the kernel API); `04` (HTTP); `07` §7.2–§7.3 (kvai's API and pages); `03` §3.1 (`syncOnly`); ADR 0002; ADR 0009 (M2.2: tooling, Playwright, no `tabs`, built-in pages, forms, marked fields, invalid answers, status items, workspaces in the browser, presentation, tables, the Settings and Extensions pages, kvai's pages, sync-only commands).

kvwebui has three kinds of tests:
- **Components** (`extensions/kvwebui/test/web/`): Vitest with `happy-dom` and `@vue/test-utils`. The whole app mounts against a fake HTTP API (`test/web/support/`), which answers `POST /api/commands/:name` and `/api/queries/:name` from a table of handlers, records every call with its `workspaceId`, and serves catalogs. Fixture extensions are plain `kernel.extensions.list` rows plus their `ui.get` answers. Timers are fake where time matters.
- **Kernel and extension** tests (`extensions/kvwebui/test/`, `extensions/kvai/test/`, `packages/testkit/test/`): the testkit, as before.
- **End to end** (`extensions/kvwebui/test/e2e/`): a real kvman child process (`--port 0 --no-open --yes`, a temporary home) with kvwebui bundled and a fixture extension by `path:`, driven by Chromium through the `playwright` library. A Vitest global setup builds kvwebui first.

## Happy path

### M2.2-H1 — a test extension's pages, nav, panels, and status items render
- **Given** a fixture extension `notes` whose `notes.ui.get` gives a page `list` (a heading and a table on `notes.note.list`), a nav item for it (icon `notebook`, order 10), a panel `help` (icon `circle-question-mark`) with a text view, and a status item on `notes.count.get` with text `notes.status.count` and `params: { count: { $output: 'count' } }`
- **When** the app loads at `/notes/list`
- **Then** the nav shows "Notes" above the divider and Settings and Extensions below it; the page shows the heading and the rows; the panel strip has the `help` icon, and clicking it opens the panel beside the page; the status bar shows "3 notes" on the start side and the health item ("kvman 0.1.0") on the end side
- Test: `extensions/kvwebui/test/web/contributions.test.ts`

### M2.2-H2 — an invalid `ui.get` shows an error card while the others render
- **Given** `notes` (valid), `broken`, whose answer names the unknown component `chart`, and `failing`, whose `failing.ui.get` fails `failing/DOWN`
- **When** the app loads
- **Then** `notes`' nav item and page work; `broken` and `failing` contribute nothing; each gets a dismissible error card naming it, with its translated Problem and a "Details" disclosure (`VALIDATION_FAILED` with the issue path for `broken`, `failing/DOWN` for `failing`); dismissing it removes it
- Test: `extensions/kvwebui/test/web/contributions.test.ts`

### M2.2-H3 — forms come from JSON Schema, and a failed command marks fields
- **Given** a page with `form { command: 'notes.note.add', fixed: { folder: 'inbox' }, submit }`, whose input schema has `folder`, `title` (string), `pages` (integer), `pinned` (boolean), `color` (enum), `due` (nullable string), `tags` (array of strings), `meta { author }` (object), `token` (`writeOnly` string), and `extra` (a record)
- **When** the form renders, then is submitted with a title the command refuses with `VALIDATION_FAILED { issues: [{ path: 'title', message }, { path: 'nowhere', message }] }`
- **Then** there is no `folder` field; the fields are a text field, a number field, a checkbox, a select, an empty-means-null text field, a one-per-line text area, an `author` field in a `meta` group, a password field, and a JSON text field, each labelled by `notes.note.add.fields.<field>` or else its description; after the failure, `title` is red with "This value isn't valid.", and a toast shows the translated `kernel.errors.VALIDATION_FAILED` with "Check the marked fields."
- Test: `extensions/kvwebui/test/web/forms.test.ts`

### M2.2-H4 — a `then` with `$output` opens the created item's page, and a `link` navigates without a command
- **Given** a page `note` with `params: ['noteId']`, a button that runs `notes.note.create` (which returns `{ id: 'n7' }`) with `then: { navigate: 'notes.note', params: { noteId: { $output: 'id' } } }`, and a `link { text, to: { page: 'notes.note', params: { noteId: 'n1' } } }`
- **When** the button is clicked, then the link
- **Then** the app is at `/notes/note/n7`, whose view reads `{ $param: 'noteId' }` as `n7`; then at `/notes/note/n1`, with no command sent for the link
- Test: `extensions/kvwebui/test/web/routes.test.ts`

### M2.2-H5 — opening `/?workspace=<id>` sets the tab's workspace and drops the parameter
- **Given** open workspaces Home and `w1` (`project`)
- **When** the app loads at `/?workspace=w1`
- **Then** the URL is `/`; the picker shows `project`; every call sends `workspaceId: 'w1'`; `sessionStorage` and `localStorage` hold `w1`
- Test: `extensions/kvwebui/test/web/workspaces.test.ts`

### M2.2-H6 — `/` shows the preset's home page; a missing one shows Extensions with `HOME_UNAVAILABLE`; Settings shows `kvwebui.home` locked
- **Given** `kvwebui.home` `notes.list`
- **When** the app loads at `/`; then again with `kvwebui.home` `ghost.start` while `ghost`'s `ui.get` fails `ghost/DOWN`; then at `/kvwebui/settings`
- **Then** `/` renders `notes.list`; then `/` renders the Extensions page with a card "The home page, ghost.start, isn't available" holding `ghost`'s translated Problem; then Settings shows `kvwebui.home` locked with its value and "Set by the test preset", with no control to change it
- Test: `extensions/kvwebui/test/web/routes.test.ts`

### M2.2-H7 — switching the language re-renders the UI in it, and a setting without `<key>.description` shows its English description
- **Given** `kernel.health.get` languages `['en', 'ar']`, and a setting `notes.pageSize` with no `notes.pageSize.description` in either catalog
- **When** the language menu picks العربية
- **Then** `kernel.settings.set { key: 'kernel.language', value: 'ar', scope: 'global' }` is sent, the `ar` catalog is loaded, and the nav reads "الإعدادات"; `<html>` has `lang="ar"` and `dir="rtl"`; the Settings page shows `notes.pageSize`'s registered English description
- Test: `extensions/kvwebui/test/web/language-theme.test.ts`

### M2.2-H8 — Arabic renders right to left (Playwright)
- **Given** a real kvman with kvwebui bundled, the fixture extension by `path:`, and `kernel.language` `ar`
- **When** Chromium opens the printed URL
- **Then** `<html dir="rtl">`; the nav sits on the right edge of the window and the panel strip on the left; the first nav item's text is Arabic; the URL has no `?workspace=`
- Test: `extensions/kvwebui/test/e2e/frame.test.ts`

### M2.2-H9 — Markdown can't inject HTML
- **Given** a `markdown` view whose translated text, and a `markdown { query, input, field }` whose data, contain `<img src=x onerror=alert(1)>`, `<script>`, a `javascript:` link, and `**bold**`
- **When** they render
- **Then** the HTML shows as text, no `img`, `script`, or `javascript:` link is in the DOM, and `bold` is a `<strong>`
- Test: `extensions/kvwebui/test/web/markdown.test.ts`

### M2.2-H10 — a sync-only command can't be queued, and kvai saves and removes a key without it reaching a job row
- **Given** kvai in a test kernel
- **When** `kvai.provider.key.set { provider: 'anthropic', key: 'sk-ant-1' }` runs sync, then with `execAsync`, then `kvai.provider.key.delete { provider: 'anthropic' }`
- **Then** the first sets kvai's secret `anthropic.apiKey` and `kvai.provider.get { id: 'anthropic' }` shows `status: 'ready'`; the second fails `VALIDATION_FAILED` and no job row or log line holds `sk-ant-1`; after the delete the status is `needsKey`
- Test: `extensions/kvai/test/provider-keys.test.ts`

## Edge cases

### M2.2-E1 — invalid `ui.get` answers contribute nothing
- **Given** one extension per rule: an unknown component; a table on a query that isn't public; a table on an unknown query; a nav item on a page with params; a nav item on a page it doesn't have; a repeated page id; a repeated status id; the icon `not-an-icon`; a form on a command that isn't public; a `$param` its page doesn't declare; a shape zod refuses (a nav item without `order`)
- **When** the app loads
- **Then** each is listed in the error card with `VALIDATION_FAILED` and contributes no page, nav item, panel, or status item
- Test: `extensions/kvwebui/test/web/contributions.test.ts`

### M2.2-E2 — the kernel's own queries and commands count as public
- **Given** a page with a table on `kernel.files.list` and a form on `kernel.workspace.open`
- **When** the app loads
- **Then** the answer is valid, and the form's field comes from the kernel's own input schema (`path`)
- Test: `extensions/kvwebui/test/web/contributions.test.ts`

### M2.2-E3 — routes, unknown pages, and links to missing pages
- **Given** `notes` with pages `list` and `note` (`params: ['noteId']`)
- **When** the app opens `/notes/note/n3`, `/notes/nope`, `/elsewhere/x/y`, and follows a `link` to `notes.gone`
- **Then** the first renders with `noteId` `n3`; the others show the "page not found" card inside the frame
- Test: `extensions/kvwebui/test/web/routes.test.ts`

### M2.2-E4 — status items rerun, show `$output`, and mark failures; the health item goes offline
- **Given** a status item on `notes.count.get`, and fake timers
- **When** the app loads; a command runs; 30 s pass; the query starts failing `notes/DOWN`; `kernel.health.get` starts failing
- **Then** the item shows the count; the query is called again after the command and after 30 s; a failure shows the error mark with the translated Problem as its tooltip; the health item shows a red "offline", and turns back to the version when health answers again
- Test: `extensions/kvwebui/test/web/status.test.ts`

### M2.2-E5 — the workspace picker, reloads, new tabs, and closed workspaces
- **Given** Home, `w1` (`project`, `/work/project`), and `w2`
- **When**:
  - the picker opens;
  - "Open a folder…" is submitted with `/work/other`, which `kernel.workspace.open` answers with `w3`;
  - the app remounts with the same `sessionStorage`;
  - it mounts with an empty `sessionStorage`, then with `?workspace=gone`;
  - `w3` is closed with its × in the picker;
  - a query answers `NOT_FOUND { workspaceId: 'w2' }` while the tab is on `w2`
- **Then**:
  - the picker lists "Home" (without ×), `project` with `/work/project`, and `w2`, each with a ×;
  - the tab moves to `w3`;
  - it comes back in `w3`;
  - the new tab starts in `w3` (from `localStorage`), and `gone` falls back to Home;
  - closing sends `kernel.workspace.close { workspaceId: 'w3' }` and moves the tab to Home;
  - the tab moves to Home with a toast naming the workspace
- Test: `extensions/kvwebui/test/web/workspaces.test.ts`

### M2.2-E6 — panels: one at a time, remembered per tab, on every page

- **Then** only the second is open, it stays open across the route change, and it's open after the remount; clicking its icon again closes it
- Test: `extensions/kvwebui/test/web/workspaces.test.ts`

### M2.2-E9 — tables: formats, badges, links, search, "Show more", empty, loading, and failures
- **Given** tables whose rows have numbers, ISO dates, byte counts, booleans, `null`, objects, a `secondary` field, and `badges` on a status field; a `rowLink` to `notes.note` with `{ noteId: { $row: 'id' } }`; a query with 42 rows; an empty query with and without `empty`; a slow query; and a query that fails `notes/DOWN`
- **When** they render in `en`
- **Then**:
  - `1234567` shows `1,234,567`, the date in medium date and short time, `1536` shows `1.5 KB`, `true` a check mark and `false` a dash (with "Yes" and "No" for screen readers), `null` a dash, and an object its JSON;
  - the secondary field shows under the first;
  - a mapped status shows its translated badge;
  - clicking a row, or Enter on it, opens `/notes/note/<id>`;
  - the 42-row table shows a search box and 10 rows, "Show more" shows 35, and typing in the search keeps only matching rows;
  - the empty tables show their `empty` text or `kvwebui.empty`;
  - the slow one shows placeholder rows until it answers;
  - the failing one shows an error card with "Try again", which calls the query again
- Test: `extensions/kvwebui/test/web/tables.test.ts`

### M2.2-E10 — buttons, confirmations, toasts, and reruns
- **Given** a row-action button with `confirm` and `input: { id: { $row: 'id' } }`, a button with `then: { toast: 'notes.done' }`, and a button whose command fails `notes/LOCKED { name }`
- **When** the first is clicked and cancelled, clicked and confirmed; the second is clicked; the third is clicked; and time passes
- **Then** cancelling sends nothing, and confirming sends the row's id and reruns every query on the page; the second shows a success toast that closes after 5 s; the third shows an error toast with `notes.errors.LOCKED` filled with `name`, which stays until closed
- Test: `extensions/kvwebui/test/web/actions.test.ts`

### M2.2-E11 — forms: fixed values, references, unions, clearing, and `then`
- **Given** a form on page `note` with `fixed: { noteId: { $param: 'noteId' } }`, and a form on a command whose input is an `anyOf` of `{ id, api, baseUrl }` and `{ id, delegate }`
- **When** the first is submitted, and the second is filled and submitted
- **Then** the first sends the route's `noteId` with the typed fields and then clears; the second shows `id`, `api`, `baseUrl`, and `delegate`, with only `id` required, and sends only the filled fields
- Test: `extensions/kvwebui/test/web/forms.test.ts`

### M2.2-E12 — the Settings page: groups, titles, scopes, sources, reset, and secrets
- **Given** settings from `kernel`, `notes` (with `notes.title` and a `notes.pageSize.title`), and a preset-only key; a key with `scopes: ['global']`; a key set for the workspace; and the secret `notes`/`token`
- **When** the Settings page renders, a value is changed and saved for "This workspace", a workspace value is reset, a secret is added, and one is deleted
- **Then**:
  - the groups are kvman's first, then `notes` with its title;
  - each key shows its title (or the key), description, key, control, and source badge;
  - the global-only key offers no "This workspace";
  - the preset-only key is locked;
  - saving sends `kernel.settings.set` with `scope: 'workspace'`, and reset sends `kernel.settings.reset`;
  - the secret shows masked, adding sends `kernel.secrets.set` from a password field, and delete asks first, then sends `kernel.secrets.delete`;
  - no secret value appears in the DOM
- Test: `extensions/kvwebui/test/web/settings-page.test.ts`
