# M4.1 — Framing and new windows in a frame: test cases

Read: `04` §4.2; `06` §6.2, §6.4; `08` §8.7 (the MCP sign-in); `03` (the web types); `15` §15.4; ADR 0099, 2, 9, 32, and 33.

The listener's policy is tested against a real kvman child (the HTTP layer) and in Chromium (Playwright, with routing for the foreign origin, so no network). kvwebui's handoff is tested in `happy-dom` against the fake API; kvcoder's sign-in against its fake `kvman`.

## Happy path

### M4.1-H1 — every answer carries the framing policy
- **Given** a kvman child with the app preset and a stored file
- **When** a JSON answer (`/api/locales/en`), a page (`/`), a static file (`/web/app/nested/page.js`), a file download, a 404 (`/web/app/missing.js`), and a `FORBIDDEN_ORIGIN` answer (Host `evil.com`) are requested
- **Then** each has `Content-Security-Policy: frame-ancestors 'self' http://127.0.0.1:* http://localhost:* vscode-webview: vscode-file:`
- Test: `packages/cli/test/http/framing.test.ts`

### M4.1-H2 — a website can't frame kvman, and a local page can
- **Given** a running kvman with kvwebui, a page at `https://example.test/` served by Playwright's routing, and a page on another port of `127.0.0.1`, each holding an `<iframe>` of kvman's address
- **When** each page is opened in Chromium
- **Then** Chromium refuses the frame of `https://example.test/` with a `frame-ancestors` message, and the local page's frame shows kvwebui's nav
- Test: `extensions/kvwebui/test/e2e/framing.test.ts`

### M4.1-H3 — `?open=parent` is taken once and kept for the tab
- **Given** the fake API
- **When** the app opens at `/?workspace=w1&open=parent`, then mounts again at `/` in the same tab
- **Then** the URL becomes `/`, `sessionStorage` holds `kvwebui.openParent` as `parent`, and the second mount still hands over (H4's click posts)
- Test: `extensions/kvwebui/test/web/new-windows.test.ts`

### M4.1-H4 — while handing over, a new-window link is posted to the parent
- **Given** the app opened with `?open=parent` and a custom component with a `target="_blank"` link to `https://example.com/a` holding a `<span>`
- **When** the span is clicked, and the link is middle-clicked
- **Then** each posts `{ kind: 'kvman.open', url: 'https://example.com/a' }` to `window.parent` with target origin `*`, the click's default is prevented, and `window.open` is never called
- Test: `extensions/kvwebui/test/web/new-windows.test.ts`

### M4.1-H5 — `kvman.open` posts while handing over, and opens a tab otherwise
- **Given** a custom component that calls `kvman.open('https://example.com/b')`
- **When** it runs in an app opened with `?open=parent`, and in one opened without it, once with `window.open` answering a tab and once answering `null`
- **Then** with handoff it posts the message and returns `'opened'`, and opens nothing; without it, `window.open` is called with the address and `_blank`, the tab's `opener` is set to `null`, and it returns `'opened'`, or `'blocked'` for `null`
- Test: `extensions/kvwebui/test/web/new-windows.test.ts`

### M4.1-H6 — kvcoder's Sign in opens its address through `kvman.open`
- **Given** kvcoder's MCP servers dialog with a server that needs a sign-in
- **When** "Sign in" is pressed, with `kvman.open` answering `'opened'`, and once `'blocked'`
- **Then** `kvman.open` gets the sign-in address; a `'blocked'` answer shows the "blocked" warning toast
- Test: `extensions/kvcoder/test/web/mcp-sign-in.test.ts` (QA30-H8, QA30-E11, now through `kvman.open`)

## Edge cases

### M4.1-E1 — a link of another scheme, or without `target="_blank"`, posts nothing
- **Given** the app opened with `?open=parent` and links to `mailto:a@b.c` and `file:///etc/hosts` with `target="_blank"`, and a link to `https://example.com/c` without a target
- **When** each is clicked
- **Then** nothing is posted, and no click's default is prevented by kvwebui
- Test: `extensions/kvwebui/test/web/new-windows.test.ts`

### M4.1-E2 — without `?open=parent`, links and `kvman.open` behave as before
- **Given** the app opened at `/` with no `kvwebui.openParent` in the tab
- **When** the `https://example.com/a` link is clicked
- **Then** nothing is posted and the click's default isn't prevented
- Test: `extensions/kvwebui/test/web/new-windows.test.ts`

### M4.1-E3 — another `open` value is not handoff
- **Given** the fake API
- **When** the app opens at `/?open=tab`
- **Then** nothing is stored, the link of H4 posts nothing, and the parameter stays in the URL
- Test: `extensions/kvwebui/test/web/new-windows.test.ts`

### M4.1-E4 — the catch ends with the app
- **Given** an app opened with `?open=parent`, then unmounted
- **When** the H4 link, added to the document, is clicked
- **Then** nothing is posted
- Test: `extensions/kvwebui/test/web/new-windows.test.ts`

### M4.1-E5 — a page hands over only with the policy's ancestors
- **Given** the framing policy (H1)
- **When** it is read
- **Then** it names no `https:` or `*` source of its own, so a website can never be an ancestor
- Test: `packages/cli/test/http/framing.test.ts`
