# QA 50 — The panel: one title with a list, updates that show themselves, a width the person drags, and a thinking list that opens upward (ADR 0071)

Asked, with two pictures of the running app: "the execution map preview and the artifacts user experience is bad … I need no horizontal scroll", "when updating artifact then it must auto shown and on updating execution map it must be auto show as well", and "the thinking levels are hidden when opened from chat box". Asked about a wide map stage, the owner kept its sideways scroll and added "allow user to resize the panel".

Every scenario is in `extensions/kvcoder/test/`.

## Happy path

- **QA50-H1 Several things to show are one title with a list.** *Given* a chat with a map and the artifacts `plan` and `report`, with the panel on `plan`, *then* the header has one button with the title of `plan` and no row of titles; *when* it is pressed, *then* a list shows `Execution map`, then the two titles in the list's order, with `aria-selected` on `plan` only; *when* `report` is pressed, *then* the panel shows `report` and the list is closed; *when* the map's entry is picked, *then* the panel shows the map. `web/artifact-picker.test.ts`
- **QA50-H2 The list is picked with the keyboard.** *Given* the open list of H1, *when* Down then Enter are pressed, *then* the entry after the shown one is shown; *when* the list is opened again and Escape is pressed, *then* it closes and nothing changes. `web/artifact-picker.test.ts`
- **QA50-H3 An updated artifact shows itself.** *Given* an open chat with `plan` (version 1) and `report`, the panel closed by the person, *when* a later read gives `plan` version 2, *then* the panel is open on `plan` with the new text; *and given* the panel then on `report`, *when* a later read gives `plan` version 3, *then* the panel shows `plan`. `web/artifact-panel.test.ts` (QA6-E13, changed)
- **QA50-H4 An updated map shows itself.** *Given* an open chat with a map (version 1) and an artifact, the panel on the artifact, *when* a later read gives the map version 2, *then* the panel shows the map; *and given* the panel closed, *when* a later read gives version 3, *then* it is open on the map. `web/execution-map-panel.test.ts`
- **QA50-H5 The later update of a map and an artifact is shown.** *Given* reads in which both changed, *then* the panel shows the map when its `updatedAt` is the later one and the artifact when the artifact's is, whichever read answers first. `web/execution-map-panel.test.ts`
- **QA50-H6 The thinking level is a list that opens upward.** *Given* a chat's send box at the bottom of the window, *when* the thinking button is pressed, *then* the five levels `Off`, `Minimal`, `Low`, `Medium`, `High` are all inside the window, above the button, with a check on the chat's level; *when* `High` is pressed, *then* `kvcoder.session.configure` runs with `{ thinking: 'high' }`, the list closes, and the button reads `High`. `e2e/thinking-picker.test.ts`
- **QA50-H7 The thinking list on the Chat page's start.** *Given* the start with no chat, *when* `Low` is picked from the thinking list and a message is sent, *then* the chat is configured with `thinking: 'low'`. `web/chat-start.test.ts` (the existing scenarios that set the level, changed to the list)
- **QA50-H8 Dragging the handle sets the panel's width, and it is kept.** *Given* a chat area 1200 px wide with the panel open, *when* the handle is dragged until the panel is 600 px wide, *then* the panel is 600 px wide and `localStorage` has `kvcoder.panelWidth` `600`; *when* the page is opened again on another chat with an artifact, *then* its panel is 600 px wide; *and* the execution map's steps are fitted to the new width. `e2e/panel-width.test.ts`
- **QA50-H9 The handle works from the keyboard and returns to the start.** *Given* the focused handle of a panel 480 px wide in a left-to-right page, *when* Left is pressed, *then* the panel is 496 px wide, and Right makes it 480 px again; in a right-to-left page Right widens it; *when* the handle is double-clicked, *then* the stored width is removed and the panel is at its starting width. `web/panel-width.test.ts`

## Edge cases

- **QA50-E1 One thing to show has a plain title.** *Then* a chat with one artifact and no map, and a chat with a map and no artifact, show the title as text with no button and no list. `web/artifact-picker.test.ts`
- **QA50-E2 The header never scrolls sideways.** *Given* an Arabic chat with five artifacts with long titles, *then* the header's `scrollWidth` is its `clientWidth`, the title is on one line, the opened list is inside the panel, and each entry is on one line with its whole title as tooltip. `e2e/artifact-panel.test.ts` (QA48-H15, the row of titles, replaced)
- **QA50-E3 The first read opens nothing.** *Then* a chat opened with artifacts and a map keeps the panel closed, and a later read with nothing changed keeps it closed. `web/artifact-panel.test.ts`, `web/execution-map-panel.test.ts`
- **QA50-E4 An update keeps Source.** *Given* the panel on `plan` in Source, *when* `plan` is updated, *then* Source shows the new text. `web/artifact-view.test.ts`
- **QA50-E5 The width stays within its limits.** *Given* a chat area 1200 px wide, *then* a drag past either end stops at 320 px and at 840 px; a stored `2000` is shown as 840 px and a stored `10` as 320 px. `web/panel-width.test.ts`
- **QA50-E6 A stored width that isn't a whole number isn't used.** *Then* with `kvcoder.panelWidth` `abc`, `12.5`, or `-40`, the panel is at its starting width. `web/panel-width.test.ts`
- **QA50-E7 No handle where the panel lies over the conversation.** *Given* a chat area under 48 rem, *then* the handle isn't shown and the panel is as wide as before whatever is stored. `e2e/panel-width.test.ts`
