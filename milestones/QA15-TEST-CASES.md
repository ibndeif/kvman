# QA 15 — disconnecting a provider and signing in with a plan (ADR 0009, 226–237)

Asked: "The user should be able to disconnect a provider" and "connect the plans such as ChatGPT Plus and others (OAuth)". The product owner chose one Disconnect button, a sign-in for every pi-ai OAuth provider, a loopback listener with a pasted-value fallback, one credential per provider (the last connected wins), and a sign-in job that polls for the pasted answer.

pi-ai's real OAuth endpoints are never called: tests give the sign-in and the credential store a fake pi-ai provider (`createProvider` with a fake `auth.oauth`) through the function parameters that production fills with the built-in catalog. Tests that run in a kernel use the secrets and the real commands only.

## Happy path

- **QA15-H1 Disconnect clears a key.** *Given* `anthropic` with a key, *when* `kvai.provider.disconnect { provider: 'anthropic' }` runs, *then* the secret `anthropic.apiKey` is gone, `kvai.provider.get` says `status: 'needsKey'` and `connection: null`, and a custom provider's key is cleared the same way. (`extensions/kvai/test/disconnect.test.ts`)
- **QA15-H2 Disconnect clears a sign-in.** *Given* the secret `openai-codex.oauth` holds a credential, *when* `kvai.provider.disconnect` runs for it, *then* the secret is gone and the row says `needsKey`, `connection: null`. (`extensions/kvai/test/disconnect.test.ts`)
- **QA15-H3 Rows say how a provider is connected.** *Then* a provider with a key has `connection: 'apiKey'`, one with `<provider>.oauth` has `connection: 'oauth'` and `status: 'ready'`, one with neither `null`; `signIn` is `true` for exactly `anthropic`, `github-copilot`, `kimi-coding`, `meta`, `openai`, `openai-codex`, `openrouter`, `radius`, and `xai` and `false` for custom providers; `apiKey` is `false` for `openai-codex` and `true` for the other built-ins and custom providers; `kvai.model.default.get.ready` is `true` for a default model of a signed-in provider. (`extensions/kvai/test/provider-connection.test.ts`)
- **QA15-H4 Saving a key replaces a sign-in.** *Given* `anthropic.oauth` is set, *when* `kvai.provider.key.set` runs, *then* `anthropic.oauth` is gone, `anthropic.apiKey` is set, and `connection` is `'apiKey'`. (`extensions/kvai/test/provider-connection.test.ts`)
- **QA15-H5 A browser sign-in saves the credential.** *Given* a fake provider whose login notifies an `auth_url` and returns a credential, *when* the sign-in runs, *then* the chunk `{ type: 'auth_url', url }` is reported, the credential is saved as JSON in `<provider>.oauth`, `<provider>.apiKey` is deleted, and the job ends `{}`. (`extensions/kvai/test/signin/signin-run.test.ts`)
- **QA15-H6 A device-code sign-in streams the code.** *Given* a login that notifies a `device_code` and `progress` events, *then* the chunks `{ type: 'device_code', userCode, verificationUri, expiresInSeconds }` and `{ type: 'progress' }` (no message) are reported and the credential is saved. (`extensions/kvai/test/signin/signin-run.test.ts`)
- **QA15-H7 A prompt waits for its answer.** *Given* a login that prompts `select`, then `text`, then `manual_code`, *when* each chunk `{ type: 'prompt', kind, message, … }` is reported and `kvai.provider.signin.answer` runs, *then* the sign-in goes on with that answer, the document `signin/<provider>` holds `{ jobId, promptKind }` while it waits, the secret `<provider>.signinAnswer` is deleted when taken, and the document is deleted when the sign-in ends. (`extensions/kvai/test/signin/signin-prompts.test.ts`)
- **QA15-H8 A call uses the sign-in.** *Given* a signed-in provider with an unexpired credential, *when* a call resolves its target, *then* it is a model target with no `apiKey` in the stream options and pi-ai reads the credential from kvai's store; with an expiring one, pi-ai refreshes it and the new credential is stored in `<provider>.oauth`. (`extensions/kvai/test/signin/signin-target.test.ts`)
- **QA15-H9 The sign-in commands are in the kernel.** *Then* `kvai.provider.signin.start` has `retries: 0` and `timeoutMs: 300000`, `kvai.provider.signin.answer` is sync only, and `kvai.provider.disconnect`, `signin.start`, `signin.answer`, and `signin.cancel` are public. (`extensions/kvai/test/signin/signin-commands.test.ts`)
- **QA15-H10 The connection card follows the state.** *Given* the component with `providerId`, *then* a built-in provider with a key and a sign-in offer shows the key form, "Sign in with your plan", and Disconnect; a custom provider shows the key form and Remove provider and no sign-in; a provider that isn't connected shows no Disconnect. (`extensions/kvai/test/web/connection.test.ts`)
- **QA15-H11 The card runs a sign-in.** *Given* a started sign-in streaming `auth_url`, `device_code`, `prompt`, and `progress` chunks, *then* the card shows a link that opens the URL in a new tab (`rel="noopener noreferrer"`), the code with its address, a field or a choice for the prompt (sending it calls `kvai.provider.signin.answer`), and a "Working…" line; when the job ends it refreshes and shows a toast; Cancel calls `kvai.provider.signin.cancel`. (`extensions/kvai/test/web/connection-signin.test.ts`)
- **QA15-H12 Disconnect and Remove ask first.** *Then* Disconnect shows an inline confirmation and calls `kvai.provider.disconnect` only when confirmed, and Remove provider (custom only) the same with `kvai.provider.remove`, then navigates to `kvai.models`; backing out calls nothing. (`extensions/kvai/test/web/connection.test.ts`)
- **QA15-H13 The page and its texts exist in both languages.** *Then* the provider page's view tree holds the `kvai.connection` custom component with `providerId`, the component source exists, `web-build.config.ts` lists `connection`, the manifest has `kvman.web`, and every new key has `en` and `ar` text. (`extensions/kvai/test/ui.test.ts`, `extensions/kvai/test/locales.test.ts`)

## Edge cases

- **QA15-E1 Unknown providers.** *Then* `disconnect`, `signin.start`, `signin.answer`, and `signin.cancel` for `nowhere` fail `kvai/PROVIDER_UNKNOWN { provider }`. (`extensions/kvai/test/signin/signin-commands.test.ts`)
- **QA15-E2 Disconnect is repeatable and narrow.** *Then* disconnecting a provider with neither does nothing, a second disconnect succeeds, `kvai.provider.key.delete` leaves a sign-in alone, and `kvai.defaultModel` is unchanged. (`extensions/kvai/test/disconnect.test.ts`)
- **QA15-E3 A sign-in-only provider takes no key.** *Then* `kvai.provider.key.set` for `openai-codex` fails `kvai/KEY_UNSUPPORTED { provider }` and writes nothing. (`extensions/kvai/test/provider-connection.test.ts`)
- **QA15-E4 No sign-in, no start.** *Then* `kvai.provider.signin.start` for a custom provider or a built-in with no OAuth (`google`) fails `kvai/SIGNIN_UNSUPPORTED { provider }`. (`extensions/kvai/test/signin/signin-commands.test.ts`)
- **QA15-E5 An answer needs a waiting sign-in.** *Then* `kvai.provider.signin.answer` with no sign-in waiting fails `kvai/SIGNIN_NOT_WAITING { provider }` and writes no secret. (`extensions/kvai/test/signin/signin-commands.test.ts`)
- **QA15-E6 An answer never reaches the database or the log.** *Given* an answer `https://localhost:1455/auth/callback?code=sekrit`, *then* `execAsync` of `signin.answer` fails `VALIDATION_FAILED`, and the value is in no job row, no store row, no stream chunk, and not in `kvman.log`. (`extensions/kvai/test/signin/signin-commands.test.ts`)
- **QA15-E7 Cancel ends a waiting sign-in.** *Given* a sign-in waiting at a prompt, *when* `kvai.provider.signin.cancel` runs, *then* the job ends `cancelled`, the document `signin/<provider>` and any answer secret are deleted, and a second cancel does nothing. (`extensions/kvai/test/signin/signin-prompts.test.ts`)
- **QA15-E8 A secret prompt fails.** *Given* a login that prompts `secret`, *then* the sign-in ends `kvai/SIGNIN_FAILED { provider, reason }`, and no credential is saved. (`extensions/kvai/test/signin/signin-run.test.ts`)
- **QA15-E9 A failed login says why and holds no token.** *Given* a login that throws an error whose text holds the answer the person pasted and the provider's old stored key, *then* `kvai/SIGNIN_FAILED` has `reason` cut to 1 000 characters with both replaced by `[secret]`, nothing is saved, and the old key is kept. (`extensions/kvai/test/signin/signin-run.test.ts`)
- **QA15-E10 The listener stays on loopback.** *Given* `PI_OAUTH_CALLBACK_HOST` is `0.0.0.0` or `192.168.1.5`, *then* the sign-in fails `kvai/SIGNIN_FAILED { reason: 'callback host' }` before pi-ai's login is called; `127.0.0.1`, `localhost`, `::1`, and unset proceed. (`extensions/kvai/test/signin/signin-run.test.ts`)
- **QA15-E11 The device id is made once.** *Then* the first sign-in that asks for the device id stores a UUID under `deviceId` in the global store, and every later ask gives the same one. (`extensions/kvai/test/signin/signin-run.test.ts`)
- **QA15-E12 A newer sign-in owns the document.** *Given* two sign-ins for one provider, *then* the document holds the newer job's id, and the older job's cleanup leaves it. (`extensions/kvai/test/signin/signin-prompts.test.ts`)
- **QA15-E13 A rejected refresh fails `kvai/SIGNIN_EXPIRED`.** *Given* a credential whose refresh the fake provider rejects (`invalid_grant`), *then* the call fails `kvai/SIGNIN_EXPIRED { provider }`, and the stored credential is kept; a refresh that fails with `fetch failed` fails `kvai/PROVIDER_ERROR` with `transient: true`. A stored `<provider>.oauth` that isn't valid credential JSON fails the same way, and its row says `oauth`. (`extensions/kvai/test/signin/signin-target.test.ts`)
- **QA15-E14 Tokens never leak from a call.** *Given* a signed-in provider whose request fails with a reason holding its access token and its refresh token, *then* the `kvai/PROVIDER_ERROR` reason shows `[secret]` for both. (`extensions/kvai/test/signin/signin-target.test.ts`)
- **QA15-E15 Refreshes take turns.** *Given* two refreshes of one provider at once, *then* the second waits for the first, reads the credential the first wrote, and does not refresh again; an expired lease is taken over; a wait past 35 s fails as a transient `kvai/PROVIDER_ERROR`; a cancel ends the wait; the lease is released when the write ends, also on failure. Time is a fake clock. (`extensions/kvai/test/signin/credential-store.test.ts`)
- **QA15-E16 The credential store is exact.** *Then* `read` gives `undefined` for a missing secret and the credential for a saved one; `list` names, among the providers it looks through, those that have one (never a secret); `delete` removes it and a missing one does nothing; `modify` returns the credential it saved. (`extensions/kvai/test/signin/credential-store.test.ts`)
- **QA15-E17 No environment, no files.** *Then* the catalog's auth context returns no environment variable and no file for any name, so a call never uses `ANTHROPIC_API_KEY` or an ambient credential. (`extensions/kvai/test/signin/signin-target.test.ts`)
- **QA15-E18 The card shows a failed sign-in.** *Given* the job ends with `kvai/SIGNIN_FAILED`, `kvai/SIGNIN_UNSUPPORTED`, or a network error, *then* the card shows the translated error text, the buttons come back, and the badge doesn't change; a prompt answer that fails shows its error and keeps the field. (`extensions/kvai/test/web/connection-signin.test.ts`)
- **QA15-E19 The card hides what doesn't apply.** *Then* `openai-codex` shows no key form, a built-in provider has no Remove provider, and a connected provider shows its connection (key or plan) in the badge. The "may go against the provider's terms" note shows with "Sign in with your plan". (`extensions/kvai/test/web/connection.test.ts`)
- **QA15-E20 The card is right to left in Arabic.** *Then* its styles use logical properties only. (`extensions/kvai/test/web/connection.test.ts`)
- **QA15-E21 A failed Disconnect, Remove, or Cancel shows its error.** *Given* `kvai.provider.disconnect` fails with a Problem, or `kvai.provider.remove` with an error that isn't one, *then* the card shows the Problem's translated text or "Something went wrong. Try again.", shows no toast, does not navigate, and the connection stays as it was; a failed `signin.cancel` is shown the same way. (`extensions/kvai/test/web/connection.test.ts`)
