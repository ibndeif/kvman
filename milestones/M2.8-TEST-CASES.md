# M2.8 — Presets lifecycle and preview workspaces: test cases

Read:

- `07` §7.1 (preview workspaces), §7.3–§7.4, §7.6.
- The parts they cite:
  - `03` §3.8: the preset and workspace types, grant-command rules, and preview tokens;
  - `03` §3.9: first-run and upgrade seeding;
  - `04` §4.1 (the `presets` and `workspace_presets` tables), §4.4 (forget), §4.7 (config rows);
  - `06` §6.3 (referential checks), §6.4 (enable and its preview-workspace rules), §6.6 (reload, used for version switches), §6.9;
  - `07` §7.2 (the trust gate, for the repo preset), §7.5;
  - `13` §13.2 (the `PRESET_*` codes, `CONFIRMATION_EXPIRED`);
  - `14` §14.3: the fault points `preset.apply.after-stage` and `preset.apply.after-version-switch`, and invariants 1–4.
- ADRs 0017, 0019, 0089, 0110, 0115, 0118, 0123–0125, 0137, 0145, and 0146–0151.

Earlier tests that M2.8 changes:

- **M2.1-E27** (`packages/testkit/test/schema/validate.test.ts`): `kernel.validate { manifest, workspaceId }` is now answered (ADR 0151); only `catalog` is still refused.
- **M2.1-E42** (`packages/testkit/test/schema/schema-endpoint.test.ts`): `?q=add` also finds `kernel.preset.import` ("Adds a previewed preset…"), ranked after the name matches.
- **M2.3-E4** (`packages/testkit/test/workspaces/open.test.ts`) and **M2.3-E52** (`packages/protocol/test/workspace-config.test.ts`): `kernel.workspace.get` also answers `repoPreset: false` (ADR 0150).
- `kernel.extension.enable` and `kernel.workspace.forget` now register access `all`, and their handlers refuse every caller but a person, or an extension with `kernel.admin` in a preview workspace (ADR 0150). So these tests expect the command to be admitted and to fail `CALLER_NOT_ALLOWED`, where they expected admission to refuse it:
  - **M2.3-E5** (`packages/testkit/test/workspaces/open.test.ts`): forget from an extension;
  - **M2.3-E18** (`packages/testkit/test/workspaces/enable.test.ts`): enable from Steward in a normal workspace;
  - **M2.4-E29** (`packages/testkit/test/capabilities/surfaces.test.ts`): enable from a job token.

Where the tests live:

- **Pure pieces**, in `packages/kernel/test/presets/`: save-as ids, the JSON Merge Patch, and import tokens.
- **Protocol shapes**, in `packages/protocol/test/presets.test.ts`.
- **Packing**, in `packages/testkit/test/install/pack-builtins.test.ts`.
- **Through a runtime**, in `packages/testkit/test/presets/`. The runtime has:
  - a temporary home folder;
  - the local npm registry of the install tests (`KVMAN_NPM_REGISTRY`);
  - packed builtin fixtures and a fixture presets folder;
  - the fake clock of the test.
- **Boot and crash points**, on in-process boots and child kernels:
  - `packages/testkit/test/presets/seeding.test.ts`;
  - `packages/testkit/test/faults/presets.test.ts`.

Terms used in the scenarios:

- "**Person**" is `user:local`, who is an administrator.
- "**Steward**" is the workspace tests' `@acme/steward`, holding `kernel.admin`. "**Caller**" is `@acme/caller`, without it. Each has a command that sends a kernel command or query and reports its result or problem code.
- **Builtins.** "**First**" and "**Second**" are the builtin fixtures `@acme/first` and `@acme/second`, packed as `pnpm build` packs `extensions/*`. First requests `shared` isolation, subscribes to Pdf's event `pdf.files.changed` (a derived capability), and has the command `first.ping`; Second has config `{ note?: string }`. Builtins run `shared` only (ADR 0128). Their integrity is `builtin:<kvman version>`, which the scenarios call `builtin:<current>`.
- **npm packages.** "**Pdf**" is `@acme/pdf` (namespace `pdf`), published to the local registry in versions:
  - `0.9.0`, with data version 1;
  - `1.0.0`, with data version 2 (step 2 migrates), requesting `files.read`;
  - `1.1.0`, with data version 2, requesting `files.read` and `llm`.

  Every version has the query `pdf.files.list` and a config schema `{ lang?: string, limit?: number ≤ 10, apiKey?: secret }`.
- "**Stash**" is `@acme/stash` (namespace `stash`), published as `1.0.0` (data version 1) and `2.0.0` (data version 2, whose step 2 throws), so enabling 2.0.0 on data at version 1 fails at its first step.
- "**Reader**" is `@acme/reader` (namespace `reader`), published as `1.0.0`, whose `requireTypes` names `pdf.files.list`. "**Clash**" is `@acme/clash`, published with namespace `pdf`.
- "**Dev**" is `@acme/devtool` (namespace `devtool`, requests nothing) and "**Devproc**" is `@acme/devproc` (namespace `devproc`, requests `process`), each a `dev:` source installed through the dev folder pipeline (ADR 0116).
- **Workspace folders** are temporary folders `A`, `B`, and `C`. The home folder is a temporary folder, never the real `~/.kvman` or `~/kvman`.
- "**Preset P**" is a shareable preset with id `pdf-app` that enables Pdf `1.0.0` with its exact grants, has one page `preset.help` on `/help`, and hides `settings.nav-general` and `pdf.debug`.
