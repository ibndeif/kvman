# QA 22 — the configuration pages after their first use (ADR 0015)

Asked: the default model is chosen from a searchable dropdown like the chat's, on every page; the Interface page has no Navigation or App section; binary connectors are in the one connectors list. Decided in ADR 0015; plan 06 §6.6, plan 07 §7.3, plan 08 §8.7. This file is the contract; every scenario's test name starts with its id.

## Happy path

- **QA22-H1 The Interface page has one section.** *Then* `/kvwebui/extension/kvwebui` shows the card "Appearance" with the row `kvwebui.theme`, and no row for `kvwebui.nav.order`, `kvwebui.nav.hidden`, `kvwebui.title`, or `kvwebui.home`. `extensions/kvwebui/test/web/extension-page.test.ts`
- **QA22-H2 The connectors are one list.** *Given* a registered `todo` and a program `gh`, *then* the list shows kvcoder's six, `todo`, and `gh`, each with a name, a description, and a switch, and no row says where it comes from. `extensions/kvcoder/test/web/connectors-list.test.ts`
- **QA22-H3 The configurations name the model components.** *Then* kvcoder's Agent card starts with the component `kvcoder.model`, its Connectors card holds the intro and the component `kvcoder.connectors` only, and no card has the settings `kvcoder.model` or `kvcoder.connectors`; kvai's card holds the component `kvai.default-model` and the link to its Models page, and kvwebui's checks accept it. `extensions/kvcoder/test/ui.test.ts`, `extensions/kvwebui/test/kvai-ui.test.ts`
- **QA22-H4 Coder's model is picked from the dropdown.** *Given* `kvcoder.model` `null` and the default model "GPT-6 Luna", *then* the row shows its title and description and the button "Default model (GPT-6 Luna)"; *when* the person opens it, *then* the first entry is "Use the default model", selected, above the provider groups; *when* they pick "Z1", *then* `kernel.settings.set { key: 'kvcoder.model', value: 'zed/z1', scope: 'global' }` runs, the button shows "Z1", and the row shows "Changed" with "Reset". `extensions/kvcoder/test/web/model-setting.test.ts`
- **QA22-H5 "Use the default model" stores null in the page's scope.** *Given* `kvcoder.model` `zed/z1` globally and `kvman.scope` `workspace`, *when* the person picks "Use the default model", *then* `kernel.settings.set { key: 'kvcoder.model', value: null, scope: 'workspace' }` runs, the row shows "Changed for notes-app", and its reset runs `kernel.settings.reset { key: 'kvcoder.model', scope: 'workspace' }`. `extensions/kvcoder/test/web/model-setting.test.ts`
- **QA22-H6 kvai's default model is picked from the dropdown.** *Given* the default "GPT-6 Luna" and callable providers, *then* the row shows "Default model", its description, and a button "GPT-6 Luna"; *when* the person opens it and picks "GPT-6 Nova" on "Only notes-app", *then* `kernel.settings.set { key: 'kvai.defaultModel', value: 'openai/gpt-6-nova', scope: 'workspace' }` runs, "The default model is set." is toasted, the popover closes, and the row shows "Changed for notes-app" with a reset that runs `kernel.settings.reset`. `extensions/kvai/test/web/default-model-setting.test.ts`
- **QA22-H7 kvai's picker behaves like the chat's.** *Given* three callable models and the default `openai/gpt-6-luna`, *when* the popover opens, *then* the default's option is selected and highlighted, shows its name and no id, and the line says "3 of 3 models"; typing "6 nova" leaves "GPT-6 Nova" and "1 of 3 models"; Up from the first option highlights the last, and Down from the last the first; Enter picks the highlighted one. `extensions/kvai/test/web/model-picker.test.ts`
- **QA22-H8 In the real app.** *Given* kvman in Chromium with the `coder` preset, *then* Coder's page has the model row with its dropdown button and no row `kvcoder.connectors`; AI's page has the default-model row with its button; and Interface's page has `kvwebui.theme` and no `kvwebui.nav.order`. `extensions/kvcoder/test/e2e/configuration.test.ts`

## Edge cases

- **QA22-E1 A search hides "Use the default model".** *When* the person types in the search box, *then* the entry isn't listed, and it is back when the box is empty; the chat header's picker never has it. `extensions/kvcoder/test/web/model-setting.test.ts`
- **QA22-E2 A workspace's own model can't be changed from "All workspaces".** *Given* `kvcoder.model` from the workspace and `kvman.scope` `global`, *then* the button is disabled and `model-own-value` names the workspace; on "Only notes-app" it is enabled. `extensions/kvcoder/test/web/model-setting.test.ts`
- **QA22-E3 A rejected change says so.** *Given* `kernel.settings.set` fails, *then* kvcoder's row toasts the Problem and keeps its label; kvai's popover stays open with the reason and nothing is toasted. `extensions/kvcoder/test/web/model-setting.test.ts`, `extensions/kvai/test/web/default-model-setting.test.ts`
- **QA22-E4 kvai's row on "All workspaces" with a workspace value.** *Then* its button is disabled and `default-own-value` names the workspace. `extensions/kvai/test/web/default-model-setting.test.ts`
- **QA22-E5 No default model.** *Given* `kvai.defaultModel` `null`, *then* kvai's button says "Choose a model", and Coder's says "Default model". `extensions/kvai/test/web/default-model-setting.test.ts`, `extensions/kvcoder/test/web/model-setting.test.ts`
- **QA22-E6 kvai's picker has no cap.** *Given* 150 callable models, *then* 150 options show, "150 of 150 models", and no hint to narrow. `extensions/kvai/test/web/model-picker.test.ts`
- **QA22-E7 No raw keys.** *Then* both rows, open and closed, show no catalog key in English or Arabic. `extensions/kvcoder/test/web/model-setting.test.ts`, `extensions/kvai/test/web/default-model-setting.test.ts`
