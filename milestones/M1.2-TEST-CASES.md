# M1.2 — Store API and step journal: test cases

Read: `04` §4.3–§4.5; ADRs 0008 (filter semantics), 0031 (writes and versions), 0036 (ordering), 0037 (merge patch), 0038 (indexed find), 0039 (size errors), 0040 (no workspace).

The store's types are the SDK's public `Store` interface (`packages/sdk`); the kernel implements it for the handler runtime. Until hosts exist (M1.6) the tests create a store in-process with a read-only connection to a real database and commit its pending writes through the M1.1 pipeline. Collection schemas are checked by the host with Zod; here a store receives a document validator. Tests live in `packages/kernel/test/store/`.

## Happy path

### M1.2-H1 — every method has the return type of `04` §4.3
- **Given** a store for an extension with a collection `files` (index `[status, createdAt]`) and a log family `history:*`
- **When** every method of `kv`, `collection()`, `log()`, and `global` is called
- **Then** `kv.get` gives the value or `undefined`, `kv.list` an array of `{ key, value }` by key; `collection.get` a document or `undefined`, `put` and `delete` nothing, `patch` the new document, `find` an array of documents, `count` a number; `log.append` its seq, `read` an array of `{ seq, value }` oldest first, `last` `{ seq, value }` or `undefined`, `truncateBefore` and `drop` nothing; and `global` offers the same three in global scope
- Test: `packages/kernel/test/store/store-api.test.ts`

### M1.2-H2 — reads see the unit's own pending writes
- **Given** committed documents and kv entries, then pending puts, patches, and deletes in the same unit
- **When** `get`, `kv.get`, `kv.list`, `find` (with a filter, order, and limit), `count`, `log.read`, and `last` run
- **Then** each sees the pending writes applied on top of committed data, filtered, sorted, and limited again
- Test: `packages/kernel/test/store/read-your-writes.test.ts`

### M1.2-H3 — a read-then-write loses to a concurrent write and succeeds on the rerun
- **Given** two invocations that both read document `f1` at version 1, and the first commits a write
- **When** the second commits its write
- **Then** it fails `STORAGE_CONFLICT`; rerunning it (a new read, then the write) commits at version 3
- Test: `packages/kernel/test/store/versions.test.ts`

### M1.2-H4 — two appends in one unit get consecutive seqs
- **Given** a log whose last committed seq is 4
- **When** a unit appends twice
- **Then** the appends return 5 and 6 and commit with those seqs
- Test: `packages/kernel/test/store/logs.test.ts`

### M1.2-H5 — a find over the cap fails instead of truncating
- **Given** 5,001 matching documents
- **When** `find` runs without a limit
- **Then** it fails `STORE_RESULT_TOO_LARGE` with a hint to add a filter or a limit; with `limit: 50` it returns 50
- Test: `packages/kernel/test/store/caps.test.ts`

### M1.2-H6 — a step started but not recorded is indeterminate unless retry-safe
- **Given** a step row `started` for a message (a crash between begin and record)
- **When** the redelivered handler calls `ctx.step` with that name
- **Then** it throws `EFFECT_INDETERMINATE` without running the function; with `retrySafe: true` it runs the function and records the result
- Test: `packages/kernel/test/store/steps.test.ts`

### M1.2-H7 — a reused step name throws
- **Given** a handler run that has already called `ctx.step('extract', …)`
- **When** it calls `ctx.step('extract', …)` again
- **Then** it throws `STEP_DUPLICATE`
- Test: `packages/kernel/test/store/steps.test.ts`

## Edge cases

### Filters and ordering in SQL (ADRs 0008, 0036, 0038) — `packages/kernel/test/store/sql-filters.test.ts`

| Id | Given | Then |
|---|---|---|
| M1.2-E1 | the M0.2 filter table and its edge cases (missing and `null`, type mismatches, code points, `in` on arrays, dotted and numeric paths, nested `$or`) run as `find` over stored documents | SQL returns exactly the documents the protocol evaluator matches |
| M1.2-E2 | documents with missing, `null`, boolean, number, string, and object values of the order field, sorted ascending and descending, with ties | the order of ADR 0036, ties by id; the same order with and without pending writes |
| M1.2-E3 | field names with a hyphen, a space, and an underscore, and a field name containing `"` | the first three filter and sort; the last fails `VALIDATION_FAILED` |
| M1.2-E4 | declared indexes, on a collection with data and SQLite statistics (the weekly `PRAGMA optimize` of `04` §4.9 gathers them) | created as partial expression indexes on the collection's rows, and SQLite's planner uses them for an indexed `find` |
| M1.2-E5 | an unindexed `find` over more than 10,000 documents in scope, the same with fewer, and an indexed `find` over more | the first fails `STORE_RESULT_TOO_LARGE`; the second runs and warns once per query shape and hour; the third runs |

### Documents (ADRs 0037, 0040) — `packages/kernel/test/store/documents.test.ts`

| Id | Given | Then |
|---|---|---|
| M1.2-E6 | `patch` with a nested object, an array, and a `null` field | nested merge, the array replaced, the field removed; `patch` of a missing id fails `STORE_NOT_FOUND` |
| M1.2-E7 | a `put` or `patch` whose result fails the collection's schema, a document without a string id, and a collection with `idField: 'fileId'` | `VALIDATION_FAILED`, `VALIDATION_FAILED`, and ids read from `fileId` |
| M1.2-E8 | `collection('unknown')` and `log('audit:1')` without such registrations | `VALIDATION_FAILED` with a hint naming what is registered |
| M1.2-E9 | a store without a workspace | `kv`, `collection()`, and `log()` throw `WORKSPACE_INVALID`; `global` works; the pipeline rejects a workspace write from such an invocation with `WORKSPACE_INVALID` |
| M1.2-E10 | a query's store | reads work; every write method throws `CAPABILITY_DENIED` |
| M1.2-E11 | `find` with `limit: 0` or `2.5`, and with a malformed filter | `VALIDATION_FAILED` |

### Versions (ADR 0031) — `packages/kernel/test/store/versions.test.ts`

| Id | Given | Then |
|---|---|---|
| M1.2-E12 | a write after a read, a write without a read, and a put after a read that found nothing | the unit carries `expectedVersion` n, no `expectedVersion`, and `expectedVersion: 0`; the last conflicts if another unit inserted the key meanwhile |
| M1.2-E13 | several writes to one key in one unit, and entries read by `find` and `kv.list` | one write per key, carrying the version first read; entries read by `find` and `list` carry their versions too |

### Logs and sizes (ADR 0039) — `packages/kernel/test/store/logs.test.ts`, `packages/kernel/test/store/caps.test.ts`

| Id | Given | Then |
|---|---|---|
| M1.2-E14 | `read` with `after`, `before`, both, `last`, and `last` with `before`; `last()`; pending `truncateBefore` and `drop` | the matching entries oldest first; the newest entry; reads that apply the pending truncation and drop |
| M1.2-E15 | `kv.set` of a value over 1 MB | throws `PAYLOAD_TOO_LARGE` with `{ limit: 'kv-value', max: 1048576 }` at the call |
| M1.2-E16 | a `find` result over 16 MB, and `kv.list` and `log.read` over 5,000 entries | `STORE_RESULT_TOO_LARGE` |

### Steps (`04` §4.5, ADR 0039) — `packages/kernel/test/store/steps.test.ts`

| Id | Given | Then |
|---|---|---|
| M1.2-E17 | a step recorded as done, then the handler runs again | the recorded result is returned without running the function (including an `undefined` result) |
| M1.2-E18 | a step whose result is over 256 KB | throws `PAYLOAD_TOO_LARGE` with `{ limit: 'step-result', max: 262144 }`; the step stays `started`, so a rerun is indeterminate |
| M1.2-E19 | a step whose function throws | the error reaches the handler and the step stays `started` |
