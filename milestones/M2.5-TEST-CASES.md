# M2.5 — kvdev, presets, and the walkthrough: test cases

Read: `09` (all); `10` (the testkit, `kvman-check`); `11` (the presets); `12` §12.1 (the in-test registry), §12.3 (cold start and RSS); `02` §2.2 (workers), §2.9 (`path:` and hot reload), §2.16 (processes); `06` §6.3–6.4 (pages, custom components); `08` §8.4 (connectors, sections), §8.7 (the result card); ADR 0006; ADR 0009 (45, M2.5: 113–129).

Kinds of tests:
- **Kernel** (`extensions/kvdev/test/`): the testkit with kvai, kvwebui, kvcoder, and kvdev, and project folders written into the test kernel's Home folder. No npm.
- **Scaffold** (`extensions/kvdev/test/scaffold/`): the same kernel, plus the in-test registry (ADR 0009, 113). The project's global setup builds kvman's packages and packs them, with every package the scaffold installs, from the monorepo's installed copies; tests reach it through `npm_config_registry` and a temporary npm cache.
- **Unit** (`extensions/kvdev/test/unit/`): TypeScript output parsing, the output cut, the preview's preset and command line, the OS branches of running npm, the free-port search, the pins.
- **Testkit** (`packages/testkit/test/check/`): `kvman-check` on fixture extensions written to a temporary folder, in-process and as the bin.
- **End to end** (`extensions/kvdev/test/e2e/`): a real kvman child (from the CLI's source, bundled extensions built by the global setup) with the fake OpenAI server added over HTTP and the in-test registry in its environment; Chromium for the main and preview pages.
- **Benchmarks** (`bench/`): the built CLI with the bundled `coder` preset.

## Happy path

### M2.5-H1 — in the `dev` preset, the agent scaffolds an extension, tests it, lists it, finds a planted missing description, previews it, and an edit hot-reloads
- **Given** a kvman child started with `--preset dev`, its model set to the fake one, the in-test registry in its environment, and the fake model scripted: `ext new '{"name":"notes","namespace":"notes","folder":"notes"}'`; `ext test '{"folder":"notes"}'`; `ext list`; a shell call that deletes the description of `notes.greeting.get` from `notes/src/index.ts`; `ext check '{"folder":"notes"}'`; a shell call that restores it; `preview start '{"extensions":["notes"]}'`; then a final answer
- **When** the person sends "Build a notes extension" and approves each shell call (the dev preset sets `kvcoder.shell.approval: ask`)
- **Then** each step's request to the model holds the previous call's result: `ext new` returns `{ folder: "notes", name: "notes", namespace: "notes", web: false }`; `ext test` returns `passed: true`, exit code 0; `ext list` holds `{ folder: "notes", name: "notes", namespace: "notes", version: "0.1.0" }`; `ext check` returns a finding whose message names the missing description; `preview start` returns `{ url }` on port 3738 or above. Chromium opens `<url>notes/hello` and shows "Hello from notes!". The test then edits the greeting in `notes/src/index.ts`; after a reload the page shows the new greeting, and `notes/dist` doesn't exist (no build ran)
- Test: `extensions/kvdev/test/e2e/walkthrough.test.ts`

### M2.5-H2 — a `web: true` scaffold builds, its page shows the component in the preview, and a component edit shows after a refresh
- **Given** a kvman child in the `dev` preset with the in-test registry
- **When** `kvdev.ext.new { name: "cards", namespace: "cards", folder: "cards", web: true }` runs, then `npm run web:build` in it, then `kvdev.preview.start { extensions: ["cards"] }`
- **Then** `cards/dist/web/components/hello.js` and `hello.css` exist; `kernel.processes.list` shows `preview` and `web-1`; Chromium at `<url>cards/hello` shows the greeting and the Hello component's text; after the test changes the component's text in `web/components/Hello.vue`, `web:watch` rewrites `hello.js`, and a refresh shows the new text; `preview stop` ends `preview` and `web-1`
- Test: `extensions/kvdev/test/e2e/web-scaffold.test.ts`

### M2.5-H3 — `kvman` with no preset flag starts the `coder` preset
- **Given** a temporary home and start folder (passed as `--home`, `--port 0`, and `--no-open`, so the test touches neither `~/.kvman`, port 3737, nor a browser)
- **When** `kvman` runs with no `--preset`
- **Then** `kernel.health.get` reports `preset: "coder"`; `kernel.extensions.list` lists kvai, kvwebui, and kvcoder only; `kernel.settings.list` shows `kvwebui.title` `kvcoder.app.title`, `kvwebui.home` `kvcoder.chat`, and `kvai.defaultModel` `anthropic/claude-sonnet-5-5`, each with `source: "preset"`
- Test: `extensions/kvdev/test/e2e/presets.test.ts`

### M2.5-H4 — every benchmark meets its target
- **Given** the built CLI and the bundled `coder` preset (the RSS run adds `kernel.workers: 3`, ADR 0009, 115)
- **When** `pnpm bench:check` runs
- **Then** cold start to URL (the median of 5 runs, each with a new home) is ≤ 3 s, idle RSS (`VmRSS` 5 s after the URL, the median of 5) is ≤ 300 MB, the other five benchmarks still meet theirs, and none regresses more than 20% from the baseline
- Test: `bench/cold-start.ts`, `bench/idle-rss.ts`

## Edge cases

### `ext new`
- **M2.5-E1** The plain scaffold writes `package.json` (`main: "dist/index.js"`, `kvman: { namespace, source: "src/index.ts", dependencies: {} }`, `peerDependencies: { "@kvman/sdk": "^0.1.0" }`, devDependencies `typescript`, `@types/node`, `@kvman/sdk`, and `@kvman/testkit` at exact versions, and the scripts `build`, `check` (`kvman-check`), and `test`), `src/index.ts`, `locales/en.json` and `ar.json`, `test/extension.test.ts`, `tsconfig.json`, and `README.md`; runs `npm install`; returns `{ folder, name, namespace, web: false }`; an existing empty folder is accepted. — `extensions/kvdev/test/scaffold/ext-new.test.ts`
- **M2.5-E2** `web: true` adds `web/components/Hello.vue`, the per-component Vite build, `kvman.web: "dist/web"`, the scripts `web:build` and `web:watch`, `kvman.dependencies` still `{}` (ADR 0009, 128), devDependencies `vite`, `@vitejs/plugin-vue`, and `vue` at exact versions, and a `hello` page that shows the `<namespace>.hello` component. — `extensions/kvdev/test/scaffold/ext-new.test.ts`
- **M2.5-E3** A folder outside the workspace folder (`../x`, or an absolute path elsewhere) fails `VALIDATION_FAILED`; a folder that holds a file fails `kvdev/FOLDER_NOT_EMPTY`, and nothing is written. — `extensions/kvdev/test/ext-new-rules.test.ts`
- **M2.5-E4** A `name` that isn't an npm package name (`Notes`, `my notes`, `@/x`) or a `namespace` that breaks the kernel's rule (lowercase kebab case, `namespaceSchema`: `Notes`, `my_notes`; and `kernel`, which the kernel keeps for itself) fails `VALIDATION_FAILED`. — `extensions/kvdev/test/ext-new-rules.test.ts`
- **M2.5-E5** A failing `npm install` (a registry that refuses connections, `npm_config_fetch_retries=0`) fails `kvdev/NPM_FAILED` whose message holds the last lines of npm's output, and the written files stay. — `extensions/kvdev/test/ext-new-rules.test.ts`
- **M2.5-E6** `npm` missing from the PATH fails `kvdev/NPM_FAILED`. — `extensions/kvdev/test/npm-missing.test.ts`

### `ext list`, `ext check`, `ext test`
- **M2.5-E7** `ext list` finds the workspace folder itself (`.`) and nested projects, skips `node_modules` and dot-folders, doesn't look inside a project it found, and sorts by folder. — `extensions/kvdev/test/ext-list.test.ts`
- **M2.5-E8** `ext check` and `ext test` of a folder whose package.json has no `kvman` field (or that has no package.json) fail `kvdev/NOT_A_PROJECT`; outside the workspace folder, `VALIDATION_FAILED`. — `extensions/kvdev/test/ext-list.test.ts`
- **M2.5-E9** `ext check` of a fresh scaffold returns `[]`; a type error returns `{ file: "src/index.ts:<line>:<col>", message: "TS…", hint }` first, then the check's own findings (a missing locale key). — `extensions/kvdev/test/scaffold/ext-check.test.ts`
- **M2.5-E10** `ext test` of a fresh scaffold returns `{ passed: true, exitCode: 0, output }`; with a failing assertion, `{ passed: false, exitCode: 1 }` and the output names the test. — `extensions/kvdev/test/scaffold/ext-check.test.ts`
- **M2.5-E11** TypeScript's `--pretty false` lines become findings with `file:line:col`, a multi-line message keeps its continuation, and a line that isn't a diagnostic is ignored; a check output's last line is read as its JSON. — `extensions/kvdev/test/unit/findings.test.ts`
- **M2.5-E12** The output cut keeps the last 30 KB and marks the cut. — `extensions/kvdev/test/unit/findings.test.ts`
- **M2.5-E13** The scaffold's pins equal the monorepo's: `@kvman/sdk` and `@kvman/testkit` versions, root `typescript` and `@types/node`, and kvwebui's `vite`, `@vitejs/plugin-vue`, and `vue`. — `extensions/kvdev/test/unit/scaffold-versions.test.ts`
- **M2.5-E14** Job options: `kvdev.ext.new` 600 000 ms, `kvdev.ext.check` 300 000, `kvdev.ext.test` 600 000, `kvdev.preview.start` 300 000, every kvdev command `retries: 0`. — `extensions/kvdev/test/unit/job-options.test.ts`
- **M2.5-E15** Running npm: on Linux and macOS it spawns `npm` directly in its own process group and a cancel kills the group; on Windows it runs `cmd.exe /d /s /c npm …` and a cancel runs `taskkill /PID <pid> /T /F`. — `extensions/kvdev/test/unit/run-program.test.ts`

### `kvman-check` (the testkit)
- **M2.5-E16** A clean extension gives no findings and exit 0; the readable output says so. — `packages/testkit/test/check/check.test.ts`
- **M2.5-E17** A registration with no description, or a name outside the namespace, gives one finding from the failed load (its `EXTENSION_INVALID` message) and exit 1. — `packages/testkit/test/check/check.test.ts`
- **M2.5-E18** A public command's or query's top-level input field with no description is a finding naming it; a private command's isn't. — `packages/testkit/test/check/check.test.ts`
- **M2.5-E19** Locale keys: a key in `en` but not `ar`, and one in `ar` but not `en`; a key the `ui.get` answer uses (a page title, a nav title, a view's text) missing; `<namespace>.title` missing; a setting's `<key>.title` missing — each a finding with its file. — `packages/testkit/test/check/locale-keys.test.ts`
- **M2.5-E20** Timer scan: `setInterval(` warns; a `setTimeout(` whose statement doesn't start with `await` warns; `await new Promise((resolve) => setTimeout(resolve, 5))` doesn't; one in a comment doesn't; warnings alone exit 0. — `packages/testkit/test/check/timer-scan.test.ts`
- **M2.5-E21** The bin run in a project folder prints readable findings, and with `--json` the `[{ file?, message, hint }]` array on its last line; every finding has a hint. — `packages/testkit/test/check/check-bin.test.ts`

### `preset new`, `preset check`
These run against a real kvman in the `dev` preset, since only there are kvai, kvwebui, and kvcoder `bundled` (a test kernel loads every extension as `path:`).
- **M2.5-E22** `preset new` writes the runnable skeleton and returns `{ file }`; an existing file fails `kvdev/FILE_EXISTS`; outside the workspace folder, `VALIDATION_FAILED`; the skeleton passes `preset check`. — `extensions/kvdev/test/e2e/preset-check.test.ts`
- **M2.5-E23** `preset check` extensions: an unknown preset key, an unknown bundled name, a `path:` folder with no package.json or none with a `kvman` field, and a non-JSON file are each a finding with `file` and a hint; an `npm:` source is accepted unfetched. — `extensions/kvdev/test/e2e/preset-check.test.ts`
- **M2.5-E24** `preset check` settings: a namespace that's neither `kernel` nor a preset extension's; an unregistered key of a loaded extension; a value that doesn't match its schema (`kvcoder.maxSteps: "x"`); a key under a `path:` extension's namespace isn't checked further. — `extensions/kvdev/test/e2e/preset-check.test.ts`
- **M2.5-E25** `preset check` pages: `kvwebui.home` naming an unknown page of a loaded extension is a finding; `kvwebui.extensions` and `kvcoder.chat` pass; a page under an unloaded `path:` extension's namespace passes. — `extensions/kvdev/test/e2e/preset-check.test.ts`

### Preview
- **M2.5-E26** `preview start` of a hand-written project returns `{ url }` once the preview answers; `preview status` returns `{ running: true, url, extensions, startedAt }`; the preview's `kernel.health.get` reports its generated preset `preview`, it loads kvai, kvwebui, and the project, its `kvwebui.home` (the page at `/`) is `kvwebui.extensions`, and its home is `<os temp>/kvman-preview-<workspaceId>`. — `extensions/kvdev/test/e2e/preview.test.ts`
- **M2.5-E27** A second `preview start` fails `PROCESS_RUNNING`; `preview stop` returns `{}`, removes the home, and `status` returns `{ running: false }`; another `stop` fails `NOT_FOUND`. — `extensions/kvdev/test/e2e/preview.test.ts`
- **M2.5-E28** With port 3738 taken the preview uses the next free one; with 3738–3837 all taken, `kvdev/NO_FREE_PORT`. — `extensions/kvdev/test/e2e/preview.test.ts`
- **M2.5-E29** A preview that exits by itself (its process killed) is cleaned up by kvdev's `kernel.process.exited` handler: its `web:watch` processes stop, its home is removed, and `status` is `{ running: false }`. — `extensions/kvdev/test/e2e/preview.test.ts`
- **M2.5-E30** A project the preview can't load (its entry registers a name outside its namespace, so the preview kvman stops with `EXTENSION_INVALID`) fails `kvdev/PREVIEW_FAILED` with the last log lines, and nothing it started keeps running. — `extensions/kvdev/test/e2e/preview.test.ts`
- **M2.5-E31** The preview stops with the main kvman: after the main kvman's Ctrl+C, the preview's process is gone. — `extensions/kvdev/test/e2e/preview.test.ts`
- **M2.5-E32** The generated preset holds the dev extensions as absolute `path:` entries plus kvai and kvwebui, with `kvwebui.home: "kvwebui.extensions"`; a given preset keeps its home and other settings, its `path:` entries become absolute, and a dev extension replaces an entry of the same name. — `extensions/kvdev/test/unit/preview-preset.test.ts`
- **M2.5-E33** The preview's command line is `process.execPath`, `process.execArgv`, `process.argv[1]`, `--home <home> --port <n> --yes --no-open`; the port search tries 3738 upward and stops at 3837. — `extensions/kvdev/test/unit/preview-preset.test.ts`
