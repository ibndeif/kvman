# M2.5 — Blobs, workspace I/O, trust: test cases

Read: `04` §4.6, `07` §7.2, `12` §12.2 (blobs), `13` §13.7, and the parts they cite: `04` §4.1 (DDL), §4.2 (the unit of work), §4.3 (Blobs), §4.4 (forget), `02` §2.2 and §2.13 (spill), `03` §3.5 (the `blobs.*` and `workspace.*` calls), §3.8 (trust types), §3.9 (boot step 6), `05` §5.4 (`ctx.files`), §5.7 (capabilities), `13` §13.2, §13.6, §13.8, `14` §14.3 (fault point `blob.put.after-file-before-ref`, invariant 9). ADRs 0018, 0055, 0089, 0094, and 0134–0138.

Where the tests live:

- **Pure pieces**, in `packages/kernel/test/blobs/` and `packages/kernel/test/workspaces/`: finding `z.blobId()` fields by schema, the blob store's put and GC steps, content sniffing, the path jail, trust tokens, and the trust check.
- **Through a runtime**, in `packages/testkit/test/blobs/` and `packages/testkit/test/files/`. The runtime has a home folder, installed fixture snapshots (ADR 0114), and applied presets written by the test helper (ADR 0124). Its clock is the fake one of the test.
- **HTTP**, in `packages/testkit/test/blobs/http.test.ts`, through the runtime's HTTP adapter on a free port.
- **Crash points and boot**, in `packages/testkit/test/faults/blobs.test.ts` and `packages/testkit/test/files/trust-boot.test.ts`, on child kernels.
- **Protocol shapes**, in `packages/protocol/test/blobs-files.test.ts`.

Terms used in the scenarios:

- "**Person**" is `user:local`.
- "**Keeper**" is the fixture `@acme/keeper` (namespace `keeper`), enabled sandboxed unless a scenario says otherwise. It requests `calls ['holder.*']`.
  - `keeper.put {text?, base64?, chunks?, mime?, name?, global?}` puts a blob (a string, bytes, or a stream of `chunks` chunks of 1 MB) and returns what the put answered.
  - `keeper.read {blobId, as, global?}` reads a blob as `text`, `bytes` (length and SHA-256), `stream` (length and SHA-256), or `stat`. The field is `z.string()`, so it hands nothing over. It returns `{ value }` or `{ code, params? }`.
  - `keeper.keep {blobId, release?}` keeps or releases a blob. `keeper.give {text}` puts a blob and `ctx.command`s `holder.take` with it. `keeper.send {blobId}` sends `holder.take` with any ID. `keeper.slow {text}` puts a blob, then waits in `ctx.command('holder.gate')` (`timeoutMs` 3 h).
  - `keeper.return {blobId}` returns `{ blobId }` in a `z.blobId()` output field. `keeper.fail {text}` puts a blob and then throws.
  - The query `keeper.look {blobId}` reads a blob (reads are allowed in a query); `keeper.query.put` tries a put in a query.
  - `keeper.global.put` (scope `global`) tries `ctx.store.blobs` and `ctx.store.global.blobs`.
- "**Holder**" is `@acme/holder` (namespace `holder`), with no capabilities.
  - `holder.take {blobId: z.blobId()}` reads the blob and returns its text.
  - `holder.peek {blobId: z.string()}` tries the same without a hand-over.
  - The query `holder.find` returns `{ blobId }` of a blob Holder put, as a `z.blobId()` output field.
  - `holder.gate` defers; `holder.open {commandId}` replies to it.
  - `holder.echo {blobId: z.blobId()}` returns it in a `z.blobId()` output field; `holder.announce {blobId}` publishes `holder.stored {blobId: z.blobId()}`.
  - It subscribes to `keeper.shared`, whose payload has a `z.blobId()` field, and records what it read.
- "**Filer**" is `@acme/filer` (namespace `filer`), enabled sandboxed with `files.read` and `files.write`.
  - `filer.run {op, path?, content?, base64?, pattern?, recursive?}` calls one `ctx.files` method and returns `{ value }` or `{ code, params? }`.
  - `filer.look {op, path?, pattern?}` is a query doing the same for the read methods; `filer.global` (scope `global`) tries `ctx.files`.
  - `filer.blob {path}` calls `ctx.store.blobs.put({ workspacePath: path })`.
  - "**Reader**" is `@acme/reader`, which requests `files.read` only; `reader.run` works like `filer.run`.
- A **workspace folder** is a temporary folder, never the real `~/kvman`; `A` is its workspace.
- "**Trusted**" means the person previewed and granted trust through `kernel.trust.preview` and `kernel.trust.grant`.
- "**GC runs**" means the kernel clock moves 10 minutes, so the GC timer fires.

## Happy path

### M2.5-H1 — a blob ID without a ref or hand-over is refused
- **Test**: `packages/testkit/test/blobs/handover.test.ts`
- **Given** Holder put a blob and holds its only reference.
- **When** Keeper reads it with `keeper.read`, and `keeper.send` sends `holder.take` with it; separately, Holder's own `holder.peek` reads a blob that Keeper put.
- **Then**:
  - the read fails `CAPABILITY_DENIED`;
  - the send is refused at admission with `CAPABILITY_DENIED`, so `keeper.send` fails with it and no `holder.take` row is stored;
  - `holder.peek` fails `CAPABILITY_DENIED`, because its field is not `z.blobId()`.

### M2.5-H2 — a symlink out of the workspace fails WORKSPACE_ESCAPE
- **Test**: `packages/testkit/test/files/jail.test.ts`
- **Given** the workspace folder holds `out`, a symlink to a folder outside it that holds `secret.txt`.
- **When** Filer reads `out/secret.txt`, lists `out`, and writes `out/new.txt`.
- **Then** each fails `WORKSPACE_ESCAPE`, and no file is created outside the workspace.

### M2.5-H3 — changing a trusted file closes the gate
- **Test**: `packages/testkit/test/files/trust.test.ts`
- **Given** A is trusted with `.kvman/rules/a.md`, and Filer reads it once.
- **When** the file's content changes on disk, and Filer reads it again.
- **Then**:
  - the second read fails `WORKSPACE_UNTRUSTED`;
  - `kernel.workspace.get` shows `trust: null`, and `kernel.workspaces.list` shows `trusted: false`;
  - one `kernel.trust.changed {workspaceId: A, trusted: false}` event is stored.

### M2.5-H4 — an SVG upload is served as an attachment
- **Test**: `packages/testkit/test/blobs/http.test.ts`
- **When** the person `PUT`s an SVG with `Content-Type: image/svg+xml` and `X-Kvman-Filename: logo.svg`, then `GET`s it.
- **Then**:
  - the PUT answers `{ blobId, size, mime: 'image/svg+xml', name: 'logo.svg' }`, and `blobId` is the SHA-256 of the bytes;
  - the GET answers the bytes with `Content-Type: application/octet-stream`, `Content-Disposition: attachment; filename*=UTF-8''logo.svg`, `X-Content-Type-Options: nosniff`, and `Content-Security-Policy: sandbox; default-src 'none'`.

### M2.5-H5 — a blob put by a handler that runs past the GC grace survives until its commit
- **Test**: `packages/testkit/test/blobs/gc.test.ts`
- **Given** `keeper.slow` has put its blob and is waiting in `holder.gate`.
- **When** the kernel clock moves 2 h, so GC runs 12 times, and then `holder.open` lets `keeper.slow` finish.
- **Then**:
  - the blob's row and file survive every run;
  - after the commit the reference is `blob:<id>` with no expiry, and no `pending:` reference is left;
  - `keeper.read` reads the blob's text.

### M2.5-H6 — a GC run and a put of the same content never leave a reference to a missing file
- **Test**: `packages/kernel/test/blobs/blob-store.test.ts`
- **Given** a blob more than 1 h old with no reference.
- **When** a put of the same bytes finishes writing its temporary file, GC runs, and then the put registers; and again, with the put registering first and GC running after it.
- **Then**:
  - in the first order, GC deletes the old row and file, and the put then restores both;
  - in the second order, GC keeps the blob, which now has a reference;
  - either way, every reference names a row whose file exists (invariant 9).

### M2.5-H7 — a write to .kvman/rules/x.md through ctx.files closes the gate
- **Test**: `packages/testkit/test/files/trust.test.ts`
- **Given** A is trusted.
- **When** Filer writes `.kvman/rules/x.md`.
- **Then**:
  - the write succeeds and the file holds the content;
  - A's trust is `null`, and one `kernel.trust.changed {workspaceId: A, trusted: false}` event is stored;
  - the next read of `.kvman/rules/x.md` fails `WORKSPACE_UNTRUSTED`.

## Edge cases

### Blob store and API

### M2.5-E1 — put and read round trip
- **Test**: `packages/testkit/test/blobs/api.test.ts`
- **When** Keeper puts a string, bytes, and a stream of 3 chunks, then reads each as text, bytes, stream, and stat.
- **Then**:
  - each ID is the lowercase SHA-256 of the bytes, and the content reads back exactly;
  - a string without a mime is `text/plain`, and bytes or a stream are `application/octet-stream`;
  - `stat` of an unknown ID the handler received answers `undefined`.

### M2.5-E2 — the same bytes are stored once, and the first put's metadata wins
- **Test**: `packages/testkit/test/blobs/api.test.ts`
- **When** Keeper puts the same bytes as `a.txt` (`text/markdown`), then as `b.txt` (`text/plain`).
- **Then**:
  - both puts answer the same ID with `mime: 'text/markdown'` and `name: 'a.txt'`;
  - one `blobs` row and one file under `blobs/ab/cd/<id>` exist.

### M2.5-E3 — a hand-over through a payload, a reply, a query result, an event, and a continuation
- **Test**: `packages/testkit/test/blobs/handover.test.ts`
- **When** each of these happens:
  - `keeper.give` puts a blob and calls `holder.take`, which reads it;
  - Keeper calls `holder.echo` with its own blob, and reads the blob named in the reply;
  - Keeper queries `holder.find` and reads the blob in the result;
  - Keeper publishes `keeper.shared` with its blob, and Holder's subscription reads it;
  - Keeper sends `holder.echo` with `onReply`, and its continuation reads the blob named in the reply.
- **Then** every read succeeds, and none of them left Holder or Keeper a reference to the blob.

### M2.5-E4 — a result may name only blobs its handler may read
- **Test**: `packages/testkit/test/blobs/handover.test.ts`
- **When** each of these happens:
  - `keeper.return` returns a blob that only Holder holds;
  - Holder's deferred `holder.gate` is answered by a `ctx.reply` naming a blob that only Keeper holds;
  - `keeper.look` is asked for a blob Keeper cannot read, and returns it.
- **Then**:
  - the command fails `CAPABILITY_DENIED`, not retryable, after one attempt;
  - the `ctx.reply` unit is rolled back with `CAPABILITY_DENIED`, and the command stays `awaiting`;
  - the query answers `CAPABILITY_DENIED`.

### M2.5-E5 — keep and release
- **Test**: `packages/testkit/test/blobs/api.test.ts`
- **When** each of these happens:
  - Holder's `holder.take` keeps a blob it received, and later, in another invocation with no hand-over, reads it;
  - Holder then releases it and reads it again;
  - Keeper keeps a blob it may not read.
- **Then**:
  - the kept read succeeds, and a `blob:<id>` reference is owned by Holder in A;
  - after the release the read fails `CAPABILITY_DENIED`;
  - Keeper's keep fails its unit with `CAPABILITY_DENIED`, and no reference is added.

### M2.5-E6 — pending references end with their invocation
- **Test**: `packages/testkit/test/blobs/api.test.ts`
- **When** `keeper.fail` puts a blob and throws; and, separately, `keeper.put` commits.
- **Then**:
  - after the failure, no reference to that blob is left;
  - after the commit, Keeper holds `blob:<id>` in A with no expiry;
  - while each handler runs, its reference is `pending:<messageId>`, expiring at the invocation deadline plus 1 h.

### M2.5-E7 — queries read blobs but cannot put, keep, or release
- **Test**: `packages/testkit/test/blobs/api.test.ts`
- **When** `keeper.look` reads a blob Keeper holds; `keeper.query.put` tries a put, a keep, and a release.
- **Then** the read answers its text, and each write fails `CAPABILITY_DENIED`.

### M2.5-E8 — a handler without a workspace uses global blobs
- **Test**: `packages/testkit/test/blobs/api.test.ts`
- **When** `keeper.global.put` tries `ctx.store.blobs.put`, then `ctx.store.global.blobs.put`.
- **Then**:
  - the first fails `WORKSPACE_INVALID` with the hint to use `ctx.store.global`;
  - the second commits a reference with `ws = ''`;
  - Keeper reads that blob from a handler in A, since a reference in any scope counts.

### M2.5-E9 — size limits
- **Test**: `packages/testkit/test/blobs/limits.test.ts`
- **When** each of these happens:
  - Keeper (enabled `shared`) puts a stream of 100 MB and one byte;
  - Keeper puts 16 MB and one byte, then reads it as text, bytes, and stream.
- **Then**:
  - the put fails `BLOB_TOO_LARGE {max: 104857600}`, and no row, reference, or temporary file is left;
  - text and bytes fail `BLOB_TOO_LARGE {max: 16777216}` with a hint naming `stream`, and the stream reads every byte.

### M2.5-E10 — a blob that does not exist
- **Test**: `packages/testkit/test/blobs/api.test.ts`
- **When** the person sends `holder.take` with the ID of bytes never stored; and Keeper reads an unknown ID it did not receive.
- **Then**:
  - the send is admitted, since people may name any blob;
  - `holder.take` fails `BLOB_NOT_FOUND`;
  - Keeper's read fails `CAPABILITY_DENIED`, the same as a blob it may not read.

### M2.5-E11 — admission checks every z.blobId() field for extension senders only
- **Test**: `packages/testkit/test/blobs/handover.test.ts`
- **When** Keeper `ctx.command`s `holder.take` with a blob only Holder holds; Keeper publishes `keeper.shared` with such a blob; the person sends `holder.take` with it.
- **Then**:
  - the command fails `CAPABILITY_DENIED` at once, with no `holder.take` row;
  - the publish rolls Keeper's unit back with `CAPABILITY_DENIED`, and no `keeper.shared` event is stored;
  - the person's command is admitted, and Holder reads the blob.

### M2.5-E12 — blob fields found by schema
- **Test**: `packages/kernel/test/blobs/blob-fields.test.ts`
- **Given** JSON Schemas as the SDK records them: nested objects, arrays, optional and nullable fields, unions, records, and `$defs` references.
- **When** the blob IDs of values are collected.
- **Then**:
  - every string at a `kvman-blob-id` field is found, once;
  - a string at a plain `string` field is not;
  - a value at a union position is collected from every branch that has a blob field there, so a check can only refuse more, never less.

### M2.5-E13 — GC collects what nothing references
- **Test**: `packages/kernel/test/blobs/blob-store.test.ts`
- **Given** blobs of these kinds:
  - one released and 2 h old, and one released and 30 minutes old;
  - one with an upload reference 25 h old;
  - one with a pending reference past its invocation deadline plus 1 h;
  - one with a kernel spill reference.
- **When** GC runs.
- **Then**:
  - the old released blob is deleted, row and file, and the young one stays;
  - the expired upload and pending references are deleted, and their blobs go once they are old enough;
  - the spilled blob stays;
  - a GC over more than one batch collects everything in bounded steps.

### M2.5-E14 — GC runs at boot and every 10 minutes
- **Test**: `packages/testkit/test/blobs/gc.test.ts`
- **Given** a blob released 2 h ago.
- **When** the runtime starts, and then the clock moves 10 minutes.
- **Then** the blob is gone after start, and a second such blob is gone after the move.

### M2.5-E15 — a crash after the file and before the reference
- **Test**: `packages/testkit/test/faults/blobs.test.ts`
- **Given** a child kernel with the fault point `blob.put.after-file-before-ref`.
- **When** `keeper.put` is sent, the kernel is killed at the point, and a new kernel starts on the same home.
- **Then**:
  - the redelivered `keeper.put` completes with the same ID;
  - every committed reference names a row whose file exists (invariant 9);
  - no `pending:` reference outlives its deadline plus 1 h;
  - no temporary blob file is left.

### M2.5-E16 — forget and uninstall drop references
- **Test**: `packages/testkit/test/blobs/gc.test.ts`
- **When** A is forgotten; and, separately, Keeper is uninstalled with `deleteData`.
- **Then** their references are deleted, and GC collects the blobs once they are 1 h old.

### Spill

### M2.5-E17 — a large payload, result, or event spills to a kernel blob
- **Test**: `packages/testkit/test/blobs/spill.test.ts`
- **When** each of these is 300 KB:
  - the person sends a command payload;
  - a handler returns a result;
  - a handler publishes a durable event payload.
- **Then**:
  - each row stores `NULL` in `payload` or `result` and the blob ID in `payload_ref`, `result_ref`, or `events.payload_ref`;
  - `blob_refs` holds `kernel` references `payload:<id>`, `result:<id>`, and `event:<id>`;
  - the handler receives the payload intact;
  - the waiter, the HTTP reply, and `GET /messages/:id` return the result;
  - the subscriber and an event-stream resume receive the event.

### M2.5-E18 — spill limits and small values
- **Test**: `packages/testkit/test/blobs/spill.test.ts`
- **When** payloads of 256 KB and of 16 MB and one byte are sent.
- **Then**:
  - the 256 KB payload is stored inline with no reference;
  - the larger one fails `PAYLOAD_TOO_LARGE {limit: 'payload', max: 16777216}`.

### M2.5-E19 — spilled blobs are never collected while their row exists
- **Test**: `packages/testkit/test/blobs/spill.test.ts`
- **Given** a spilled payload.
- **When** the clock moves 3 h and GC runs.
- **Then** its file and row stay, and the message still reads intact.

### HTTP

### M2.5-E20 — PUT /blobs headers and limits
- **Test**: `packages/testkit/test/blobs/http.test.ts`
- **When** each of these PUTs is sent:
  - one without `Content-Type`, and one naming `X-Kvman-Filename: %D9%85%D9%84%D9%81.txt`;
  - one with a malformed filename or mime;
  - one naming an unknown `X-Kvman-Workspace`;
  - one of 100 MB and one byte;
  - one with a foreign `Origin`.
- **Then**:
  - the first answers `mime: 'application/octet-stream'` and no name, the second `name: 'ملف.txt'`, and each holds an upload reference (owner `user`, ref `upload`, 24 h) in global scope, or in the named workspace when one is given;
  - the malformed headers answer 400 `VALIDATION_FAILED`;
  - the unknown workspace answers 422 `WORKSPACE_INVALID`;
  - the oversized PUT answers 413 `BLOB_TOO_LARGE {max: 104857600}`, and no temporary file is left;
  - the foreign Origin answers 403 `HOST_FORBIDDEN`.

### M2.5-E21 — GET /blobs/:id serving policy
- **Test**: `packages/testkit/test/blobs/http.test.ts`
- **When** these blobs are fetched:
  - a real PNG, JPEG, GIF, and WebP;
  - UTF-8 text stored as `text/plain`;
  - an HTML page, a PDF, and HTML bytes stored as `image/png`;
  - text with a NUL byte stored as `text/plain`;
  - the PNG again with `?download=1`;
  - an unknown ID and a malformed ID.
- **Then**:
  - the images are inline with their type, and the text is inline as `text/plain; charset=utf-8`;
  - the HTML, the PDF, the spoofed PNG, the text with NUL, and the downloaded PNG are attachments as `application/octet-stream`;
  - every answer carries `nosniff` and the sandbox CSP;
  - the unknown ID answers 404 `BLOB_NOT_FOUND`, and the malformed one 400 `VALIDATION_FAILED`.

### M2.5-E22 — content sniffing
- **Test**: `packages/kernel/test/blobs/blob-serving.test.ts`
- **Given** byte prefixes for each allowlisted type, truncated signatures, a WebP header without `WEBP`, invalid UTF-8, and text with NUL.
- **When** the serving policy is computed for each stored mime and those bytes.
- **Then** inline happens only when the stored mime is allowlisted and the bytes match it; everything else is an attachment.

### M2.5-E26 — the jail's rules

### Trust

### M2.5-E29 — preview and grant
- **Test**: `packages/testkit/test/files/trust.test.ts`
- **Given** `.kvman/` holds `rules/a.md`, `skills/s/SKILL.md`, and an empty folder.
- **When** the person previews and grants `always`.
- **Then**:

### M2.5-E30 — the gate while untrusted
- **Test**: `packages/testkit/test/files/trust.test.ts`

### M2.5-E31 — every kind of change closes the gate once
- **Test**: `packages/testkit/test/files/trust.test.ts`
- **Given** A trusted.
- **When** each case runs on its own trusted workspace:
  - a file is added;
  - a file is removed;
  - a file's content changes;
  - a file is replaced by a symlink;
  - a file is touched with the same content;
  - two reads race after a change;

- **Then**:
