# M2.7 — Reload, versions, migrations, schedules: test cases

Read:

- `06` §6.6–§6.7, `04` §4.8, `03` §3.4 (timers), §3.6, §3.9.
- The parts they cite:
  - `02` §2.4 (access), §2.6 (priority);
  - `03` §3.5 (hosts), §3.8 (`kernel.extension.reload`, `rollback`, `unquarantine`; `kernel.extension.reloaded`, `.unquarantined`);
  - `04` §4.1 (the `schedules` table), §4.4 (forget);
  - `05` §5.3 (`registerSchedule`, `registerDataVersion`), §5.7 (grants);
  - `06` §6.4 (enable checks), §6.8 (uninstall);
  - `13` §13.2;
  - `14` §14.3: the fault points `reload.after-drain`, `reload.after-migrate-before-swap`, and `migration.mid`; invariant 12.
- ADRs 0046, 0050, 0080, 0086, 0089, 0091, 0115, 0123, 0130, and 0142–0145.

Earlier tests that M2.7 changes:

- ADR 0142 reverses the `compatibleWith` rule, so M1.3-E6 (`packages/testkit/test/recording/manifest-entries.test.ts`) now expects higher versions.
- Kernel schema 5 adds the `schedules` table: M1.1-E3 lists it, and M1.6-E40 names schema 5.
- Enable now checks every stored config value (`04` §4.8, ADR 0143), so the issue of M2.3-E17 is at `workspaces.<A>.limit`.

Where the tests live:

- **Pure pieces**, in `packages/kernel/test/`:
  - the cron parser and occurrence computation in `schedules/`;
  - the migration batches and the part-way rule in `migrations/`.
- **Manifest rules**, in `packages/testkit/test/validation/`.
- **Through a runtime**, in `packages/testkit/test/reload/` and `packages/testkit/test/schedules/`. The runtime has a home folder, installed fixture snapshots (ADR 0114; each version of a fixture is its own snapshot), applied presets written by the test helper (ADR 0124), and the fake clock of the test.
- **Crash points, restarts, and boot**, on child kernels and in-process boots:
  - `packages/testkit/test/faults/migrations.test.ts`;
  - `packages/testkit/test/reload/upgrade-boot.test.ts`;
  - `packages/testkit/test/reload/memory.test.ts`;
  - `packages/testkit/test/schedules/restart.test.ts`.
- **Protocol shapes**, in `packages/protocol/test/reload.test.ts`.

Terms used in the scenarios:

- "**Person**" is `user:local`, who is an administrator.
- "**Notes**" is the fixture `@acme/notes` (namespace `notes`), installed in several versions, each its own snapshot. Every version has:
  - a collection `items` (`{ id, text }` in data version 1);
  - kv entries, a log family `history:*`, and a plain log `audit`;
  - config `{ limit?: number }`;
  - commands `notes.add {id, text}` (writes a document, a kv entry `item:<id>`, and entries in `history:<id>` and `audit`) and `notes.hold` (waits until it is aborted);
  - queries `notes.version.get` (returns its package version) and `notes.items.list`.

  The versions:

  | Version | Folder | Difference |
  |---|---|---|
  | `1.0.0` | `notes-1` | data version 1 |
  | `1.1.0` | `notes-1-compat` | data version 1 with `compatibleWith: [2]` |
  | `2.0.0` | `notes-2` | data version 2; step 2 renames `text` to `title`, wraps kv values as `{ v: 2, value }`, adds `v: 2` to every log entry, and removes kv keys starting `old:` |
  | `2.0.1` | `notes-2-fail` | data version 2; step 2 throws an error |
  | `3.0.0` | `notes-3` | data version 3; step 2 as `notes-2`; step 3 throws while the stored global config has `blockStep3: true` |
  | `2.1.0` | `notes-2-process` | as `notes-2`, and requests `process` |
  | `2.2.0` | `notes-2-strict` | data version 1; its config schema caps `limit` at 10 |
  | `2.3.0` | `notes-2-config-fix` | data version 2; caps `limit` at 10, and step 2 sets every stored `limit` to 10 |
  | `2.3.1` | `notes-2-config-keep` | data version 2; caps `limit` at 10, and step 2 renames items but leaves `limit` alone |
  | `2.4.0` | `notes-2-hang` | data version 2; step 2 never ends |
  | `2.5.0` | `notes-2-exit` | data version 2; step 2 ends its host process |
  | `2.6.0` | `notes-2-narrow` | data version 1; drops `notes.items.list` |
  | `2.7.0` | `notes-2-bad-doc` | data version 2; step 2 returns an item without `title` |

- "**Lister**" is `@acme/lister` (namespace `lister`), whose `requireTypes` names `notes.items.list`.
- "**Caller**" is `@acme/caller` (namespace `caller`), without `kernel.admin`; `caller.call {type, payload}` sends a kernel command and reports its result or problem code. "**Steward**" is the workspace tests' `@acme/steward`, with `kernel.admin`.
- "**Ticker**" is `@acme/ticker` (namespace `ticker`), in two versions:
  - `1.0.0` has:
    - `tick` (`every: '1h'` → `ticker.tick`);
    - `daily` (`cron: '0 9 * * *'` → `ticker.daily`);
    - `sweep` (`every: '30m'` → the global `ticker.sweep`);
    - `broken` (`every: '1h'` → `ticker.broken`, which throws the non-retryable `ticker/BROKEN`).

    Each command is access `internal` and records its message envelope (source, priority, workspace, payload, `notBefore`) in a global collection, read with the query `ticker.runs.list`.
  - `2.0.0` changes `tick` to `every: '2h'`, removes `daily`, keeps `sweep` and `broken`, and adds `hourly` (`cron: '0 * * * *'` → `ticker.tick`).
- **Workspace folders** are temporary folders: `A` and `B`. The home folder is a temporary folder, never the real `~/.kvman` or `~/kvman`.
- "**Stored version**" is Notes' `schema_versions` row.
- Tests that depend on local time set `TZ` for the process under test: `UTC`, or `America/New_York` for the DST cases.

## Happy path

### M2.7-H1 — an upgrade with a migration runs it once
- **Test**: `packages/testkit/test/reload/migrations.test.ts`
- **Given** Notes `1.0.0` enabled in A and B (sandboxed), stored version 1, with items, kv entries, and log entries in A, B, and global.
- **When** the person sends `kernel.extension.reload {name: '@acme/notes', digest: <2.0.0>}`.
- **Then**:
  - it answers `{ digest: <2.0.0> }`;
  - step 2 ran once: it is recorded once, and every item in A, B, and global has `title` and no `text`;
  - the stored version is 2, `extensions.migrating` is cleared, and `active_digest` is `2.0.0`;
  - `notes.version.get` answers `2.0.0`;
  - `kernel.extension.reloaded` is published once for A and once for B;
  - sending the same reload again answers the same without running step 2 again.

### M2.7-H2 — a migration that fails at its first step leaves the old version active
- **Test**: `packages/testkit/test/reload/migrations.test.ts`
- **Given** Notes `1.0.0` enabled in A, stored version 1, with items.
- **When** the person reloads to `2.0.1` (step 2 throws an error).
- **Then**:
  - it fails `MIGRATION_FAILED`, and its detail names step 2;
  - `migrating` is cleared, the stored version is 1, and every item is unchanged;
  - `active_digest` is `1.0.0`, Notes is not quarantined, and `notes.version.get` answers `1.0.0`;
  - `kernel.extension.reloaded` is not published.

### M2.7-H3 — a migration that fails after a committed step quarantines; Retry upgrade resumes it
- **Test**: `packages/testkit/test/reload/migrations.test.ts`
- **Given** Notes `1.0.0` enabled in A, stored version 1, and global config `{ blockStep3: true }`.
- **When** the person reloads to `3.0.0`.
- **Then**:
  - it fails `MIGRATION_FAILED`;
  - the stored version is 2 (step 2 committed), and `migrating` is `{ digest: <3.0.0> }`;
  - Notes is quarantined with reason `MIGRATION_FAILED`, and `kernel.extension.quarantined` is published;
  - a command to Notes fails `HANDLER_UNAVAILABLE`.
- **When** the global config is set to `{ blockStep3: false }` and the person sends `kernel.extension.reload {name, digest: <3.0.0>}` (Retry upgrade).
- **Then**:
  - it succeeds; step 2 did not run again, and step 3 ran once;
  - the stored version is 3, `migrating` is cleared, and `active_digest` is `3.0.0`;
  - the quarantine is cleared, and `kernel.extension.unquarantined` is published.

### M2.7-H4 — a daemon killed mid-migration resumes and finishes the swap at boot
- **Test**: `packages/testkit/test/faults/migrations.test.ts`
- **Given** a child kernel with Notes `1.0.0` enabled, stored version 1, started with `KVMAN_FAULTS=migration.mid`.
- **When** it reloads Notes to `3.0.0` (with `blockStep3: false`), is killed at `migration.mid` (after step 2 committed, before step 3), and starts again without faults.
- **Then**:
  - boot resumed from stored version 2: step 3 ran, and step 2 did not run again;
  - the stored version is 3, `migrating` is cleared, and `active_digest` is `3.0.0`;
  - `kernel.extension.reloaded` is published once for the workspace;
  - invariant 12 holds.

### M2.7-H5 — an upgrade that requests a new capability fails until reloaded with grants
- **Test**: `packages/testkit/test/reload/grants.test.ts`
- **Given** Notes `1.0.0` enabled in A and B, both without `process`.
- **When** the person reloads to `2.1.0` (which requests `process`) without `grants`.
- **Then**:
  - it fails `EXT_GRANTS_REQUIRED` with `params { digest: <2.1.0>, workspaces: [{ workspaceId: A, missing: ['process'] }, { workspaceId: B, missing: ['process'] }] }`;
  - `pending_digest` is `2.1.0`, and `kernel.extensions.list` shows Notes as `needs-approval`;
  - `active_digest` is still `1.0.0`, and no migration ran.
- **When** the person reloads with `grants` for A and B that include `process`.
- **Then**:
  - it succeeds; `active_digest` is `2.1.0`, and `pending_digest` is cleared;
  - the applied presets of A and B list the new grants, `digest`, and `source`;
  - `kernel.preset.changed {cause: 'enable'}` is published for A and B.

### M2.7-H6 — a schedule fires on time and survives a restart
- **Test**: `packages/testkit/test/schedules/restart.test.ts`
- **Given** an in-process kernel booted on a home with Ticker `1.0.0` enabled in A, the clock at 08:00 UTC.
- **When**:
  - the clock reaches 09:00 (`tick` and `daily` are due, `sweep` twice);
  - the kernel shuts down at 09:10, and a new kernel boots on the same home at 09:20;
  - the clock reaches 10:00.
- **Then**:
  - `ticker.tick` ran at 09:00 and 10:00 in A;
  - `ticker.daily` ran at 09:00;
  - `ticker.sweep` ran without a workspace at 08:30, 09:00, 09:30, and 10:00;
  - each run's source is `kernel` and its priority `normal`;
  - no run happened twice, and the `schedules` rows survived the restart with the next due times.

### M2.7-H7 — an upgrade whose config schema rejects a stored value fails CONFIG_INVALID unless a migration fixes it
- **Test**: `packages/testkit/test/reload/config-check.test.ts`
- **Given** Notes `1.0.0` enabled in A and B, stored global config `{ limit: 50 }`, and A's workspace config `{ limit: 40 }`.
- **When** the person reloads to `2.2.0` (caps `limit` at 10, no migration).
- **Then**:
  - it fails `CONFIG_INVALID`, and its issues list `limit` for the global config and for A;
  - nothing is written, and `1.0.0` stays active.
- **When** the person reloads to `2.3.0` (step 2 sets every `limit` to 10).
- **Then**:
  - it succeeds, and the stored config values are `{ limit: 10 }`;
  - the stored version is 2.

### M2.7-H8 — 20 hot reloads of a shared extension return the pool to its baseline
- **Test**: `packages/testkit/test/reload/memory.test.ts`
- **Given** a child kernel started with `--expose-gc`, with Notes enabled `shared` in A.
- **When**:
  - the person reloads Notes once and answers one `notes.version.get`, to take the baseline;
  - the person then reloads it 20 more times, answering one `notes.version.get` after each.
- **Then**:
  - every shared worker that loaded an earlier version has exited;
  - the shared pool holds no more workers than at the baseline;
  - the daemon's `heapUsed` after a forced GC is within 10 MB of the baseline.

### M2.7-H9 — a query during a reload fails HANDLER_UNAVAILABLE and succeeds after the delay
- **Test**: `packages/testkit/test/reload/drain.test.ts`
- **Given** Notes `1.0.0` enabled in A, with a `notes.hold` running.
- **When** the person reloads to `2.0.0`, and `notes.version.get` is sent while the reload drains.
- **Then**:
  - the query fails `HANDLER_UNAVAILABLE`, retryable, with `retryAfterMs: 1000`;
  - the same query, sent after the reload finishes, answers `2.0.0`.

## Edge cases

### Migrations

### M2.7-E1 — a reload of an extension enabled nowhere runs no migration; enable does
- **Test**: `packages/testkit/test/reload/migrations.test.ts`
- **Given** Notes `1.0.0` installed with stored version 1 and items, enabled in no workspace.
- **When** the person reloads to `2.0.0`, then enables Notes in A.
- **Then**:
  - the reload answers `{ digest: <2.0.0> }` without running step 2, the stored version stays 1, and no `kernel.extension.reloaded` is published;
  - the enable runs step 2 once with `2.0.0`'s code before any Notes message runs;
  - the stored version is 2, `migrating` is cleared, and the items have `title`.

### M2.7-E2 — without a stored version, no migration runs and the row is written
- **Test**: `packages/testkit/test/reload/migrations.test.ts`
- **Given** Notes `2.0.0` installed, with no `schema_versions` row.
- **When** the person enables it in A; after a disable in A, a reload to `3.0.0` and an enable.
- **Then**:
  - the enable wrote stored version 2 and ran no step;
  - the second enable ran only step 3, and the stored version is 3.

### M2.7-E3 — a stored version newer than the code fails SCHEMA_TOO_NEW unless covered
- **Test**: `packages/testkit/test/reload/migrations.test.ts`
- **Given** stored version 2, with `1.0.0` active and enabled nowhere.
- **When** the person enables it in A; then reloads to `1.1.0` (`compatibleWith: [2]`) and enables it in A.
- **Then**:
  - the first enable fails `SCHEMA_TOO_NEW`, and nothing is written (the preset revision and stored version are unchanged);
  - the second enable succeeds without a migration, and the stored version stays 2.

### M2.7-E4 — m.each visits every workspace and global, in order, as committed at the start of the step
- **Test**: `packages/testkit/test/reload/migration-context.test.ts`
- **Given**:
  - Notes `1.0.0` with kv entries, items, and entries in `history:x`, `history:y`, and `audit`, in global, B, and A;
  - A's workspace id sorts before B's;
  - a kv key `old:1`.
- **When** the person reloads to `2.0.0`, whose step also records what it visited.
- **Then**:
  - each `each` visited global first (`workspaceId: null`), then A, then B, with keys, ids, and seqs ascending, and family keys `x` before `y`;
  - `audit` entries have no `key`;
  - every kv value is `{ v: 2, value }`, and `old:1` is gone;
  - every log entry has `v: 2` with its seq unchanged;
  - an `each` after a rewrite in the same step saw the committed values, not the rewrite;
  - `m.config.get('global')` after `m.config.set` returned the value just set.

### M2.7-E5 — a replaced document that breaks its schema fails the step
- **Test**: `packages/testkit/test/reload/migration-context.test.ts`
- **Given** Notes `1.0.0` enabled in A with items.
- **When** the person reloads to `2.7.0` (returns an item without `title`).
- **Then**:
  - it fails `MIGRATION_FAILED`, whose detail names `VALIDATION_FAILED` and the collection;
  - nothing is written, and `1.0.0` stays active.

### M2.7-E6 — a part-way failure keeps the active version when it covers the intermediate version
- **Test**: `packages/testkit/test/reload/migrations.test.ts`
- **Given** Notes `1.1.0` (`compatibleWith: [2]`) active and enabled in A, stored version 1, and `blockStep3: true`.
- **When** the person reloads to `3.0.0`.
- **Then**:
  - it fails `MIGRATION_FAILED`, and the stored version is 2;
  - `migrating` is cleared, `1.1.0` stays active, and Notes is not quarantined;
  - `notes.version.get` answers `1.1.0`.

### M2.7-E7 — the config check runs inside the last step
- **Test**: `packages/testkit/test/reload/config-check.test.ts`
- **Given** Notes `1.0.0` enabled in A with items and stored global config `{ limit: 50 }`.
- **When** the person reloads to `2.3.1` (step 2 renames items but leaves `limit` at 50).
- **Then**:
  - it fails `CONFIG_INVALID`, listing `limit` for the global config;
  - step 2's writes were discarded: the stored version is 1, and the items are unchanged;
  - `migrating` is cleared, and `1.0.0` stays active without a quarantine.

### M2.7-E8 — a step running over 10 minutes is aborted, and its host is replaced without a charge
- **Test**: `packages/testkit/test/reload/migration-limits.test.ts`
- **Given** Notes `1.0.0` enabled in A (sandboxed).
- **When** the person reloads to `2.4.0` (step 2 never ends), and the clock passes 10 minutes and then 2 s more; this is repeated three times.
- **Then**:
  - each reload fails `MIGRATION_FAILED`, whose detail says the step ran out of time;
  - the stored version stays 1, and `1.0.0` stays active;
  - each migration host was stopped;
  - Notes is not quarantined for `HOST_FAILURES`.

### M2.7-E9 — a host that crashes during a step fails it without a charge
- **Test**: `packages/testkit/test/reload/migration-limits.test.ts`
- **Given** Notes `1.0.0` enabled in A (sandboxed).
- **When** the person reloads to `2.5.0` (step 2 ends its host process) three times.
- **Then**:
  - each reload fails `MIGRATION_FAILED`;
  - the stored version stays 1;
  - Notes is not quarantined.

### M2.7-E10 — a migration runs at the most isolated level granted
- **Test**: `packages/testkit/test/reload/migrations.test.ts`
- **Given** Notes `1.0.0` enabled `shared` in A and `sandboxed` in B.
- **When** the person reloads to `2.0.0`, and the test lists the hosts while step 2 runs.
- **Then**:
  - step 2 runs in a sandboxed host of Notes, started for the target digest's snapshot;
  - no shared worker loaded `2.0.0` before the swap.

### M2.7-E11 — crash points of reload and migration keep invariant 12
- **Test**: `packages/testkit/test/faults/migrations.test.ts`
- **Given** a child kernel with Notes `1.0.0` enabled.
- **When** it reloads to `3.0.0` (with `blockStep3: false`), is killed at `reload.after-drain`, `reload.after-migrate-before-swap`, or `migration.mid`, and is started again.
- **Then**:
  - after `reload.after-drain`, `migrating` is unset and `1.0.0` is active; the redelivered reload completes to `3.0.0`;
  - after `reload.after-migrate-before-swap`, boot performed the swap: `3.0.0` is active and `migrating` is cleared; the redelivered reload answers `{ digest: <3.0.0> }` without changes;
  - after `migration.mid`, see H4;
  - in every case invariant 12 holds, and the invariants of M1.9 hold.

### M2.7-E12 — an interrupted enable is resumed at boot, which clears only migrating
- **Test**: `packages/testkit/test/faults/migrations.test.ts`
- **Given** a child kernel with `3.0.0` active, enabled nowhere, and stored version 1.
- **When** the person enables it in A, the kernel is killed at `migration.mid`, and it is started again.
- **Then**:
  - boot finished step 3 with `3.0.0`'s code and cleared `migrating`;
  - boot did not write the enable itself; the redelivered enable enables Notes in A without running a step.

### M2.7-E13 — a resumption that fails at boot quarantines, and boot continues
- **Test**: `packages/testkit/test/faults/migrations.test.ts`
- **Given** the state H4 leaves at the kill, with `blockStep3: true`.
- **When** the kernel starts again.
- **Then**:
  - boot finished, and `/health` answers `degraded`;
  - Notes is quarantined with `MIGRATION_FAILED`, and `migrating` is kept.

### Reload

### M2.7-E14 — a reload that would break a workspace fails VALIDATION_FAILED listing it
- **Test**: `packages/testkit/test/reload/reload.test.ts`
- **Given** Notes `1.0.0` and Lister enabled in A.
- **When** the person reloads Notes to `2.6.0` (drops `notes.items.list`).
- **Then**:
  - it fails `VALIDATION_FAILED`, and its issues name A, Lister, and `notes.items.list`;
  - nothing changes, and no dispatch was paused.

### M2.7-E15 — reload grants follow enable's rules
- **Test**: `packages/testkit/test/reload/grants.test.ts`
- **Given** Notes `1.0.0` enabled in A and B, and installed but not enabled in a workspace C.
- **When** the person reloads to `2.1.0`, in turn:
  - with grants for A only;
  - with grants for C;
  - with grants for A that omit `process`.
  Then with grants for A and B, after which the person reloads to `2.0.0` (no `process`) without grants, with grants for B that equal `2.0.0`'s requests.
- **Then**:
  - the first fails `EXT_GRANTS_REQUIRED`, listing only B;
  - the second fails `VALIDATION_FAILED`;
  - the third fails `CAPABILITY_DENIED`, listing `process` as missing;
  - after the last reload, A's grants no longer list `process` (it is no longer requested), and B's grants are the ones sent.

### M2.7-E16 — a reload with grants is a grant command; without grants it is for administrators
- **Test**: `packages/testkit/test/reload/grants.test.ts`
- **Given** Notes `1.0.0` enabled in A, Steward enabled in A (`kernel.admin`), and Caller enabled in A (no `kernel.admin`).
- **When**:
  - Steward sends `kernel.extension.reload` without grants, and then with grants;
  - Caller sends it without grants.
- **Then**:
  - the first succeeds;
  - the second fails `CALLER_NOT_ALLOWED`, because a reload with grants is a grant command, which only a person sends (`03` §3.8);
  - the third fails `CAPABILITY_DENIED`.

### M2.7-E17 — the drain lets commands wait and redelivers an aborted invocation without an attempt
- **Test**: `packages/testkit/test/reload/drain.test.ts`
- **Given** Notes `1.0.0` enabled in A, with `notes.hold` running at attempt 1.
- **When** the person reloads to `2.0.0`, `notes.add` is sent during the drain, and the clock passes 10 s.
- **Then**:
  - `notes.add` is admitted and waits;
  - `notes.hold` is aborted, returns to `pending` with `attempts` unchanged, and runs again on `2.0.0`;
  - `notes.add` runs on `2.0.0`, after the swap.

### M2.7-E18 — the swap updates every applied preset in one unit and announces the reload per workspace
- **Test**: `packages/testkit/test/reload/reload.test.ts`
- **Given** Notes `1.0.0` enabled in A, and listed but disabled in B's applied preset.
- **When** the person reloads to `2.0.0`.
- **Then**:
  - both applied presets list `2.0.0`'s `digest` and `source`;
  - only A's grants are touched (unchanged), so no `kernel.preset.changed` is published;
  - `kernel.extension.reloaded {workspaceId: A, name, digest}` is published once, and none for B.

### M2.7-E19 — a reload replaces hosts
- **Test**: `packages/testkit/test/reload/hosts.test.ts`
- **Given** Notes `1.0.0` enabled `shared` in A, `dedicated` in B, and `sandboxed` in C, each having answered `notes.version.get`.
- **When** the person reloads to `2.0.0`.
- **Then**:
  - the dedicated and sandboxed hosts of Notes were stopped;
  - each shared worker that loaded `1.0.0` stopped receiving invocations and exited;
  - `notes.version.get` answers `2.0.0` in A, B, and C from fresh hosts.

### M2.7-E20 — reload of an unknown extension or digest fails NOT_FOUND; without a digest it reloads the active one
- **Test**: `packages/testkit/test/reload/reload.test.ts`
- **Given** Notes `1.0.0` enabled in A, having answered `notes.version.get` on a shared worker.
- **When** the person reloads `@acme/missing`, then Notes with an unknown digest, then Notes without a digest.
- **Then**:

  - the third answers `{ digest: <1.0.0> }`, replaces the worker, and publishes `kernel.extension.reloaded` for A.

### M2.7-E21 — a reload to a lower data version fails EXT_ROLLBACK_BLOCKED
- **Test**: `packages/testkit/test/reload/rollback.test.ts`
- **Given** Notes at `2.0.0` with stored version 2, enabled in A.
- **When** the person reloads to `1.0.0`.
- **Then**:
