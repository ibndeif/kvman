# M1.5 — Scheduler: test cases

Read: `03` §3.4, `02` §2.6 (lanes, reentrancy, priority), §2.12–§2.13 (lifecycle, attempts); ADRs 0032 (priority codes), 0051 (admission assigns, the pending index), 0053 (delivery handlers), 0059 (attempts and backoff), 0060 (host interface), 0061 (kernel types), 0062 (dead replies), 0063 (lanes held by running messages), 0064 (aging and fairness), 0065 (handler priority).

Tests live in `packages/kernel/test/scheduler/` and use a real database, the M1.4 router and commit pipeline, a manual clock with manual timers, and an in-memory dispatcher (ADR 0060) that records each claim, reports `{ inFlight, cap }` per host, and lets the test end an invocation (`settled`, `failed`, `conflicted`). Handlers do not run: hosts arrive in M1.6. A "slot" is one free place in the dispatcher's host.

## Happy path

### M1.5-H1 — one message per lane at a time, in seq order
- **Given** `pdf.translate` sent for `f1` three times and for `f2` once
- **When** the scheduler runs
- **Then** the first `f1` message and the `f2` message are claimed; the second `f1` message is claimed only after the first settles, and the third after the second
- Test: `packages/kernel/test/scheduler/lanes.test.ts`

### M1.5-H2 — a flood in one workspace does not starve another
- **Given** 200 keyless commands pending in workspace A, then one in workspace B, all `normal`, and a host with 4 command slots
- **When** the scheduler fills the slots and settles them one by one
- **Then** workspace B's command is claimed within the first two claims after it arrived, while A still has more than 190 pending
- Test: `packages/kernel/test/scheduler/fairness.test.ts`

### M1.5-H3 — retries follow 1 s → 5 s → 30 s and end dead
- **Given** a command whose definition sets `maxAttempts: 4`, and a subscriber of `kernel.message.dead-lettered` enabled in the workspace
- **When** each attempt fails with a retryable problem
- **Then** the message returns to `pending` with `notBefore` now + 1 s, then now + 5 s, then now + 30 s, and is not claimed before; the fourth failure makes it `dead` with 4 attempts and the reply `MESSAGE_DEAD`; the same transaction stores one `kernel.message.dead-lettered` event `{ messageId, type, correlationId }` and a delivery row for the subscriber
- Test: `packages/kernel/test/scheduler/retries.test.ts`

### M1.5-H4 — a call into an ancestor's lane fails at once
- **Given** a running `pdf.translate` for `f1` whose handler sent `agent.run`, which is running too
- **When** `agent.run`'s invocation asks to call into the lane `@acme/pdf|file:f1`, and into its own lane
- **Then** both fail `LANE_REENTRANT` at once, without waiting
- Test: `packages/kernel/test/scheduler/lane-reentrancy.test.ts`

### M1.5-H5 — a user chain is interactive, and a higher class is lowered
- **Given** a person's command whose handler sends a command, a process's command requesting `interactive`, and one free slot
- **When** the scheduler picks between them and a `normal` command admitted earlier
- **Then** the handler's send is stored `interactive` and claimed first; the process's command is stored `normal` and claimed in `seq` order with the other `normal` one
- Test: `packages/kernel/test/scheduler/priority.test.ts`

## Edge cases

### Selection (`03` §3.4, `02` §2.6, ADR 0064) — `packages/kernel/test/scheduler/priority.test.ts`, `packages/kernel/test/scheduler/fairness.test.ts`

| Id | Given | Then |
|---|---|---|
| M1.5-E1 | a `background`, a `normal`, and an `interactive` command (in that `seq` order) and one slot at a time | claimed `interactive`, `normal`, `background` (`priority.test.ts`) |
| M1.5-E2 | a `background` command runnable since t0 and a `normal` one admitted later; picks at t0 + 29 s and at t0 + 30 s; and a `background` command delayed 60 s, picked 10 s after it came due | at 29 s the `normal` one first; at 30 s the `background` one first (it counts as `normal` and has the lower `seq`); the delayed one still counts as `background` (`priority.test.ts`) |
| M1.5-E3 | 3 commands in workspace A, 3 in workspace B, and 3 global-scope commands (no workspace), one slot at a time | claims alternate between the three participants (no workspace, A, B, …) (`fairness.test.ts`) |
| M1.5-E4 | in one workspace, lanes `f1` and `f2` with 2 messages each and 2 keyless messages of one handler, one slot at a time, each settled before the next pick | the three queues take turns: one message from each before any second one (`fairness.test.ts`) |
| M1.5-E5 | one handler's keyless queue with `normal` seq 1, `interactive` seq 2, `normal` seq 3 | claimed seq 2, 1, 3 (`priority.test.ts`) |

### Limits (`03` §3.4, ADR 0060) — `packages/kernel/test/scheduler/limits.test.ts`

| Id | Given | Then |
|---|---|---|
| M1.5-E6 | a keyless command whose definition sets `concurrency: 2` with 5 pending, and one without `concurrency` with 20 pending | 2 and 16 in flight; settling one claims the next of that handler |
| M1.5-E7 | 70 pending commands of one extension spread over 5 handlers, and an ample host | 64 in flight; the next is claimed when one settles |
| M1.5-E8 | a host with cap 8, 10 pending commands, then 3 queries | 6 commands in flight (75%, rounded down); 2 queries are dispatched into the reserved share; the third waits until a query or command ends |
| M1.5-E9 | a command in lane `f1` that defers (`awaiting`) and the next `f1` message | settling the deferred invocation releases the lane: the next `f1` message is claimed while the first stays `awaiting` (ADR 0063) |

### Queries (`03` §3.4) — `packages/kernel/test/scheduler/queries.test.ts`

| Id | Given | Then |
|---|---|---|
| M1.5-E10 | pending commands filling a lane and a handler's concurrency, then a `normal` query and an `interactive` query | both queries are dispatched ahead of any further command, `interactive` first, with handler `query:<type>` and attempt 1; no row is stored |

### Claims (`03` §3.4) — `packages/kernel/test/scheduler/claims.test.ts`

| Id | Given | Then |
|---|---|---|
| M1.5-E11 | a pending command and a pending event delivery | each is `running` in SQLite and gone from the index; the dispatcher receives the stored message (lane without its extension prefix), the extension, the handler (`command:<type>`, `subscription:<pattern>`), and attempt 1 |
| M1.5-E12 | a pending message whose row was changed to `cancelled` before the claim | it is not dispatched and leaves the index; its lane is free for the next message |

### Timers (`02` §2.2, ADR 0051) — `packages/kernel/test/scheduler/timers.test.ts`

| Id | Given | Then |
|---|---|---|
| M1.5-E13 | a send with `delayMs: 5000`, one with `at` = now + 2000, and one with neither | the undelayed one is claimed at once; the others only when the manual timer fires at their `notBefore`, earliest first |
| M1.5-E14 | a message delayed 5 s in lane `f1` and an undelayed `f1` message after it | the undelayed one is claimed at once (a timer does not block its lane); the delayed one joins the lane when due and is claimed after the other settles |
| M1.5-E15 | a scheduler rebuilt from SQLite with a pending timer | the timer is armed again and fires at its `notBefore` |

### Retries and dead letters (`03` §3.4, `02` §2.12, ADRs 0059, 0061, 0062) — `packages/kernel/test/scheduler/retries.test.ts`

| Id | Given | Then |
|---|---|---|
| M1.5-E16 | a command without `maxAttempts` failing each attempt | retried after 1 s and 5 s; the third failure makes it `dead` with 3 attempts |
| M1.5-E17 | a retrying message in lane `f1` and a later `f1` message | during the backoff the later message is not claimed; the retried one runs first, then the later one (FIFO per lane) |
| M1.5-E18 | an invocation conflicting 5 times, then a sixth time, then its next attempt conflicting once | the first 5 redispatch it at once with the same attempt and no `attempts` change; the sixth sets `attempts` 1 and `notBefore` now + 1 s; the next attempt's conflict redispatches at once again |
| M1.5-E19 | a dead message's reply, and its event | the reply is `{ ok: false, problem: MESSAGE_DEAD }` whose detail names the last attempt's code; the event has `correlationId` of the message, `causationId` = its id, source `kernel`, and its workspace; a dead global-scope message gives an event without a workspace |
| M1.5-E20 | a scheduler rebuilt from SQLite while a lane message waits for its retry backoff | the later message of that lane is still not claimed before the retry runs |
