# M1.1 — Monorepo: test cases

Read: `01` §1.4, `12` §12.1, `CLAUDE.md`; ADR 0009 (M1.1).

Lint tests run ESLint with the repository's `eslint.config.js` and `cwd` set to `test/fixtures/lint-repository/`, a small tree of `package.json` files (packages `sdk`, `kernel`, `cli`, `testkit`; extensions `notes`, `tasks`, `other`). Each fixture in `test/fixtures/lint/` is linted as if it were at a path inside that tree (the "virtual path"), which decides the wall that applies. In the fixture tree, `kernel` declares `better-sqlite3`; `notes` declares `marked`, the devDependency `fast-check`, and the `kvman.dependencies` entry `@kvman/tasks`; `tasks` exports `./connector` (`src/connector.ts`); `other` exports `./helper` and is no dependency of `notes`.

## Happy path

### M1.1-H1 — every gate passes on the empty packages
- **Given** the empty packages `packages/sdk`, `kernel`, `cli`, and `testkit`
- **When** `pnpm typecheck`, `pnpm lint`, `pnpm build`, and `pnpm bench:check` run (`pnpm test` runs this scenario)
- **Then** each exits 0; `bench:check` reported that there were no benchmarks until M1.3 added the first one, and since then it runs as its own gate, never inside `pnpm test` (measuring under the test suite's load would be meaningless), so the test runs the other three; `pnpm build` writes `dist/index.js` and `dist/index.d.ts` for every package, and the packages are named `@kvman/sdk`, `@kvman/kernel`, `kvman`, and `@kvman/testkit`
- Test: `test/tooling/gates.test.ts`

### M1.1-H2 — a file that breaks a wall fails lint
- **Given** a fixture that imports `@kvman/kernel`
- **When** it is linted at `packages/sdk/src/fixture.ts`
- **Then** lint reports one `kvman/import-walls` error saying `packages/sdk` may not import `@kvman/kernel`
- Test: `test/tooling/import-walls-packages.test.ts`

### M1.1-H3 — a 301-line file fails lint
- **Given** a 301-line fixture
- **When** it is linted at `packages/kernel/src/fixture.ts`
- **Then** lint reports one `max-lines` error
- Test: `test/tooling/max-lines.test.ts`
