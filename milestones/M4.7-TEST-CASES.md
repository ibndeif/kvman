# M4.7 — The VS Code view, reviewed: test cases

Read: `15`; `06` §6.2, §6.4; `08` §8.7; ADR 0101.

The layers are those of M4.6: the session's decisions (`session.test.ts`), the controller with a fake host, the entry with the fake `vscode` module, the view's page in `happy-dom` (where a message's origin is set by the test), kvwebui's pages mounted with the fake API, and kvcoder's components. The by-hand check runs in a real VS Code, as in M4.2, and is recorded at the end.

## Happy path

### M4.7-H1 — the page passes the extension's messages from its own origin, and has no padding
- **Given** the view's page framing kvman on 3911
- **When** messages `kvman.pages`, `kvman.new`, and `kvman.insert` come at the page's own origin, with no source and with a source that isn't the page's parent
- **Then** each is posted to the frame at `http://127.0.0.1:3911`; the stylesheet gives `body` no padding
- Test: `packages/vscode/test/web/relay.test.ts`, `packages/vscode/test/manifest.test.ts`

### M4.7-H2 — the frame offers New, and a press reaches the page
- **Given** a framed kvman whose frame said `kvman.state`
- **When** the frame posts `kvman.actions` with `new: true`, then the person presses New
- **Then** the context key `kvman.canNew` is set true, and the frame gets `{ kind: 'kvman.new' }`
- Test: `packages/vscode/test/session.test.ts`, `packages/vscode/test/extension.test.ts`

### M4.7-H3 — a page's New offer, in kvwebui
- **Given** an embedded page whose component calls `kvman.host.offerNew(handler)`
- **When** it mounts, the host sends `kvman.new`, and the component unmounts
- **Then** the page posts `{ kind: 'kvman.actions', new: true }`, the handler runs once, and the page posts `{ kind: 'kvman.actions', new: false }`
- Test: `extensions/kvwebui/test/web/embedded-host.test.ts`

### M4.7-H4 — `kvman.lost` with kvman gone starts kvman again in a new frame
- **Given** a window that joined kvman on 3911, with its frame ready
- **When** the frame posts `kvman.lost`, the health check finds nothing, and the new start's `running` line comes at the same address
- **Then** kvman is started; the frame view is a new one (its start number changed), so the page loads it again; the frame waits for its own `kvman.state`
- Test: `packages/vscode/test/session.test.ts`

### M4.7-H5 — a `running` line of the same start keeps the frame ready
- **Given** a framed kvman whose frame said `kvman.state`
- **When** a `restarting` line, then a `running` line at the same address come, then Pages runs
- **Then** the frame view is unchanged, and Pages sends `kvman.pages` at once
- Test: `packages/vscode/test/session.test.ts`

### M4.7-H6 — the health check has 2 seconds
- **Given** a server on a port that accepts the request and never answers
- **When** the extension checks kvman's health there
- **Then** it answers "not alive" after 2 seconds
- Test: `packages/vscode/test/health.test.ts`

### M4.7-H7 — "Add to kvman chat" adds the open file, and has Ctrl+Alt+K
- **Given** an editor on `/w/src/a.ts` with no selection
- **When** "Add to kvman chat" runs with no resource; and the manifest is read
- **Then** the text is `` `src/a.ts` ``; the manifest binds `kvman.addToChat` to `ctrl+alt+k` (`cmd+alt+k` on macOS) when `editorTextFocus`
- Test: `packages/vscode/test/add-to-chat.test.ts`, `packages/vscode/test/manifest.test.ts`

### M4.7-H8 — the manifest's New button and description
- **Given** the manifest
- **When** it is read
- **Then** `kvman.new` has the `$(add)` icon, is first in `view/title` when `view == kvman.view && kvman.canNew`, and the description says the primary side bar, in English and Arabic
- Test: `packages/vscode/test/manifest.test.ts`

### M4.7-H9 — the embedded pages menu: panels and Language
- **Given** an embedded `notes` page whose extension has the `help` panel, with English and Arabic catalogs
- **When** the host sends `kvman.pages`, the person picks Help, closes the sheet, opens the menu again, opens Language, and picks العربية
- **Then** the menu lists the nav items, Help, Settings, Extensions, and "Language English"; Help opens a sheet titled Help with a close button that closes it; the pick runs `kernel.settings.set` with `kernel.language` `ar` globally, and the page turns Arabic and right to left
- Test: `extensions/kvwebui/test/web/embedded-menu.test.ts`

### M4.7-H10 — the embedded status line
- **Given** an embedded `notes` page whose extension has a status item
- **When** the page is shown
- **Then** a status line at the bottom shows the item's text, and no workspace folder
- Test: `extensions/kvwebui/test/web/embedded-status.test.ts`

### M4.7-H11 — kvman not answering, while embedded
- **Given** an embedded page
- **When** two calls find kvman not answering, then a call reaches kvman, then another call finds it not answering
- **Then** the page posts `kvman.lost` once for the first two and again for the last; no toast shows; the status line says "kvman doesn't answer. Reconnecting…" while kvman doesn't answer
- Test: `extensions/kvwebui/test/web/embedded-status.test.ts`

### M4.7-H12 — identical toasts show once
- **Given** an open error toast "Nope."
- **When** the same toast is shown again, then one with another text
- **Then** two toasts are open
- Test: `extensions/kvwebui/test/web/toasts.test.ts`

### M4.7-H13 — kvcoder offers New while embedded
- **Given** kvcoder's conversation, embedded, on a chat
- **When** it is shown, and the host sends `kvman.new`
- **Then** the compact header has History and no New chat button; the page opens the Chat page with no chat
- Test: `extensions/kvcoder/test/web/compact-header.test.ts`

### M4.7-H14 — one picker's menu at a time
- **Given** the composer's model and thinking pickers
- **When** the model picker's menu is opened, then the thinking picker's
- **Then** only the thinking picker's menu is open
- Test: `extensions/kvcoder/test/web/composer-pickers.test.ts`

## Edge cases

### M4.7-E1 — a message at another origin isn't the extension's
- **Given** the view's page
- **When** `{ from: 'extension', message: { kind: 'kvman.insert', text } }` comes from kvman's origin, from an artifact's `null` origin, and from `http://127.0.0.1:5173`
- **Then** none is posted to the frame as an insert
- Test: `packages/vscode/test/web/relay.test.ts`

### M4.7-E2 — a lost frame hides New
- **Given** a frame that offered New
- **When** kvman's process ends, or a new start's `running` line comes
- **Then** `kvman.canNew` is set false; a New press before the new frame says `kvman.state` sends nothing
- Test: `packages/vscode/test/session.test.ts`

### M4.7-E3 — `kvman.lost` with kvman answering, or in the window that owns it, changes nothing
- **Given** a joined window, and a window that owns kvman
- **When** each frame posts `kvman.lost`; in the joined one the health check answers
- **Then** the joined window starts nothing; the owner checks nothing, since its own process tells it when kvman ends
- Test: `packages/vscode/test/session.test.ts`

### M4.7-E4 — no offer, or not embedded
- **Given** an embedded page with no New offer, and a page that isn't embedded
- **When** the host sends `kvman.new`; the page that isn't embedded offers New and a call finds kvman not answering
- **Then** nothing runs; the page that isn't embedded posts nothing, and shows the OFFLINE toast as before
- Test: `extensions/kvwebui/test/web/embedded-host.test.ts`, `extensions/kvwebui/test/web/embedded-status.test.ts`

### M4.7-E5 — a status line with nothing to show is hidden
- **Given** an embedded page whose extensions have no status items, and kvman answering
- **When** the page is shown
- **Then** there is no status line
- Test: `extensions/kvwebui/test/web/embedded-status.test.ts`

### M4.7-E6 — a webview's subscriptions end with it
- **Given** the view resolved, and the Settings tab open
- **When** VS Code disposes the view, and the Settings tab is closed
- **Then** their message and visibility subscriptions are disposed
- Test: `packages/vscode/test/extension.test.ts`

### M4.7-E7 — nothing to add
- **Given** no editor and no resource, and an editor on an untitled document with no selection
- **When** "Add to kvman chat" runs
- **Then** there is nothing to add, and the view isn't shown
- Test: `packages/vscode/test/add-to-chat.test.ts`

## The by-hand check

Done on 2026-10-22, on Linux, in VS Code 1.141.2 with a profile and extensions folder of its own, the repository's kvman on port 3911 with a home of its own, and a second VS Code instance with another profile on another folder, both driven through their debugging ports, as in M4.2.

- **Before the fixes**, the review found what ADR 0101 lists: Pages and "Add to kvman chat" did nothing (the extension's messages came with an `event.source` that isn't the page's `window.parent`); the frame was 257 px wide in a 297 px view (VS Code's `body { padding: 0 20px }`); the Models page had two scrollbars (kvai's hidden label stretched the document to 1670 px); the composer's pickers were clipped; and closing the window that owned kvman left the other window with four "kvman didn't answer" toasts and no kvman.
- **The view.** The frame is 297 px wide, the root has `kvwebui-embedded`, and the title bar reads New, Pages, Settings, Open in browser. The composer's attach, model, thinking, and "Decide for me" buttons and Send are one row.
- **Pages** opened the menu: Chat, Models, Settings, Extensions, then Language "English". Language → العربية turned the view Arabic and right to left; English turned it back.
- **The Models page** scrolls once (`scrollHeight` 794 of 794 for the document), with a thin scrollbar and a 1.25rem title.
- **New** shows on the Chat page and is gone on the Models page; it comes back on the way back.
- **The status line** shows "Waiting for you: 0" and kvai's workspace total.
- **Ctrl+Alt+K** in `app.ts` with no selection put `` `app.ts` `` in the send box; a drag over lines 1 to 3 then "Add to kvman chat" put the path, the lines, and the fenced code.
- **Settings** opened the "kvman Settings" tab, its frame 786 px wide, edge to edge.
- **Two windows.** The second instance joined the running kvman. Quitting the first stopped that kvman within a second; within 5 seconds the second window had started its own kvman (a new process on 3911), reloaded its frame, and showed no toast, in VS Code's light theme. Quitting the second stopped its kvman within a second, and port 3911 was free.
- **Not driven**: a panel sheet (no bundled extension has a panel; covered by M4.7-H9), and a New press on a chat (there is no model key in the test home; covered by M4.7-H2, H3, and H13).
