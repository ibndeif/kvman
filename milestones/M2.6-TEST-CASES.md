# M2.6 — Processes, local socket, `kv`: test cases

Read:

- `03` §3.7, `12` §12.4, §12.6.
- The parts they cite:
  - `02` §2.4 (access), §2.6 (priority), §2.9 (cancel), §2.10 (context);
  - `03` §3.3 (admission), §3.5 (the `process.*` calls), §3.8 (`kernel.processes.list`), §3.9 (boot step 6, shutdown);
  - `04` §4.1 (the `processes` table), §4.4 (forget), §4.9 (retention);
  - `05` §5.4 (`ctx.process`), §5.7 (capabilities);
  - `10` §10.2 (how `shell` uses processes);
  - `13` §13.2, §13.6;
  - `14` §14.3: the fault points `process.after-spawn-before-release`, `process.after-release`, and `process.after-exit-before-onexit`; invariants 5 and 13.
- ADRs 0088, 0122, 0133, 0134, and 0139–0141.

Where the tests live:

- **Pure pieces**, in `packages/kernel/test/processes/`: output capture, the gated start, reconciliation of a reused PID, the `kv` argument parser, help rendering, socket frames, and the process calls on forged frames.
- **Through a runtime**, in `packages/testkit/test/processes/`. The runtime has a home folder, installed fixture snapshots (ADR 0114), applied presets written by the test helper (ADR 0124), the socket adapter on `<home>/kernel.sock`, and the `kv` shim in `<home>/bin`. Its clock is the fake one of the test. The processes are real.
- **Crash points, restarts, and boot**, in `packages/testkit/test/faults/processes.test.ts`, `packages/testkit/test/processes/restart.test.ts`, and `packages/testkit/test/daemon/socket-boot.test.ts`, on child kernels and daemons.
- **Protocol shapes**, in `packages/protocol/test/processes.test.ts`.

Terms used in the scenarios:

- "**Person**" is `user:local`.
- "**Runner**" is the fixture `@acme/runner` (namespace `runner`). It is enabled sandboxed with `process` unless a scenario says otherwise. Its types:
  - `runner.run {spawn, before?, wait?, waitTwice?, read?}` spawns each of `before` without waiting, then `spawn`. With `wait` it waits and returns `{ processId, result }` (with `read`, also `log`, the log blob's text read with `blobs.text`; with `waitTwice`, also `again`, a second `wait()`). Otherwise it returns `{ processId }`. A failure returns `{ code, params? }`.
  - `runner.hold` does the same with a handler `timeoutMs` of 1,000 and one attempt; `runner.global.run` (scope `global`) does the same without a workspace.
  - `runner.kill {processId}` calls `ctx.process.kill`.
  - `runner.finish` (internal) is the `onExit` command. Its input has `logBlobId: z.blobId()`. It records the payload, its message envelope (source, context, priority, correlation, causation, idempotency key, workspace), and the log text.
  - The query `runner.exits.list` returns what `runner.finish` recorded; the query `runner.probe.get` tries a spawn.
  - The kv targets:
    - `runner.echo {text}` returns `{ text, message }` with its message envelope; being access `all`, it is also the wrong `onExit` of E3;
    - `runner.status.get` is a query;
    - `runner.reveal` has access `user`;
    - `runner.record` has access `internal`;
    - `runner.serve` has access `extensions`;
    - `runner.defer` defers its reply; `runner.fail` throws `runner/FAILED`.
  - `runner.output.written` is a live event with text chunks.
- "**Target**" is `@acme/target` (namespace `target`), with no capabilities. `target.ping {text}` (access all) echoes; `target.serve` has access `extensions`; `target.approve` has access `user`.
- "**Delegator**" is `@acme/delegator` (namespace `delegator`), with `calls ['runner.run', 'target.ping', 'target.serve']`. `delegator.start {spawn, context?}` `ctx.command`s `runner.run` with the options it is given, adding `context` to the chain.
- A **token process** prints its job token and sleeps, detached with `onExit: 'runner.finish'`; the test reads the token from its log and sends frames on `kernel.sock` itself.
- A **workspace folder** is a temporary folder, never the real `~/kvman`; `A` is its workspace. The home folder is a temporary folder, never the real `~/.kvman`.
- "**`sh -c`**" scripts use only POSIX tools (`sleep`, `echo`, `cat`, `printf`).

## Happy path

### M2.6-H1 — a killed kernel leaves no orphan process after restart
- **Test**: `packages/testkit/test/processes/restart.test.ts`
- **Given** a child kernel in which Runner spawned `sleep 1000` twice, once detached (with `onExit: 'runner.finish'`) and once not, and both PIDs are alive.
- **When** the child kernel is killed with SIGKILL and started again on the same home folder.
- **Then**:
  - both PIDs are gone once boot finishes;
  - both `processes` rows are `state 'killed'`, `reason 'kernel-restart'`;
  - `kernel.processes.list` lists neither as running (the interrupted `runner.run` is redelivered and may start a new one).

### M2.6-H2 — a token cannot call a type outside its set or any access-user type
- **Test**: `packages/testkit/test/processes/socket.test.ts`
- **Given** Runner spawned a process with the token `{ calls: ['runner.echo', 'runner.reveal'] }`.
- **When** the process sends `runner.echo`, `runner.status.get` (not in the set), and `runner.reveal` (access `user`, in the set) over `kernel.sock`.
- **Then**:
  - `runner.echo` answers `{ ok: true, data }` with `source: 'proc:<processId>'`;
  - `runner.status.get` answers `CAPABILITY_DENIED`;
  - `runner.reveal` answers `CALLER_NOT_ALLOWED`;
  - no message row exists for the refused two.

### M2.6-H3 — kv help lists only allowed types
- **Test**: `packages/testkit/test/processes/kv.test.ts`
- **Given** Runner spawned `sh -c 'kv help'` with the token `{ calls: ['runner.*', 'target.ping'] }`.
- **When** the process ends.
- **Then**:
  - its output lists `runner.echo`, `runner.status.get`, `runner.serve`, `runner.defer`, `runner.fail`, `runner.run`, and the other access-`all` or access-`extensions` types of Runner, one per line with kind and description;
  - it lists no `runner.reveal` (user), `runner.record` or `runner.finish` (internal), and no `target.ping` (Runner has no `calls` grant for it);
  - the exit code is 0.

### M2.6-H4 — a detached process delivers exactly one onExit when it exits
- **Test**: `packages/testkit/test/processes/detached.test.ts`
- **Given** Runner spawned `sh -c 'echo done'` with `detached: true, onExit: 'runner.finish'`, and `runner.run` returned.
- **When** the process exits by itself.
- **Then**:
  - exactly one `runner.finish` message exists, with idempotency key `<processId>:exit`;
  - its payload is `{ processId, exitCode: 0, signal: null, reason: 'exited', logBlobId, tail: 'done\n', truncated: false, durationMs }`;
  - Runner read the log text `done\n` through the `z.blobId()` field;
  - the `processes` row is `state 'exited'`.

### M2.6-H5 — a detached process delivers exactly one onExit when it is killed
- **Test**: `packages/testkit/test/processes/detached.test.ts`
- **Given** Runner spawned `sleep 1000` detached with `onExit: 'runner.finish'`.
- **When** `runner.kill {processId}` kills it from another invocation, and `runner.kill` is sent a second time.
- **Then**:
  - the PID is gone;
  - exactly one `runner.finish` exists, with `reason: 'killed'`, `signal: 'SIGTERM'`, and `exitCode: null`;
  - the second kill succeeds as a no-op.

### M2.6-H6 — a detached process delivers exactly one onExit when a kernel restart kills it
- **Test**: `packages/testkit/test/processes/restart.test.ts`
- **Given** a child kernel in which Runner spawned `sleep 1000` detached with `onExit: 'runner.finish'`.
- **When** the kernel is killed and started again, and then started a third time.
- **Then**:
  - after the second start, exactly one `runner.finish` exists, with `reason: 'kernel-restart'`, the spawning message's context and correlation, and a readable `logBlobId`;
  - the third start adds none.

### M2.6-H7 — forgetting a workspace with a running process kills it and leaves no processes row
- **Test**: `packages/testkit/test/processes/forget.test.ts`
- **Given** Runner in A spawned `sleep 1000` detached with `onExit: 'runner.finish'`, and `sleep 1000` from a handler still waiting.
- **When** the person forgets A.
- **Then**:
  - both PIDs are gone;
  - `runner.finish` ran before the deletion, with `reason: 'killed'`; its row is gone with the rest of A's messages;
  - no `processes` row and no `process:<id>` blob ref names either process;
  - `kernel.workspace.forgotten` is stored.

## Edge cases

**Spawning and waiting**

### M2.6-E1 — spawn and wait return the process's result
- **Test**: `packages/testkit/test/processes/api.test.ts`
- **When** Runner spawns and waits for `sh -c 'printf a; printf b 1>&2; printf c; cat; pwd; echo "$X-$KVMAN_HOME_TEST"'`, with `stdin: 'in'`, `env: { X: 'x' }`, `read: true`. The daemon environment of the test holds `KVMAN_HOME_TEST=secret`.
- **Then**:
  - the result is `{ exitCode: 0, signal: null, truncated: false }`, with `durationMs ≥ 0`;
  - the log text is `abcin<workspace root>\nx-\n`: the streams interleave in order, stdin arrives, `cwd` is the workspace root, and the `KVMAN_*` variable is removed;
  - `tail` equals the log text;
  - the log blob is `text/plain`, held by the ref `process:<processId>` (owner `kernel`), and readable by Runner in that invocation;
  - `<home>/jobs/<processId>.log` no longer exists.

### M2.6-E2 — without the process capability, and in a query, spawn is refused
- **Test**: `packages/testkit/test/processes/api.test.ts`
- **Given** Runner is enabled in workspace B without `process`.
- **When** it spawns and kills there, and the query `runner.probe.get` spawns in A.
- **Then** each fails `CAPABILITY_DENIED`, and no `processes` row is written.

### M2.6-E3 — invalid spawn options fail VALIDATION_FAILED
- **Test**: `packages/testkit/test/processes/api.test.ts`
- **When** Runner spawns with each of:
  - `detached: true` without `onExit`;
  - `onExit: 'runner.echo'` (not internal);
  - `onExit: 'target.ping'` (not its own);
  - `onExit` without `detached`;
  - `timeoutMs: 86_400_001`;
  - `logCapBytes: 104_857_601`.
- **Then** each fails `VALIDATION_FAILED`, and nothing is spawned or recorded.

### M2.6-E4 — the working folder is jailed in the workspace
- **Test**: `packages/testkit/test/processes/api.test.ts`
- **Given** A's folder holds `sub/` and `out`, a symlink to a folder outside it.
- **When** Runner spawns `pwd` with each of these `cwd` values:
  - `sub`, and an absolute path to it;
  - `..`, `/tmp`, and `out`;
  - `missing`;
  - a file.
  And `runner.global.run` spawns without `cwd`, and with an absolute temporary folder.
- **Then**:
  - `sub` and its absolute path work;
  - `..`, `/tmp`, and `out` fail `WORKSPACE_ESCAPE`;
  - `missing` and the file fail `NOT_FOUND`;
  - `runner.global.run` without `cwd` fails `WORKSPACE_INVALID`;
  - with the absolute folder, it prints that folder.

### M2.6-E5 — a missing command exits 127
- **Test**: `packages/testkit/test/processes/api.test.ts`
- **When** Runner spawns and waits for `kvman-no-such-command`.
- **Then** the result has `exitCode: 127`, and the log names the command.

### M2.6-E6 — output over the cap is truncated and drained
- **Test**: `packages/testkit/test/processes/output.test.ts`
- **When** Runner spawns and waits for a script that prints 64 KB of `x` followed by `END`, with `logCapBytes: 1024`.
- **Then**:
  - the process exits 0: it never blocks;
  - the log is 1,024 bytes of `x` followed by `\n[kvman: output truncated at 1024 bytes]\n`;
  - `truncated` is `true`;
  - `tail` is the last 4 KB of kept output, which here is the whole kept log;
  - the row's `truncated` is 1.

### M2.6-E7 — tail, log cap, and live chunks at the byte level
- **Test**: `packages/kernel/test/processes/process-output.test.ts`
- **Given** a `ProcessOutput` with a 10,000-byte cap, a 100 ms coalescing window on a fake clock, and a recording live sink.
- **When** it receives chunks with multi-byte UTF-8 characters split across chunks and across the 4 KB tail boundary, then passes the cap.
- **Then**:
  - `tail` is at most 4,096 bytes and starts on a character boundary;
  - live chunks arrive only when the clock moves 100 ms, each within the 16 KB live payload limit, with no split characters;
  - after the cap, bytes are counted but not written and not streamed, and the marker is written once.

### M2.6-E8 — live output streams under the spawner's run
- **Test**: `packages/testkit/test/processes/output.test.ts`
- **When**:
  - Runner spawns and waits for `printf hello` with `live: 'runner.output.written:job-1'`;
  - separately, Runner spawns with `live: 'target.ping:x'` and with `live: 'runner.echo:x'`.
- **Then**:
  - before the result returns, the live bus carries `{ text: 'hello' }` on `runner.output.written:job-1` (what is buffered is flushed at the end), with `run` set to the `runner.run` message;
  - `target.ping:x` and `runner.echo:x` fail `CAPABILITY_DENIED` (not an own live event).

### M2.6-E9 — a process that is not detached ends with its invocation
- **Test**: `packages/testkit/test/processes/api.test.ts`
- **When**:
  - `runner.run` spawns `sleep 1000` without waiting and returns;
  - separately, `runner.hold` (handler `timeoutMs` 1,000, one attempt) waits on `sleep 1000`, and the clock passes the timeout.
- **Then**:
  - both PIDs are gone;
  - both rows are `state 'killed'`, `reason 'killed'`;
  - `runner.hold` ends dead, `MESSAGE_DEAD`, since its one attempt timed out.

### M2.6-E10 — timeoutMs kills with SIGTERM, then SIGKILL after 3 s
- **Test**: `packages/testkit/test/processes/kill.test.ts`
- **When**:
  - Runner spawns and waits for `sleep 1000` with `timeoutMs: 500`, and the clock moves 500 ms;
  - separately, it spawns `sh -c 'trap "" TERM; echo ready; while :; do sleep 1; done'`, with `timeoutMs: 500`. Once its log file shows `ready`, the clock moves 500 ms, then 3 s.
- **Then**:
  - the first ends with `signal: 'SIGTERM'`;
  - the second is still alive after SIGTERM, and ends with `signal: 'SIGKILL'` after the 3 s;
  - both have `reason: 'killed'`.

### M2.6-E11 — kill and wait are idempotent and scoped
- **Test**: `packages/testkit/test/processes/kill.test.ts`
- **When**:

  - Runner kills its own process that has already ended.
- **Then**:
  - both waits return the same result;
  - the unknown id fails `NOT_FOUND`;
  - the ended one resolves without effect.

### M2.6-E12 — the process group ends with its leader

### M2.6-E15 — the same sample spawns in every isolation mode

**The kv shim**

### M2.6-E28 — kv maps flags by the input schema
- **Test**: `packages/kernel/test/processes/kv-arguments.test.ts`
- **When** the parser reads, against a schema with `fileId: string`, `count: integer`, `ratio: number`, `force: boolean`, `tags: string[]`, and `meta: object`:
  - `--file-id a --count 3 --ratio 0.5 --force --tags x --tags y --meta '{"k":1}'`;
  - `--no-force`;
  - `--count x`;
  - `--unknown 1`;
  - `--count`;
  - `--wait 70000`;
  - `--json -` with stdin;
  - `--meta-file -` with stdin.
- **Then**:
  - the first gives `{ fileId: 'a', count: 3, ratio: 0.5, force: true, tags: ['x', 'y'], meta: { k: 1 } }`;
  - `--no-force` gives `force: false`;

  - `--wait 70000` is a usage error (above 60,000);
  - `--json -` takes the whole payload from stdin;
