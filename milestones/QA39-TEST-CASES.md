# QA 39 — `/build-kvman` in place of `kvman init`, and kvcustomizer becomes kvbuilder (ADR 0027)

Asked: "we have did an update earlier to not auto load customizer stuff in the main agent prompt and implemented a new slash command to load them and start customizing kvman, but i can't see it in this release"; then "I don't want the agent to call it and we need to init it with a slash command", "change the command name to '/build-kvman' and also rename customizer extension to kvman builder".

It replaces QA35-H1 to H4, H9 to H11, and E1 to E5, whose subject was `kvman init`. QA35-H5 to H8, E6, and E7 now hold for the text of `docs/guide.md` and are in `extensions/kvbuilder/test/guide.test.ts`. Every earlier scenario that names `kvcustomizer` is read with `kvbuilder`.

## Happy path

- **QA39-H1 `/build-kvman` is in the send box's list.** *Given* the `coder` extensions and an open chat, *when* the person types `/bu`, *then* the list has one row, `/build-kvman`, with the description "Start building kvman in this chat". `extensions/kvbuilder/test/e2e/build-kvman.test.ts`
- **QA39-H2 A bare `/build-kvman` loads the guide and starts a turn.** *When* the person runs `/build-kvman`, *then* the chat shows the note "Building kvman is on for this chat", then the person's message "I want to change this app.", and a turn runs whose request to the model has the guide in its system prompt. `extensions/kvbuilder/test/e2e/build-kvman.test.ts`
- **QA39-H3 `/build-kvman <request>` starts on the request.** *When* the person runs `/build-kvman add a notes page`, *then* the person's message is "add a notes page", with `source.kind` `user`, and the translated line isn't sent. `extensions/kvbuilder/test/e2e/build-kvman.test.ts`
- **QA39-H4 Before the command, a chat knows nothing about building kvman.** *Given* a new session, *then* its prompt has no section of `@kvman/kvbuilder`, its connector index has none of `kvman`, `ext`, `preset`, `preview`, and `docs`, and it doesn't contain "Build an extension, in this order" or "Manage the app:". `extensions/kvbuilder/test/build-start.test.ts`
- **QA39-H5 `kvbuilder.build.start` sets the guide, enables the connectors, and adds the note.** *When* it runs with `{ sessionId, argument: '' }`, *then* it answers `{}`; `kvcoder.section.list { sessionId }` has `{ id: 'guide', title: 'Building kvman', order: 20, owner: '@kvman/kvbuilder', global: false, sessionId }`; the prompt contains the text of `docs/guide.md` and its index lists the five connectors; and the session's last message is the note `kvbuilder.build.started`. It is a public command. `extensions/kvbuilder/test/build-start.test.ts`
- **QA39-H6 kvbuilder registers its slash command.** *Then* `kvcoder.slash.list` answers `[{ name: 'build-kvman', description: 'kvbuilder.slash.build-kvman', command: 'kvbuilder.build.start', message: 'kvbuilder.slash.build-kvman.message', owner: '@kvman/kvbuilder' }]`, and both keys are in the `en` and `ar` catalogs. `extensions/kvbuilder/test/registration.test.ts`
- **QA39-H7 kvbuilder's connectors are `optIn`.** *Then* `kvcoder.connector.list` has `kvman`, `ext`, `preset`, `preview`, and `docs` with `optIn: true`, and their commands are the QA34 ones. `extensions/kvbuilder/test/registration.test.ts`
- **QA39-H8 There is no `init`.** *Then* the `kvman` connector has no command `init`, its description doesn't contain "init", and no query `kvbuilder.app.guide.get` is registered. `extensions/kvbuilder/test/registration.test.ts`
- **QA39-H9 The extension is kvbuilder.** *Then* `kernel.extensions.list` has `@kvman/kvbuilder` with the namespace `kvbuilder` and none named `@kvman/kvcustomizer`; every command and query of it starts with `kvbuilder.`; `kvbuilder.title` is "kvman builder"; and the bundled `coder` preset lists `@kvman/kvbuilder`. `extensions/kvbuilder/test/rename.test.ts`
- **QA39-H10 The docs page is `building`.** *Then* `kvbuilder.docs.list` answers only `building`; the page describes `/build-kvman` and has no `init`; `kvbuilder.docs.get { topic: 'guide' }` fails `NOT_FOUND`. `extensions/kvbuilder/test/docs-own.test.ts`
- **QA39-H11 An extension registers slash commands.** *Given* an extension with the public command `todo.list.start`, *when* it calls `kvcoder.slash.register { commands: [{ name: 'todo', description: 'todo.slash.todo', command: 'todo.list.start' }, { name: 'todo-add', description: 'todo.slash.add', command: 'todo.list.start', message: 'todo.slash.add.message' }] }`, *then* `kvcoder.slash.list` answers both, by name, each with `owner`, and `message` only where it was given. `extensions/kvcoder/test/slash-register.test.ts`
- **QA39-H12 The owner unregisters one.** *When* it calls `kvcoder.slash.unregister { name: 'todo' }`, *then* the list has only `todo-add`. `extensions/kvcoder/test/slash-register.test.ts`
- **QA39-H13 An `optIn` connector is off until enabled.** *Given* a connector registered with `optIn: true`, *then* `kvcoder.connector.list` has it with `optIn: true` (and any other with `false`), and a new session's prompt index and `run` tool enum don't have it; *when* its owner calls `kvcoder.connector.enable { sessionId, names: [name] }`, *then* both have it, and a `run` call of it runs. `extensions/kvcoder/test/connector-opt-in.test.ts`
- **QA39-H14 The send box lists registered commands after kvcoder's own.** *Given* `kvcoder.slash.list` answers `build-kvman` and `todo`, *when* `/` is typed, *then* the rows are `compact`, `export`, `fork`, `new`, `prompt`, `rename`, `build-kvman`, `todo`, each registered one with its translated description; `/to` shows only `todo`, and Tab completes it. `extensions/kvcoder/test/web/slash-registered.test.ts`
- **QA39-H15 Running a registered command calls it, then sends its message.** *When* `/todo-add milk` runs, *then* `todo.list.start` is called with `{ sessionId, argument: 'milk' }` and then `kvcoder.message.send` with `{ sessionId, text: 'milk' }`; a bare `/todo-add` sends the translated text of `todo.slash.add.message`; and `/todo`, which has no `message`, calls its command with `argument: ''` and sends nothing. `extensions/kvcoder/test/web/slash-registered.test.ts`

## Edge cases

- **QA39-E1 kvcoder's own names are taken.** *Then* registering `compact`, `export`, `fork`, `new`, `prompt`, or `rename` fails `kvcoder/NAME_TAKEN` with `owner: '@kvman/kvcoder'`. `extensions/kvcoder/test/slash-register.test.ts`
- **QA39-E2 Another extension's name is taken.** *Given* `todo` registered by one extension, *then* a second extension's `register` of `todo` fails `kvcoder/NAME_TAKEN` naming the first, and its `unregister` of it fails the same way; the entry is unchanged. `extensions/kvcoder/test/slash-register.test.ts`
- **QA39-E3 A call registers all of its commands or none.** *Then* a call with one good entry and a name given twice fails `VALIDATION_FAILED`, as does one whose second entry is invalid, and the list is unchanged after each. `extensions/kvcoder/test/slash-register.test.ts`
- **QA39-E4 The command must be the caller's public command.** *Then* a private command, another extension's command, a query, and a name nothing has each fail `VALIDATION_FAILED`. `extensions/kvcoder/test/slash-register.test.ts`
- **QA39-E5 A name is kebab case.** *Then* `Todo`, `todo_add`, and `/todo` fail `VALIDATION_FAILED`. `extensions/kvcoder/test/slash-register.test.ts`
- **QA39-E6 Only an extension registers.** *Then* `kvcoder.slash.register` called as the user fails `VALIDATION_FAILED`. `extensions/kvcoder/test/slash-register.test.ts`
- **QA39-E7 Unregistering a missing name does nothing.** *Then* it answers `{}`. `extensions/kvcoder/test/slash-register.test.ts`
- **QA39-E8 Slash commands last one run.** *Given* a registered command, *when* the kernel restarts, *then* the list has what the extensions registered at that start, once each. `extensions/kvcoder/test/slash-register.test.ts`
- **QA39-E9 Registering a name again replaces the caller's own.** *Then* the list has it once, with the new values. `extensions/kvcoder/test/slash-register.test.ts`
- **QA39-E10 Only the owner's `optIn` connectors can be enabled.** *Then* `kvcoder.connector.enable` fails `VALIDATION_FAILED` for a connector without `optIn`, for another extension's `optIn` connector, for a name no connector has, for kvcoder's own `shell`, and when called as the user; the session's prompt is unchanged after each. `extensions/kvcoder/test/connector-opt-in.test.ts`
- **QA39-E11 The session must be a top-level one that exists.** *Then* an unknown `sessionId` fails `kvcoder/SESSION_NOT_FOUND`, and a subagent's fails `VALIDATION_FAILED`. `extensions/kvcoder/test/connector-opt-in.test.ts`
- **QA39-E12 A call to one that isn't enabled finds no connector.** *When* the model calls `run` with an `optIn` connector the chat didn't enable, *then* the call's result is the one for a connector that doesn't exist, and the command doesn't run. `extensions/kvcoder/test/connector-opt-in.test.ts`
- **QA39-E13 `optIn` takes only `true`.** *Then* `optIn: false` fails `VALIDATION_FAILED`. `extensions/kvcoder/test/connector-opt-in.test.ts`
- **QA39-E14 Enabling is kept, and twice is once.** *Given* a connector enabled twice in a session, *when* the kernel restarts and the owner registers again, *then* the session's prompt index lists it once. `extensions/kvcoder/test/connector-opt-in.test.ts`
- **QA39-E15 Another chat is untouched.** *Given* one session with the connector enabled, *then* a second session's prompt doesn't have it. `extensions/kvcoder/test/connector-opt-in.test.ts`
- **QA39-E16 A fork starts with none enabled.** *Given* a session with the connector enabled, *then* its fork's prompt doesn't have it. `extensions/kvcoder/test/connector-opt-in.test.ts`
- **QA39-E17 A subagent follows its chat.** *Given* a worker whose connectors list an `optIn` connector, *then* its subagent's prompt has the connector when the top-level session enabled it, and not otherwise. `extensions/kvcoder/test/connector-opt-in-subagent.test.ts`
- **QA39-E18 The setting still turns it off.** *Given* an enabled `optIn` connector named in `kvcoder.connectors.disabled`, *then* the prompt doesn't have it. `extensions/kvcoder/test/connector-opt-in.test.ts`
- **QA39-E19 A session stored before `optIn` reads as none enabled.** *Then* a session record without `optedIn` parses with `optedIn: []`. `extensions/kvcoder/test/unit/old-records.test.ts`
- **QA39-E20 A registered command that fails sends nothing.** *Given* a command that fails with a Problem, *when* `/todo-add milk` runs, *then* the Problem is toasted and `kvcoder.message.send` isn't called. `extensions/kvcoder/test/web/slash-registered.test.ts`
- **QA39-E21 With no chat yet, nothing runs.** *Given* the Chat page, *when* `/build` is typed, *then* the registered row is greyed under "Send a first message to use commands", and Enter runs and sends nothing. `extensions/kvcoder/test/web/slash-registered.test.ts`
- **QA39-E22 While a chat action runs, a registered command doesn't run.** *Given* the send box is `blocked`, *then* Enter on `/todo` calls nothing. `extensions/kvcoder/test/web/slash-registered.test.ts`
- **QA39-E23 An unknown name is still "No such command".** *Given* registered commands, *then* `/nothing` shows "No such command" and runs nothing. `extensions/kvcoder/test/web/slash-registered.test.ts`
- **QA39-E24 A second `/build-kvman` adds no second note.** *When* `kvbuilder.build.start` runs twice in a session, *then* the session has one note `kvbuilder.build.started` and one section `guide`. `extensions/kvbuilder/test/build-start.test.ts`
- **QA39-E25 Another chat stays clean.** *Given* one session where `kvbuilder.build.start` ran, *then* a second session's prompt is as in QA39-H4. `extensions/kvbuilder/test/build-start.test.ts`
- **QA39-E26 An unknown session.** *Then* `kvbuilder.build.start` fails `kvcoder/SESSION_NOT_FOUND`. `extensions/kvbuilder/test/build-start.test.ts`
- **QA39-E27 The connectors work only where building is on.** *Given* the model calls `kvman settings-list` in a chat without `/build-kvman`, *then* the call's result is the one for a connector that doesn't exist; after `kvbuilder.build.start` the same call answers the settings. `extensions/kvbuilder/test/build-start.test.ts`
- **QA39-E28 The guide never mentions `init`.** *Then* `docs/guide.md` doesn't contain "init", and is at most 16 KB. `extensions/kvbuilder/test/guide.test.ts`
