# M3.2 — The desktop app: test cases

Read: `14` §14.1, §14.3–§14.6, §14.9; `02` §2.6, §2.12; `04` §4.2; `06` §6.2, §6.4; `12` §12.1; ADR 0038, 19 to 45.

No test drives the real window (ADR 0038, 36). The shell is built so that what it decides is apart from the window that carries it out:

- **The session** (Rust, `packages/desktop/src-tauri`) takes what happens (a line from kvman, a button, the window closing, kvman ending) and answers with what to do (show a dialog, write a line, load an address, quit). Its tests give it happenings and compare the answers. `cargo test` runs them.
- **The kvman process and its API** (Rust) are tested against `tests/fixtures/fake-kvman.mjs`: a Node program that writes the lines a test asks for, reads its stdin, and serves the few API routes on 127.0.0.1, recording each request's headers.
- **The page** (TypeScript, `packages/desktop/src`) is tested with vitest and `happy-dom` against a fake of the shell's functions.

Each Rust test is a function named with its scenario id (`m3_2_h1_…`); each vitest test's name starts with the id. Tests use temporary folders and never the real `~/.kvman`.

## Happy path

### M3.2-H1 — a second launch focuses the open window and starts no second kvman
- **Given** a session that has started kvman
- **When** a second launch is reported
- **Then** the one thing to do is focus the window; nothing is started
- Test: `packages/desktop/src-tauri/tests/session.rs`

### M3.2-H2 — a `trust` line shows the dialog; Accept and Quit answer it
- **Given** a session waiting for kvman's first line
- **When** the line `{ "kind": "trust", "language": "en", "versions": [two versions] }` comes; then, once, Accept is pressed, and once, Quit is pressed or the dialog is closed
- **Then** the dialog to show has both versions as `name@version (source)` and the buttons Quit and Accept; Accept writes `{"trust":true}`; Quit writes `{"trust":false}`, and the `failed` line that follows shows no dialog and quits the app
- Test: `packages/desktop/src-tauri/tests/session.rs`

### M3.2-H3 — a `failed` line shows the Problem with its hint, and Quit quits
- **Given** a session waiting for kvman's first line
- **When** `failed` lines come with `PORT_IN_USE` and `"language": "ar"`, and with the code `INTERNAL` and `"language": "en"`
- **Then** the first dialog is in Arabic with the code, the message, and the `PORT_IN_USE` hint; the second is in English with the code, the message, and `<home>/logs/kvman.log`; each has one button, and pressing it quits
- Test: `packages/desktop/src-tauri/tests/session.rs`

### M3.2-H4 — a `running` line shows the home screen, Home first
- **Given** the fake kvman with Home and two open workspaces, one under the user's home folder and one outside it
- **When** its `running` line comes and the home screen is loaded
- **Then** the session says to show the home screen; its rows are Home with `~`, then each workspace's name and folder, the one under the home folder with `~`; the page shows the title, the three rows in that order, and "Open a folder…"
- Test: `packages/desktop/src-tauri/tests/home.rs`; `packages/desktop/test/home.test.ts`

### M3.2-H5 — a click on a row loads that workspace in the same window
- **Given** the home screen with a workspace whose id is `0199-a b`
- **When** its row is clicked
- **Then** the page asks the shell to continue with that id, and the session says to load `http://127.0.0.1:<port>/?workspace=0199-a%20b` in the window
- Test: `packages/desktop/test/home.test.ts`; `packages/desktop/src-tauri/tests/session.rs`

### M3.2-H6 — the remove button closes the workspace, and Home has none
- **Given** the home screen with Home and two workspaces
- **When** one workspace's remove button is pressed
- **Then** the fake kvman got `kernel.workspace.close` with that id, the list is read again and no longer has it; Home's row has no remove button
- Test: `packages/desktop/src-tauri/tests/home.rs`; `packages/desktop/test/home.test.ts`

### M3.2-H7 — "Open a folder…" opens the chosen folder and continues into it
- **Given** the home screen, and a folder dialog that answers a folder
- **When** "Open a folder…" is pressed
- **Then** the fake kvman got `kernel.workspace.open` with the folder the dialog answered, and the window is told to load that workspace's URL
- Test: `packages/desktop/src-tauri/tests/home.rs`

### M3.2-H8 — a call that fails shows its Problem's translated text above the list
- **Given** the home screen, a catalog with `kernel.errors.NOT_FOUND`, and a fake kvman that answers `kernel.workspace.close` with `{ ok: false, problem: { code: "NOT_FOUND", … } }`
- **When** a remove button is pressed
- **Then** the home screen has the catalog's text for `NOT_FOUND` above the list, and the list is still shown
- Test: `packages/desktop/src-tauri/tests/home.rs`; `packages/desktop/test/home.test.ts`

### M3.2-H9 — the home screen follows `kernel.language`
- **Given** a fake kvman whose `kernel.settings.list` has `kernel.language` `ar`, then `fr`
- **When** the home screen is loaded
- **Then** for `ar` its texts are the Arabic catalog's and the page's direction is `rtl`; for `fr` they are the English catalog's and the direction is `ltr`
- Test: `packages/desktop/src-tauri/tests/home.rs`; `packages/desktop/test/home.test.ts`

### M3.2-H10 — `kvwebui.theme` chooses the colours
- **Given** a fake kvman whose `kernel.settings.list` has `kvwebui.theme` `light`, `dark`, `system`, and no such key
- **When** the home screen is loaded
- **Then** the theme is `light`, `dark`, `system`, and `system`; the page carries `light` and `dark` as its theme and nothing for `system`, where the stylesheet follows the system
- Test: `packages/desktop/src-tauri/tests/home.rs`; `packages/desktop/test/home.test.ts`

### M3.2-H11 — a `joined` line shows the home screen, and closing leaves that kvman running
- **Given** a session whose kvman wrote a `joined` line and exited 0
- **When** the window is closed
- **Then** the home screen was shown for the joined port, kvman's exit showed no dialog, and closing quits at once with nothing written to and nothing stopped in any process
- Test: `packages/desktop/src-tauri/tests/session.rs`

### M3.2-H12 — a new window and another origin open in the system's browser
- **Given** kvman on port 3737
- **When** the window itself begins to load `http://127.0.0.1:3737/kvwebui/settings`, then `https://example.com/docs`; and a page asks for a new window for `http://127.0.0.1:3737/x` and for `https://example.com/`
- **Then** the first changes nothing; the second is opened in the system's browser and the window is sent back to `http://127.0.0.1:3737/`; both new windows are opened in the system's browser and none is opened in the app
- Test: `packages/desktop/src-tauri/tests/navigation.rs`; `packages/desktop/src-tauri/tests/session.rs`

### M3.2-H13 — closing the window stops kvman, and ends its process tree after the wait
- **Given** a fake kvman that exits when its input closes; and one that ignores it and has a child process of its own
- **When** the window is closed, with a wait of 15 seconds for the first and a short wait for the second
- **Then** the first got its input closed, exited by itself, and the app quits with no kill; the second, still alive after the wait, has its whole tree ended (both processes are gone) and the app quits; the command that ends a tree is SIGKILL to the group on Linux and macOS and `taskkill /PID <pid> /T /F` on Windows
- Test: `packages/desktop/src-tauri/tests/kvman_process.rs`

### M3.2-H14 — a `running` line with another port moves the window
- **Given** a session past the home screen on port 3737
- **When** the lines `restarting` and `running` with port 3999 come; and, in another session, `restarting` and `running` with port 3737
- **Then** the first says to load the new line's `url`; the second says to do nothing
- Test: `packages/desktop/src-tauri/tests/session.rs`

### M3.2-H15 — a kvman that ends by itself shows the dialog that names the log file
- **Given** a session past the home screen, with home folder `<home>`
- **When** kvman's process ends without the app asking
- **Then** the dialog says kvman stopped unexpectedly and names `<home>/logs/kvman.log`, and its one button quits
- Test: `packages/desktop/src-tauri/tests/session.rs`

### M3.2-H16 — the shell's calls carry no `Origin`, and the page makes none
- **Given** the fake kvman recording request headers; and the page's files and the app's configuration
- **When** the shell lists, opens, and closes workspaces, reads the settings, and reads a catalog
- **Then** every request has the Host `127.0.0.1:<port>` and no `Origin` header; the page's source has no `fetch`, `XMLHttpRequest`, `WebSocket`, or `EventSource`, and the app's content security policy lets the page connect to nothing but the shell
- Test: `packages/desktop/src-tauri/tests/kvman_api.rs`; `packages/desktop/test/page-rules.test.ts`

## Edge cases

### M3.2-E1 — each line is read into its shape, and anything else is refused
- **Given** the five lines as kvman writes them; and `nonsense`, `{"kind":"other"}`, `{"kind":"running","url":"x"}`, and a `running` line with one more key
- **When** each is read
- **Then** the five give their shapes (a `failed` line with and without `language`, a Problem with and without `params`); the others are refused
- Test: `packages/desktop/src-tauri/tests/lines.rs`

### M3.2-E2 — a line the shell can't read ends the session
- **Given** a session whose kvman runs
- **When** the line `nonsense` comes
- **Then** the session shows the dialog of a kvman that ended by itself, and stops kvman as closing does
- Test: `packages/desktop/src-tauri/tests/session.rs`

### M3.2-E3 — how kvman is started
- **Given** a Node program at `/app/node/bin/node`, kvman's entry at `/app/kvman/dist/main.js`, the user's home folder, and a `PATH` of `/usr/bin`
- **When** the command to start kvman is built, for Linux and for Windows
- **Then** it runs that Node with the entry and exactly `--pipe --no-open`, in the user's home folder, with stdin and stdout as pipes; `PATH` is `/usr/bin:/app/node/bin` on Linux and macOS, and uses `;` on Windows; `KVMAN_HOME` is passed on as it is
- Test: `packages/desktop/src-tauri/tests/kvman_process.rs`

### M3.2-E4 — the lines of a real child are read, and an answer reaches it
- **Given** the fake kvman told to write a `trust` line, wait for a line, and write `running` if it was `{"trust":true}`
- **When** it is started and the answer is written
- **Then** the shell gets the `trust` line, then the `running` line, each as its shape, in order
- Test: `packages/desktop/src-tauri/tests/kvman_process.rs`

### M3.2-E5 — a kvman that ends before any line
- **Given** a fake kvman that exits 1 with no line
- **When** it is started
- **Then** the session shows the dialog of a kvman that ended by itself
- Test: `packages/desktop/src-tauri/tests/session.rs`

### M3.2-E6 — at a restart, the trust dialog's first button is "Don't run", and the window stays
- **Given** a session past the home screen
- **When** the lines `restarting` and `trust` come and the first button is pressed; then `running` on the same port comes
- **Then** the dialog's buttons are "Don't run" and Accept; the button writes `{"trust":false}`; the `running` line changes nothing and nothing quits
- Test: `packages/desktop/src-tauri/tests/session.rs`

### M3.2-E7 — a decline at a restart that can't be undone is a failed start
- **Given** the same session and the same decline
- **When** a `failed` line with `EXTENSION_INVALID` comes instead of `running`
- **Then** the failed-start dialog is shown with the `EXTENSION_INVALID` hint, and its button quits
- Test: `packages/desktop/src-tauri/tests/session.rs`

### M3.2-E8 — a second launch while kvman starts, and while a dialog is open
- **Given** a session that hasn't got its first line; and one showing the trust dialog
- **When** a second launch is reported
- **Then** each only focuses the window
- Test: `packages/desktop/src-tauri/tests/session.rs`

### M3.2-E9 — closing the window while kvman starts
- **Given** a session whose kvman hasn't written `running` yet
- **When** the window is closed, and the `running` line comes afterwards
- **Then** kvman's input is closed, the late `running` line shows no home screen, kvman's exit shows no dialog, and the app quits
- Test: `packages/desktop/src-tauri/tests/session.rs`

### M3.2-E10 — the dialogs' text by language
- **Given** the trust, failed-start, and stopped dialogs
- **When** each is made for `ar`, `en`, `fr`, and no language
- **Then** `ar` gives the Arabic catalog's texts; `en`, `fr`, and no language give the English ones
- Test: `packages/desktop/src-tauri/tests/messages.rs`

### M3.2-E11 — the four hints and the fallback
- **Given** the codes `KVMAN_RUNNING`, `PORT_IN_USE`, `EXTENSION_INVALID`, `VALIDATION_FAILED`, and `INTERNAL`
- **When** the hint of each is asked for, in `en` and `ar`
- **Then** the first four have their own hint in both languages, and the last names `<home>/logs/kvman.log`
- Test: `packages/desktop/src-tauri/tests/messages.rs`

### M3.2-E12 — a folder is shown with `~` only under the user's home folder
- **Given** the home folder `/home/ahmed`, and `C:\Users\ahmed` on Windows
- **When** `/home/ahmed`, `/home/ahmed/work/x`, `/home/ahmedx/y`, `/srv/data`, and `C:\Users\ahmed\work` are shown
- **Then** they read `~`, `~/work/x`, `/home/ahmedx/y`, `/srv/data`, and `~\work`
- Test: `packages/desktop/src-tauri/tests/home.rs`

### M3.2-E13 — an answer that isn't the envelope is a failure
- **Given** a fake kvman that answers a call with `not json`, and with `{ "ok": true }` with no `output`
- **When** the shell makes the call
- **Then** each fails, and the home screen shows its general failure text above the list
- Test: `packages/desktop/src-tauri/tests/kvman_api.rs`; `packages/desktop/src-tauri/tests/home.rs`

### M3.2-E14 — a Problem's text: params, an extension's code, and a missing key
- **Given** a catalog with `kernel.errors.NOT_FOUND` as `No {thing} was found.` and `kvcoder.errors.BUSY`
- **When** the texts of `NOT_FOUND` with `{ "thing": "workspace" }`, of `kvcoder/BUSY`, and of `TOO_LARGE` (not in the catalog) are asked for
- **Then** they are `No workspace was found.`, the catalog's `kvcoder.errors.BUSY`, and the Problem's own English message
- Test: `packages/desktop/src-tauri/tests/home.rs`

### M3.2-E15 — a cancelled folder dialog changes nothing
- **Given** the home screen, and a folder dialog that answers nothing
- **When** "Open a folder…" is pressed
- **Then** the fake kvman got no call, and nothing is loaded
- Test: `packages/desktop/src-tauri/tests/home.rs`

### M3.2-E16 — a folder that can't be opened shows its text and stays
- **Given** a fake kvman that answers `kernel.workspace.open` with `VALIDATION_FAILED`
- **When** a folder is chosen
- **Then** the home screen shows the catalog's text above the list, and nothing is loaded
- Test: `packages/desktop/src-tauri/tests/home.rs`

### M3.2-E17 — a port that changes while the home screen shows
- **Given** a session on the home screen with port 3737
- **When** `restarting` and `running` with port 3999 come, and a row is then clicked
- **Then** nothing is loaded by the line, and the click loads `http://127.0.0.1:3999/?workspace=<id>`
- Test: `packages/desktop/src-tauri/tests/session.rs`

### M3.2-E18 — only kvman's own origin stays in the window
- **Given** kvman on port 3737
- **When** the window is asked to go to `http://localhost:3737/`, `http://127.0.0.1:3738/`, `https://127.0.0.1:3737/`, `http://127.0.0.1:3737.example.com/`, and the shell's own page
- **Then** the first four open in the system's browser, and the shell's own page is allowed
- Test: `packages/desktop/src-tauri/tests/navigation.rs`

### M3.2-E19 — a download's name
- **Given** a Downloads folder with `report.pdf` and `report (1).pdf`, with `notes`, and with `.env`
- **When** `report.pdf`, `notes`, `.env`, and `new.txt` are downloaded
- **Then** they are saved as `report (2).pdf`, `notes (1)`, `.env (1)`, and `new.txt`, and no file there is replaced
- Test: `packages/desktop/src-tauri/tests/downloads.rs`

### M3.2-E20 — a kvman that exits inside the wait is not killed
- **Given** a fake kvman that exits a moment after its input closes
- **When** the window is closed with a wait of 15 seconds
- **Then** the app quits as soon as kvman has exited, and no kill was issued
- Test: `packages/desktop/src-tauri/tests/kvman_process.rs`

### M3.2-E21 — the stop the app asked for shows no dialog
- **Given** a session that closed kvman's input
- **When** kvman exits
- **Then** no dialog is shown, and the app quits
- Test: `packages/desktop/src-tauri/tests/session.rs`

### M3.2-E22 — the catalogs
- **Given** the package's `locales/en.json` and `locales/ar.json`
- **When** they are read
- **Then** they have the same keys, every key starts with `desktop.`, no text is empty, and each Arabic text keeps the `{…}` placeholders of its English one; the Arabic catalogs' rules (ADR 0013, 10) read this catalog too
- Test: `packages/desktop/test/catalogs.test.ts`

### M3.2-E23 — the page's rows can be used without a mouse, and name what they do
- **Given** the home screen with Home and a workspace `notes`
- **When** the page is rendered
- **Then** each row and "Open a folder…" is a button; the remove button's name is the catalog's text with `notes` in it; while kvman starts the page shows the name "kvman" and a progress mark and no other text
- Test: `packages/desktop/test/home.test.ts`

### M3.2-E24 — the colours are kvwebui's, and the styles are logical
- **Given** the page's stylesheet and kvwebui's `web/src/styles/main.css`
- **When** they are read
- **Then** each `--kv-color-*` value the page defines, for light and for dark, equals kvwebui's; and the page's stylesheet has no `left`, `right`, `margin-left`, `padding-right`, or other physical property
- Test: `packages/desktop/test/page-rules.test.ts`

### M3.2-E25 — the `desktop` import wall
- **Given** a file in `packages/desktop/src`
- **When** it imports a file beside it, `@kvman/sdk`, `@kvman/kernel`, `kvman`, `marked`, and `node:fs`
- **Then** the first is clean, and each of the others fails lint
- Test: `test/tooling/import-walls-packages.test.ts`

### M3.2-E26 — the page gets nothing but what the home screen shows
- **Given** the app's configuration
- **When** it is read
- **Then** the shell's functions are granted to the app's own page only, never to `http://127.0.0.1`, and the list of them is the home screen's own (load, continue, remove, open a folder)
- Test: `packages/desktop/test/page-rules.test.ts`

### M3.2-E27 — the page refuses an answer of another shape
- **Given** a home screen as the shell answers it; and answers that are `null`, a list, or have another language, another theme, a row without its fields, a failure that isn't text, or a text that isn't text
- **When** the page reads each
- **Then** the first is taken as it is, and each of the others is refused
- Test: `packages/desktop/test/home.test.ts`

### M3.2-E28 — the app is kvman at the root version
- **Given** the root `package.json`, the package's `package.json` and `Cargo.toml`, and the app's configuration
- **When** they are read
- **Then** the three versions are the same, the product name is `kvman`, and the identifier is `com.ibndeif.kvman`
- Test: `packages/desktop/test/page-rules.test.ts`

### M3.2-E29 — only a web address is handed to the system's browser
- **Given** a session past the home screen
- **When** a page asks for a new window for `file:///etc/passwd`, `vscode://open?x`, and `javascript:alert(1)`; and the window begins to load each
- **Then** nothing is opened in the system's browser for any of them, and the window is sent back to kvman; `http:` and `https:` addresses are the only ones that are opened
- Test: `packages/desktop/src-tauri/tests/navigation.rs`
