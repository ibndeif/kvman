# ADR 0060 — lighter summaries, no task list, a live turn line, and a guard on the git index

Status: accepted by the product owner by choice on 2026-10-12, before source. This records KVC-40, 43, 44, and 46.

## Decisions

1. **Summaries (KVC-40).** The owner asked for the best change that doesn't break the provider's cache. Cutting old call results to one line was considered and rejected: it rewrites the cached prompt from the first cut result on, and leaves a larger prompt that every later step reads again, so with caching it costs more than a summary does. The summary's request stays a step's own (ADR 0032, 2). Its instruction now asks for at most 1,500 words, to fold an earlier summary into the new one instead of repeating it, and to leave out what the files themselves record. The length is asked for, not enforced: a longer summary is stored whole, because a cut summary loses its end. `kvcoder.compactAt`, `kvcoder.compactKeep`, and the 10% minimum are unchanged.
2. **No task list (KVC-43).** kvcoder gets no task list of its own. An extension that keeps tasks shows them to the model with `kvcoder.section.set` and a connector (plan 08 §8.4). Nothing is built.
3. **The live turn line (KVC-44).** While a turn runs, the running line also shows the turn's steps and its estimated cost so far, "Turn: 18 steps · about $0.84", from `kvcoder.turn.list`, as the last finished step left them. A turn with no priced call shows its steps alone, and one before its first step shows neither. It is display only: nothing stops or pauses the work, and there is no spending limit. With no task list (decision 2), the line counts no tasks.
4. **The git staging guard (KVC-46).** The owner chose to detect a change and offer to restore the staging area.
   - **Marks.** Before a program worker's program starts, and after it ends, kvcoder marks the workspace folder's Git state: the tree of what is staged, written from a copy of the index so the person's index file is never touched, and the commit `HEAD` names. A folder that isn't in a Git repository, a machine without Git, and an index with unresolved conflicts have no mark, and the run goes on unguarded.
   - **Detection.** When the two marks differ, the run record keeps `staging: { tree, after, head, headMoved, paths, restored: false }`: the tree before, the tree and head after, whether `HEAD` moved, and the number of paths whose staged content differs. The run's result gains a last line for the model: "kvman: this run changed what is staged in Git (`<paths>` paths differ from before it ran)." and, when `HEAD` moved, "kvman: this run moved HEAD from `<before>` to `<after>`." A run that ends by a stop, a lost job, or kvman stopping is not marked after.
   - **What the person sees.** `kvcoder.job.list` and `kvcoder.job.get` give such a row `staging: { state: 'changed' | 'restored', paths, headMoved }`. The call's result card (through `details.staging: { runId }`) and the job's row in the Running popover show "This run changed what is staged in Git (`<paths>` paths)." with a "Restore staging" button.
   - **Restore.** `kvcoder.delegate.staging.restore { sessionId, runId }` → `{}`, a user-only command, puts the staged tree back as it was before the run (`git read-tree`), and marks the run restored. It changes no file in the folder and no commit. It fails `VALIDATION_FAILED` when the run has no kept change, was restored already, moved `HEAD`, or when the staging area or `HEAD` is no longer as the run left it, so that it never discards what the person staged since.
   - **Limits.** A run that moved `HEAD` (a commit, a checkout, a reset) is reported and can't be restored here: the card says so, and offers no button. File contents are never rolled back. Subagents aren't guarded: their commands go through the shell's approval.
