# ADR 0023 — `kvman init` in place of kvcustomizer's global prompt section

The product owner raised two problems (2026-10-06):

- kvcustomizer's text is in every kvcoder prompt of every workspace: a 4 KB global section, `guide`, that tells the agent how to build an extension, and the five connectors' lines. When the person builds something else (a website, a script), the text steers the model toward extensions and costs accuracy.
- A person who isn't a developer and doesn't know kvman's internals asks the agent to "customize the app to do x and y". The agent has to turn that into kvman's concepts without asking the person about them.

The product owner proposed a command that loads the customizer's knowledge and asks the person what they need, and chose its place, `kvman init`, over a connector of its own and over `docs init`. The alternatives that were weighed and not chosen: a short pointer section with the method read through `docs get`; a `customizer` worker that holds the method (a worker asks the person only when blocked, ADR 0022, 3, and costs a second run); and connectors hidden until a customizing mode is switched on (new kvcoder machinery, against ADR 0010, 4). Where the rules for a non-expert live was asked: in kvcustomizer, not in kvcoder's base prompt, which stays generic. A restart command was asked for and is not part of this ADR (decision 9).

## Decisions

1. **The global `guide` section is gone.** kvcustomizer no longer calls `kvcoder.section.set`, and its prompt text is the result of `init` (decision 2). Sections are stored until removed (plan 08 §8.4), so kvcustomizer's `kernel.started` handler removes the old one, `kvcoder.section.remove { id: 'guide', global: true }`, which does nothing when it is missing. Every prompt then holds only the connector index's lines for kvcustomizer.
2. **`kvman init` is a read.** The `kvman` connector gains the command `init`, first in its list, which runs the public query `kvcustomizer.app.guide.get` (`{}` → `{ instructions }`). It is a query because it writes nothing, so its name ends in a read verb (`CLAUDE.md` §4); the connector's word `init` is the product owner's. It never asks the person.
3. **The `kvman` connector's description opens with the trigger**: "Call `init` first when the person asks to change, extend, or customize the app itself: what it does, how it looks, its model, or its settings." The connector index is always in the prompt, so this line is what makes the agent call `init`. The descriptions of `ext`, `preset`, `preview`, and `docs` are unchanged.
4. **What `init` returns** is English text for the model, kept in `docs/init.md` (the file `docs/section.md` was), not served as a page of `kvcustomizer.docs.get`. It has three parts, in this order:
   - **Who and what to ask.** Settle which app is meant: kvman, which the `kvman` connector changes, or the project in the workspace folder, which `fs` edits; ask once with `ask choice` unless the request is clear. Find out what the person wants in their own words: if the goal isn't known, one `ask text`; if it is, ask only about what is missing, one question per `ask` call, options written as outcomes and the recommended one first. Never ask what reading `extensions-list`, `settings-list`, or `preset-get` would answer.
   - **The rules for a person who isn't a developer.** Never ask them about, or say to them, extensions, namespaces, presets, setting keys, or commands, and never put those words in a call's `description`, which is the text of the approval card ("Add a Notes page to your app", not "extensions-install notes"); the agent chooses the mechanism. Look before building, and choose the smallest thing that gives them what they asked: a setting, an extension that is installed, an extension to build, and a new preset only for a different app; say plainly when kvman can't do it. Show before changing: preview an extension, give the person its address, and `ask confirm` before it is added to the app. Say how to undo each change (`settings-reset`, `extensions-uninstall`), and tell them to restart kvman after a change to the extensions, and what is left unchecked.
   - **The method** that the section was: building an extension in order, improving one that exists, and managing the app (ADR 0022, 12 to 15).
5. **`init` is a recommendation, not a gate.** The other `kvman` commands work without it; nothing enforces the order, since that would need new machinery in kvcoder for no more than the connector's description already says.
6. **The guide lives in the conversation.** A registered connector command receives only its payload, never the session's id, so `init` can't set a section of the session without changing kvcoder's contract for every extension; the result is a tool result like any other. A summary of the chat may drop it, and the text says to call `init` again then. A command can't call `ask` (it is a tool-level suspend of kvcoder), so the questions are the agent's: the text tells it to ask.
7. **`docs/customizing.md` documents `init` and the rules** for people and other harnesses, in the connector table, in the guidance for talking with a person who isn't a developer, and where it said that kvcustomizer adds "a short guide to the agent's prompt".
8. **The names.** The public query is `kvcustomizer.app.guide.get`. The plan's `guide` section name stays free for any extension to use.
9. **Left out: a restart command.** The product owner wants an approval-gated command that restarts kvman, so that a person who isn't a developer needn't know how. It changes the kernel or the CLI (a foreground process re-running itself, the terminal it leaves, and a branch per OS), so it has its own ADR after this one. Until then `init` tells the agent to say plainly how to restart (ADR 0022, 15).

## Consequences

- Plan 09 (intro, §9.1, §9.4) is corrected, and plan 13 notes the change. This changes ADR 0006, 1, ADR 0009, 170 (the section's text), ADR 0010, 4 (`guide`), and ADR 0022 (the guide section's method, now `init`'s).
- QA 17 (E21), QA 34 (H12), and M2.5 (E35) described the section; their scenarios are updated.
- No new dependency. kvcoder and the kernel are unchanged.
