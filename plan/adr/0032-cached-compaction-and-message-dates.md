# ADR 0032 — Compaction that reads the cache, and the date on a person's message

The product owner asked (2026-10-07): "Does our kvcoder is a model cache friendly?", then "Develop a plan to fix the caching issues and we need to give the model access to current date, Also we need to fix a ui issue where the chat page has a scorll to empty section".

The latest chat of the running kvman was read through its queries: 46 model calls on `openai/gpt-6.1-sol`, 181,854 input tokens paid in full and 2,579,456 read from the provider's cache, which is 93.4%. From the sixth call on, each step read the whole previous prompt. So a step is cache friendly already. What isn't: a summary is asked for with a prompt of its own over a flattened transcript, so none of it is read from the cache; and the model is never told the date, which can't go in the system prompt without rewriting the cache whenever it changes.

On the chat page, the main area scrolled 4,740 px past the conversation (a client height of 814 px and a scroll height of 5,554 px). The screen-reader text "chosen" of an answered question's card is positioned absolutely, and the nearest positioned box around it was outside the message list's scroller, so the scroller didn't clip it.

Decisions 1 to 4 were asked with alternatives. Decisions 5 to 9 are the smallest way to carry them out; the product owner may overrule any of them.

## Decisions

1. **A person's message carries its date** (chosen over a date line in the system prompt, which rewrites a chat's cache at the first step after midnight, and over telling the model to run the shell's `date`, which costs a call). The date comes from the message's stored `createdAt`, so every step sends the same text and the cache is untouched.
2. **A summary is asked for with the step's own request** (chosen over keeping the separate summarizer prompt): the session's system prompt, the `run` tool, the session's thinking level, and the older messages as a step sends them, then one last `user` message with the instruction. The older messages are read from the cache.
3. **The cache's lifetime stays the provider's default** (chosen over always asking for the long one, and over a setting). `kvai.complete` gains no input.
4. **A changed system prompt may rewrite a chat's cache** (chosen over storing each chat's prompt at its first step). Enabling a connector, adding an MCP server, and an extension changing a section each cost one cache write.
5. **The stamp.** A step, and a summary's request, send a `user` message whose `source` is the person (`{ kind: 'user' }`) with one line before its text: `[<weekday> <YYYY-MM-DD> <HH:mm> <±HH:mm>]`, a line break, then the text. The weekday is the English name, the time is the 24-hour local time of the computer kvman runs on, and the last part is that time's offset from UTC, as in `[Wednesday 2026-10-07 04:55 +03:00]`. A message with any other `source` (a job's result, a subagent's, an extension's) has no stamp, and neither has the summary's lead. What is stored, what `kvcoder.message.list` returns, and what the conversation shows don't change. A chat that started before this change rewrites its cache once.
6. **The base prompt says so**, in one sentence after the reply-language line: `Each message from the person starts with the date and time it was sent, in brackets; the newest one is the current time.`
7. **The instruction** is the last message of a summary's request: `Summarize the conversation above for the agent that continues it: the goal, the decisions, the files and commands that matter, what is done, and what is left. Keep names, paths, and numbers exact. Reply with the summary only, and call no tool.` An earlier summary is sent first, with its lead, as a step sends it.
8. **A summary with no text failed.** When the answer has no text, as when the model called the tool, the notice `SUMMARY_FAILED` is added with `params: { code: 'kvcoder/SUMMARY_EMPTY' }`, nothing is stored, and the step goes on, as for a summary whose call failed. `kvcoder/SUMMARY_EMPTY` is a new error code of kvcoder, shown in the notice as "The model returned no summary." (`kvcoder.errors.SUMMARY_EMPTY`, with its Arabic entry).
9. **The message list's scroller contains what is in it.** `.kvc-scroll` is a positioned box, so an absolutely positioned element in a message is clipped by the list and never makes the page scroll.
