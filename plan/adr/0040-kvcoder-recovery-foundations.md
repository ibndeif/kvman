# ADR 0040 — kvcoder recovery foundations and collection continuation

Status: accepted, 2026-10-09. The product owner chose `recover-on-workspace-command` and `find-after-cursor` after reviewing the current SDK and kernel boundaries. These refine the selected KVC-02/03 implementation, not completion of durable scheduling.

## Decisions

1. **Do not extend cross-workspace job calls.** Do not add the proposed `execAsyncInWorkspace`, a workspace override to `execAsync`, or a new workspace lifecycle point. Reconcile kvcoder's safe intents within a later command in their own workspace; no promise of automatic home-wide intent launch from Home at startup. Existing kernel queued jobs and workspace pause/resume policy remain. Generation, claim and intent data contracts still require documentation and approval before their source implementation.
2. **Add an exclusive ID position to collection find.** `FindOptions` is `{ limit: number; order?: 'asc' | 'desc'; after?: string }`. `after`, when present, is a non-empty string position; it need not still identify an existing document. Ascending results have IDs greater than it, descending results IDs less than it. Default order remains ascending. The cursor is not a count or offset.
3. **Keep existing calls and returns.** A call without after is unchanged. Limit remains required, a positive integer at most1000. Ordinary collection calls return Promise arrays; transaction calls return arrays synchronously. Filters, count, schema validation, extension/workspace/global isolation and transaction atomicity remain unchanged. Invalid options fail VALIDATION_FAILED; no new error code, dependency, table or stored-data format is introduced.
4. **Bind the position as a SQL parameter.** Only the validated enum decides direction; user position values never become SQL syntax. No SQL is exposed to extensions, nor is a general long-operation framework added.
5. **Do not promise a snapshot across calls.** Deleting the cursor does not break continuation; deleting unread rows removes them, and new matching IDs beyond the position can appear. Updating a row behind the cursor does not cause it to be revisited. Each consumer must specify its consistency/revalidation needs. This does not make jobs.list exhaustive or turn a missing/truncated job listing into a replay permit.
6. **Preserve safe recovery.** A new schema default is not evidence of an unexecuted legacy step; null filtering matches explicit JSON null, not missing fields. Pagination permits complete legacy enumeration, but unknown external effects must never be blindly replayed. KVC-01–07/09/10 are not implemented by this foundation.

7. **Reconcile safe intents across the current workspace on positive user actions.** The owner chose `recover-safe-workspace-intents`: later authorized send/answer commands reconcile safe intents for all sessions in their own workspace, not only the target session. Stop/delete commands never dispatch new work. This does not broaden SDK workspace scope or promise Home-wide startup dispatch; claimed steps with uncertain effects are not replayed.
8. **Use the existing interrupted outcome for unconfirmed claimed steps.** The owner chose `interrupt-and-explicit-continue`: when a claimed job is terminal or missing without confirmed settlement, end the affected turn as interrupted and give an explicit unknown-effects notice. Continue only through a new explicit request, never by replaying the old step or reusing its approval. Preserve tracking for work whose shutdown is uncertain. Do not add a new public paused/review status or dedicated resume command for this case. Exact intent/generation/claim fields still require presentation and approval before implementation.

## Implementation and verification order

Update plan02 §2.5, plan03 §3.4, plan08's recovery-scope note, and the developer storage guide. Add M1.2-E19 and M1.3-E19–E25 scenarios before source. New tests: `packages/sdk/test/store-pagination-types.test.ts` and `packages/kernel/test/store/pagination.test.ts`. Prove meaningful failures against the previous API/backend, then change only FindOptions, option validation and the collection find query. Run related SDK/kernel typechecks, lint, type/docs tests and existing store regressions; the owner requested the complete suite only after all selected fixes.

Add a backward-compatible SDK patch changeset; the kernel/CLI use the manually coordinated root release procedure. Do not bump versions, stage, commit or publish here. An older kernel that does not implement this option is not claimed to support after: updated SDK types alone cannot update an installed kernel. Full release-candidate verification remains deferred, including the recorded nested-gate timeout. No CI test gate or timeout/benchmark relaxation.
