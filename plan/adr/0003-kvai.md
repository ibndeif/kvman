# ADR 0003 — kvai

Status: accepted, 2026-09-29. Decided with the product owner in question rounds.

1. **Scope.** kvai exposes LLM calls, providers, and models only. Agents, tools, context, harnesses, and loops are built by the extensions that need them (kvcoder, kvdev, …).
2. **Registry.** `kvai.model.list` merges pi-ai's built-in models with custom ones kept in kvai's global store. The public commands `kvai.provider.add`, `kvai.model.add`, and `kvai.model.remove` add custom providers and models, as pi-ai `Model` objects (for example Ollama, or another extension's provider). A model id is `<provider>/<model>`, and the setting `kvai.defaultModel` names the default.
3. **API keys.** Only kvai secrets: `<provider>.apiKey`, set from the Settings page's secrets section. Environment variables are ignored, and OAuth providers wait for a later phase.
4. **Dependency.** (Replaced by `@earendil-works/pi-ai` 0.99.1: ADR 0009, 51.) `@mariozechner/pi-ai`, pinned exactly (0.73.1 at the time of writing).
5. **Streaming.** A nested job's progress goes to its root job's stream (ADR 0001, 79), so the UI that started a harness's turn sees kvai's deltas.
6. **The call.** (Usage also has `cacheRead` and `cacheWrite`: ADR 0008, 39.) The public command `kvai.complete` takes `{ model?, systemPrompt?, messages, tools?, thinking?, maxTokens? }` and returns `{ message, stopReason, usage: { input, output, cost } }`.
   - `messages` and `message` are pi-ai's own JSON types, validated with zod in kvai. `tools` are `{ name, description, parameters }`, where `parameters` is JSON Schema.
   - `model` defaults to `kvai.defaultModel`, and `thinking` is `off`, `minimal`, `low`, `medium`, or `high`.
   - Tool calls in the answer are returned, never run.
7. **Deltas.** `{ type: 'text' | 'thinking', delta }`, and `{ type: 'toolcall', name }` when a tool call starts. They reach the root job's stream as `{ source: '@kvman/kvai', data }`.
8. **Failures.** `kvai.complete` registers `retries: 0`, since a retried stream would repeat deltas. It fails with `kvai/RATE_LIMITED`, `kvai/PROVIDER_ERROR`, `kvai/KEY_MISSING`, `kvai/MODEL_UNKNOWN`, or `kvai/CONTEXT_TOO_LONG`, and the harness decides whether to call again. Cancel aborts the provider call through the job signal.
9. **Usage.** Each call adds its tokens and cost to per-workspace, per-model totals in kvai's store; there's no per-call history.
10. **Providers from extensions.** `kvai.provider.add` takes one of two forms:
    - `{ id, title, api, baseUrl, headers?, compat? }`: pi-ai speaks that wire API.
    - `{ id, title, delegate: '<public command>' }`: `kvai.complete` forwards to that command, which takes and returns `kvai.complete`'s shapes and may stream the same deltas.
11. **Admin API.**
    - `kvai.provider.list {}` → `[{ id, title, builtIn, key: 'set' | 'missing' }]`
    - `kvai.provider.add` → `{}`
    - `kvai.provider.remove { id }` → `{}` (also removes its models)
    - `kvai.model.list { provider? }` → `[{ id, name, provider, reasoning, input, contextWindow, maxTokens, cost, builtIn }]`
    - `kvai.model.add { provider, id, name, reasoning, input, contextWindow, maxTokens, cost? }` → `{}`
    - `kvai.model.remove { id }` → `{}`
    - `kvai.usage.get {}` → `[{ model, input, output, cost }]`
    - Removing a built-in provider or model fails with `kvai/BUILT_IN`.
12. **UI.** `kvai.ui.get` contributes:
    - a Models page: providers with key state, their models, forms to add a custom provider or model, and a default-model picker;
    - a status item with the workspace's tokens and cost.
13. **Testing.** Tests run a small scripted OpenAI-compatible streaming server on 127.0.0.1 and add it with `kvai.provider.add { api: 'openai-completions', baseUrl }`. The real code path runs, and harness tests reuse the helper.
14. **Namespaces.** (kvinterviewer removed: ADR 0005, 8.) Package-like: `kvai`, `kvwebui`, `kvinterviewer`, `kvcoder`, `kvdev`.
15. **Duplicates.** Adding a custom provider or model with an existing custom id replaces it. A built-in id fails with `kvai/BUILT_IN`.
16. **Context size.** `kvai.complete` registers `maxInputBytes: 33554432` (32 MiB), per ADR 0001, 80.
