# ADR 0024 — Restarting kvman, and undoing a change that stops it from starting

A change to the extensions or the preset applies at the next start (ADR 0010, 5), and nothing could restart kvman: the agent told the person to do it (ADR 0022, 15; ADR 0023, 9). A person who isn't a developer may not know how, and a change that stops kvman from starting leaves a dead page and no agent to fix it. The product owner asked for an approval-gated restart command (2026-10-06), and chose the answers below from alternatives.

Chosen, over the alternative in parentheses:

- **In-process restart** (over a supervisor process that re-runs kvman on a special exit code, and over `process.execve`, which is POSIX only): the terminal, the lock, and the trust prompt stay, and no code has a branch per OS.
- **The trust prompt stays in the terminal** (over accepting a version when the install card is allowed, which would relax "non-bundled versions need the person's trust at start", `CLAUDE.md` §3).
- **A failed start is undone** (over exiting with the Problem, which leaves a person who isn't a developer with a dead page).
- **The turn that asked ends `interrupted`** (over a continuation, which needs new kvcoder machinery).

Decisions 6 to 11 are the smallest way to carry these out, were listed for the product owner with the plan, and were approved with it.

## Decisions

1. **A restart is a stop and a start in the same process.** `kvman` keeps its lock and its process, and runs the stop sequence (plan 02 §2.14, steps 1 to 5), then the start sequence again, steps 2 to 11, with the arguments it was given (`--home`, `--preset`, `--mode`, `--port`, `--log-level`, `--yes`). Step 3 reads the preset again from where it came, so an edit applies. It prints `kvman is restarting…`, then `kvman is running at <url>` as at any start, updates `kvman.lock` with the new port, and doesn't open the browser again. A second `kvman` that starts in between finds the old port dead and fails `KVMAN_RUNNING`, as for a kvman that doesn't answer (ADR 0009, 43). Ctrl+C after the restart stops it as before; a Ctrl+C while it starts ends the process as it does at the first start.
2. **`kernel.restart` is a command of the kernel.** `{}` → `{ restarting: true }`. It asks the run to restart and answers at once; the run stops after it answers, so the answer may not reach a caller whose connection the stop closes. It is public, like the kernel's other commands, and several calls before the stop begins make one restart. The kernel only reports the request (`Kernel.restartRequested`, a promise); whoever embeds it decides what a restart is. The CLI restarts, and a test kernel does nothing.
3. **What a restart stops.** Everything a stop stops: running jobs are aborted with the reason `shutdown`, and an attempt that didn't finish fails `INTERRUPTED` and runs again if it has retries left; long-lived processes (§2.16), including a preview and a server the agent started, are stopped. Open workspaces are remembered and open again (plan 02 §2.6), and a turn that was running ends `interrupted` with kvcoder's notice (plan 08 §8.1); the person sends a message to go on.
4. **The first edit after a good start keeps a backup.** `kernel.extensions.install` and `uninstall` first write the preset as it was running to `<preset file>.good` unless that file exists, so later edits before the next start keep the same backup, and a first edit of the bundled preset backs up the bundled one. A start that succeeds, with its HTTP port listening, deletes `.good`.
5. **A start that fails because of the preset is undone.** When a start fails with `EXTENSION_INVALID` or `VALIDATION_FAILED` and `.good` exists beside the preset file, the CLI restores the file from it, deletes `.good`, prints the Problem and `The last change to the preset was undone.`, and starts once more. The second start's `kernel.health.get` has `rolledBack`, the first failure's Problem (`{ code, message, params? }`), and no other start has it. If the restored preset fails too, that second Problem is printed and kvman exits 1 (the backup has been used); if the start fails for another reason (`PORT_IN_USE`, a failed database), the Problem is printed, kvman exits 1 as before, and `.good` stays. This holds for any start, not only a restart: a person who answers `N` to the trust prompt after an install gets the app back as it was.
6. **`kernel.health.get` gains `rolledBack`.** Optional; it changes `healthSchema` of `@kvman/sdk`. The kernel takes it as the start option `rolledBack`.
7. **kvcustomizer has `kvman restart`.** The `kvman` connector's command `restart` runs the public command `kvcustomizer.app.restart` (`{}` → `{ restarting: true }`), which runs `kernel.restart`. It has `asks: true`, so the person is asked first, whatever `kvcoder.shell.approval` says (ADR 0022, 5). It follows `extensions-uninstall` in the connector's list.
8. **The guide for the agent changes** (ADR 0023, 4): after a change to the extensions or the preset, it makes one `kvman restart` call whose `description` says in plain words what stops (running work, a preview, a server it started), tells the person that the terminal may ask them to trust a new extension, and that the page may need to be reloaded when kvman is back; it reads `health-get` after the restart and, if `rolledBack` is set, says that the change was undone and why, and fixes it. "You can't restart it yourself" is gone.
9. **The Extensions page has "Restart now".** The banner "Restart kvman to apply" gets a button that asks once, inline ("Restart kvman? What is running stops."), calls `kernel.restart`, shows "Restarting…", asks `kernel.health.get` every second until it answers after not answering, or answers with a smaller uptime, and then reloads the page. When `kernel.health.get` has `rolledBack`, the page shows a banner with its message ("The last change was undone because kvman couldn't start with it").
10. **Left out.** A continuation of the turn that asked for the restart; a restart of a preview's kvman (it ends with its parent); restarting from another mode (there is only `web`); a restart that applies a change without stopping the run.
11. **The names.** `kernel.restart`, `kvcustomizer.app.restart`, the connector word `restart`, the file `<preset file>.good`, and the health field `rolledBack`.

## Consequences

- Plan 01 §1.2, plan 02 §2.10, §2.12, §2.14, and §2.15, plan 06 §6.6, and plan 09 §9.1 and §9.4 are corrected. This changes ADR 0010, 5 ("a restart applies it" is now done by `kernel.restart`), ADR 0022, 15, and ADR 0023, 9.
- `@kvman/sdk` gains `kernel.restart` and `rolledBack`; kvcustomizer and kvwebui change; the CLI becomes a loop.
- No new dependency.
