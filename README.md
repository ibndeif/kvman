# kvman

An app that works like a small operating system for every kind of user: a kernel runs extensions, and a preset shapes them into the app a person uses.

The specification is `plan/` (start with `plan/README.md`). The previous implementation is on the branch `archive/v2`.

```
kvman [--mode web] [--preset coder] [--home <dir>] [--port <n>] [--yes] [--no-open] [--log-level <level>]
```

## Developing

Node 24 and pnpm (the version in `package.json` `packageManager`).

```
pnpm install
pnpm typecheck && pnpm lint && pnpm test && pnpm build && pnpm bench:check
```

| Script | Does |
|---|---|
| `pnpm typecheck` | TypeScript 6.0 strict on every package and the repository's own tooling |
| `pnpm lint` | ESLint: the import walls (`eslint/`), 300 lines per file, no `any`, and the other `CLAUDE.md` §5 rules |
| `pnpm test` | Vitest |
| `pnpm build` | Builds each package into its `dist/` |
| `pnpm bench:check` | Runs the benchmarks against their targets and `bench/baseline.json`; `pnpm bench:record` stores a new baseline |
| `pnpm changeset` | Adds a changeset (needed for every change to `@kvman/sdk`, `@kvman/testkit`, or an extension) |

| M1.3 Storage | The kernel's storage, not yet reachable from a running kvman: `kvman.db` (SQLite, WAL) with the kernel's tables; the store (kv and collections checked by their schema, `find` and `count`, transactions, workspace and global scopes, the 16 MiB cap); settings resolution with scopes; `secrets.json` with atomic writes; files with the 1 GiB cap; UUIDv7 ids. `pnpm bench:check` runs the collection `find` benchmark. |

| M1.6 Workspaces, kernel API, localization, hot reload | Workspaces (Home, remembered folders, closing as a pause, reopening by path) and the `kernel.workspace.opened` point; every `kernel.*` command and query (settings with scopes, secrets by name only and `set` sync only, jobs, files, extensions with JSON Schemas and revisions, processes, health), typed through `@kvman/sdk`; `ctx.settings.set`, `ctx.files`, and `ctx.processes` (process groups on Linux and macOS, `taskkill` on Windows, capped logs, `kernel.process.exited`, leftovers killed at start); locale catalogs merged per language with the `en` fallback, and the open `kernel.language`; hot reload of `path:` extensions (fresh workers while the old ones drain, the old code kept on failure, `kernel.started` rerun for dependents). |
| M1.7 HTTP | The kernel's HTTP API (`startHttp`, Hono on 127.0.0.1): Host and Origin checks (`FORBIDDEN_ORIGIN`); the envelope routes for commands (sync and async) and queries, with the `jobId`, route mismatches, raw-body caps, and cancel when a sync call's client leaves; jobs (get, cancel, and the SSE stream of progress, then the result or Problem); uploads and downloads (always attachments, naming their workspace); locales; `kvman.web` folders and `/` with the `index.html` fallback. The route tests arrive with the CLI in M1.8 (ADR 0009, 35); M1.7 unit-tests the pure parts. `pnpm bench:check` adds the HTTP round-trip benchmark. |

| M2.3 kvwebui custom components and effects | Extensions' own Vue components: a `custom` view (`{ component: '<namespace>.<name>', props }`, with `$param` and `$row` in `props`) loads `/web/<namespace>/components/<name>.js` and its `.css` with the extension's revision in the URLs, sharing kvwebui's Vue through the page's import map (build components with `vue` external). A component injects `kvman` (`inject('kvman')`, typed by `@kvman/sdk/web`): `exec` and `execAsync` (both count as commands the UI ran), `stream(jobId)` as an async iterable of progress chunks and the result, `follow`, `navigate`, `toast`, `panel`, `t`, a live `workspace`, and `View` for view trees and Markdown. To try it, put a component in an extension's `kvman.web` folder under `components/` and show it from its `ui.get`. |
| M2.4 kvcoder | `extensions/kvcoder` (`@kvman/kvcoder`), the app-building harness: sessions, turns as chains of async steps (each streams kvai's deltas and sends `follow` chunks; the session's `stepJobId` lets a page reattach), one shell tool (`bash -lc` on Linux and macOS, `pwsh` or `powershell.exe` on Windows, or `kvcoder.shell.path`) with approval, a 120 s default and 600 s cap, tree kills, and 30 KB output cuts; all calls of a reply in parallel, approvals asked together; connectors (`kvcoder.connector.register` with commands or a binary, `-h` from descriptions, schemas, and examples, stdin JSON as a heredoc or a here-string, `--async` with background results as messages, and the `jobs` connector); the built-in `ask` (text, choice, confirm) and `subagent` (fresh or fork, parallel, `--async`); sections (global, workspace, or session, 16 KB each and 64 KB together); session points through `kvcoder.handler.*`; compaction that keeps the last 10 messages; cancel; interrupted steps ended through `kernel.job.failed`; notices and notes, the welcome session of a new workspace, titles, fork, JSON export, image attachments, and daily retention. To try it, start kvman with a preset file such as `{ "name": "try", "extensions": { "@kvman/kvai": "bundled", "@kvman/kvwebui": "bundled", "@kvman/kvcoder": "bundled" }, "settings": { "kvwebui.home": "kvcoder.chat", "kvai.defaultModel": "anthropic/claude-sonnet-5-5" } }` after `pnpm build`, and add your provider's key on the Models page. |
| M2.5 kvdev, presets, and the walkthrough | `presets/coder.json` and `presets/dev.json`: a bare `kvman` starts `coder` (kvai, kvwebui, kvcoder), and `kvman --preset dev` adds `extensions/kvdev` (`@kvman/kvdev`), which extends kvcoder with the `ext`, `preset`, `preview`, and `docs` connectors and a global prompt section. `ext new '{"name":"notes","namespace":"notes","folder":"notes"}'` scaffolds a project (`src/index.ts` loaded with no build, a sample query and page, `en` and `ar` catalogs, a passing `node:test` test, and with `"web": true` a Vue component and its per-component Vite build) and runs `npm install`; `ext list`, `ext check` (TypeScript, then the testkit's new `kvman-check`), and `ext test` work on projects in the workspace; `preset new` writes a preset that runs as-is and `preset check` checks its extensions, settings, and home page; `preview start` runs a second kvman on a temporary home and port 3738 or the next free one, with the projects as `path:` extensions (edits reload live) and their `web:watch`, and returns its URL, which kvcoder's result card shows as a link.
