# kvman

kvman is a local **actor runtime with a UI shell**: a small kernel delivers typed messages between actors (extensions, people, processes) and commits their effects atomically. Every feature, including the AI agent, is an extension. The specification is in [`plan/`](plan/README.md); working rules are in [`CLAUDE.md`](CLAUDE.md).

| M1.7 Deadlines, cancellation, supervision | done | Each invocation gets a deadline at claim: `min(deadlineAt, claim + timeoutMs)`, with defaults of 60 s for commands, 30 s for events, and 5 s for queries. At that moment the host is sent `abort` and `ctx.signal` fires. The attempt ends at once with `DEADLINE_EXCEEDED` (final), `HANDLER_TIMEOUT` (retried with a fresh timeout), or `QUERY_TIMEOUT`, and whatever the handler returns later is discarded. A handler still running 2 s after its abort makes its worker stuck: the worker is stopped, its extension is charged, and the other invocations on it return without an attempt penalty. Pending and awaiting messages expire from a deadline wheel that survives restarts; a deferred command also sends its `onAbort`. `ctx.command` inherits the caller's deadline; `ctx.send`, timers, and continuations do not. Nested `ctx.command` calls stop at depth 8. `kernel.cancel { messageId } \| { correlationId }` runs in the in-process kernel host. It walks every descendant (including transient deliveries), ends each unfinished one with `CANCELLED` and its `onAbort`, aborts running handlers, and frees their lanes; only the caller's own messages may be cancelled unless it holds `kernel.admin`. A crash charges every extension running on the worker; three charges within 10 minutes quarantine it (`HOST_FAILURES`), and manifest drift quarantines with `EXT_MANIFEST_INVALID`. A quarantine is stored and announced with `kernel.extension.quarantined`, is refused at admission, and leaves the extension's pending messages waiting. `pnpm vitest run packages/testkit/test/supervision` |
| M1.8 Lifecycle and minimal adapters | done | `kvman start` runs the kernel as a daemon, one per home folder: `--home`, else `KVMAN_HOME`, else `~/.kvman`. | M2.7 Reload, versions, migrations, schedules | done | `kernel.extension.reload { name, digest?, grants? }` (admin; with `grants`, a person) switches an extension to any installed digest, or reloads the active one. | M2.8 Presets lifecycle and preview workspaces | done | The preset catalog lives in the `presets` table: `kernel.presets.list` (by name, then id), `kernel.preset.get`, `kernel.preset.current.get` (the applied copy, with its `config` rebuilt from the workspace's config rows), and `kernel.preset.export.get { presetId } | { workspaceId }` (shareable JSON: integrity kept, local digests removed). `kernel.preset.import.preview { json }` checks a preset without changing anything and refuses it with every issue and one code (`PRESET_INVALID`, then `PRESET_UNSHAREABLE` for loose, `dev:`, or `local:` sources and digests, then `PRESET_SECRET`); a built-in id is `PRESET_READONLY`. Its signed token carries the preset, so `kernel.preset.import { confirmationToken }` (a person) needs nothing else (ADR 0147). `kernel.preset.save` stores a workspace's copy under an id derived from the name (`مترجم` → `preset`, `-2`, `-3` when taken), and `kernel.preset.delete` removes a non-built-in entry (ADR 0149). `kernel.preset.apply.stage { workspaceId, presetId | json }` (admin) fetches every version the preset names, enabled or not: builtins always use the bundled version, `npm:` and `git:` entries reuse an installed version with the same source and integrity or are fetched and must match it (`PRESET_INTEGRITY_MISMATCH`). It runs every check of apply (grants, rollbacks, version switches, namespaces, required types, config) and answers the preview: installs with their capability requests, enables, disables, version switches with each other workspace's capability diff, notes, pages, config fields, and hidden items, with a 10-minute token. `kernel.preset.apply { confirmationToken }` (a person) checks again, imports and installs in one unit, switches versions through reload, migrates newly enabled extensions' data, and commits the applied copy at its revision + 1 with the preset's config rows, `kernel.extension.enabled`/`.disabled`, and `kernel.preset.changed { cause: 'apply' }`; a failure keeps the previous preset (ADR 0148). `kernel.preset.update { workspaceId, patch, revision }` applies a JSON Merge Patch to the listed keys; a patch that touches `extensions` is a person's only and may change only `enabled`, `grants`, and `disable` (ADR 0149). A trusted folder's `.kvman/preset.json` shows as `repoPreset` on `kernel.workspace.get` and is read with `kernel.workspace.preset.get` through the trust gate (ADR 0150). `kernel.workspace.preview.create { name, from }` makes a workspace under `<home>/previews/<name>/` with a copy of `from`'s preset and config; there an extension with `kernel.admin` may enable `dev:` sources, and every `dev:` enable is sandboxed and never granted `process`, `network`, or `kernel.admin`; previews are never trusted, and forgetting one deletes its folder (ADR 0150). `kernel.validate { workspaceId }` now runs the non-UI checks against a workspace (ADR 0151). `pnpm build` packs `presets/*.json` into the kernel's builtin folder; a first run seeds them into the catalog and an upgrade re-seeds them (ADR 0146; none ship until their extensions do). The fault points `preset.apply.after-stage` and `preset.apply.after-version-switch` are covered. `pnpm vitest run packages/testkit/test/presets packages/testkit/test/faults/presets.test.ts packages/kernel/test/presets packages/protocol/test/presets.test.ts` |

A daemon serves the kernel's own types and the extensions it installs and enables:

- health, schema, and validation: `kernel.health.get`, `kernel.schema.get`, `kernel.validate`;
- extensions: `kernel.extensions.list`, `kernel.extension.get`, `stage`, `install`, `uninstall`, `enable`, `disable`, `reload`, `rollback`, and `unquarantine`;
- workspaces: `kernel.workspace.open`, `rename`, `forget`, `preview.create`, `kernel.workspaces.list`, `kernel.workspace.get`, and `kernel.workspace.preset.get`;
- presets: `kernel.presets.list`, `kernel.preset.get`, `current.get`, `export.get`, `import.preview`, `import`, `apply.stage`, `apply`, `update`, `save`, and `delete`;
- config and secrets: `kernel.config.get` and `set`, `kernel.secret.set` and `clear`;
- inspection: `kernel.messages.list` (admin only), `kernel.subscribers.list`, and `kernel.processes.list`;
- `kernel.cancel` and `kernel.shutdown`.
