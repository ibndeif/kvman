# kvman

kvman is a local **actor runtime with a UI shell**: a small kernel delivers typed messages between actors (extensions, people, processes) and commits their effects atomically. Every feature, including the AI agent, is an extension. The specification is in [`plan/`](plan/README.md); working rules are in [`CLAUDE.md`](CLAUDE.md).

| M1.6 Shared hosts and `ctx` messaging | done | Handlers run in a shared pool of worker threads (`min(4, cores - 1)`, at least 1, started lazily; each invocation goes to the least-loaded worker). A worker imports an extension, re-runs `setup` to bind its functions, and refuses a recording that differs from the installed manifest (`EXT_MANIFEST_INVALID`). Kernel and hosts talk in validated frames (`invoke`, `rpc`, `rpcResult`, `complete`), and a bad frame counts as the loss of that worker. One dispatch path serves every kind: commands and durable event deliveries through inbox rows; transient events as deliveries without rows; queries on the priority path, answered in memory and never stored. `ctx` has `message`, `context`, `workspace`, `ids`/`now` (recorded and replayed on redelivery), `command` (waits; key `<id>:command:<n>`; `LANE_REENTRANT` checked first), `send` (with `idempotencyKey` and `onReply` continuations), `query`, `publish`, `live` (own live events only; resets for attempts that do not commit), `defer`/`reply` (`REPLY_NOT_AWAITING`, `onAbort` stored), `problem` (registered errors), `step`, `store`, and `log` (attributed and redacted). Queries can only read and query. A worker that exits fails its attempts as retryable `INTERNAL` and is replaced. Kernel schema 2 adds `messages.on_abort` and `recorded_values`. `pnpm vitest run packages/testkit/test/hosts` (real workers) and `packages/kernel/test/hosts` |
| M1.7 Deadlines, cancellation, supervision | done | Each invocation gets a deadline at claim: `min(deadlineAt, claim + timeoutMs)`, with defaults of 60 s for commands, 30 s for events, and 5 s for queries. At that moment the host is sent `abort` and `ctx.signal` fires. The attempt ends at once with `DEADLINE_EXCEEDED` (final), `HANDLER_TIMEOUT` (retried with a fresh timeout), or `QUERY_TIMEOUT`, and whatever the handler returns later is discarded. A handler still running 2 s after its abort makes its worker stuck: the worker is stopped, its extension is charged, and the other invocations on it return without an attempt penalty. Pending and awaiting messages expire from a deadline wheel that survives restarts; a deferred command also sends its `onAbort`. `ctx.command` inherits the caller's deadline; `ctx.send`, timers, and continuations do not. Nested `ctx.command` calls stop at depth 8. `kernel.cancel { messageId } \| { correlationId }` runs in the in-process kernel host. It walks every descendant (including transient deliveries), ends each unfinished one with `CANCELLED` and its `onAbort`, aborts running handlers, and frees their lanes; only the caller's own messages may be cancelled unless it holds `kernel.admin`. A crash charges every extension running on the worker; three charges within 10 minutes quarantine it (`HOST_FAILURES`), and manifest drift quarantines with `EXT_MANIFEST_INVALID`. A quarantine is stored and announced with `kernel.extension.quarantined`, is refused at admission, and leaves the extension's pending messages waiting. `pnpm vitest run packages/testkit/test/supervision` |

| M1.8 Lifecycle and minimal adapters | done | `kvman start` runs the kernel as a daemon, one per home folder: `--home`, else `KVMAN_HOME`, else `~/.kvman`. A folder that holds other files and no `kvman.db` is refused with `HOME_INVALID`. The daemon binds 4173, else the next free port up to 4199, or exactly `--port`, and only then writes `daemon.lock` `{ pid, processStart, nonce, port, startedAt }` atomically. A lock whose process is alive with the same start time is `DAEMON_CONFLICT`; any other lock is taken over. Boot recovers what a crash left running (the attempt counts, and at `maxAttempts` the message is dead) before the scheduler claims anything, then publishes `kernel.started` and records `kvman.version`. Shutdown (`kvman stop` → `kernel.shutdown`, SIGTERM, or SIGINT) refuses new work with `KERNEL_STOPPING`, gives running handlers 10 s, sets the rest back to pending without counting an attempt, answers waiting requests `202`, closes the event streams, and releases the lock. HTTP (`/api/v1`): `GET /health` (= `kernel.health.get`, `degraded` while an extension is quarantined), `POST /commands/:type` (`200 { id, reply }` within `wait`, else `202 { id, state }` with the late reply sent to the tab's stream), `POST /queries/:type`, and `GET /messages/:id`. Failed replies and refusals are Problems with the status of their code. Every request passes the Host, Origin, and `Sec-Fetch-Site` checks first. The event stream (`GET /events`) sends `hello` first, then `event` (a durable event's seq is its `id:`), `live` (the ring first), `reply`, `resync`, and `close`, plus a ping every 20 s. Subscriptions outlive a disconnect for 5 minutes, and `Last-Event-ID` or `since` replays what was missed. Over a 1 MB send buffer, live messages are dropped first, then the stream closes as a slow consumer. Kernel logs are Pino JSON in `logs/kernel.log`, rotated daily and at 50 MB, with 14 files kept. `pnpm vitest run packages/cli packages/testkit/test/daemon packages/testkit/test/adapters` |

## Requirements

- Node 24 LTS
- pnpm 12.6.0 (pinned in `package.json`; `corepack pnpm` or any pnpm that switches to the pinned version)

## Commands

```sh
pnpm install
pnpm typecheck     # tsc for every package (sources resolved through the @kvman/source condition) and the repository tests
pnpm lint          # ESLint with zero warnings allowed: import walls, max 300 lines per source file, code rules
pnpm test          # Vitest: every test in the repository (and a check that each milestone scenario has exactly one test)
pnpm build         # tsc builds every package into dist/, in dependency order
pnpm bench:check   # benchmark regression gate; prints "no baseline yet" until M1.9
node packages/kernel/scripts/permission-probe.ts   # the sandbox probe on its own: prints its report, exits 1 on any bypass
```

Run a kernel (from the sources; `pnpm build` makes `packages/cli/dist/main.js` the `kvman` binary):

```sh
node --conditions=@kvman/source packages/cli/src/main.ts start [--home <dir>] [--port <n>] [--foreground]
node --conditions=@kvman/source packages/cli/src/main.ts status [--home <dir>]   # the /health JSON, or "kvman is not running" (exit 1)
node --conditions=@kvman/source packages/cli/src/main.ts stop [--home <dir>]
curl http://127.0.0.1:4173/api/v1/health       # the port is in <home>/daemon.lock
```

Until M2.2 installs extensions, a daemon serves only the kernel's own types (`kernel.health.get`, `kernel.cancel`, `kernel.shutdown`).

A milestone is done when all five pass: `pnpm typecheck && pnpm lint && pnpm test && pnpm build && pnpm bench:check`. There is no CI for now (ADR 0007); the gates run locally.
