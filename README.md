# kvman

kvman is an app that works like a small operating system. A kernel runs extensions, and a preset chooses which extensions run and how they are set up, which makes the app a person uses. Every feature is an extension, including the web UI and the AI agent. The bundled preset, `coder`, is an AI agent that works in your folders. Your own preset can be a different product built on the same pieces.

## Install and run

You need Node.js 24.

```sh
npm i -g kvman --no-fund --loglevel=error
cd ~/projects/my-app
kvman
```

kvman runs in the foreground on `127.0.0.1:3737`, opens the folder you start it from as a workspace, and opens the app in your browser. Press Ctrl+C to stop it. Then connect a model on the **Models** page and ask the agent something on the **Chat** page.

```text
kvman [--mode web] [--preset coder] [--home <dir>] [--port <n>] [--yes] [--no-open] [--log-level <level>] [--pipe]
kvman uninstall [--home <dir>] [--yes] [--keep-data | --delete-data]
```

Every flag is described in [installing](docs/user-guide/installing.md). `kvman uninstall` removes kvman, and asks before it deletes your data.

## What you get

- **An agent in your folders.** It reads the project and asks about the decisions only you can make. It plans larger work on an **execution map** that you approve, and works through connectors (shell, files, artifacts, MCP servers, your own programs). It asks before risky calls, can hand focused jobs to specialist workers in the background (each run titled with the expert it needs, such as "Node.js streams expert", which the helper is told it is on its prompt's first line, and a brief with one kind, find, change, check, or review, a goal, a done condition, the files a change may touch, and a step budget; their answers wake the chat, you can keep talking meanwhile, and each worker's card shows its headline, step, time, and last call; helpers think at medium, and never above `kvcoder.delegate.thinkingLimit`, high by default), puts a complex request whose approach is open to the **council** worker first (a debate between an engineer, a devil's advocate, a dumb customer, and the field's top expert, ending in one final plan), and works in few steps, reading several files at once. Its prompt doesn't tell it to run or write tests: say so in your request or in the project's `AGENTS.md` when you want them. A chat's old tool results are cleared in large batches so the model's cache keeps answering quickly, and past 60K tokens finished turns shrink to one line each, which names the files and artifacts the turn changed, so the agent keeps an artifact's id (and `artifact list` names them all); a lost connection waits and goes on by itself, an MCP server over HTTP or with a port keeps its session for the turn, project rule files are kept for the chat (an edit is told once), `notify` on a background line wakes the chat when it ends, and the **Running** popover can restart a dev server or run an ended one again without asking the agent. A preview of a dev server goes from the chat's artifacts when the server ends; you or the agent can delete an outdated artifact, and an optional age limit clears old ones. See [the coding app](docs/user-guide/coding-app.md) and [how the agent works](docs/user-guide/the-agent.md).
- **A chat you can read and review.** The agent talks as it works: every reply that makes a call starts with a short sentence on what it does and why, a go-ahead you gave is never asked again, and its last answer gives the result first for each thing you asked; helpers finish their whole job, and a helper's result that needs nothing from you arrives without a reply. The calls under each step fold into short rows titled by the step's headline and saying what they did ("Checking why the import fails · Read 3 files, changed 1 file, ran 1 command"), with its thinking one press away, and a finished background job is one quiet line (✓ or ✗, its name, how long it ran); the running line shows the latest headline, the turn's time, and the map's step in progress, and a test that fails while the agent fixes it reads calmly (`exit 1`), not as an alarm, counts read right in English and Arabic, its answer is marked, a **Changes** view shows each file the chat changed as a diff you can undo or ask it to commit, and **Edit** on a message you typed, or **Undo** on the latest one, takes the chat back to just before it, with the files kvman changed since ([ADR 0118](plan/adr/0118-edit-and-undo-a-message.md)). Approvals can be remembered per command ("Always allow"), denied with a reason, or skipped entirely with **Decide for me**; your standing **preferences** reach every chat, kvman notifies you when a chat needs you, and the agent reads web pages as Markdown, asking before each new site ([the coding app](docs/user-guide/coding-app.md)).
- **UI in the chat.** The agent can answer with cards, choices, follow-up suggestions, short forms, and buttons instead of text alone, drawn in kvman's theme and in Arabic right to left: a fenced `openui` block in a reply, or an artifact with `format: 'openui'` for a dashboard or report you keep. Pressing a button or sending a form sends your answer as your next message (only in the newest reply and in artifacts; older replies stay as they were), and nothing it draws reaches the network. The agent reads the reference it needs with `openui guide`, by place and by component group; turn the `openui` connector off on kvcoder's page to keep it to text. It uses [OpenUI](https://github.com/thesysdev/openui)'s language (OpenUI Lang 0.5, read by `@openuidev/vue-lang`) and OpenUI's own components by their names, drawn by kvwebui ([ADR 0124](plan/adr/0124-openui.md)); M5.18 has its layout, content, form, button, icon, tag, follow-up, and section components, and tables, charts, card blocks, and images come next. What only the owner can check, with a model (M5.18-H21): in a real chat, in English and then in Arabic, ask for something with a choice to make; the agent reads `openui guide` and the groups it needs, answers with buttons and follow-ups and a short form, and reads and acts on the answer it gets.
- **Any model.** Sign in with a Claude, ChatGPT, or GitHub Copilot plan, use an API key, or point kvman at your own server ([models and providers](docs/user-guide/models-and-providers.md)). New models, such as GPT-6.1 Terra, appear without a kvman release: the coder preset takes them from pi.dev's live catalog at start and every 4 hours ([ADR 0110](plan/adr/0110-live-model-catalog.md)).
- **An app you can change by asking.** Type `/build-kvman` in a chat to have the agent change kvman's model, settings, and extensions, or build a new extension or a separate app for you ([building kvman](docs/user-guide/building-kvman.md)).
- **A platform for your own products.** A preset can turn kvcoder's agent into a product for people who aren't developers: its own identity, its own words, and no developer screens. It can ship as a desktop app of its own ([building a product](docs/developers/products.md)).
- **Local by design.** kvman listens only on 127.0.0.1. Your data stays in one folder (`~/.kvman`), and secrets stay in `secrets.json`. kvman has no telemetry ([privacy and security](docs/user-guide/privacy-and-security.md)).

## The desktop app

`packages/desktop` is a Tauri shell around the same kvman. It starts `kvman --pipe` and shows a home screen where you choose a workspace or open a folder, then shows kvman in its own window. It asks about new extensions in a dialog. Closing the window stops kvman. It is described in [the desktop app](docs/user-guide/desktop-app.md) and specified in [plan/14-desktop.md](plan/14-desktop.md).

```sh
pnpm build && pnpm desktop:dev                # run it from the repository
pnpm desktop:build                            # build the app, with its own Node and kvman, for this system
pnpm desktop:brand <brand.json>               # build a product's own desktop app and its installers
```

It needs Rust with `rustfmt` and `clippy`. On Linux it also needs Tauri's libraries (`libwebkit2gtk-4.1-dev` and the others in [Tauri's prerequisites](https://v2.tauri.app/start/prerequisites/)).

## The VS Code extension

`packages/vscode` shows kvman in VS Code's side bar, under its own activity bar icon, like a native chat extension. It runs the `kvman` on the PATH with `--pipe` in the window's first folder (or offers to install it), and frames the web app embedded (`?embed=parent`): no frame of its own, VS Code's colors and fonts, Pages, Settings, and Open in browser in the view's title bar, "Open diff" and file paths that open in VS Code's editor, "Add to kvman chat" from the editor and the explorer, and sign-ins in the system's browser. A page can offer the title bar's **New** button (kvcoder's chat does); the Pages menu also lists panels and has a **Language** row; a slim status line shows the status items; and **Ctrl+Alt+K** adds the selection or the open file to the chat. The window that started kvman stops it when it closes, and another window notices at once (the frame posts `kvman.lost`), starts kvman again, and reloads its view. The view's text is VS Code's size, and at side-bar width the chat's header stays on one row and the artifact panel's name has its own row. kvman must be at least as new as the extension: an older `kvman` on the PATH shows **Update kvman**, and an older kvman that is already running shows **Start again** and **Open anyway**. Remote windows aren't supported yet. It is described in [the VS Code extension](docs/user-guide/vscode-extension.md) and specified in [plan/15-vscode.md](plan/15-vscode.md) (ADR 0099, ADR 0100, ADR 0101, and ADR 0106).

```sh
pnpm vscode:package                           # build packages/vscode/dist/kvman.vsix
code --extensionDevelopmentPath=$PWD/packages/vscode/dist/extension   # try it after pnpm build
```

The setting `kvman.path` names the `kvman` to run, such as a script that runs `node packages/cli/dist/main.js`.

## Videos

kvvideo (`extensions/kvvideo`, bundled in `coder`) makes any kind of video: a lesson, an explainer, a tutorial, a promotion, a story, a social clip. Type `/video` in a chat to give it the `video` connector and its production guide, loaded in that chat only: a workflow of ten stages for any kind of video (ready, brief, research, concept, treatment, production map, voice first, pictures, assemble and review, deliver), then how a good video looks and sounds. The agent asks only what it couldn't find out, has the council debate a concept that is open and offers you two or three directions, then shows a treatment (the script and storyboard, the look and sound, `style.css`, and style frames) for you to agree to before anything costs money; that agreement starts the production map. Narration comes first and sets the clock the pictures follow; with four or more HTML scenes, designer helpers build them in parallel; the agent reviews and fixes the video in up to three rounds. Videos are polished unless you ask otherwise, there is no music, and images are never generated. `video look` shows the agent a page's or a website's frames at up to six moments, so each scene is checked before it is narrated and recorded; a page's animations wait for the recording to start, so an element timed to a caption line arrives with its words. The agent can run `video check`, which says whether ffmpeg (with libass), Chrome or Edge, and a narration service are ready, and `video fonts`, the bundled caption fonts (Amiri, IBM Plex Sans Arabic, Lato, Poppins). `video record` records any website (never kvman's own address), or an HTML page of the workspace with the files beside it, in a fresh, headless Chrome or Edge at 2× density, as an H.264 MP4 encoded by the ffmpeg on the PATH. Its steps (click, type, scroll, wait, and more) move an arrow pointer that appears on its first move along eased, gently curved paths, type at a natural pace, and scroll smoothly; `device: 'phone'` records a touch screen with taps. Given a scene's narration, a step can wait for a caption line with `atLine`. It answers each step's times and the box of its target, writes them in a sidecar `<file>.kvvideo.json` beside the recording, and reports each step as progress. `video narrate` turns a scene's script into an MP3 with the narration service you choose on kvvideo's extension page (ElevenLabs, OpenAI, or Piper on this computer; nothing is chosen until you do), sentence by sentence with 250 ms between sentences, and answers its length and its captions: each sentence's lines start where its audio does, and with ElevenLabs each line and word takes the service's own character times. `tone` (OpenAI) and `speed` (all three) direct the voice, the setting `kvvideo.narration.pronunciations` makes it say words differently without changing the captions, and ElevenLabs hears the sentences around each one so they sound like one take. Every sentence is kept in a cache, so an unchanged sentence is never paid for twice; the answer says how many were reused, and a sidecar beside the MP3 holds the captions. Add the ElevenLabs or OpenAI key there as the secret `elevenlabs.apiKey` or `openai.apiKey`; Piper needs `pip install piper-tts` and a voice's `.onnx` file. `video compose` makes scenes of recorded clips, pages, or images into an H.264 and AAC MP4, 1920 × 1080 by default, and the chat shows a player. A recorded website sits in a window with rounded corners and a soft shadow (or a phone outline when recorded as a phone) on a gradient, colour, or image background, and the camera zooms smoothly to each click and typing and back out; an image zooms slowly. Callouts, highlights, and blurs (for private data) mark places on a recording by its step or a box. Captions come from the narration's sidecar, burned in as `boxed` (the default), `outline`, or `highlight` (word by word with ElevenLabs), or `off`, in a bundled font, the brand's, or a `.ttf` or `.otf` in the workspace; Arabic reads right to left. `video brand` and `brand-set` keep the workspace's logo, colours, and font for every video; scenes are joined by crossfades (the default), cuts, fades through black, or slides (mirrored for right-to-left videos), with quiet sound effects kvvideo made itself (a click, key taps, a whoosh, a pop; `sounds: false` turns them off), and the whole mix is levelled to −14 LUFS. A narration starts 300 ms into its scene. Beside the video come a poster `.jpg` (shown on the chat's player), and a sidecar; `extraSizes` makes up to two more shapes (as 1080 × 1920 for a phone), recording an HTML page again at each shape; `video review` measures a video's silences, black and frozen pictures, and loudness, and makes contact sheets of its frames, labelled with their times, that the agent looks at before saying it's ready; and you can narrate in your own voice: kvcoder's `ask record` shows a card in the chat with each sentence to say (stressed words in bold, pauses marked, the tone and pace, an example to hear), records it with your microphone (in the browser, the desktop app, and VS Code where it allows; else open the chat in a browser or upload a file), and `video voice` cleans the takes (rumble, noise, silence at the ends, level) and joins them with their captions; the newest 10 videos of a workspace stay playable there. kvman's file downloads now answer byte ranges, so a video can seek. kvvideo's end-to-end tests need Chrome and ffmpeg (with libass) installed. A video can also have no voice, just on-screen text and sound effects: then no narration service is needed. In a chat without `/video`, the agent tells you to type it, and a video link's Open in the chat opens it in a new tab ([ADR 0119](plan/adr/0119-fixes-from-the-video-chats.md)). Your own voice needs no narration service, and when you want a generated one the agent can set Piper or a service up for you after asking, with `video narration-set` (Piper and its voices go in `check`'s `toolsFolder`, never in your project). A composed video now passes its own review's loudness check (true peak at most −1 dBTP), `video review` says what each problem measured ("The picture doesn't change for 3.5 s."), flags any 3 s with no change, and leaves an end card's short silence alone; captions are cut into even lines, breaking after commas where they can, and each sentence of a take is its own caption; `ask record` can stress or pause after a run of words ([ADR 0120](plan/adr/0120-videos-that-move.md)). Every HTML scene can load kvvideo's own files from `kvvideo/`: `kvvideo/motion.css`, a motion kit (entrances, exits, emphasis, slow ambient motion, word-by-word text, lines that draw, numbers that count; one element can combine them, and they mirror in right-to-left pages), `kvvideo/brand.css` with your brand's colours and font as CSS variables, your logo at `kvvideo/logo.<ext>`, the bundled fonts, and three.js (with its addons), anime.js, and lottie-web, bundled with kvvideo ([`kit/NOTICES.md`](extensions/kvvideo/kit/NOTICES.md)); `video record` and `video look` list each file a page or site couldn't load, so a missing font is never silently replaced. The production guide now asks for scenes that move at every moment with the motion kit, 3D where it earns it, a moving preview clip in the treatment, re-timing from the recorded voice, and no post-processing outside kvvideo. An HTML scene recorded with only `wait` steps is drawn frame by frame at 60 frames a second on kvvideo's own clock, which drives its CSS animations, `requestAnimationFrame`, timers, `Date`, and `Math.random`: three.js and other script animation come out exact and smooth however busy the computer is, and the same every time; `video look` steps through the same clock. An element with `data-sound="pop"` (or `whoosh`, `click`) plays that sound as it enters, crossfades get a soft whoosh, every finished video is 60 frames a second, a recorded page slowly pushes in, and captions are boxed in your brand's colour by default (outlined when there is no brand). The guide's craft lives in six notes the agent reads with `video craft` when a stage needs them (`story`, `scenes`, `motion`, `charts`, `tutorial`, `social`): how to open and structure a script, write numbers as they are said, and hold the key moment; scene patterns, frame layout, and sizes for video; varied motion and what each transition means; charts that build in time; tutorials narrated by outcome; and social clips that hook in their first second. Designer helpers read the scene and motion notes themselves before building ([ADR 0121](plan/adr/0121-craft-notes-for-better-videos.md)). It is specified in [plan/16-kvvideo.md](plan/16-kvvideo.md) (ADRs 0107, 0115, 0117, 0119, 0120, and 0121).

The whole video by hand (plan 16 §16.12) runs here as `extensions/kvvideo/test/e2e/whole-video.test.ts`: an Arabic title page, a website in a window and on a phone, and an image, with the camera, a callout, a highlight, a blur, every transition, sound effects, and Arabic and English captions in each style, each reviewed. What only the owner can check, with their keys and hosts:

- Have the agent use a licensed image from the web: it is saved in the video's folder, with its source and licence in the script.
- Narrate once with ElevenLabs and once with OpenAI, with `tone` and `speed`: each plays with its captions in time.
- Record a scene with `ask record` in the browser, in the desktop app on Linux, macOS, and Windows, and in VS Code: each host records, or shows its fallback (open the chat in a browser, or upload a file).
- Make the KVCare promotion again with `/video` ("promotional video about kvcare in Arabic", your own voice, 16:9) (ADR 0120, M5.16-H3): no key is asked for, the treatment shows a moving preview, every scene moves in the app's font and colours with its logo, there are sound effects, the captions are even or off, and `video review` reports no problem.
- Make an explainer with a chart and a tutorial of an app with `/video` (ADR 0121, M5.17-H5): the agent reads `video craft` `story`, `scenes`, `motion`, and `charts` (and `tutorial` for the tutorial) at their stages, and its designer helpers read `scenes` and `motion`.

## Developing

You need Node 24 and pnpm (the version in `package.json`'s `packageManager`).

```sh
pnpm install
pnpm build
node packages/cli/dist/main.js        # run kvman from source
```

Before a commit, every gate must pass:

```sh
pnpm typecheck && pnpm lint && pnpm test && pnpm build && pnpm bench:check
```

`node release/candidate/local-candidate-main.ts` runs the same gates once, in that order, and stops at the first failure. It also checks the published packages' names and their JavaScript and declaration entries. It runs on this machine only: it doesn't cover other platforms, Rust, or the installers.

| Script | Does |
|---|---|
| `pnpm typecheck` | TypeScript strict on every package and the repository's own tooling |
| `pnpm lint` | ESLint: the import walls, 300 lines per file, no `any`, and the other rules in `CLAUDE.md` §5 |
| `pnpm test` | Vitest |
| `pnpm build` | Builds each package into its `dist/` |
| `pnpm bench:check` | Runs the benchmarks against `bench/baseline.json`; `pnpm bench:record` stores a new baseline |
| `pnpm desktop:check` | The desktop shell's Rust: `cargo fmt --check`, `cargo clippy` with warnings as errors, and `cargo test` |
| `pnpm desktop:dev`, `desktop:build`, `desktop:brand` | Run, build, or brand the desktop app |
| `pnpm vscode:package` | Builds the VS Code extension and packs it into `packages/vscode/dist/kvman.vsix` |
| `pnpm changeset` | Adds a changeset, needed for every change to `@kvman/sdk`, `@kvman/testkit`, or an extension |
| `pnpm --filter @kvman/kvwebui openui:reference` | Writes kvwebui's OpenUI reference pages into `extensions/kvwebui/docs/` after an OpenUI component's definition changes; a test fails while they differ |

The rules for changing kvman are in `CLAUDE.md` and [contributing](docs/developers/contributing.md). [`milestones/`](milestones/) holds what each milestone built and the scenarios that test it.

## Releasing

Nine packages are published to npm under MIT: `kvman`, `@kvman/sdk`, `@kvman/kernel`, `@kvman/testkit`, and the five extensions `@kvman/kvai`, `@kvman/kvwebui`, `@kvman/kvcoder`, `@kvman/kvbuilder`, and `@kvman/kvvideo`, which `kvman` depends on ([ADR 0026](plan/adr/0026-npm-publishing.md)).

1. `pnpm changeset version` turns the pending changesets into versions and changelogs.
2. Set the version of the root, `packages/kernel`, `packages/cli`, and `packages/vscode`. Run every gate, then commit. The release workflow runs no tests, so the tests run here are the only ones that count.
3. Tag the commit `v<root version>` and push the tag.

[`.github/workflows/release.yml`](.github/workflows/release.yml) runs on the tag. It stops unless the tag is `v<root version>`. It runs `pnpm build`, `pnpm typecheck`, and `pnpm lint`, then `pnpm changeset publish`, which publishes each version that isn't on npm yet. It uses npm trusted publishing; only the first release needed a token, in the repository secret `NPM_TOKEN`.

Its `vscode` job packs the VS Code extension, attaches `kvman.vsix` to the tag's draft GitHub Release (creating the draft when there is none), and publishes it to the Visual Studio Marketplace and Open VSX under the publisher `ibndeif`, with the repository secrets `VSCE_PAT` and `OVSX_PAT` ([ADR 0099](plan/adr/0099-vscode-extension.md)). The publisher and both tokens must exist before the first tag that carries the extension.
